Lec 09 · Section 1 · บท 0034

ตัวเลขไม่เต็ม และ RAM vs QRAM

📖 อ่านเต็ม: บท 0034 · โหลดข้อมูลจริงเข้า register: fixed point → RAM → QRAM (สไลด์ Lec 09 p1–21)

ตั้งแต่ Lec 02 เราใส่ input ด้วย WRITE เป็นจำนวนเต็มเล็กๆ ที่พิมพ์เองมาตลอด · แต่ข้อมูลจริงมีทศนิยม และเก็บอยู่ใน memory เป็นพันเป็นหมื่นค่า · คาบนี้จึงเปิดด้วยคำถาม 2 ข้อ: ① จะแทนข้อมูลที่ซับซ้อนใน register ยังไง และ ② จะโหลดข้อมูลที่เก็บไว้เข้า register ยังไง

⭐ 1.1 fixed point (จุดทศนิยมตายตัว) และ Q notation

คอมพิวเตอร์ธรรมดาเก็บทศนิยมได้ 2 แบบ คือ floating point (ยืดหยุ่นแต่ซับซ้อน) กับ fixed point · สไลด์เลือก fixed point เพราะง่ายกว่า และ qubit มีราคาแพง · หลักการคือตกลงกันไว้ล่วงหน้าว่าบิตไหนเป็นจำนวนเต็ม บิตไหนเป็นเศษ · ฝั่งจำนวนเต็มมีค่า 1, 2, 4, … เหมือนเดิม · ฝั่งเศษไล่ลงจากจุดไปเป็น ½, ¼, ⅛, … (ขยับขึ้น 1 บิตค่า ×2 ขยับลง 1 บิตค่าก็ ÷2)

Qn.m = register n บิตทั้งหมด ซึ่ง m บิตเป็นเศษ → เหลือ n − m บิตเป็นจำนวนเต็ม · (Q ตรงนี้ไม่ได้ย่อมาจาก quantum)

ตัวอย่างในสไลด์ (Figure 9-1): เก็บ 3.640625 ใน register 8 qubit แบบ Q8.6 (เศษ 6 บิต, จำนวนเต็ม 2 บิต):

① อ่านสายจากล่างขึ้นบน: 1 1 │ 1 0 1 0 0 1 → 11101001
② บวกเฉพาะสายที่เป็น 1: 2 + 1 + ½ + ⅛ + 1/64 = 2 + 1 + 0.5 + 0.125 + 0.015625 = 3.640625 ✓

ข้อแลกเปลี่ยน: เพิ่มบิตฝั่งจำนวนเต็ม = ได้ range (ช่วงค่า) กว้างขึ้น · เพิ่มบิตฝั่งเศษ = ได้ accuracy (ความแม่นยำ) ละเอียดขึ้น · เลขส่วนใหญ่ (เช่น 0.1) เขียนเป็นผลรวมของ ½, ¼, ⅛, … ได้ไม่ลงตัว จึงเก็บได้แค่ค่าใกล้เคียง

มักเข้าใจผิด: n ใน Qn.m คือจำนวนบิตทั้งหมด ไม่ใช่จำนวนบิตของส่วนจำนวนเต็ม · Q8.6 จึงมีจำนวนเต็มแค่ 2 บิต · และ register ไม่รู้ตัวเองว่าเข้ารหัสแบบไหน: บิต 1101 เป็นได้ทั้ง 13, −3 (two's complement) หรือ 3.25 (Q4.2) · คนเขียนโปรแกรมต้องจำเอง

⭐ 1.2 RAM ธรรมดา: โหลดได้ทีละค่า

RAM รับ address register (ตำแหน่งที่อยากอ่าน) แล้วเขียนค่าที่เก็บไว้ ณ ตำแหน่งนั้นลง output register · ถ้าต้องการแค่ค่าเดียว ก็ใช้ได้สบาย: อ่านค่าจาก RAM → write() ลง register → คำนวณ → read() กลับ · สไลด์ยกตัวอย่าง a = [4,3,5,1] แล้วให้ QPU บวก 1 ให้ a[2] (5 → 6) ด้วยวงจร +1 ของ Lec 05 (Figure 9-3)

ทวนของเก่า · วงจร +1 (Lec 05) CCNOT(0x1, 0x2 → 0x4) → CNOT(0x1 → 0x2) → NOT(0x1) · ไล่จากบิตบนลงล่างคือการ "ทด" แบบบวกเลขฐานสอง · เช่น 5 = 101 → CCNOT ไม่ทำงาน (0x2 = 0) → CNOT พลิก 0x2 → NOT พลิก 0x1 → 110 = 6 · ทวนเต็มที่ บท 0018

ปัญหา: ถ้าอยากให้ register เป็น superposition ของค่าที่เก็บไว้ เช่น a[2] กับ a[3] พร้อมกัน · RAM ทำไม่ได้เลย เพราะคนเลือก address คือ CPU ธรรมดาที่เลือกได้ทีละ address และ write() รับได้แค่ค่าเดียว

⭐ 1.3 QRAM: address เป็น superposition ได้

QRAM (Quantum RAM) เหมือน RAM ทุกอย่าง คือรับ address register กับ output register · ต่างกันที่ทั้งสองตัวเป็น qubit register · จึงใส่ address เป็น superposition แล้วได้ output เป็น superposition ของค่าที่เก็บไว้ กลับมา

ตัวอย่างเดิมเป๊ะ (a = [4,3,5,1] + วงจร +1) แต่เปลี่ยนวิธีโหลดเป็น QRAM (Example 9-2 / Figure 9-5):

var qram = qram_initialize(a, reg_qubits);   // เอา array ใส่ QRAM
qreg.write(0);
addr.write(2);
addr.hadamard(0x1);      // address = |2⟩ + |3⟩
qram_load(addr, qreg);   // ← แทน qreg.write(a[index])
qreg.add(1);
เทียบกับ Figure 9-3 (แบบ RAM) ส่วน +1 (CCNOT → CNOT → NOT) เหมือนกันทุก gate · ต่างกันแค่ช่วงโหลด: Figure 9-3 ใช้ WRITE เขียนเลข 5 ลง qreg ตรงๆ แล้วจบด้วย READ (ค่าเดียว) · Figure 9-5 ใส่ H ลง addr แล้วโหลดผ่านกล่อง QRAM (D/A) และไม่มี READ เพราะ qreg เป็น superposition
① addr เริ่มที่ 2 (= 10) · H บนบิต 0x1 → addr = |2⟩ + |3⟩
② qram_load: address 2 → a[2] = 5 · address 3 → a[3] = 1 → qreg เป็น 5 กับ 1 พร้อมกัน
③ add(1) ทำกับทั้งสองค่าในทีเดียว → qreg = |6⟩ + |2⟩ (อย่างละ 50%)

qreg กับ addr ผูกกัน (entangled): ถ้า READ addr ได้ 2 qreg จะเป็น 6 แน่นอน

▫️ รู้ไว้ว่ามี

  • overflow (ล้น): ผลลัพธ์ใหญ่เกินกว่าที่ register แทนได้ ได้เลขที่ไม่มีความหมาย เกิดง่ายทั้งกับ two's complement และ fixed point · ทางแก้ตามสไลด์คือเพิ่ม qubit (1.5)
  • เขียน superposition กลับลง QRAM ไม่ได้: QRAM มีไว้อ่านค่าธรรมดาแบบ superposition · ที่เก็บ superposition ไว้นานๆ ได้เรียกว่า persistent quantum memory ซึ่งเป็นฮาร์ดแวร์อีกชนิด · หนังสือไม่ได้บอกว่าสร้าง QRAM จริงยังไง ให้มองเป็น fundamental resource (ทรัพยากรพื้นฐาน) แล้วสร้าง vector/matrix ต่อบนมัน (3.4)
  • detector ที่บอกค่า (Figure 9-3): เหลือง + ขีด = อ่านได้ 1 · เทา + วงกลม = อ่านได้ 0 (สัญลักษณ์วงจร อาจออกสอบ)
เช็คความเข้าใจ ① · register Q4.2 สายบน→ล่างเป็น 1, 1, 0, 1 เก็บเลขอะไร? Q4.2 มีเศษ 2 บิต → สายบน→ล่างมีค่า ¼, ½, 1, 2 · บวกสายที่เป็น 1: ¼ + ½ + 2 = 2.75 · (ถ้าได้ 13 แปลว่าลืมไปว่ามีบิตเศษ)
เช็คความเข้าใจ ② · ใน Example 9-2 ถ้าเปลี่ยนเป็น addr.write(0); addr.hadamard(0x2); หลัง +1 แล้ว qreg เป็นอะไร? addr = |0⟩ + |2⟩ → โหลดได้ a[0] = 4 และ a[2] = 5 → บวก 1 → qreg = |5⟩ + |6⟩ · RAM ธรรมดาทำแบบนี้ไม่ได้ เพราะ CPU เลือก address ได้ทีละตัว

vector: state encoding vs amplitude encoding

📖 อ่านเต็ม: บท 0035 · เก็บ vector: state encoding vs amplitude encoding (สไลด์ Lec 09 p22–39)

ขยับจากตัวเลขตัวเดียวเป็น vector (เวกเตอร์) คือรายการตัวเลขหลายตัว ซึ่งเจอบ่อยมากใน quantum machine learning · ตัวอย่างที่ใช้ตลอดคาบคือ v⃗ = [0, 1, 2, 3] (4 component)

⭐ 2.1 เก็บได้ 2 แบบ

state encoding (การเข้ารหัสแบบสถานะ) component ละ 1 register แล้วเขียนค่าเป็นเลขฐานสองแบบที่ทำมาตลอด · [0,1,2,3] ใช้ register ละ 2 qubit × 4 = 8 qubit (Figure 9-6) · ✔ ไม่ต้องมี QRAM · ✘ เปลือง qubit และใช้ superposition/phase ไม่ได้เลย (ก็คือใช้ QPU เป็นแค่กล่องเก็บเลขฐานสอง)
amplitude encoding (การเข้ารหัสลงแอมพลิจูด) register เดียว · component ตัวที่ i ไปเป็น amplitude ของวง |i⟩ · [0,1,2,3] ใช้แค่ 2 qubit (Figure 9-7) · ✔ ประหยัดมาก และใช้ความสามารถของ QPU ได้เต็มที่ · ✘ มีข้อควรระวัง 2 ข้อ (หัวข้อ 2.2)
state encoding เก็บค่าไว้ในว่าวงไหนเต็ม · amplitude encoding เก็บค่าไว้ในว่าแต่ละวงใหญ่แค่ไหน · vector n component ใช้แค่ ⌈log₂ n⌉ qubit (ต้องมีวงอย่างน้อย n วง) · เช่น n = 1,000,000 ใช้แค่ 20 qubit (2²⁰ ≈ 1.05 ล้าน)

Table 9-1 เทียบ 3 vector ให้เห็นว่าฝั่ง amplitude ใช้ 2 qubit เท่าเดิมทุกแถว (ขึ้นกับจำนวน component อย่างเดียว) · ส่วน state encoding ต้องขยายตามค่าที่ใหญ่สุดและความละเอียดทศนิยม: [0,1,2,3] → 8 qubit · [6,1,1,4] → 12 qubit · [0.52, 0.77, 0.26, 0.26] → 28 qubit

ในโค้ดใช้ amplitude_encode(vector, reg) (Example 9-3) · ถ้า component ติดลบ amplitude ติดลบ = phase 180° (เข็มชี้ลง) ซึ่ง state encoding ทำไม่ได้

⭐ 2.2 ข้อควรระวัง 2 ข้อของ amplitude encoding

ข้อ 1 · output ที่เป็นควอนตัมอ่านไม่ได้: READ ได้ผลเดียวแบบสุ่มแล้ว superposition ก็ยุบ · ถ้าคำตอบเป็น vector ที่กระจายอยู่ใน amplitude เราจะอ่านค่าทีละ component กลับออกมาไม่ได้ · ตอนเป็น input ไม่มีปัญหา (เราโหลดเองจึงรู้ค่าอยู่แล้ว) แต่ตอนเป็น output มีปัญหา · สิ่งที่ยังรู้ได้คือ global properties (คุณสมบัติภาพรวม) ของ vector · สไลด์สรุปว่า "no free lunch" · เห็น QML ตัวไหนอ้างว่าเร็วกว่ามหาศาล ให้ถามก่อนว่า "output เป็น quantum output หรือเปล่า"

amplitude-encoded outputข้อมูลล้านตัวอยู่ใน 20 qubit แต่ READ ได้ทีละเลขวงแบบสุ่ม แล้วที่เหลือหายหมด
≈
ห้องสมุดที่ยืมได้เล่มเดียวหนังสือล้านเล่มอยู่ในห้องเดียว แต่ยืมได้เล่มเดียวแบบจับฉลาก แล้วห้องสมุดก็ปิดถาวร

ข้อ 2 · vector ต้อง normalize (ทำให้เป็นหน่วย): |amplitude|² คือความน่าจะเป็น และ READ แล้วต้องได้สักค่าแน่นอน จึงต้องมี |a₀|² + |a₁|² + … = 1 · [0,1,2,3] ได้ 0 + 1 + 4 + 9 = 14 ≠ 1 จึงเป็น state จริงไม่ได้ · วิธีแก้คือหารด้วยความยาวของ vector:

① ผลรวมกำลังสอง = 14 → ตัวหาร = √14 ≈ 3.74 (normalization factor)
② [0, 1, 2, 3] ÷ 3.74 = [0, 0.27, 0.53, 0.80] · เช็ค: 0 + 0.07 + 0.28 + 0.64 ≈ 1 ✓
③ ทิศของ vector ไม่เปลี่ยน แค่ลูกศรสั้นลง · ถ้าต้องใช้ความยาวเดิม ก็เก็บ 3.74 ไว้ใน register อื่นได้
มักเข้าใจผิด 2 จุด: ① ตัวหารคือ √(ผลรวมกำลังสอง) = √14 ไม่ใช่ 14 · ② ใน circle notation พื้นที่ที่ระบาย = amplitude² ไม่ใช่ amplitude · |1⟩ กับ |3⟩ มี component ต่างกัน 3 เท่า (0.27 กับ 0.80) แต่พื้นที่ต่างกัน 9 เท่า · อ่านค่าจากรูปจึงต้องถอดรูทพื้นที่เสมอ (ระบายครึ่งวง → √0.5 ≈ 0.71)

▫️ รู้ไว้ว่ามี

  • QCEngine ไม่มี QRAM แล้วทำ amplitude_encode() ได้ยังไง: สร้างวงจรได้โดยไม่มี QRAM แต่ทำแบบ efficient ไม่ได้ · จึงเป็นการจำลองที่ช้า (1.6)
  • ทำไมชื่อ amplitude ไม่ใช่ magnitude encoding: amplitude มีทั้งขนาดและ phase → เก็บ vector เชิงซ้อนได้ด้วย (2.4)
เช็คความเข้าใจ ① · vector 8 component ค่าอยู่ในช่วง 0–7 ใช้กี่ qubit ถ้าเก็บแบบ amplitude encoding และแบบ state encoding? amplitude: ต้องมี 8 วง → 2³ → 3 qubit · state: ค่า 7 ใช้ 3 บิต × 8 register = 24 qubit
เช็คความเข้าใจ ② · amplitude-encode [6, 1, 1, 4] แล้ว READ · โอกาสได้ |0⟩ คือเท่าไร? ผลรวมกำลังสอง = 36 + 1 + 1 + 16 = 54 · ความน่าจะเป็น = 6² ÷ 54 = 36/54 ≈ 67% · (ถ้าได้ 82% แปลว่าหยุดที่ amplitude 6/√54 แล้วลืมยกกำลังสอง)

matrix → QPU operation → quantum simulation

📖 อ่านเต็ม: บท 0036 · เก็บ matrix: quantum simulation (สไลด์ Lec 09 p40–61)

⭐ 3.1 ไม่เก็บ matrix เป็นตัวเลข แต่ทำให้เป็น operation

วิธีที่คิดได้ทันทีคือ amplitude-encode matrix ทีละแถวลงหลาย register · ใส่ตัวเลขเข้า QPU ได้ก็จริง แต่ไม่ชัดเลยว่าจะ transpose หรือคูณกับ vector ใน register อื่นยังไง · ทีนี้ถ้าถามว่าปกติเราใช้ matrix ทำอะไร คำตอบเกือบทุกครั้งคือเอาไปคูณกับ vector ซึ่ง vector ก็อยู่ใน register อยู่แล้ว · สไลด์จึงกำหนดว่า ให้แทน matrix ด้วย QPU operation ที่กระทำกับ register ของ vector ได้

เก็บ matrix เป็นตัวเลขเหมือนจดสูตรอาหารลงกระดาษ ข้อมูลครบ แต่กระดาษทำอาหารเองไม่ได้
