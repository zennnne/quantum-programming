Quantum Programming · Lec 06 · บทที่ 0023 (เปิดคาบ)

เฟสซ่อนคำตอบไว้ — flip + mirror ดึงมันออกมาให้อ่านได้

ตลอด Lec 05 เราทำลอจิกบน superposition ได้แล้ว และเก็บคำตอบไว้ในเฟสได้ด้วย (บท 0020) — แต่ติดปัญหาเดิมที่ค้างไว้: READ มองไม่เห็นเฟส · บทนี้คือเครื่องมือตัวแรกที่แก้ปัญหานั้น ชื่อว่า amplitude amplification (AA — การขยายแอมพลิจูด)

ทำไมต้องเรียนบทนี้ — คำนวณใน superposition ได้เก่งแค่ไหนก็ไร้ประโยชน์ ถ้า READ แล้วได้แค่เลขสุ่ม · บทนี้จับหลักแค่ 2 อย่าง: ① flip = ทำเครื่องหมายคำตอบด้วยเฟส 180° ② mirror = แปลงความต่างของเฟส → ความต่างของขนาดวง · และวงจร flip/mirror คือสัญลักษณ์ที่ออกสอบได้ตรงๆ

ส่วนที่ 1 · ปัญหา: 3 สถานะที่ READ แยกไม่ออก

quantum primitive คืออะไร

สไลด์ p2 เรียก AA ว่า quantum primitive (ท่าพื้นฐานของ QPU) ตัวแรก — คือ “ท่า” สำเร็จรูปที่ใช้จัดรูป superposition ให้ READ ได้คำตอบอย่างเชื่อถือได้ มี primitive หลายตัว แต่ละตัวเหมาะกับโจทย์คนละแบบ (บทหน้าๆ จะเจอ QFT เป็นต้น)

คำนวณใน superpositionเหมือนเขียนคำตอบไว้ด้วยหมึกล่องหน — ข้อมูลอยู่ครบในกระดาษจริงๆ
→
quantum primitiveคือไฟฉาย UV ที่ทำให้หมึกล่องหนโผล่ขึ้นมา ก่อนที่เราจะ “ถ่ายรูป” (READ) ซึ่งถ่ายได้แค่ครั้งเดียว

ตัวอย่างที่ใช้ทั้งคาบ: สถานะ A, B, C

มีรีจิสเตอร์ 4 qubit (16 ค่า ∣0⟩–∣15⟩) อยู่ในสถานะใดสถานะหนึ่งจาก 3 แบบ แต่เราไม่รู้ว่าแบบไหน · ทั้ง 3 แบบมี 16 ค่าขนาดเท่ากันหมด ต่างกันแค่ว่าค่าไหนโดนพลิกเฟสเป็น 180° — เรียกค่านั้นว่า marked value (ค่าที่ถูกทำเครื่องหมาย) (สไลด์ p4–5)

ลองคิดเองก่อนเลื่อนต่อ: ถ้า READ รีจิสเตอร์ตอนนี้ได้ผลออกมาเป็น 3 เราสรุปได้ว่าอะไร?
ถูกค่ะ — ความน่าจะเป็นมาจากขนาดวงอย่างเดียว เฟสไม่มีผลเลย · ซ้ำร้าย READ ยังทำลายข้อมูลเฟสทิ้งด้วย (p5) ถามซ้ำก็ไม่ได้
ยังไม่ใช่ค่ะ — ย้อนดูผังด้านบน วงทุกวงในทั้ง 3 แถวขนาดเท่ากัน และ READ เห็นแค่ขนาด (บท 0003) เฟส 180° ที่ ∣3⟩ จึงไม่ทำให้โอกาสได้ 3 เปลี่ยนเลย

AA ทำอะไร (นิยามจากสไลด์ p3)

amplitude amplification แปลง ความต่างของเฟส (READ ไม่เห็น) → ความต่างของ magnitude (READ เห็น) — และแปลงย้อนกลับได้ด้วย

เกร็ดชื่อ: เพราะมันขยาย magnitude จริงๆ ชื่อ “magnitude amplification” จะตรงกว่า แต่วงการใช้ “amplitude amplification” จนเป็นมาตรฐานไปแล้ว

ส่วนที่ 2 · วงจร prep → flip → mirror และผลรอบแรก

วงจรเต็มจากสไลด์ p6–7 (ตัวอย่างนี้ mark ค่า 3 = สถานะ B) · อ่านซ้าย→ขวาเป็น 3 กล่อง:

var number_to_flip = 3;       // ค่าที่จะ mark
var num_qubits = 4;
qc.reset(num_qubits);
var reg = qint.new(num_qubits, 'reg');
reg.write(0);

reg.hadamard();               // prep  : 16 ค่าเท่ากันหมด
reg.not(~number_to_flip);     // flip ①: NOT เฉพาะบิตที่เป็น 0
reg.cphase(180);              // flip ②: CZ คร่อมทุกสาย
reg.not(~number_to_flip);     // flip ③: NOT คืน (uncompute)
reg.Grover();                 // mirror ทั้งกล่อง

ไล่ flip ทีละสเต็ป — ทำไมมันพลิกเฟสค่า 3 ได้ค่าเดียว

ท่านี้คือท่าเดียวกับ phase-encoded result ในบท 0020 เป๊ะ — แค่ตอนนี้คร่อม 4 สาย:

① 3 = 0011 (0x8 0x4 0x2 0x1) · ~3 เลือกบิตที่เป็น 0 คือสาย 0x4 กับ 0x8 → ใส่ ⊕ ตรงนั้น → ค่า 3 กลายเป็น 1111 = 15
② CZ 4 จุด (cphase(180)) พลิกเฟส 180° เฉพาะค่าที่ทุกบิตเป็น 1 — มีค่าเดียวคือ 15 (ซึ่งตอนนี้คือ 3 ตัวเดิมที่ปลอมตัวมา)
③ ⊕ ที่ 0x4, 0x8 อีกรอบ → ทุกค่ากลับชื่อเดิม แต่ ∣3⟩ ติดเฟส 180° มาด้วย
ถ้าอยาก mark ค่า 12 (สถานะ C) แทน ต้องวาง ⊕ ของกล่อง flip ที่สายไหน? (เขียน 12 เป็นเลขฐานสองก่อน)
ถูกค่ะ — 12 = 1100 บิตที่เป็น 0 คือ 0x1, 0x2 → ⊕ ตรงนั้น แล้ว CZ 4 จุดเหมือนเดิม · กล่อง flip เปลี่ยนตามค่าที่ mark แต่ CZ ไม่เปลี่ยน
ยังไม่ใช่ค่ะ — 12 = 8 + 4 = 1100 ⊕ ต้องตกที่บิตที่เป็น 0 (ให้ทุกบิตกลายเป็น 1 ก่อนเข้า CZ) · 0x4/0x8 คือคำตอบของค่า 3

mirror — กล่องที่หน้าตาไม่เคยเปลี่ยน

mirror = H → ⊕ → CZ 4 จุด → ⊕ → H ทุกสาย · ในโค้ดคือ reg.Grover() บรรทัดเดียว · ต่างจาก flip ตรงที่ไม่ขึ้นกับว่า mark ค่าไหน — จำหน้าตาเดียวจบ (ทำไมมันถึงชื่อ “mirror” และข้างในทำงานยังไง เก็บไว้บท 0026 ค่ะ)

เข็มทุกวงชี้ 180° แล้วมันไม่ “พลิก” กลับไปเหมือนเดิมเหรอ? — ไม่ค่ะ ที่ READ สนใจคือเฟสสัมพัทธ์ (relative phase, บท 0003) · ทุกวงหมุนไปเท่ากันหมด = ไม่มีวงไหนต่างจากใคร = ไม่มีข้อมูลในเฟสเหลืออยู่ · ข้อมูลทั้งหมดย้ายไปอยู่ในขนาดวงแล้ว
หลัง mirror 1 รอบ เรา READ สถานะ B แล้วได้ 3 — ประโยคไหนถูกที่สุด?
ถูกค่ะ — 47.3% คือ “ดีขึ้นมาก แต่ยังเกือบโยนเหรียญ” (p9) · คำถามที่ค้างไว้ให้บทหน้า: ทำ flip + mirror ซ้ำอีกรอบได้ไหม?
ยังไม่ใช่ค่ะ — ข้อมูลไม่ได้หาย แค่ย้ายจากเฟสไปอยู่ที่ขนาด แต่ 47.3% ก็ยังห่างจาก 100% มาก → ได้ 3 ออกมาทำให้น่าเชื่อว่าเป็น B แต่ไม่ใช่แน่นอน

mirror = Grover iteration

สไลด์ p10: routine flip-mirror ถูกใช้ครั้งแรกใน Grover's algorithm สำหรับ unstructured database search (การค้นข้อมูลแบบไม่มีโครงสร้าง) · AA ที่เรียนอยู่คือรุ่นขยาย (generalization) ของอัลกอริทึมนั้น · หนังสือเรียกกล่องนี้ว่า “mirror” เพราะจำผลของมันง่ายกว่า

ระวังชื่อเรียก — สไลด์ p10 บอก mirror = Grover iteration → ตอบตามนี้ตอนสอบ · แต่ในตำราทั่วไป (เช่น Wikipedia: Grover's algorithm) คำว่า Grover iteration มักหมายถึง oracle + diffusion คือ flip + mirror รวมกัน ส่วน mirror เดี่ยวๆ เรียก diffusion operator · เวลาไปอ่านที่อื่นจะได้ไม่งง
ทดสอบความจำ (ตอบในใจก่อนเปิด)
  1. ทำไมคำนวณใน superposition ได้แล้วยังต้องมี quantum primitive?
    เพราะ READ ได้แค่ค่าสุ่มค่าเดียว ถ้าไม่จัดรูป superposition ก่อน คำตอบก็อ่านไม่ออก
  2. AA แปลงอะไรเป็นอะไร?
    ความต่างของเฟส (READ ไม่เห็น) → ความต่างของ magnitude (READ เห็น) และย้อนกลับได้
  3. marked value คืออะไร?
    ค่าที่ถูกพลิกเฟสเป็น 180° ต่างจากค่าอื่น
  4. กล่อง flip ของค่า 5 (0101) มี ⊕ ที่สายไหน?
    0x2 กับ 0x8 (บิตที่เป็น 0) → CZ 4 จุด → ⊕ คืนที่เดิม
  5. วาดกล่อง mirror จากความจำ
    H ทุกสาย → ⊕ ทุกสาย → CZ 4 จุด → ⊕ ทุกสาย → H ทุกสาย
  6. ระหว่าง flip กับ mirror กล่องไหนเปลี่ยนตามโจทย์?
    flip เปลี่ยน · mirror เหมือนเดิมเสมอ
  7. หลัง mirror 1 รอบ (4 qubit) marked value มีโอกาสกี่ %?
    ≈ 47.3% (ค่าอื่นเหลือ ≈ 3.5% ต่อค่า)
  8. หลัง mirror เฟสของ marked value เป็นยังไงเทียบกับค่าอื่น?
    เท่ากันหมดแล้ว — ความต่างย้ายไปอยู่ที่ขนาด
  9. ตามสไลด์ mirror มีชื่อเรียกทั่วไปว่าอะไร?
    Grover iteration

สรุปบทนี้

  • quantum primitive = ท่าจัดรูป superposition ให้ READ ได้ · ตัวแรกคือ amplitude amplification
  • ปัญหา: สถานะที่ต่างกันแค่เฟส READ แยกไม่ออก (6.25% เท่ากันหมด) และ READ ยังทำลายเฟสทิ้ง
  • flip = not(~n) → CZ ทุกสาย → not(~n) · ⊕ ตกที่บิตที่เป็น 0 ของค่าที่ mark
  • mirror = H → ⊕ → CZ → ⊕ → H ทุกสาย = Grover() · หน้าตาเดียวทุกโจทย์
  • flip + mirror 1 รอบ: marked 6.25% → 47.3% · เฟสเท่ากันหมด → ยังไม่พอ → บทหน้า: ทำซ้ำ
