แบ่งภาพเป็น tile: วาด 16 subpixel พร้อมกัน

สองบทที่แล้วเราวาดรูปลงผ้าใบ 16×16 ทั้งผืนในคราวเดียว · แต่เป้าหมายจริงของคาบนี้คือ supersampling คือย่อภาพละเอียดให้เหลือ pixel น้อยลง · บทนี้จึงหั่นผ้าใบเป็นช่องเล็กๆ เรียกว่า tile แล้ววาดทีละช่อง ใช้วงจรที่เล็กลงจาก 8 qubit ของพิกัด เหลือแค่ 4

ทำไมต้องเรียนบทนี้: จับหลัก 4 อย่าง ① 1 tile = 4×4 subpixel → ย่อเหลือ 1 pixel ของภาพผลลัพธ์ · ภาพ 16×16 จึงกลายเป็น 4×4 ② qx, qy เหลืออย่างละ 2 qubit (ตำแหน่งในช่อง) · tx, ty เป็นเลขธรรมดา (ช่องที่เท่าไร) · พิกัดจริง = qx + 4·tx ③ วาดเส้นด้วยสูตร 7 ขั้น: คัดลอกลง qacc → บวก offset → เช็ค "== N" → flip → ย้อนกลับ ④ Figure 11-10 ในสไลด์มีจุดผิด 3 จุด · หนูจำลองแล้ว วงจรตามรูปเป๊ะๆ วาดไม่ได้อะไรเลย

1.1 กลับมาที่โจทย์ supersampling

ทวนจาก บท 0041: supersampling คือ คำนวณจุดย่อย (subpixel) หลายๆ จุดใน 1 pixel แล้วรวมให้เหลือค่าเดียว · สไลด์ p22 จำลองเรื่องนี้แบบนี้ค่ะ

  • มองผ้าใบ 16×16 เป็นข้อมูลละเอียด (256 subpixel)
  • หั่นเป็น 16 tile ขนาด 4×4
  • แต่ละ tile ต้องย่อเหลือ 1 pixel → ภาพผลลัพธ์มี 16 pixel (4×4)
tile 1 ช่อง = ภาพโมเสก 1 ชิ้นข้างในมีจุดย่อย 16 จุด บางจุดดำบางจุดขาว · ถอยออกมาดูไกลๆ ทั้งชิ้นจะกลายเป็นสีเทาสีเดียว เข้มแค่ไหนขึ้นกับว่ามีจุดดำกี่จุด

2.1 โค้ด: สูตรวาดเส้น 7 ขั้น

โค้ด "Drawing lines using an accumulator" (p26–27) วาดเส้นนอนแล้วต่อด้วยเส้นตั้ง · ทั้งสองเส้นใช้ 7 ขั้นเดียวกัน เปลี่ยนแค่ตัวแปร

qc.reset(8);
var qx   = qint.new(2, 'qx');
var qy   = qint.new(2, 'qy');
var qacc = qint.new(4, 'qacc');
qc.write(0);
qx.hadamard();
qy.hadamard();

var tx = 2;    // tile column
var ty = 1;    // tile row

// Hz line y=3            // Vt line x=10
qacc.cnot(qy);            qacc.cnot(qx);         // ① คัดลอกพิกัดในช่อง
qacc.add(ty * 4);         qacc.add(tx * 4);      // ② บวก offset → พิกัดจริง
qacc.not(~3);             qacc.not(~10);         // ③ ทำให้ "== N" กลายเป็น "ทุกบิตเป็น 1"
qacc.cphase(180);         qacc.cphase(180);      // ④ flip ถ้าทุกบิตเป็น 1
qacc.not(~3);             qacc.not(~10);         // ⑤ ย้อน ③
qacc.subtract(ty * 4);    qacc.subtract(tx * 4); // ⑥ ย้อน ②
qacc.cnot(qy);            qacc.cnot(qx);         // ⑦ ย้อน ① → qacc กลับเป็น 0

หนูเรียงสองเส้นไว้คู่กันเพื่อให้เห็นว่าเหมือนกัน · ในสไลด์เขียนต่อกันลงมา และบรรทัด qacc.cnot(…) แรกไม่มี ;

ขั้น ①–③ คือ "คำนวณ" · ④ คือ "flip" · ⑤–⑦ คือ "uncompute" · ขั้น ⑦ สำคัญเพราะเราใช้ qacc ตัวเดิมวาดเส้นที่สองต่อ จึงต้องคืนให้เป็น 0 ก่อน

2.2 ทริก not(~N): เปลี่ยน "เท่ากับ N" เป็น "ทุกบิตเป็น 1"

CZ (หรือ cphase(180) ทั้ง register) flip เฉพาะตอนทุกบิตเป็น 1 · ถ้าอยากเช็ค "qacc == N" ก็ NOT บิตที่ N เป็น 0 ทิ้ง (~N = กลับบิตของ N) · ค่าที่เท่ากับ N พอดีจะกลายเป็น 1111 ตัวเดียว นี่คือ phase-logic AND จาก บท 0037 ที่เอา NOT มาครอบขาที่ต้องการให้เป็น 0

N = 3 3 = 0011 → ~3 = 1100 → NOT บิต 0x4, 0x8
N = 10 10 = 1010 → ~10 = 0101 → NOT บิต 0x1, 0x4

อ่านบิตจากซ้ายไปขวาเป็น 0x8 0x4 0x2 0x1 · ใช้ 4 บิตเพราะ qacc มี 4 qubit

③ ถ้าอยากวาดเส้นตั้งที่ x = 5 แทน ขั้น qacc.not(~5) จะวาง ⊕ บนบิตไหนของ qacc
เป๊ะค่ะ 5 = 0101 → ~5 = 1010 → NOT บิต 0x2 กับ 0x8 · ตัวเลือกที่สองคือบิตที่เป็น 1 ใน 5 ซึ่งกลับด้านกัน
5 = 0101 (0x4 + 0x1) · ~5 = 1010 → NOT บิตที่ 5 เป็น 0 คือ 0x2 กับ 0x8 · ถ้า NOT บิตที่เป็น 1 จะได้ "== 10" แทน

2.4 หนูไล่ค่าแล้ว: สไลด์ขัดกันเอง 3 จุด

⚠️ จุดที่สไลด์ผิด (ตอบตามสไลด์ตอนสอบ แต่รู้ของจริงไว้)
  1. ป้าย flip if qacc==10 อยู่เหนือครึ่งเส้นนอน · แต่ gate ข้างใต้ NOT 0x4, 0x8 = เช็ค == 3 · 10 เป็นของครึ่งเส้นตั้ง
  2. โค้ดตั้ง ty = 1 แต่รูปขยายกรอบ tile ที่ ty = 3
  3. บล็อกบวก offset ในวงจรสลับครึ่งกัน (อธิบายข้างล่าง) → วงจรตามรูปเป๊ะๆ ไม่ flip วงไหนเลย

วิธีตรวจ: หนูจำลองทุก gate ของวงจรด้วย python กับ subpixel ทั้ง 16 วง (ทุก gate เป็นการสลับค่า + CZ จึงไล่ตรงๆ ได้) และเทียบกับโค้ดที่ tile ต่างๆ · การวิเคราะห์ในหัวข้อนี้เป็นของหนูเอง สไลด์ไม่ได้พูดถึง

บล็อกบวกในวงจรบวกเท่าไรกันแน่ · ⊕ ตัวเดียวบน 0x8 = +8 ตรงไปตรงมา · ส่วน "⊕ บน 0x4 แล้ว ● 0x4 → ⊕ 0x8" ลองไล่ดูนะคะ

qacc = 0 0000 → ⊕ 0x4 → 0100 → 0x4 เป็น 1 จึง ⊕ 0x8 → 1100 = 12
qacc = 4 0100 → ⊕ 0x4 → 0000 → 0x4 เป็น 0 ไม่ทำอะไร → 0
สรุป ทุกค่า v ได้ v − 4 · ใน 4 บิต (mod 16) ลบ 4 = บวก 12 (overflow แบบ บท 0019)

ดังนั้นวงจรในรูปทำแบบนี้ค่ะ

  • ครึ่งเส้นนอน: y จริง = qy + 8 → อยู่ในช่วง 8–11 → ไม่มีทางเท่ากับ 3
  • ครึ่งเส้นตั้ง: x จริง = qx + 12 → อยู่ในช่วง 12–15 → ไม่มีทางเท่ากับ 10

ผลคือ tile ชมพูล้วน (= tile tx = 3, ty = 2) · แต่ถ้าเอาบล็อกบวกสองอันสลับครึ่งกัน จะได้ +12 = 4·3 ให้เส้นนอน (ty = 3) และ +8 = 4·2 ให้เส้นตั้ง (tx = 2) ตรงกับ tile ที่กรอบไว้พอดี · คนวาดรูปน่าจะเอา offset ของ tx กับ ty ไปใส่ผิดครึ่ง

จุดที่ 2 (ty = 1 กับ ty = 3) จึงไม่ทำให้ภาพเพี้ยน เพราะ tile ty = 1, 2, 3 ของคอลัมน์ tx = 2 มีแต่เส้นตั้ง หน้าตาเหมือนกันทุกช่อง · ส่วนโค้ดเองถูกต้อง ถ้ารันโค้ดตามสไลด์จะได้ภาพขวาสุด

④ ถ้าจะวาด tile tx = 0, ty = 0 (มุมซ้ายบน) บล็อกบวก offset ทั้งสองครึ่งหน้าตาเป็นยังไง
ใช่ค่ะ บวก 4·0 = 0 จึงไม่มี gate · พิกัดจริง = พิกัดในช่องพอดี · tile นี้จึงมีแค่เส้นนอนที่แถวล่าง (qy = 3) ส่วนเส้นตั้งอยู่ไกลเกิน (qx ไปไม่ถึง 10)
offset = 4·tx กับ 4·ty และทั้งคู่ = 0 → ไม่ต้องบวกอะไรเลย บล็อกจึงว่างทั้งสองครึ่ง · gate ในบล็อก offset เปลี่ยนตาม tile เพราะ tx, ty เป็นเลขธรรมดาที่รู้ตอนสร้างวงจร
⑤ วาด tile tx = 2, ty = 0 ด้วยวงจรที่ถูกต้อง จะได้วงเขียวกี่วง (จาก 16)
ถูกค่ะ แถวล่าง 4 วง + คอลัมน์ qx = 2 อีก 4 วง · วง (2, 3) อยู่ในทั้งสองชุด (นับซ้ำ 1) และโดน flip สองรอบจนกลับเป็นชมพู (หักอีก 1) → 4 + 4 − 2 = 6
tile นี้มีทั้งสองเส้น · แถวล่าง (qy = 3) 4 วง + คอลัมน์ qx = 2 อีก 4 วง แต่วง (2, 3) อยู่ในทั้งสองชุด โดน flip 2 รอบ = ชมพู · เหลือ 3 + 3 = 6 วง (ดูที่ tile นี้ใน Figure 11-9 ด้านบน)

2.5 ภาพทดสอบที่น่าสนใจกว่า (p28–29)

เส้นนอน-เส้นตั้งง่ายเกินไปสำหรับทดสอบ supersampling · สไลด์ p28 จึงใช้ shader ที่ซับซ้อนกว่าวาด วงแหวนซ้อนกัน ที่ยิ่งออกห่างจากมุมซ้ายบนแถบยิ่งบางและถี่ (รายละเอียดความถี่สูง ที่การ sample แบบเดิมทำพังง่าย) · วงแหวนพวกนี้ก็คือแถบโค้งจาก overflow ที่เจอในบท 0042 นั่นเอง แต่คราวนี้ใช้โดยตั้งใจ

ดูขอบขวาล่างของภาพนะคะ แถบถี่จนตาเห็นเป็นลายวงกลมปลอมๆ (moiré) ทั้งที่ไม่ได้วาดไว้ · Figure 11-11 ในสไลด์ก็มีลายแบบนี้ · นี่แหละคือ noise ที่ supersampling ต้องแก้

  • ภาพเต็ม 256×256 แบ่งเป็น 4,096 tile × 16 subpixel ต่อ tile (p29)

  • เสริมจากหนู: 4,096 × 16 = 65,536 = 256 × 256 · และ 4,096 = 64 × 64 → ภาพผลลัพธ์ 64×64 pixel

ตัวแปร 5 ตัวในวงจร tile: ตัวไหนเป็น qubit กี่ตัว ตัวไหนเป็นเลขธรรมดา และพิกัดจริงคำนวณยังไง qx, qy = qubit อย่างละ 2 (ตำแหน่งในช่อง) · qacc = qubit 4 ตัว (accumulator) · tx, ty = digital (ช่องที่เท่าไร) · x จริง = qx + 4·tx · y จริง = qy + 4·ty
สูตรวาดเส้น 7 ขั้น (เส้นตั้ง x = 10) qacc.cnot(qx) → add(tx*4) → not(~10) → cphase(180) → not(~10) → subtract(tx*4) → cnot(qx)
วาดครึ่ง "flip ถ้า qacc == 10" ของ Figure 11-10 (3 คอลัมน์) ⊕ บน qacc 0x1 และ 0x4 → จุดดำ 4 จุดต่อกันบน qacc ทั้ง 4 สาย → ⊕ บน 0x1 และ 0x4 ซ้ำ
Figure 11-10 ในสไลด์ผิดตรงไหน ① ป้าย flip if qacc==10 อยู่ผิดครึ่ง (ครึ่งนั้นเช็ค 3) ② โค้ด ty = 1 แต่รูปกรอบ ty = 3 (ภาพออกมาเหมือนกัน) ③ บล็อกบวก offset สลับครึ่ง: เส้นนอนได้ +8 เส้นตั้งได้ +12 (= −4) → วงจรตามรูปไม่ flip อะไรเลย
