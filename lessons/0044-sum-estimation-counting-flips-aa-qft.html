นับว่า tile โดน flip กี่วง: AA + QFT

ตั้งแต่บท 0041 เราวาดรูปลง phase ได้แล้ว แต่ READ ออกมาได้แค่ค่าสุ่มวงเดียว · พอแบ่งภาพเป็น tile ในบท 0043 ปมก็ชัดขึ้นอีก: สิ่งที่อยากรู้จริงๆ คือใน tile นี้มี subpixel ขาวกี่ตัว เพราะตัวเลขนี้คือความสว่างของ pixel ผลลัพธ์ · บทนี้ตอบว่า QPU นับได้ยังไง โดยไม่ต้องอ่าน subpixel ทีละตัวเลย

ทำไมต้องเรียนบทนี้: จับหลัก 4 อย่าง ① Quantum Sum Estimation = เอาโปรแกรมวาดรูปไปเป็น flip ของ AA แล้วต่อด้วย QFT → ได้จำนวนที่ถูก flip ② QSS ไม่ได้ทำงานน้อยกว่า · ที่ชนะคือลักษณะของ noise: pixel ถูกเป๊ะเยอะขึ้นเกือบ 2 เท่า ③ กลไก: counter register บอกว่าจะวน AA กี่รอบ → HAD ใส่ทุกจำนวนรอบพร้อมกัน → เกิดการแกว่งที่เร็วช้าตามจำนวนที่ถูก flip → QFT อ่านความเร็วนั้น ④ เป็นเครื่องเดียวกับ phase estimation ในบท 0033 แค่เปลี่ยนตัว U
ของเก่าที่จะกลับมาใช้: AA วนกี่รอบ โอกาสได้คำตอบจะขึ้นๆ ลงๆ เป็นคลื่น (บท 0024) · QFT อ่านความถี่ที่ซ่อนอยู่ใน register (บท 0027) · และชื่อ "Quantum Sum Estimation" เคยโผล่มาแล้วครั้งหนึ่งตอนท้าย Lec 06 (บท 0025)

เป้าหมายต่อ 1 tile: นับ subpixel ที่ถูก flip

จำได้ไหมคะว่าในภาพที่เข้ารหัสด้วย phase (phase-encoded image) ขาว = phase ถูก flip เป็น 180° · ดำ = ไม่ถูก flip · ดังนั้นถ้านับได้ว่า tile นี้มี subpixel ที่ถูก flip กี่ตัวจาก 16 ตัว ก็ได้ ความสว่าง (intensity) ของ pixel ผลลัพธ์ทันที เช่น 4 ตัวจาก 16 = สว่าง 25% (p30)

QSS · Quantum Sum Estimation ให้โปรแกรมวาดรูปทำหน้าที่ flip ของ amplitude amplification (AA) · รันหลายรอบเหมือนกัน · ต่อท้ายด้วย QFT → READ ได้ค่าที่บอกจำนวนที่ถูก flip
Quantum Sum Estimation (การประมาณผลรวมเชิงควอนตัม): มองโปรแกรมควอนตัมที่วาดรูปเป็น flip subroutine ของ AA แล้วรวมกับ Quantum Fourier Transform → ประมาณจำนวน subpixel ที่ถูก flip ทั้งหมดใน tile (p30)

ทำไม noise แบบ QSS ถึงน่าสนใจ

ลองนึกถึงบทที่ 0041 ค่ะ: noise ที่ "เพี้ยนนิดๆ ทุก pixel" ลบออกด้วยมือแทบไม่ได้ เพราะไม่รู้จะแก้ตรงไหนก่อน · แต่ noise ที่ "ถูกเกือบหมด ผิดแรงแค่บางจุด" หาจุดผิดเจอง่าย เพราะจุดขาวจัด/ดำจัดโดดออกมาจากพื้นเรียบ

QSS ไม่เหมือน Monte Carlo ตรงไหนกันแน่ (p36)

QSS shader ไม่เคย output ค่าของ subpixel ตัวใดตัวหนึ่งออกมาเลย · มันใช้ superposition ของค่าทั้งหมด เพื่อประมาณผลรวมอย่างเดียว · ถ้าอยากได้ค่าทุก subpixel ระหว่างทาง ใช้คอมพิวเตอร์ปกติเหมาะกว่า · ถ้าอยากได้แค่ผลรวม หรือคุณสมบัติของกลุ่ม subpixel นั่นแหละที่ QPU น่าสนใจ

ขั้น ① counter register = "จะวน AA กี่รอบ"

แก่นของ QSS คือเอา AA iteration มารวมกับ QFT เพื่อประมาณจำนวนของที่ถูก flip โดย flip ของ AA ในที่นี้ก็คือโปรแกรมวาดรูป ซึ่ง flip phase ของ subpixel ขาวทั้งหมด (p37) · แล้วเพิ่ม register ใหม่ชื่อ counter (ตัวนับ) ที่ค่าของมันกำหนดว่าจะทำ AA กี่รอบ: ค่า counter = 5 → ทำ AA 5 รอบ

ทริกของ p37: ถ้า HAD counter ให้เป็น superposition ก่อน ก็เท่ากับทำ superposition ของจำนวนรอบ AA ที่ต่างกัน · counter 4 qubit = ทำ 0, 1, 2, …, 15 รอบพร้อมกันในคราวเดียว

ขั้น ② จำนวนรอบต่างกัน → เกิดการแกว่ง

จากบท 0024: วน AA ไปเรื่อยๆ โอกาสเจอของที่ถูก mark จะขึ้นแล้วลงแล้วขึ้นใหม่ เป็นคลื่น · ตอนนี้ counter ถือทุกจำนวนรอบไว้พร้อมกัน คลื่นนั้นจึงกลายเป็นลายแกว่งเป็นคาบ (periodic oscillation) ที่กางอยู่ตลอดแนว amplitude ของ counter register · และที่สำคัญ: ความถี่ของการแกว่งขึ้นกับจำนวนที่ถูก flip (p38)

กราฟซ้ายคือ amplitude ของส่วน "subpixel ขาว" เมื่อทำ AA ไป k รอบ (k = ค่าของ counter) · กราฟขวาคือสิ่งที่ QFT เห็น · tile มี 16 subpixel

คณิตย่อๆ (หนูเติมเอง สไลด์ไม่ได้ให้สูตร): ถ้ามีของที่ถูก flip M ตัวจาก N ตัว ให้ sin²θ = M/N · หลังทำ AA k รอบ amplitude ของส่วนที่ถูก flip เป็น sin((2k+1)θ) · คือคลื่นที่ก้าวทีละ 2θ ต่อรอบ · ใน register 16 ช่อง peak จึงอยู่ราวๆ 16 × θ / 180° · เช่น M = 4: sin²θ = 4/16 → θ = 30° → 16 × 30 / 180 ≈ 2.7 → peak ที่ช่อง 3 · มุมมองที่ใช้คือ mirror = "สะท้อนรอบค่าเฉลี่ย" แบบบท 0026
ใช้สูตรในกล่องคณิต: tile ที่มีขาว 8 ตัวจาก 16 (เทาครึ่งๆ) peak จะอยู่ช่องไหน
ถูกค่ะ · sin²θ = 8/16 = 0.5 → sinθ ≈ 0.707 → θ = 45° → 16 × 45 / 180 = 4 พอดี · ลงช่องเต็มพอดีแบบนี้ peak จะคมกริบ ไม่บานไปช่องข้างๆ · (θ = 90° คือกรณีขาวครบ 16 ตัว → peak ที่ 8)
ลองใหม่นะคะ เริ่มจาก sin²θ = 8/16 = 0.5 ก่อน · sinθ = √0.5 ≈ 0.707 → θ เท่าไร แล้วค่อยคูณ 16 หาร 180

ขั้น ③ QFT อ่านความถี่ → จำนวน → ความสว่าง

จะอ่านความถี่ที่ซ่อนอยู่ใน register ต้องใช้ QFT · ได้ความถี่ ก็ได้จำนวน subpixel ที่ถูก flip · แล้วเอาจำนวนนั้นไปกำหนด brightness (ความสว่าง) ของ pixel ในภาพความละเอียดต่ำ (p38)

จำนวนที่ถูก flip → ความถี่ของการแกว่ง → QFT อ่านความถี่ → ได้จำนวนกลับมา → ความสว่างของ pixel
สังเกตว่า peak บานได้: กราฟขาว 4 ตัว (2.7) กับขาว 12 ตัว (5.3) ไม่ลงช่องเต็ม → ความแรงรั่วไปช่องข้างๆ · ค่าที่ READ ได้จึงสุ่มได้หลายค่า และในโค้ดจริงของ QCEngine เลขช่องยังถูกสลับลำดับอีกชั้น · นี่คือเหตุผลที่ต้องมี QSS lookup table แปลค่า READ เป็นจำนวน subpixel · เป็นเรื่องของบทถัดไป (p41 เป็นต้นไป)
สไลด์ใช้คำไม่ตรงกัน: p37 บอกว่า flip ของ subpixel "white" แต่ p38 เรียกว่า "shaded subpixels" · หมายถึงกลุ่มเดียวกัน คือ subpixel ที่ shader flip phase · ตอบตามสไลด์ได้ แต่รู้ไว้ว่าเป็นของชิ้นเดียวกัน

function do_qss_image() {
    var sp = {};
    var total_qubits = 2 * res_aa_bits + num_counter_bits + accum_bits;
    qc.reset(total_qubits);
    sp.qx      = qint.new(res_aa_bits, 'qx');
    sp.qy      = qint.new(res_aa_bits, 'qy');
    sp.counter = qint.new(num_counter_bits, 'counter');
    sp.qacc    = qint.new(accum_bits, 'scratch');
    sp.qacc.write(0);
    for (sp.ty = 0; sp.ty < res_tiles; ++sp.ty)      // วนทุก tile
        for (sp.tx = 0; sp.tx < res_tiles; ++sp.tx)
            qss_tile(sp);
}

function qss_tile(sp) {
    // ① เตรียมผ้าใบของ tile + counter
    sp.qx.write(0);  sp.qy.write(0);  sp.counter.write(0);
    sp.qx.hadamard(); sp.qy.hadamard(); sp.counter.hadamard();

    // ② รัน shader หลายรอบ
    for (var cbit = 0; cbit < num_counter_bits; ++cbit) {
        var iters = 1 << cbit;                              // 1, 2, 4, 8, …
        var qxy_bits = sp.qx.bits().or(sp.qy.bits());
        var condition = sp.counter.bits(iters);              // counter qubit น้ำหนัก iters
        var mask_with_condition = qxy_bits.or(condition);
        for (var i = 0; i < iters; ++i) {
            shader_quantum(sp.qx, sp.qy, sp.tx, sp.ty, sp.qacc,
                           condition, sp.qcolor);            // flip
            grover_iteration(qxy_bits, mask_with_condition);  // mirror
        }
    }
    invQFT(sp.counter);

    // ③ อ่านและแปลผล
    sp.readVal = sp.counter.read();
    sp.hits = qss_count_to_hits[sp.readVal];              // lookup table (บทถัดไป)
    sp.color = sp.hits / (res_aa * res_aa);
    return sp.color;
}

iters = 1 << cbit + counter.bits(iters) qubit น้ำหนัก 1, 2, 4, 8 สั่ง AA 1, 2, 4, 8 รอบ → ค่า counter = จำนวนรอบ
shader_quantum + grover_iteration AA 1 รอบ = flip (วาดรูป) + mirror · ทั้งคู่มีเงื่อนไขบน counter qubit ตัวนั้น
invQFT(sp.counter) ③ อ่านความถี่ของการแกว่ง
