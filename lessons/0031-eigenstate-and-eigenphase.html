eigenstate และ eigenphase: สิ่งที่ phase estimation หา

AA (บท 0023) กับ QFT (บท 0027) บอกเราเรื่อง state ของ register · คาบนี้เป็น primitive ตัวที่สาม ชื่อ phase estimation (การประมาณเฟส) ซึ่งบอกเราเรื่องตัว operation ที่กระทำกับ register แทน · ก่อนจะใช้มันได้ ต้องรู้ก่อนว่า “คุณสมบัติของ operation” หน้าตาเป็นยังไง → คำตอบคือ eigenstate กับ eigenphase ค่ะ

ทำไมต้องเรียนบทนี้: จับหลัก 3 อย่าง ① eigenstate (สถานะเฉพาะ) = state ที่ operation ไม่เปลี่ยน (ได้มากสุดแค่ global phase) ② eigenphase (เฟสเฉพาะ) = global phase ที่ eigenstate ตัวนั้นได้รับ · เซตของคู่นี้ระบุ operation ได้แบบไม่ซ้ำ ③ phase estimation รับ U + eigenstate → คืน มุม θ ไว้ใน register อีกตัวที่ READ ได้ (Figure 8-3 · เรื่องสอบ)

ทำไมต้องมี primitive ที่ “สอนเราเรื่อง operation”? (p2–3)

ฟังดูแปลกนะคะ — วงจรเราสร้างเอง ก็น่าจะรู้ทุกอย่างของมันอยู่แล้ว · แต่สไลด์บอกว่า input บางแบบถูก encode ไว้ใน operation ไม่ได้อยู่ใน register · ถ้าอยากได้คำตอบ ก็ต้องมีเครื่องมือที่ “ส่อง” operation ได้ · สไลด์ยอมรับเองด้วยว่านี่อาจเป็น primitive ที่ยากที่สุดจนถึงตอนนี้ เพราะ ① มันพูดเรื่อง operation ไม่ใช่ state ② ประโยชน์ของ eigenphase อธิบายยากถ้าไม่ใช้คณิตขั้นสูง → บทนี้เลยจะไปช้าๆ ทีละขั้นค่ะ

ส่วนที่ 1 · eigenstate และ eigenphase (ตัวอย่าง HAD)

ทบทวนก่อน: global phase vs relative phase (บท 0003, 0008)
· relative phase = เฟสต่างกันระหว่างวง → มีผล (เช่น H ถัดไปจะให้ผลต่างกัน)
· global phase = หมุนทุกวงเท่ากัน → READ ยังไงก็ได้ความน่าจะเป็นเดิม ไม่มีทางสังเกตได้ → ถือว่าเป็น state เดิม
จำประโยคสุดท้ายไว้ เพราะมันคือ “ปม” ของทั้งคาบนี้ค่ะ

⚠️ “180°” ในตารางนี้มี 2 ความหมาย อย่าปนกัน
· 180° ในวง |0⟩ ของ eigenstate 2 = relative phase → เป็น “หน้าตา” ของ state ก่อนเข้า HAD
· 180° ในคอลัมน์ eigenphase = global phase ที่ HAD ใส่ให้ทั้ง state ตอนกระทำ
ตัวเลขบังเอิญเท่ากันเฉยๆ ค่ะ · (เกร็ด: ค่าจริงคือ cos²22.5° ≈ 85.36% — สไลด์พิมพ์ 85.35% เพราะปัดเศษ ผลรวมเลยได้ 99.99% · ตอบตามสไลด์ได้เลย)
เกร็ดคณิต (ไม่ต้องจำ): ในภาษา linear algebra เขียนว่า U|ψ⟩ = eiθ|ψ⟩ · ตัวคูณ eiθ เรียกว่า eigenvalue · ของ HAD คือ +1 (θ = 0°) กับ −1 (θ = 180°) · เพราะ QPU operation ไม่ยืด/หดความยาว state ตัวคูณเลยมีขนาด 1 เสมอ → ต่างกันแค่ “มุม” θ นี่แหละคือ eigenphase

ลองเอง: เช็คว่าเป็น eigenstate ไหม

วิธีคิด: ① กระทำ operation กับทุกวง ② เทียบกับก่อน — magnitude เท่าเดิมไหม? ทุกวงหมุนเท่ากันไหม?

① ใส่ NOT (สลับวง |0⟩ กับ |1⟩) ให้ state ข้างบน · state นี้เป็น eigenstate ของ NOT ไหม?
ถูกค่ะ! สลับแล้วได้ |0⟩ เฟส 180°, |1⟩ เฟส 0° → เทียบกับเดิม (0°, 180°) ทุกวงหมุนไป 180° เท่ากัน = global phase 180°
ลองวาดหลังสลับดูนะคะ: |0⟩ ได้เฟส 180° (มาจาก |1⟩ เดิม) · |1⟩ ได้ 0° · magnitude 50/50 เท่าเดิม แล้วทุกวงหมุนไปกี่องศาจากเดิม?
② ใส่ PHASE(90°) (หมุนเฉพาะวง |1⟩ ไป 90°) ให้ |1⟩ · ผลคืออะไร?
ถูกค่ะ! วง |0⟩ ว่าง → วงที่มีของอยู่มีแค่ |1⟩ วงเดียว · หมุนมัน 90° = หมุน “ทุกวงที่มีของ” เท่ากัน = global phase 90°
ใบ้: วง |0⟩ ว่าง (magnitude 0) · relative phase ต้องมีอย่างน้อย 2 วงที่มีของถึงจะเทียบกันได้ · แล้ววง |1⟩ หมุนไปกี่องศา?
③ ใส่ HAD ให้ |+⟩ (50/50 เฟส 0° ทั้งคู่ — หน้าตาคล้าย eigenstate 1) · เป็น eigenstate ของ HAD ไหม?
ถูกค่ะ! H|+⟩ = |0⟩ 100% → magnitude เปลี่ยน = state ใหม่ · HAD มี eigenstate แค่ 2 ตัวใน Table 8-1 เท่านั้น (85/15 ไม่ใช่ 50/50)
ย้อนดูบท 0005: H บน |+⟩ ทำให้สองทางหักล้างกันที่ |1⟩ → ออกมาเป็น |0⟩ 100% · magnitude เปลี่ยนแล้วนะคะ

ส่วนที่ 2 · phase estimation ทำอะไร (p9–11)

2.1 ปัญหา: eigenphase คือ global phase → อ่านตรงๆ ไม่ได้

ถ้าเอา eigenstate ไปใส่ U แล้ว READ เลย ผลที่ได้จะเหมือนเดิมทุกครั้ง ไม่ว่า θ จะเป็นเท่าไร (เพราะ global phase ไม่เปลี่ยนความน่าจะเป็น) · จุดเด่นของ phase estimation คือ ย้ายข้อมูลเรื่อง global phase นั้นไปไว้ใน register อีกตัว ในรูปที่ READ ได้ (p9)

ใน QCEngine เรียกผ่านฟังก์ชัน phase_est() · หน้าตากล่องดำเป็นแบบนี้:

cont_u(Access to subroutine conditionally performing U)
ส่วนคืออะไร
qout (บน · m qubit)register สำหรับคำตอบ · เริ่มด้วย write 0 ทุกสาย (▷ วงฟ้า) · ปลายทาง READ ทุกสาย → ตัวเลขที่อ่านได้รวมกันแทน θ
qin (ล่าง · n qubit)ใส่ eigenstate ของ U ที่เตรียมไว้ (ในรูปเป็นตัวอย่าง: สายแรก write 1 = ▷ สามเหลี่ยมเหลือง) · ปลายทางไม่ READ · ออกมายังเป็น eigenstate เดิม
cont_u (กล่องเทาใต้กล่องใหญ่)ลูกศรชี้เข้ากล่อง = เราต้องส่ง subroutine ที่ทำ U “แบบมีเงื่อนไข” (controlled-U) ให้มันใช้ · ไม่ใช่สายควบคุมในวงจร

ในสไลด์มี ⋮ แทน “กี่ qubit ก็ได้” (m กับ n) และ detector ของ qout มีป้ายผลตัวอย่าง 0, 1, 1 (สองตัวหลังพื้นเหลือง = อ่านได้ 1) · หนูวาดเป็น 3+3 สายแทน ⋮ นะคะ

⑤ ทำไมเราไม่ใส่ U ให้ eigenstate แล้ว READ qin ตรงๆ ให้จบเรื่อง?
ถูกค่ะ! eigenphase เป็น global phase → ความน่าจะเป็นตอน READ เท่าเดิมไม่ว่า θ เป็นเท่าไร → ข้อมูล θ หายไปหมด · ต้องมีกลไกย้ายมันไปเป็น relative phase ของ register อื่น (บท 0033 จะเปิดดูว่าทำยังไง)
ย้อนไปกล่องทบทวนต้นส่วนที่ 1: global phase เปลี่ยนความน่าจะเป็นตอน READ ไหมคะ?
ชิมลางบทหน้า: qout ไม่ได้คืนเลข “180” ออกมาตรงๆ แต่คืนเป็นเศษส่วนของ 360° — สูตรเดียวกับกฎ θ = n/2ᴺ × 360° ที่พี่เพิ่งเรียนในบท 0030 เลยค่ะ · บท 0032 จะลองหา eigenphase ของ HAD จริงด้วยโค้ด แล้วอ่านได้เลข 8… ลองเดาไว้ก่อนว่าทำไม 8 ถึงแปลว่า 180°
ทดสอบความจำ (ปิดหน้าจอแล้วตอบเองก่อนเปิด)
  1. phase estimation ต่างจาก AA และ QFT ยังไง? → บอกคุณสมบัติของ operation ไม่ใช่ของ state
  2. eigenstate คืออะไร? → state ที่ operation ไม่เปลี่ยน ยกเว้นใส่ global phase
  3. eigenstate ของ HAD มีกี่ตัว หน้าตาแบบไหน? → 2 ตัว: 85.35/14.64 เฟส 0,0 และ 14.64/85.35 เฟส 180,0
  4. eigenphase ของแต่ละตัว? → 0° และ 180°
  5. 180° ใน eigenstate 2 กับ eigenphase 180° ต่างกันยังไง? → relative (หน้าตา state) vs global (ที่ HAD ใส่ให้)
  6. ทำไม eigenphase ถึงน่าสนใจ? → เซต eigenstate + eigenphase ระบุ operation ได้แบบไม่ซ้ำ
  7. วาด Figure 8-3: register ไหนอยู่บน, อันไหน READ, cont_u อยู่ตรงไหน? → qout (m) บน + READ → θ · qin (n) ล่างไม่ READ · cont_u ลูกศรเข้าใต้กล่อง

สรุป

  • phase estimation = primitive ตัวที่ 3 · บอกเรื่อง operation (AA/QFT บอกเรื่อง state)
  • eigenstate = state ที่ U ไม่เปลี่ยน (ยกเว้น global phase) · eigenphase θ = global phase นั้น
  • HAD: eigenstate 2 ตัวเท่านั้น → eigenphase 0° และ 180° (Table 8-1)
  • เซต eigenstate + eigenphase = ลายนิ้วมือที่ระบุ operation ได้แบบไม่ซ้ำ
  • global phase อ่านไม่ได้ → phase estimation ย้าย θ ไปไว้ใน qout ที่ READ ได้ · input = qin (eigenstate) + qout (เริ่ม 0) + cont_u
