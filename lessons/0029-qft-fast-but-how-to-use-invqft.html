QFT เร็วมาก แต่เอาไปใช้ยังไง? → กลับด้านเป็น invQFT

บท 0028b จบด้วยข่าวร้ายว่า QFT ทำได้เหมือน DFT เป๊ะ แต่ READ ได้ความถี่เดียวแบบสุ่ม · บทนี้ตอบคำถามต่อว่า “แล้วจะลงทุนใช้ QPU ทำ QFT ไปทำไม” · คำตอบมีสองชั้น: QFT เร็วกว่า FFT แบบทิ้งห่าง แต่ติดปัญหา 2 ข้อ · แล้วเราจะพลิกเครื่องมือกลับด้านเป็น invQFT เพื่อสร้างสัญญาณแทนที่จะอ่านมันค่ะ

ทำไมต้องเรียนบทนี้: จับหลัก 4 อย่าง ① FFT ใช้ O(n·2ⁿ) ส่วน QFT ใช้ O(m²) → QFT ชนะหลังราว 22 บิต ② ปัญหา 2 ข้อ: ใส่สัญญาณเข้า register ยาก และ อ่านผลออกได้ค่าเดียว → QFT จึงเป็น phase manipulation primitive ③ invQFT: เขียน “ความถี่” ลง register แล้ว invQFT → ได้สัญญาณ (เฟสแกว่ง หรือ magnitude แกว่งถ้าเขียนแบบสมมาตร) ④ แก้ความถี่: QFT → +1 → invQFT · และแยกวงจร QFT กับ invQFT ออกด้วย เครื่องหมายมุม + ตำแหน่ง SWAP (เรื่องสอบ)

ส่วนที่ 1 · QFT เร็วแค่ไหน และทำไมยังเอาไปแทน FFT ไม่ได้

ตั้งคำถามก่อน: ลงทุนขนาดนี้เพื่ออะไร

สไลด์ p40 ยอมรับตรงๆ ว่า QPU ทั้งจุกจิก (finicky) และแพง · การใช้มันทำ DFT ซ้ำสิ่งที่โน้ตบุ๊กทำได้อยู่แล้วฟังดูไม่คุ้ม · แต่ต้องจำไว้ว่า

เหตุผลหลักที่ใช้ QFT เป็น primitive คือเพื่อจัดการผลลัพธ์ที่เข้ารหัสอยู่ในเฟส (phase-encoded results) ไม่ใช่เพื่อมาแทน FFT (p40)

ถึงอย่างนั้นก็ยังน่าเทียบความเร็วดู เพราะ QFT เร็วกว่าคู่แข่งคลาสสิกที่ดีที่สุด “far, far faster”

วัด “ความเร็ว” ยังไง

ไม่ได้จับเวลาเป็นวินาที แต่ดูว่า จำนวน operation โตแค่ไหน เมื่อสัญญาณมีจำนวนบิตมากขึ้น (p41) · เรียกแนวคิดนี้ว่า computational complexity (ความซับซ้อนเชิงคำนวณ) · นับ operation แทนเวลาได้ เพราะแต่ละ gate ใช้เวลาคงที่

คิดเองก่อนเลือก: สัญญาณ 20 บิต → เพิ่มเป็น 21 บิต · งานของ FFT (n·2ⁿ) กับ QFT (m²) โตขึ้นประมาณกี่เท่าตามลำดับ
ถูกค่ะ · FFT: (21·2²¹)/(20·2²⁰) = 2 × 21/20 = 2.1 · QFT: 21²/20² = 441/400 ≈ 1.1 · เพิ่มบิตทีละตัว FFT เบิ้ลงานทุกครั้ง แต่ QFT แทบไม่ขยับ → นี่คือเหตุผลที่ FFT “ระเบิด” ในกราฟ
ลองแทนค่าตรงๆ: FFT = (21·2²¹)/(20·2²⁰) และ QFT = 21²/20² · ตัว 2ⁿ ต่างหากที่ทำให้คูณ 2

ปัญหา 1 (p44): square wave ในบท 0028b สร้างได้ง่ายเพราะมันเป็นแค่ had + phase(180, 16) · แต่ถ้าอยากใส่ข้อมูลคลาสสิกอะไรก็ได้ (เช่นไฟล์เสียงจริง) วงจรง่ายๆ แบบนั้นอาจไม่มี · ต้นทุนการเตรียม register อาจกลืนความได้เปรียบของ QFT จนหมด · มีเทคนิคช่วยอยู่บ้าง แต่มักต้องเพิ่มฮาร์ดแวร์นอกเหนือจาก QPU มาตรฐาน

เปรียบเทียบ: QFT เหมือนเครื่องคั้นน้ำผลไม้ที่คั้นได้ในเสี้ยววินาที แต่ต้องปอกผลไม้ทีละลูกด้วยมือก่อนใส่ · ถ้าปอกนาน 10 นาที ความเร็วตอนคั้นก็แทบไม่มีความหมาย

ปัญหา 2 (p45): ถ้าสัญญาณมีความถี่เดียว READ แล้วได้คำตอบชัดเจน · แต่สัญญาณซับซ้อน (เช่น square wave) ให้ superposition ของหลายความถี่ → READ ได้ความถี่เดียวแบบสุ่ม · ไม่ได้ spectrum ทั้งกราฟแบบ DFT

กรณี 1 · คำตอบไหนก็ได้ในกลุ่ม

ด้วยสองกรณีนี้ QFT จึงยังมีค่าในฐานะ phase manipulation primitive (ตัวดำเนินการพื้นฐานสำหรับจัดการเฟส) · และจะได้เห็นมันทำหน้าที่นี้ใน Shor's factoring algorithm (Lec 12) (p47)

ส่วนที่ 2 · invQFT: เขียนความถี่ลงไป แล้วได้สัญญาณออกมา

กลับด้านเครื่องมือ

ปัญหา 1 บอกว่าเตรียมสัญญาณยาก · แต่ทุก QPU operation ยกเว้น READ มี inverse (ตัวผกผัน) · QFT ก็เช่นกัน (p48):

QFTรับสัญญาณ (เข็มหมุนเป็นจังหวะ) → คืน ความถี่ (peak)
⇄
invQFTรับ ความถี่ (frequency space) → คืนสัญญาณที่มีความถี่นั้น

ในโลกความถี่ สัญญาณคาบง่ายๆ หน้าตาเป็นแค่ “ค่าเดียว” ที่เขียนลงไปง่ายมาก · สูตรเตรียม superposition ที่เป็นคาบจึงมี 2 ขั้น:

① เตรียม register ให้เป็น state ที่ต้องการในโลกความถี่ (มักง่ายกว่าสร้างสัญญาณตรงๆ มาก)
② ใส่ invQFT → ได้สัญญาณที่ต้องการใน register เดิม

แบบที่ 1 · เฟสแกว่ง 3 รอบ: write(3) + invQFT (p49)

// Setup
var num_qubits = 4; qc.reset(num_qubits);
var qin = qint.new(num_qubits, 'qin');
// Write the frequency we want to register
qin.write(3);
// Inverse QFT to turn into a signal
qin.invQFT()
สไลด์ขัดกันเอง (p49): บรรทัดนำเขียนว่า “qubyte register” แต่โค้ดและรูปเป็น 4 qubit (num_qubits = 4) · ยึดตามโค้ด/รูปเป็นหลัก · ถ้าข้อสอบถามจากรูปนี้ ตอบ 4 qubit

ก่อนและหลัง invQFT (คาโฮะจำลองวงจรตามรูปทีละ gate แล้ว ผลตรงกับที่สไลด์บอก):

magnitude เท่ากันทุกวง (6.25%) · เข็มหมุนเพิ่มวงละ 3 × 360°/16 = 67.5° → ตลอด 16 วงหมุนครบ 3 รอบ · นี่คือสถานะ “ความถี่ 3” แบบเดียวกับสถานะ A/B/C ในบท 0027 แค่เดินย้อนทาง

คำนวณเอง: ถ้าเปลี่ยนเป็น qin.write(5) แล้ว invQFT (4 qubit) · เข็มของวง |2⟩ ชี้ที่มุมเท่าไร
ถูกค่ะ · หมุนวงละ 5 × 22.5° = 112.5° · วง |2⟩ = 2 × 112.5° = 225°
ขั้นแรกหามุมต่อวง: 5 × (360°/16) = 5 × 22.5° · แล้ววง |k⟩ หมุนไป k เท่าของมุมนั้น

แบบที่ 2 · magnitude แกว่ง: ต้องเขียนความถี่แบบสมมาตร (p50–51)

ย้อนบท 0028: สัญญาณที่แกว่งใน magnitude เป็น real signal (สัญญาณจำนวนจริง) ซึ่งใน frequency space มี peak คู่สะท้อน f กับ N−f เสมอ · ถ้าจะเดินย้อนทางด้วย invQFT ก็ต้องเขียนทั้งคู่ลงไป = symmetric representation (การแทนแบบสมมาตร)

// Setup
var num_qubits = 4; qc.reset(num_qubits);
var qin = qint.new(num_qubits, 'qin');   // สไลด์พิมพ์ 'qin’ (quote ปิดเอียง) → รันไม่ผ่าน
qin.write(0);
// Write the frequencies we want to register
qin.had(1);
qc.cnot(14,1);
qin.not(2);
qc.cnot(1,2);
qin.not(2);
//Inverse QFT to turn into a signal
qin.invQFT()
อ่านโค้ดให้ถูก: ตัวเลขทุกตัวคือ bitmask ไม่ใช่เลขสาย · qc.cnot(14, 1) = (target, control) → target 14 = 0x2+0x4+0x8, control 1 = 0x1 (เหมือนบท 0022) · และสไลด์ p51 พิมพ์ 'qin’ ด้วย smart quote — ในข้อสอบเขียน 'qin'

ลองไล่เองก่อนเปิดดูเฉลย: ช่วง Write freq ทำให้ register เป็น superposition ของค่าอะไร

เฉลยทีละขั้น (ลองเขียนในกระดาษก่อนนะคะ)
① write(0) → |0⟩
② had(1) → |0⟩ + |1⟩ (ละ √2 ไว้)
③ cnot(14,1): ถ้า 0x1 เป็น 1 ให้พลิก 0x2, 0x4, 0x8 → |0⟩ + |15⟩
④ not(2): พลิก 0x2 → |2⟩ + |13⟩
⑤ cnot(1,2): ถ้า 0x2 เป็น 1 ให้พลิก 0x1 → |2⟩ กลายเป็น |3⟩ · |13⟩ = 1101 บิต 0x2 เป็น 0 ไม่เปลี่ยน → |3⟩ + |13⟩
⑥ not(2): พลิก 0x2 → |1⟩ + |15⟩ = ความถี่ +1 กับภาพสะท้อน 16−1 ✔ สมมาตร

ได้ขนาดวงแกว่ง 1 รอบ (ใหญ่ → หาย → ใหญ่ → หาย) และเข็มมีแค่ 0° กับ 180° = จำนวนจริง · หน้าตาเดียวกับ Figure 7-13 ในบท 0028 เพียงแต่เดินกลับทาง

4 qubit · อยากได้ magnitude แกว่ง 2 รอบ ตลอด register · ก่อน invQFT ต้องเขียน register ให้เป็นอะไร
ถูกค่ะ · magnitude = สัญญาณจริง → ต้องมีคู่สะท้อน f กับ 16 − f = 2 กับ 14 · ถ้าเขียน |2⟩ อย่างเดียวจะได้เฟสแกว่ง 2 รอบ แต่ magnitude เท่ากันหมด
กฎคู่สะท้อนจากบท 0028: f คู่กับ N − f · ที่นี่ N = 16 · ส่วน |2⟩ ตัวเดียวให้เฟสแกว่ง ไม่ใช่ magnitude

แก้ความถี่ของสัญญาณ: QFT → +1 → invQFT (p52–53)

invQFT ยังช่วยแก้ (alter) ความถี่ของสัญญาณที่มีอยู่แล้วได้ด้วย · สมมติกลางอัลกอริทึม อยากให้เฟสแกว่งเร็วขึ้น:

① QFT → ย้ายสัญญาณเข้า frequency space
② บวก 1 → ทุก frequency component เลื่อนขึ้น 1 (ใช้วงจร +1 จากบท 0018)
③ invQFT → กลับเป็นสัญญาณ แต่ความถี่สูงขึ้น
var n=4;
// Prepare a complex sinusoidal signal
qc.reset(n);
var freq = 2;
qc.write(freq);
var signal = qint.new(n, 'signal');
signal.invQFT();
// Move to frequency space with QFT
signal.QFT();
// Increase the frequency of signal
signal.add(1)
// Move back from frequency space
signal.invQFT();

ตามรอยด้วยตัวเลข: เฟสหมุนวงละ 45° (ความถี่ 2) → QFT ได้ |2⟩ 100% → +1 ได้ |3⟩ → invQFT ได้เฟสหมุนวงละ 67.5° (ความถี่ 3) · คาโฮะจำลองวงจรเต็มทั้ง 4 บล็อกแล้วได้ผลนี้จริง

กฎเลือกผลลัพธ์ของ invQFT (p53): ความถี่เดียว หรือหลายความถี่ที่ไม่สมมาตร → คาบใน relative phase · ความถี่ที่สมมาตร (f คู่กับ N−f) → คาบใน magnitude · สไลด์เตือนด้วยว่าสัญญาณ input ที่เป็นจำนวนจริงจัดการใน frequency space ยากกว่า
คิดต่อจากกฎข้างบน: ถ้าใช้ QFT → +1 → invQFT กับสัญญาณ magnitude แกว่ง 1 รอบ (|1⟩ + |15⟩ ในโลกความถี่) จะเกิดอะไรขึ้นตอน +1
ถูกค่ะ · 15 + 1 = 16 ล้นกลับเป็น 0 · คู่สะท้อนที่ควรเป็น 14 กลับถูกเลื่อนออกไปอีกทาง · นี่คือเหตุที่สไลด์บอกว่าสัญญาณจำนวนจริง “trickier” — +1 ไม่ได้ทำให้แกว่งเร็วขึ้นแบบตรงไปตรงมา
+1 บวกเท่ากันทุกค่า: 1 → 2 และ 15 → 16 ซึ่ง register 4 bit เก็บได้ถึง 15 เลยล้นเป็น 0 · แล้วเช็คว่า 2 กับ 0 เป็นคู่ f / 16−f ไหม

ทดสอบความจำ (ตอบในหัวก่อน แล้วค่อยเปิด)
  1. FFT กับ QFT ใช้ operation กี่ตัวในรูป Big-O · จุดตัดในกราฟอยู่ราวกี่บิต → O(n·2ⁿ) vs O(m²) · ~22 บิต (~4 ล้าน sample)
  2. ปัญหา 2 ข้อของการใช้ QFT ทำ signal processing → ใส่สัญญาณเข้ายาก (อาจกลืนข้อได้เปรียบ) · READ ได้ความถี่เดียวแบบสุ่ม
  3. 2 กรณีที่ผลสุ่มยังใช้ได้ → ยอมรับคำตอบไหนก็ได้ในกลุ่ม · verify ได้แล้วรันซ้ำ
  4. write(3) + invQFT บน 4 qubit ได้อะไร → magnitude เท่ากัน · เฟสเพิ่มวงละ 67.5° · 3 รอบ
  5. อยากได้คาบใน magnitude ต้องเขียนความถี่แบบไหน → สมมาตร f กับ N − f
  6. สามขั้นแก้ความถี่ → QFT → +1 → invQFT
  7. แยก QFT/invQFT ในรูป → มุมลบ = QFT · มุมบวก = invQFT · (สไลด์ชุดนี้ SWAP ท้าย vs ต้น)

สรุป

  • QFT O(m²) เทียบ FFT O(n·2ⁿ) · เพิ่ม 1 บิต FFT งานเบิ้ล QFT แทบไม่ขยับ · ชนะจริงหลัง ~22 บิต
  • ผลของ QFT ล็อกอยู่ใน register → ติด ใส่เข้ายาก + อ่านออกได้ค่าเดียว → ใช้เป็น phase manipulation primitive (→ Shor, Lec 12)
  • invQFT: เขียนความถี่ → invQFT → ได้สัญญาณ · ความถี่เดียว = เฟสแกว่ง · สมมาตร = magnitude แกว่ง
  • Example 7-6: had(1); cnot(14,1); not(2); cnot(1,2); not(2) → |1⟩ + |15⟩
  • แก้ความถี่: QFT → add(1) → invQFT · ระวังสัญญาณจริง: +1 ทำลายความสมมาตร
  • ชี้ขาด QFT/invQFT ด้วยเครื่องหมายมุม · สัญลักษณ์ใหม่: ▷ เหลืองทึบ = write 1
