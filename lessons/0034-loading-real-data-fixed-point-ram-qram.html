Quantum Programming · Lec 09 · บทที่ 0034 (บทเปิดคาบ)

โหลดข้อมูลจริงเข้า register: fixed point → RAM → QRAM

ตั้งแต่ Lec 02 ถึง Lec 08 เราใส่ input ด้วย WRITE เป็นจำนวนเต็มเล็กๆ ที่พิมพ์เองด้วยมือ มาตลอด · แต่ข้อมูลจริงมีทศนิยม และถูกเก็บอยู่ใน memory เป็นพันเป็นหมื่นค่า · สไลด์เปิดคาบด้วยคำถาม 2 ข้อที่เราเคยข้ามไป (p2–4): ① จะแทนข้อมูลที่ซับซ้อนใน register ยังไง และ ② จะโหลดข้อมูลที่เก็บไว้เข้า register ยังไง · บทนี้ตอบทั้งสองข้อในเวอร์ชันที่ง่ายที่สุดก่อน คือ ตัวเลขทีละตัว · ส่วน vector กับ matrix จะเป็นของบท 0035 กับ 0036

ทำไมต้องเรียนบทนี้: จับหลัก 3 อย่าง ① ตัวเลขที่ไม่เต็มเก็บแบบ fixed point และเขียนเป็น Qn.m (n บิตทั้งหมด, m บิตเป็นเศษ) ② RAM ธรรมดา โหลดค่าเข้า register ได้ ทีละค่าเดียว (วงจร +1 ของ Lec 05 คือตัวอย่าง) ③ ถ้าอยากได้ superposition ของค่าที่เก็บไว้ ต้องใช้ QRAM ซึ่งรับ address ที่เป็น superposition ได้ · สัญลักษณ์ใหม่ที่น่าจะออกสอบ: กล่อง QRAM (Fig 9-4), กล่อง D/A (Fig 9-5), detector ที่บอกค่า (Fig 9-3)

ส่วนที่ 1 · ตัวเลขไม่เต็ม: fixed point และ Q notation (p6–9)

1.1 ทำไมต้องคิดเรื่องนี้

register ที่เราใช้มาตลอดแทนจำนวนเต็ม: สายบนสุด (0x1) มีค่า 1, สายถัดไป 2, 4, 8, … (บท 0008) · และเรายังรู้วิธีแทนเลขติดลบด้วย two's complement (บท 0019) · แต่ถ้าข้อมูลคือ 3.64 ล่ะ? คอมพิวเตอร์ธรรมดามีคำตอบอยู่ 2 แบบ (p6):

  • floating point (จุดทศนิยมลอยตัว): ยืดหยุ่น ปรับช่วงค่าได้เอง แต่ซับซ้อน
  • fixed point (จุดทศนิยมตายตัว): ตกลงกันไว้ล่วงหน้าว่าบิตไหนเป็นจำนวนเต็ม บิตไหนเป็นเศษ · ง่ายกว่า และ qubit มีราคาแพง → สไลด์เลือกแบบนี้
ราคาสินค้าในร้านตกลงกันว่าหลังจุดมีเลข 2 หลักเสมอ (99.50 บาท) · จุดอยู่ที่เดิมทุกครั้ง ไม่ต้องเก็บว่าจุดอยู่ไหน
≈
fixed pointตกลงกันว่า m บิตล่างเป็นเศษ · register ไม่รู้หรอกว่ามีจุด เราต้องจำเอง

1.2 ค่าของแต่ละบิต: ฝั่งเต็มคูณ 2 ฝั่งเศษหาร 2

fixed point แบ่ง register เป็น 2 ส่วน (p6):

  • ส่วน integer (ส่วนจำนวนเต็ม): บิตมีค่า 2⁰, 2¹, 2², … เหมือนเดิมทุกอย่าง
  • ส่วน fractional (ส่วนเศษ): ไล่ลงจากจุดไป บิตมีค่า ½, ¼, ⅛, … (= 1/2¹, 1/2², 1/2³, …)

มันคือกฎเดิมที่ต่อลงไปข้างล่าง: ถ้าขยับขึ้น 1 บิตค่า ×2 ขยับลง 1 บิตค่าก็ ÷2 · ต่ำกว่า 1 ลงไปจึงเป็น ½, ¼, …

1.3 Q notation: บอกว่าจุดอยู่ตรงไหน (p7)

Qn.m = register n บิต ซึ่ง m บิตเป็นเศษ → เหลือ n − m บิตเป็นจำนวนเต็ม · (Q ตรงนี้ไม่ได้ย่อมาจาก quantum นะคะ สไลด์บอกไว้เอง)

ตัวอย่างในสไลด์ (Figure 9-1): เก็บ 3.640625 ใน register 8 qubit แบบ Q8.6 → เศษ 6 บิต, จำนวนเต็ม 2 บิต · ป้ายซ้ายมือคือค่าของแต่ละสาย (เขียนแบบ QCEngine คือมี 0x นำหน้าแม้แต่เศษส่วน)

① อ่านจากสายล่างขึ้นบน (ค่ามากไปน้อย): 1 1 │ 1 0 1 0 0 1 → เขียนเป็นเลขฐานสอง 11101001 (ตรงกับ caption ของสไลด์)
② บวกเฉพาะสายที่เป็น 1: 2 + 1 + ½ + ⅛ + 1/64
③ = 2 + 1 + 0.5 + 0.125 + 0.015625 = 3.640625 ✓
ลองเอง: register 4 qubit แบบ Q4.2 · สายบน→ล่างเขียนค่าเป็น 1, 1, 0, 1 · register นี้เก็บเลขอะไร? (คิดก่อนว่าสายบนสุดมีค่าเท่าไร)
ถูกค่ะ! Q4.2 → สายบน→ล่างมีค่า ¼, ½, 1, 2 · สายที่เป็น 1 คือ ¼ + ½ + 2 = 2.75
ยังไม่ใช่ค่ะ · Q4.2 มีเศษ 2 บิต → สายบน→ล่างมีค่า ¼, ½, 1, 2 (ไม่ใช่ 1, 2, 4, 8) · บวกสายที่เป็น 1: ¼ + ½ + 2 = 2.75 · ถ้าได้ 13 แปลว่าลืมไปว่ามีเศษ

1.4 ข้อแลกเปลี่ยน: range กับ accuracy (p8)

3.640625 ลงตัวพอดีเพราะบังเอิญเป็นผลรวมของ 2¹, 2⁰, ½, ⅛, 1/64 · ปกติเราไม่โชคดีขนาดนั้น · เช่นเลข 0.1 ไม่มีทางเขียนเป็นผลรวมของ ½, ¼, ⅛, … ได้พอดี จึงได้แค่ค่าใกล้เคียง · เวลาจะเพิ่มบิต เราต้องเลือกว่าจะเพิ่มฝั่งไหน:

เพิ่มบิตฝั่งได้อะไรตัวอย่าง (เทียบกับ Q4.2)
integerrange (ช่วงค่า) กว้างขึ้น: เก็บเลขใหญ่ได้ขึ้นQ5.2: ค่าสูงสุดจาก 3.75 เป็น 7.75
fractionalaccuracy (ความแม่นยำ) ละเอียดขึ้น: ขั้นเล็กลงQ5.3: ขั้นจาก ¼ เหลือ ⅛

ตัวเลขในคอลัมน์ขวาหนูคำนวณเองเพื่อให้เห็นภาพ ไม่ได้อยู่ในสไลด์ค่ะ

register Q3.2 (ขั้นละ ¼) ต้องเก็บเลข 1.3 · ค่าที่ register เก็บได้ใกล้ที่สุดคือเท่าไร?
ถูกค่ะ · ค่าที่เก็บได้คือ 0, 0.25, 0.5, …, 1.25, 1.5, … · 1.3 ห่างจาก 1.25 แค่ 0.05 → error นี้แหละคือราคาของบิตเศษที่น้อย
ยังไม่ใช่ค่ะ · Q3.2 มีเศษ 2 บิต → ค่าที่เก็บได้ก้าวทีละ ¼: …, 1.00, 1.25, 1.50, … · เก็บ 1.3 ตรงๆ ไม่ได้ · ที่ใกล้ที่สุดคือ 1.25

1.5 สองเรื่องที่ต้องระวัง (p9)

① register ไม่รู้ว่าตัวเองใช้ encoding อะไร · บิต 1101 อาจเป็น 13 (binary ธรรมดา), −3 (two's complement) หรือ 3.25 (Q4.2) ก็ได้ · เราต้องจำเองว่า register ไหนเข้ารหัสแบบไหน ไม่งั้นตีความผิดหมด
② overflow (ล้น) เกิดง่ายทั้งกับ two's complement และ fixed point = ผลลัพธ์ใหญ่เกินกว่าที่ register แทนได้ ได้เลขที่ไม่มีความหมาย · สไลด์บอกว่าทางแก้จริงมีทางเดียวคือเพิ่ม qubit ให้ register

ตัวอย่าง −3 กับ 3.25 ในข้อ ① หนูคิดเพิ่มเองเพื่อให้เห็นภาพ (1101 อ่านจากซ้าย = บิตค่ามาก) · ข้อความหลักมาจากสไลด์ค่ะ

ส่วนที่ 2 · โหลดค่าจาก RAM ธรรมดา ทีละค่า (p10–14)

2.1 RAM ทำงานยังไง (p10–11 · Figure 9-2)

ตอนนี้เราแทนตัวเลขได้แล้ว แต่ถ้าต้องพิมพ์ WRITE เองทุกค่าก็คงเหนื่อยแย่ · สิ่งที่อยากได้คือ อ่านจาก memory โดยบอก address · RAM ธรรมดา (conventional RAM) รับ register 2 ตัว:

  • address register (register ที่อยู่): ตั้งค่าเป็นตำแหน่งที่อยากอ่าน
  • output register (register ผลลัพธ์): ยังว่างอยู่ RAM จะเขียนค่าที่เก็บไว้ ณ address นั้นลงมา
⚠️ ลำดับบิตในรูปนี้ขัดกันเอง · ถ้าอ่าน address บน→ล่าง = “10” ตารางให้ “100” แต่ output ที่ออกมาบน→ล่างคือ 0,0,1 (กลับด้าน) · ถ้าใช้ convention ของ QCEngine (สายบน = 0x1) address จะเป็น 01 → ตารางให้ 110 → ก็ยังไม่ตรงกับ 0,0,1 · ไม่มี convention ไหนอธิบายรูปนี้ได้ทั้งรูป · ตอบตามสไลด์ตอนสอบ (address 10 → ค่า 100) แต่รู้ไว้ว่ารูปนี้ไม่สอดคล้องกัน · หลักที่ต้องจำคือหน้าที่ของ RAM: ใส่ address → ได้ค่าที่เก็บไว้ ณ address นั้น

2.2 ใช้ RAM โหลดค่าเดียว: ได้สบาย (p12–14 · Figure 9-3)

ถ้าต้องการให้ register เป็นค่าธรรมดาค่าเดียว RAM ใช้ได้ดีเลย: อ่านค่าจาก RAM แล้ว write() ลง register, คำนวณเสร็จก็ read() กลับไปเก็บ · สไลด์บอกว่า QCEngine ที่เราใช้มาตลอดก็คุยกับ register ด้วยวิธีนี้ (p12) · ตัวอย่างคือ a[2] += 1 โดยให้ QPU เป็นคนบวก:

// Using a QPU to increment a number in RAM
var a=[4,3,5,1];
qc.reset(3);
var qreg = qint.new(3, 'qreg');
  qc.print(a);          // 4,3,5,1
  increment(2, qreg);
  qc.print(a);          // 4,3,6,1
function increment(index, qreg) {
    qreg.write(a[index]);       // a[2] → qreg
    qreg.add(1);                // บวก 1 บน QPU
    a[index] = qreg.read();     // qreg → a[2]
}

ผลที่ print ในคอมเมนต์หนูคำนวณเอง · สไลด์ขึ้นต้นคอมเมนต์ด้วย # ซึ่งใน JavaScript ต้องเป็น // หนูแก้ให้แล้วค่ะ

สัญลักษณ์ใหม่: detector ที่บอกค่า (เรื่องสอบ) · ใน Figure 9-3 detector มีสีด้วย: เหลือง + ขีด = อ่านได้ 1 · เทา + วงกลม = อ่านได้ 0 (เข้าชุดกับ ▷ ของ WRITE ที่ใช้สีและขีด/วงแบบเดียวกัน) · รูปนี้อ่านได้ 0x1 = 0, 0x2 = 1, 0x4 = 1 → 110 = 6 ✓ · หลัง READ เส้นสายจางลงเพราะค่าถูกส่งกลับไปที่ RAM แล้ว
① เริ่มที่ 5: 0x1 = 1, 0x2 = 0, 0x4 = 1
② CCNOT: ต้องการ 0x1 และ 0x2 เป็น 1 → 0x2 เป็น 0 จึงไม่ทำงาน
③ CNOT: 0x1 = 1 → พลิก 0x2 เป็น 1 · ④ NOT: พลิก 0x1 เป็น 0
⑤ ได้ 0x1 = 0, 0x2 = 1, 0x4 = 1 = 2 + 4 = 6 ✓
ลองไล่เอง: เปลี่ยนเป็น increment(1, qreg) (a[1] = 3) · วงจรเดิมทุกอย่าง · ตอน READ detector สาย 0x1, 0x2, 0x4 จะเป็นสีอะไร?
ถูกค่ะ! 3 = 011 → CCNOT ทำงาน (0x1, 0x2 เป็น 1 ทั้งคู่) พลิก 0x4 → CNOT พลิก 0x2 เป็น 0 → NOT พลิก 0x1 เป็น 0 → 100 = 4 = 3 + 1 ✓ · มีแค่ 0x4 ที่เหลือง
ยังไม่ใช่ค่ะ · 3 + 1 = 4 = มีแค่บิต 0x4 ที่เป็น 1 → เทา · เทา · เหลือง · ไล่ทีละ gate: 011 → CCNOT (ทำงาน เพราะ 0x1 และ 0x2 เป็น 1) → 0x4 = 1 → CNOT พลิก 0x2 → 0 → NOT พลิก 0x1 → 0

ส่วนที่ 3 · อยากได้ superposition ของค่าที่เก็บไว้ → QRAM (p15–21)

3.1 RAM ธรรมดาตันตรงไหน (p15–16)

ในตัวอย่างข้างบน คนที่เลือก a[index] คือ CPU ธรรมดา แล้วส่งค่าเดียวให้ QPU · ทีนี้ถ้าเราอยากให้ register เป็น superposition ของค่าที่เก็บไว้ 2 ค่า ล่ะ? เช่นอยากได้ a[2] กับ a[3] พร้อมกัน · write() รับได้แค่ค่าเดียว และ CPU เลือก address ได้ทีละ address → ไม่มีทางทำได้เลย ด้วย RAM ธรรมดา

⚠️ สไลด์ p15 เขียนตัวเลขผิด: ยกตัวอย่างว่า RAM เก็บ “3 (110) ที่ address 0x01 และ 5 (111) ที่ address 0x11” · แต่ 111 = 7 ไม่ว่าจะอ่านทางไหน · ถ้าอ่านบิตซ้ายเป็นค่ามาก จะได้ 110 = 6 และ 111 = 7 ซึ่งตรงกับ Figure 9-4 ในหัวข้อถัดไป · ส่วน “0x01, 0x11” จริงๆ หมายถึงเลขฐานสอง 01 และ 11 · ตอบตามสไลด์ตอนสอบ แต่ให้ยึด Figure 9-4 เป็นหลักในการเข้าใจ
นิยาม QRAM (Quantum Random Access Memory) (p16): เหมือน RAM ทุกอย่าง คือรับ address register กับ output register · ต่างกันตรงที่ ทั้งสองตัวเป็น qubit register · จึงใส่ address เป็น superposition ได้ และได้ output เป็น superposition ของค่าที่เก็บไว้กลับมา

3.2 QRAM ทำงานยังไง (p17 · Figure 9-4)

① address: สายบน (0x1) = 1 คงที่ · สายล่าง (0x2) โดน H เป็นได้ทั้ง 0 และ 1 → address = |1⟩ + |3⟩ (= 01 กับ 11)
② ดูตาราง: 01 → 110 · 11 → 111
③ อ่านบิตซ้ายเป็นค่ามาก: 110 = 6 · 111 = 7 → output = |6⟩ + |7⟩ ตรงกับวงที่สไลด์วาด ✓

ป้าย 0x1/0x2 ของ address ไม่ได้อยู่ในรูป · หนูอนุมานจากวง |1⟩, |3⟩ ที่สไลด์วาดไว้ ซึ่งลงตัวพอดีค่ะ

ลองเอง: ใช้ QRAM ตารางเดียวกับ Figure 9-4 · แต่เปลี่ยนให้ address สายบน (0x1) เขียน 0 (สายล่างยังเขียน 0 แล้ว H เหมือนเดิม) · output register จะเป็น superposition ของอะไร?
ถูกค่ะ! address = |0⟩ + |2⟩ = 00 กับ 10 → ตารางให้ 011 = 3 และ 100 = 4 · สังเกตว่า |0⟩ + |2⟩ คือ address ไม่ใช่ค่าที่ได้
ยังไม่ใช่ค่ะ · ทำทีละขั้น: ① address = 0x1 เป็น 0, 0x2 เป็นได้ทั้ง 0/1 → |0⟩ + |2⟩ = 00, 10 · ② เปิดตาราง: 00 → 011, 10 → 100 · ③ แปลงเป็นเลข: 3 กับ 4

3.3 ทำ a[2] + 1 ผ่าน QRAM (p18–20 · Figure 9-5 · Example 9-2)

คราวนี้เอาตัวอย่างเดิม a = [4,3,5,1] + วงจร +1 มาทำใหม่ แต่โหลดค่าผ่าน QRAM · วางคู่กับ Figure 9-3 แล้วจะเห็นว่าต่างกันแค่ช่วงโหลด ส่วน +1 เหมือนเดิมเป๊ะ

var a=[4,3,5,1];
var reg_qubits = 3;
qc.reset(2 + reg_qubits + qram_qubits());
var qreg = qint.new(3, 'qreg');
var addr = qint.new(2, 'addr');
var qram = qram_initialize(a, reg_qubits);   // เอา array ใส่ QRAM

qreg.write(0);
addr.write(2);
addr.hadamard(0x1);      // address = |2⟩ + |3⟩

qram_load(addr, qreg);   // ← แทน qreg.write(a[index])
qreg.add(1);
Figure 9-3 (RAM)
CPU เลือก a[2] → qreg.write(5) → +1 → read() ได้ 6 · ค่าเดียว
Figure 9-5 (QRAM)
address เป็น superposition → qram_load → +1 · qreg เป็น superposition ของหลายค่า · ไม่มี READ
① addr.write(2) = 10 · hadamard(0x1) ทำให้บิต 0x1 เป็นได้ทั้ง 0/1 → addr = |2⟩ + |3⟩
② qram_load: address 2 → a[2] = 5 · address 3 → a[3] = 1 · qreg = 5 กับ 1 พร้อมกัน (แต่ละค่าผูกกับ address ของมัน)
③ add(1) ทำกับทั้งสองค่าในคราวเดียว → qreg = |6⟩ + |2⟩ (อย่างละ 50%)

ผลลัพธ์ 6/2 หนูคำนวณเอง สไลด์ไม่ได้แสดงผลไว้ค่ะ · คำว่า “ผูกกับ address” คือ qreg กับ addr พันกัน (entangled): ถ้า READ addr ได้ 2 qreg จะเป็น 6 แน่นอน

เปลี่ยน Example 9-2 เป็น addr.write(0); addr.hadamard(0x2); (ที่เหลือเหมือนเดิม) · หลัง qreg.add(1) qreg เป็น superposition ของอะไร?
ถูกค่ะ! addr = |0⟩ + |2⟩ → โหลดได้ a[0] = 4 กับ a[2] = 5 → +1 → 5 กับ 6
ยังไม่ใช่ค่ะ · ① hadamard(0x2) ทำบิตค่า 2 → addr = |0⟩ + |2⟩ · ② a[0] = 4, a[2] = 5 · ③ อย่าลืม +1 → 5 กับ 6 (ถ้าได้ 4, 5 แปลว่าลืม add)

3.4 สิ่งที่ QRAM ไม่ใช่ และทำไมมันสำคัญ (p20–21)

  • เขียน superposition กลับลง QRAM ไม่ได้ · QRAM มีไว้ให้ อ่านค่าธรรมดาที่เขียนไว้ตามปกติ แบบ superposition · ส่วนที่เก็บ superposition ไว้ได้นานๆ เรียกว่า persistent quantum memory (หน่วยความจำควอนตัมถาวร) เป็นฮาร์ดแวร์อีกชนิดเลย และน่าจะสร้างยากกว่า
  • หนังสือไม่ได้บอกว่าสร้าง QRAM จริงยังไง (เหมือนหนังสือ C++ ที่ไม่สอนว่า RAM ทำงานยังไง) · qram_load ใน QCEngine เป็นแค่ simulator ที่เลียนพฤติกรรม · สไลด์บอกด้วยว่า QPU ที่ทรงพลังอาจมาก่อน QRAM ที่ใช้งานได้จริงนานมาก (p16)
  • สิ่งที่ต้องจำคือมองมันเป็น fundamental resource (ทรัพยากรพื้นฐาน): ใส่ address แบบ superposition → ได้ค่าที่เก็บไว้แบบ superposition · แล้วสร้างของที่ซับซ้อนกว่าบนมัน คือ vector (บทหน้า) และ matrix
ทดสอบความจำก่อนปิดบท (พยายามตอบเองก่อนเปิด)
  1. Q8.6 แปลว่าอะไร มีบิตจำนวนเต็มกี่บิต? → register 8 บิต เศษ 6 บิต จำนวนเต็ม 2 บิต
  2. เพิ่มบิตฝั่ง integer ได้อะไร ฝั่ง fractional ได้อะไร? → range / accuracy
  3. overflow แก้ยังไง (ตามสไลด์)? → เพิ่ม qubit ให้ register
  4. วาด detector ที่อ่านได้ 1 กับอ่านได้ 0 → เหลือง+ขีด / เทา+วง
  5. RAM ธรรมดาโหลดอะไรเข้า register ไม่ได้? → superposition ของค่าที่เก็บไว้หลายค่า
  6. QRAM ต่างจาก RAM ตรงไหน? → address และ output เป็น qubit register ทั้งคู่
  7. ใน Figure 9-5 ตัว D กับ A หมายถึงอะไร? → D = register ที่รับข้อมูล (qreg) · A = address register
  8. เขียน superposition กลับลง QRAM ได้ไหม? → ไม่ได้ · นั่นคือ persistent quantum memory (คนละอย่างกัน)
