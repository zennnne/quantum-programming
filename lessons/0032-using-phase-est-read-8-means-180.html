ใช้ phase_est() จริง: อ่าน 8 แปลว่า 180°

บท 0031 เราเห็นกล่องดำ Figure 8-3 แล้ว: ใส่ eigenstate ลง qin ส่ง cont_u เข้าไป แล้ว READ คำตอบจาก qout · บทนี้เราจะเปิดใช้มันจริงกับ HAD ทีละบรรทัด แล้วตอบคำถามที่ทิ้งไว้: ทำไมอ่านได้ 8 แต่หมายถึง 180° · จากนั้นค่อยดู “ตัวหนังสือเล็ก” (fine print) ว่าเครื่องมือนี้มีข้อจำกัดอะไรบ้างค่ะ

ทำไมต้องเรียนบทนี้: จับหลัก 3 อย่าง ① phase_est(qin, qout, cont_u) รับ 3 อย่าง · cont_u ต้องเป็น controlled-U ที่เราเขียนเอง ② qout คืน θ เป็นเศษส่วนของ 360°: R = θ/360° × 2ᵐ (Equation 8-1 · เรื่องสอบ) ③ ถ้า θ ไม่ลงช่องพอดี → ได้ superposition รอบค่าที่ใกล้สุด (โอกาสถูก > 40%) · ต้นทุน O(m²) · ใส่ superposition ของ eigenstate ได้

1.2 โค้ดตัวอย่าง: หา eigenphase ของ HAD (Example 8-1 · p17–18)

จากบท 0031: HAD มี eigenstate ตัวหนึ่งที่ eigenphase = 180° (Table 8-1) · ลองดูว่า phase_est() หาเจอไหม:

var m = 4;                          // ขนาด qout → กำหนดความละเอียดของคำตอบ
var n = 1;                          // ขนาด qin → พอใส่ eigenstate ของ HAD
qc.reset(m + n);
var qout = qint.new(m, 'output');
var qin  = qint.new(n, 'input');
qout.write(0);                      // qout = |0000⟩
qin.write(0);
qin.roty(-135);                     // → eigenstate ของ HAD ที่ eigenphase 180°
                                    //   (ถ้าอยากได้ตัว 0° ใช้ qin.roty(45))
function cont_u(qcontrol, qtarget, control_count) {
    // HAD ทำซ้ำจำนวนคู่ = ไม่ทำอะไร → สนใจแค่ว่าคี่ไหม
    if (control_count & 1)
        qtarget.chadamard(null, ~0, qcontrol.bits(control_count));
}
phase_est(qin, qout, cont_u);
qout.read();
① ทำไมส่ง controlled-HAD ไม่ส่ง HAD ตรงๆ? (p19) กลไกข้างใน phase estimation ต้องใช้ controlled-U (บท 0033 จะเปิดดูว่าทำไม) · การสร้าง controlled version ของ operation ใดๆ ไม่ใช่เรื่องง่าย → phase_est() เลยโยนหน้าที่นี้ให้ผู้ใช้เขียนเอง · HAD โชคดีที่ QCEngine มี chadamard() (controlled-HAD) ให้ใช้เลย
② control_count คือ “ให้ทำ U กี่ครั้ง” · ในโค้ดข้างใน (p31) primitive เรียก cont_u(q_out, q_in, 1 << j) = 1, 2, 4, 8 ครั้ง สำหรับ qout แต่ละสาย · ค่าเดียวกันนี้ยังใช้เลือกสายควบคุมผ่าน qcontrol.bits(control_count)
③ ทำไมเช็คแค่ control_count & 1? HAD·HAD = ไม่ทำอะไร (บท 0005) → ทำ 2, 4, 8 ครั้งก็เท่ากับไม่ทำ · ทำจริงเฉพาะตอนจำนวนครั้งเป็นคี่ (บิตสุดท้าย = 1) · นี่คือตัวอย่างของ “ทำ Uk ให้เร็ว” ที่บท 0033 จะพูดถึง

สไลด์ไม่ได้อธิบาย argument null, ~0 ของ chadamard → ไม่ต้องจำค่ะ จำแค่ว่า “ทำ HAD บน qtarget โดยมีบิตใน qcontrol เป็นตัวควบคุม”

① ถ้าอยากได้คำตอบ θ ที่ละเอียดขึ้น ต้องแก้ตัวแปรไหนในโค้ด?
ถูกค่ะ! คำตอบถูกเขียนลง qout → qout มีกี่ qubit ก็แบ่งรอบ 360° ได้ละเอียดเท่านั้น (p14) · n แค่ต้องพอใส่ eigenstate
คำตอบ θ ถูกเขียนลง register ไหนคะ? register นั้นแหละที่ต้องใหญ่ขึ้น

1.4 ทำไม 8 = 180°: เศษส่วนของรอบ (p21–22)

ข้างใน phase estimation ไม่ได้เก็บ “องศา” แต่เก็บ θ เป็นเศษส่วนของ 360° แล้วเขียนลง qout เป็น เศษส่วนเดียวกันของขนาด register (2ᵐ ค่า) · 180° = ครึ่งรอบ · qout 4 qubit มี 2⁴ = 16 ค่า → ครึ่งหนึ่ง = 8

หน้าปัดนาฬิกา 16 ขีดเข็มชี้ขีดที่ 8 = ครึ่งรอบ · ไม่มีใครพิมพ์ “180°” บนหน้าปัด เราต้องแปลงเอง
≈
qout m qubitมี 2ᵐ ขีดรอบวง · ค่าที่อ่านได้ R = ขีดที่เข็ม θ ชี้
R = θⱼ360° × 2ᵐ   ⇔   θⱼ = R × 360°2ᵐ

Equation 8-1 · R = ค่าที่อ่านจาก qout · m = จำนวน qubit ของ qout

HAD 180/360 × 2⁴ = ½ × 16 = 8 ✓ (p22)
สไลด์ 90° กับ qout 3 qubit: 90/360 × 2³ = ¼ × 8 = 2 ✓ (p21)
นี่คือกฎเดิมจากบท 0030 แค่กลับข้าง! ตอนนั้น invQFT อ่านวงที่หมุนวงละ θ = n/2ᴺ × 360° ออกมาเป็น |n⟩ · ตอนนี้ θ = R × 360°/2ᵐ สูตรเดียวกันเป๊ะ (n ↔ R, N ↔ m) → เป็นเบาะแสว่าข้างใน phase estimation มี invQFT ซ่อนอยู่ (บท 0033 จะเปิดดู)
ตัวยกหายในสไลด์ (p21–22) — เขียน “the 23 = 8 possible values” และ “24 = 16 values” → ที่ถูกคือ 2³ = 8 และ 2⁴ = 16 (แบบเดียวกับ Lec 07) · อย่าลอก “23” ไปตอบนะคะ
② eigenphase = 270° ใช้ qout 4 qubit — READ qout จะได้เลขอะไร? (คิดเองก่อนกด)
ถูกค่ะ! 270/360 = ¾ ของรอบ · ¾ × 16 = 12
270° เป็นกี่ส่วนของรอบ? แล้วเอาไปคูณกับ 2⁴ = 16 ค่ะ
③ qout มี 5 qubit อ่านได้ 10 — eigenphase คือกี่องศา?
ถูกค่ะ! 2⁵ = 32 ขีด · 10/32 × 360° = 112.5°
ใช้สูตรกลับด้าน θ = R × 360°/2ᵐ · ระวัง 2⁵ = 32 ไม่ใช่ 16 นะคะ

2.2 มุมไม่ลงขีด → superposition รอบค่าที่ใกล้สุด (p25–26)

ลองหา eigenphase 150° ด้วย qout 3 qubit: 150/360 × 8 = 3.33 → ไม่ใช่จำนวนเต็ม อยู่ระหว่าง 011 (135°) กับ 100 (180°) · ผลคือ qout ไม่ได้เป็นค่าเดียว แต่เป็น superposition ที่กระจุกรอบค่าใกล้สุด (Figure 8-5):

  • READ แล้วได้ 3 (= 135°) บ่อยสุด ≈ 69% · ได้ 4 (= 180°) ≈ 17.5% · ค่าอื่นๆ ที่เหลือรวมกัน ≈ 14%
  • เราได้ “ค่าประมาณที่ดีที่สุดในความละเอียดนั้น” แค่ด้วยความน่าจะเป็นระดับหนึ่ง ไม่ใช่ทุกครั้ง (p26)
  • เฟสของแต่ละวง (เข็ม) ไม่ต้องจำ — สิ่งที่ต้องจำคือขนาดวงกระจุกที่ 3 กับ 4
เคยเห็นแล้วในบท 0028: ความถี่ที่ไม่ลงช่องพอดี (เช่น 8.4) ทำให้ peak ใน spectrum บานไปช่องข้างๆ · ตรงนี้คืออาการเดียวกัน เพราะ qout ถูกอ่านด้วย invQFT ที่ “ฟังความถี่” ได้แค่เป็นช่องๆ
④ eigenphase = 60° · ต้องใช้ qout กี่ qubit ถึงจะอ่านได้เป๊ะ 100%?
ถูกค่ะ! 60° = 1/6 ของรอบ · ต้องหา 2ᵐ ที่ 1/6 × 2ᵐ เป็นจำนวนเต็ม → 2ᵐ ต้องหารด้วย 3 ลงตัว ซึ่งไม่มีวันเกิด · เพิ่ม m ได้แค่ “ใกล้ขึ้น” + โอกาสถูกสูงขึ้น
ลองแทนสูตร R = 60/360 × 2ᵐ = 2ᵐ/6 ดูค่ะ · มี m ไหนที่ทำให้ 2ᵐ หาร 6 ลงตัวไหม?

2.3 โอกาสถูก และสูตรเลือก m (p27)

โอกาสได้ค่าประมาณที่ดีที่สุด มากกว่าราว 40% เสมอ (150° ข้างบนได้ 69%) และเพิ่มได้ด้วยการเพิ่มขนาด qout · ถ้าอยากได้ eigenphase แม่น p บิต และยอมให้พลาดได้ไม่เกินความน่าจะเป็น ε (epsilon) ให้ใช้:

m = p + ⌈ log( 2 + 1ε ) ⌉

⌈ ⌉ = ceiling (ปัดขึ้นเป็นจำนวนเต็ม) · log ฐาน 2 (นับเป็น “กี่บิต”)

ตัวอย่าง อยากได้ p = 3 บิต ยอมพลาด ε = 0.1 (10%): log₂(2 + 10) = log₂ 12 ≈ 3.58 → ปัดขึ้น = 4 → m = 3 + 4 = 7 · แปลว่าต้องจ่าย qubit เกินมา 4 ตัวเพื่อความมั่นใจ
สูตรในสไลด์ต่างจากตำรามาตรฐานนิดหน่อย — Nielsen & Chuang ใช้ log₂(2 + 1/(2ε)) (มี 2 ที่ตัวส่วน) · ตัวอย่างข้างบนตามตำราจะได้ m = 3 + ⌈log₂ 7⌉ = 6 แทน 7 · สไลด์ก็ไม่ได้บอกฐานของ log · → ตอบสอบตามสไลด์ (1/ε) แต่รู้ไว้ว่าตำราคมกว่านิดนึงค่ะ

2.4 ต้นทุน: O(m²) และ cont_u ต้องเร็ว (p28)

ตัว primitive เองใช้ operation ราว O(m²) (m = ขนาด qout) · อยากละเอียดขึ้น = จ่ายมากขึ้นแบบกำลังสอง
ข้อจำกัดใหญ่สุด: cont_uต้องสมมติว่ามี controlled-U ที่ทำได้เร็ว เพราะถูกเรียกหลายครั้ง · ถ้า cont_u แพงกว่า O(m²) ข้อได้เปรียบของ phase estimation จะถูก “กัดกร่อน” (eroded)

HAD ง่ายเพราะ HADk ขึ้นกับแค่ว่า k คี่หรือคู่ · operation ส่วนใหญ่ไม่โชคดีขนาดนั้น (บท 0033 · และเป็นหัวใจของ Shor ใน Lec 12)

2.5 ใช้จริง: ใส่ superposition ของ eigenstate (p29–30)

ฟังดูประดิษฐ์ (contrived) ไหมคะ — ถ้ารู้ eigenstate อยู่แล้ว ทำไมจะไม่รู้ eigenphase? (สไลด์ถามเองเลย) · คำตอบ:

ใส่ superposition ของ eigenstate → ได้ superposition ของ eigenphase ที่คู่กัน · magnitude ของแต่ละ eigenphase ใน qout = magnitude ของ eigenstate ตัวนั้นใน qin เป๊ะๆ (p29)
และ state ใดๆ มองเป็น superposition ของ eigenstate ของ operation ใดๆ ได้เสมอ → ใส่ |x⟩ อะไรก็ได้ แล้ว primitive จะบอกว่า eigenphase ไหนบ้างที่ characterize (กำหนดลักษณะ) การกระทำของ U ต่อ |x⟩ · ใช้ทำงาน linear algebra (พีชคณิตเชิงเส้น) แบบ parallelize (ทำขนาน) บน QPU ได้ — แต่ก็มี fine print เสมอ (p30)
ลองกับ HAD (คาโฮะคำนวณเอง ไม่อยู่ในสไลด์) · |0⟩ ไม่ใช่ eigenstate ของ HAD · แต่ |0⟩ = 0.924 × (eigenstate 0°) + 0.383 × (eigenstate 180°) — ลองบวกดู: 0.924·(0.924|0⟩+0.383|1⟩) + 0.383·(0.383|0⟩−0.924|1⟩) = 1·|0⟩ + 0·|1⟩ ✓
⑤ รัน Example 8-1 (m = 4) แต่เปลี่ยน qin เป็น |0⟩ เฉยๆ — READ qout จะได้อะไร?
ถูกค่ะ! |0⟩ = 0.924·(eigenstate 0°) + 0.383·(eigenstate 180°) → eigenphase 0° (อ่านได้ 0) ด้วยโอกาส 0.924² ≈ 85% และ 180° (อ่านได้ 8) ด้วยโอกาส 0.383² ≈ 15%
ดูกล่องสีเขียว: magnitude ของแต่ละ eigenphase = magnitude ของ eigenstate ตัวนั้นใน qin · แล้ว |0⟩ แตกเป็น eigenstate ไหนบ้าง อย่างละเท่าไร?
ทดสอบความจำ (ปิดหน้าจอแล้วตอบเองก่อนเปิด)
  1. input 3 ตัวของ phase_est? → qin = eigenstate (n) · qout = m qubit เริ่ม 0 · cont_u = controlled-U
  2. ทำไม cont_u ต้องเป็น controlled? → กลไกข้างในต้องใช้ · สร้าง controlled-U ไม่ง่าย เลยให้ผู้ใช้เขียน
  3. ทำไม cont_u ของ HAD เช็คแค่ control_count & 1? → HAD จำนวนคู่ครั้ง = ไม่ทำอะไร
  4. Example 8-1 อ่านได้เท่าไร แปลว่าอะไร? → 8 · 8/16 ของรอบ = 180°
  5. Equation 8-1? → R = θ/360° × 2ᵐ
  6. θ ไม่ลงขีด เกิดอะไร? → superposition รอบค่าใกล้สุด · โอกาสได้ค่าดีสุด > 40%
  7. สูตรเลือก m (ตามสไลด์)? → m = p + ⌈log(2 + 1/ε)⌉
  8. complexity + ข้อจำกัดใหญ่สุด? → O(m²) · ต้องมี cont_u ที่เร็ว

สรุป

  • phase_est(qin, qout, cont_u): qin = eigenstate · qout = m qubit เริ่ม 0 · cont_u = controlled-U ที่ผู้ใช้เขียน
  • HAD + eigenstate 180° + m = 4 → qin ไม่เปลี่ยน · qout อ่านได้ 8 = ครึ่งรอบ = 180°
  • R = θ/360° × 2ᵐ — กฎเดียวกับ invQFT ในบท 0030
  • ความละเอียด = 360°/2ᵐ · มุมไม่ลงขีด → superposition รอบค่าใกล้สุด (> 40%) · เลือก m ด้วย p และ ε
  • ต้นทุน O(m²) · cont_u ต้องเร็ว · ใส่ superposition ของ eigenstate → ได้ superposition ของ eigenphase
