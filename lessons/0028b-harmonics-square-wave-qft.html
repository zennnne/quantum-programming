DFT ใช้ได้กับทุกสัญญาณ — ฮาร์มอนิก และ square wave ใน QPU

บท 0028 ใช้แต่ sine ความถี่เดียว เลยได้ peak เดียว (บวกภาพสะท้อนของมัน) · แต่สไลด์ p17 สารภาพว่าตัวอย่างพวกนั้น “เลือกมาแล้ว” (cherry-picked) · บทนี้ลองกับสัญญาณที่ไม่ใช่ sine เช่นสัญญาณผสม ค่าเส้นฐาน และ square wave (คลื่นสี่เหลี่ยม) · แล้วจะเห็นว่าพอเอา square wave ไปใส่ QPU register แล้วทำ QFT ผลที่ได้ ตรงกับ DFT ทุกอย่างค่ะ

ทำไมต้องเรียนบทนี้: จับหลัก 4 อย่าง ① DFT/QFT บอก ความถี่ + สัดส่วน + offset ของคลื่น sine ที่เอามาบวกกันแล้วได้สัญญาณนั้น ② ค่าที่ความถี่ 0 = DC bias (เส้นฐาน) ③ square wave ไม่ใช่ sine เลยได้ หลาย peak ที่ฮาร์มอนิกคี่ (f, 3f, 5f, …) และ peak เตี้ยลงเรื่อยๆ ④ square wave ใน register (เฟส 0°/180°) → QFT ได้ peak คู่สมมาตร · READ ได้ความถี่เดียวแบบสุ่มตามน้ำหนัก (เรื่องสอบ)

ส่วนที่ 1 · DFT Everything: สัญญาณผสม, DC bias, square wave

DFT บอกอะไรเราแน่ๆ

ที่ผ่านมาเราพูดกว้างๆ ว่า DFT “บอกความถี่ในสัญญาณ” · สไลด์ p32 ให้คำตอบที่ตรงกว่านั้น:

DFT (และ QFT) บอก ความถี่ (frequencies), สัดส่วน (proportions) และ offset ของคลื่น sine ง่ายๆ ที่เอามาบวกกันแล้วได้สัญญาณ input นั้น (p32)

ลองนึกถึง สูตรน้ำผลไม้ปั่น ดูค่ะ: ชิมแก้วเดียวแล้วบอกได้ว่ามี “ส้ม 60% มะม่วง 30% สับปะรด 10%” · DFT ก็ทำแบบนั้นกับสัญญาณ: บอกว่ามีคลื่น sine ความถี่ไหนบ้าง และแต่ละตัวใส่มากน้อยแค่ไหน · sine เดี่ยวจากบทก่อนก็คือน้ำส้มล้วน เลยได้ peak เดียว

สัญญาณผสม 3 ความถี่ (Figure 7-14)

สัญญาณข้างล่างเกิดจาก sine 3 ตัวบวกกัน: ตัวหลักความถี่ 4 และตัวเล็กอีก 2 ตัวที่ความแรงราว 1/3 · ดูทางซ้ายแทบเดาไม่ออก แต่ DFT แยกออกมาให้ทันที (ตัวเลขเลือกมาให้หน้าตาคล้ายรูปในสไลด์)

ความสูงของ peak = สัดส่วน: peak ที่ 4 สูงกว่าอีก 2 ตัวราว 3 เท่า เพราะใส่มาแรงกว่า 3 เท่า · ถ้าดูเฟสของค่าเชิงซ้อนที่ DFT คืนมาด้วย จะรู้ว่าแต่ละคลื่นเหลื่อมกัน (offset) เท่าไร (p34) · และเพราะ input เป็นจำนวนจริง ครึ่งขวาเป็นแค่ภาพสะท้อน ตัดทิ้งได้เลย (p34 · ทวนบท 0028)

ลองคิดก่อนเลือก: สัญญาณจริงยาว 256 sample = sine ความถี่ 10 (แรง 1) + sine ความถี่ 30 (แรง 0.5) · กราฟ DFT จะมี peak กี่อันและอยู่ที่ไหน?
ถูกค่ะ! ความถี่ละ 1 peak ในครึ่งซ้าย แล้วสัญญาณจริงได้ภาพสะท้อนที่ N − f: 256 − 30 = 226 และ 256 − 10 = 246 · peak ที่ 10 สูงเป็น 2 เท่าของที่ 30
ยังไม่ใช่ค่ะ: มี sine 2 ตัว ครึ่งซ้ายเลยได้ 2 peak (10, 30) · สัญญาณเป็นจำนวนจริงจึงมีภาพสะท้อนที่ N − f ด้วย → 246 และ 226

DC bias: ค่าที่ความถี่ 0

ทุกสัญญาณที่ผ่านมาแกว่งรอบศูนย์ · ถ้ายกทั้งเส้นขึ้นไป (เช่นแกว่งรอบ 0.6 แทน) DFT จะมี peak โผล่ที่ช่อง 0 ค่านี้เรียกว่า DC bias = baseline (เส้นฐาน) ที่สัญญาณแกว่งรอบๆ · สไลด์บอกให้เช็คช่อง 0 เสมอ (p34)

ทำไมความถี่ 0 ถึงหมายถึงเส้นฐาน? คลื่นที่แกว่ง 0 รอบคือเส้นตรงนิ่งๆ · สัญญาณนี้ก็คือ “เส้นตรงสูง 0.6 + sine” นั่นเอง

square wave: สัญญาณที่ไม่เหมือน sine เลย (Figure 7-15)

square wave กระโดดขึ้นลงระหว่าง +1 กับ −1 เป็นเหลี่ยมๆ · ดูยังไงก็ไม่ใช่ sine แต่ DFT ก็ยังแยกมันเป็นผลบวกของ sine ได้ แค่ต้องใช้หลายตัว:

peak อยู่ที่ 8, 24, 40, 56 … = 8 × 1, 8 × 3, 8 × 5, 8 × 7 ซึ่งเป็นจำนวนคี่เท่าของความถี่หลัก · เรียกพวกนี้ว่า harmonic (ฮาร์มอนิก): ตัวหลัก 8 คือ fundamental ส่วน 24, 40, … คือฮาร์มอนิกคี่ · ครึ่ง 256 ช่องมีฮาร์มอนิกคี่ 8 ตัว รวมภาพสะท้อนอีก 8 = 16 peak ห่างเท่ากัน ตรงกับรูปในสไลด์

อยากเห็นกับตาว่ามันจริงไหม? ลองบวก sine แค่ 3 ตัวแรกตามสูตรนั้น (8 แรง 1 · 24 แรง 1/3 · 40 แรง 1/5):

square wave สั่น 4 รอบ ใน 256 sample · peak ครึ่งซ้าย 3 อันแรกอยู่ที่ไหน?
ถูกค่ะ! ฮาร์มอนิกคี่ของ 4 = 4×1, 4×3, 4×5 → 4, 12, 20 · ความสูง 1, ⅓, ⅕
ยังไม่ใช่ค่ะ: square wave มีแต่ฮาร์มอนิกคี่ (×1, ×3, ×5) ของความถี่หลัก → 4, 12, 20 · ไม่มี ×2 (8) และไม่ใช่ ×1, ×4, ×9

ส่วนที่ 2 · square wave ใน register 4 qubit

เฟส 180° = amplitude ติดลบ

จะทำ square wave ใน QPU ได้ต้องมีค่า “+1” กับ “−1” · สไลด์ p18 บอกว่าเข็มชี้ลง (เฟส 180°) เทียบเท่า amplitude ติดลบ · ดังนั้นเข็มที่มีแค่ขึ้น/ลงคือสัญญาณจำนวนจริง (ทวนกับดักจากบท 0028) → คาดได้เลยว่า QFT จะให้ peak คู่สะท้อน

⚠️ สไลด์ p17–18 วาดแค่ |0⟩ ถึง |14⟩: register 4 qubit ต้องมี 16 วง วง |15⟩ ถูกครอปหาย · ในบทนี้หนูเติมให้ครบแล้ว (|15⟩ ของ A เข็มลง ส่วน B, C, D ก็เข็มลงเหมือนกัน) · ถ้าข้อสอบให้นับวงจากรูป ให้นึกไว้ว่ามี 16 วงเสมอ

ถูกค่ะ! ฮาร์มอนิกคี่ของ 2 คือ 2 กับ 6 (6 = 2×3 · 10 = 2×5 เกินครึ่ง 8 แล้วเลยไม่นับเป็นฮาร์มอนิก) · ภาพสะท้อน 16 − 2 = 14 กับ 16 − 6 = 10
ยังไม่ใช่ค่ะ: เป็น square wave จึงมีฮาร์มอนิกคี่ 2×1 = 2 และ 2×3 = 6 · เป็นสัญญาณจริงเลยมีภาพสะท้อน 16 − 2 = 14 และ 16 − 6 = 10

ผลหลัง QFT (Figure 7-7)

อ่านรูปนี้ด้วยสิ่งที่รู้แล้วทั้งหมด:

  • A ได้ |8⟩ วงเดียว เพราะความถี่ 8 = ครึ่งพอดี ภาพสะท้อน 16 − 8 = 8 ทับตัวเอง · ฮาร์มอนิกถัดไป 24 ก็เกิน register
  • B ได้ |4⟩ กับ |12⟩ (ฮาร์มอนิก 12 = ภาพสะท้อนของ 4 พอดี จึงไม่เห็นเป็น peak แยก)
  • C, D ได้ฮาร์มอนิกคี่ + ภาพสะท้อน · วงใหญ่สุดคือ fundamental แล้วเล็กลงเรื่อยๆ เข้ากลาง เหมือน DFT เป๊ะ
  • คู่สะท้อน (k กับ 16 − k) ขนาดเท่ากัน และเข็มเอียงกลับด้านกัน (เช่น B: +45° กับ −45°) · สไลด์บอกว่าแบบนี้ “ตีความยากกว่า” เพราะเฟสกระโดดบวก/ลบ แทนที่จะหมุนต่อเนื่องเหมือนบท 0027 (p18–19)

วงจรและโค้ด (Figure 7-8) · เรื่องสอบ

สร้าง square wave ง่ายนิดเดียว: HAD ทุกสาย (ได้ superposition เท่ากัน) แล้ว PHASE 180° สายเดียว · สายที่โดน 180° กำหนดว่าพลิกทุกกี่ค่า (p20–21)

var num_qubits = 4;
qc.reset(num_qubits);
var signal = qint.new(num_qubits, 'signal')
var wave_period = 2;       // A:1 B:2 C:4 D:8
// prepare the signal
signal.write(0);
signal.hadamard();
signal.phase(180, wave_period);
signal.QFT()
⚠️ ชื่อตัวแปรหลอก: wave_period ไม่ใช่คาบ แต่เป็น bitmask ของ qubit ที่จะโดน 180° · ค่า 2 = สาย 0x2 = พลิกทุก 2 ค่า → คาบจริง 4 · ความถี่ 4 (ทวนตาราง p ข้างบน)
ถ้าแก้โค้ดเป็น signal.phase(180, 8) วงจร prep จะเปลี่ยนยังไง และ READ หลัง QFT มีโอกาสสูงสุดที่จะได้ค่าไหน?
ถูกค่ะ! mask 8 = สาย 0x8 = แถว D (ความถี่ 1) · วงใหญ่สุดคือ |1⟩ กับ |15⟩ อย่างละ ~41%
ยังไม่ใช่ค่ะ: เลข 8 คือ bitmask → φ ไปอยู่สาย 0x8 ตัวเดียว (ไม่ใช่ทำ 8 ครั้ง) · พลิกทุก 8 = แถว D ความถี่ 1 → peak ใหญ่ที่ |1⟩, |15⟩

ส่วนที่ 3 · square wave บน qubyte: QFT = DFT เป๊ะ

ขยายเป็น 8 qubit (qubyte) = 256 ค่า จะได้เทียบกับ DFT 256 sample ของ Figure 7-15 ตรงๆ (p36)

qc.reset(8);
qc.write(0);
qc.had();
// ใส่เครื่องหมายลบด้วยความถี่หนึ่ง
qc.phase(180, 16);
qc.QFT();
⚠️ สไลด์ p36 รูปวงจรไม่มีกล่อง QFT (หนูเปิดรูปจริงเช็คแล้ว จบที่ φ แล้วลากเส้นเปล่า) แต่โค้ดมี qc.QFT() · รูปนั้นเป็นแค่ส่วน prep · ของจริงต้องมีกล่อง QFT 8 สายต่อท้าย (หน้าตาวงจร 8 สายจะเจอบท 0030)

input (p37): mask 16 → พลิกทุก 16 ค่า → คาบ 32 → 256 ÷ 32 = 8 รอบ · 32 วงแรก (2 แถวแรกของกริด 16×16 ในสไลด์) หน้าตาแบบนี้ (ที่เหลือซ้ำไปอีก 7 รอบ):

output (p38–39): เหลือวงไม่ว่างแค่ 8 + 16k = 8, 24, 40, …, 248 · กราฟความน่าจะเป็นตอน READ:

ทำไมกราฟนี้เตี้ยลงเร็วกว่ากราฟ DFT? DFT ของ square wave มีความสูง 1, ⅓, ⅕ (= amplitude) · แต่การ READ ได้ความน่าจะเป็น = |amplitude|² → 1, 1/9, 1/25 · ลองเช็ค: 40.7 ÷ 9 ≈ 4.5 ≈ แท่งที่ 24 ✓
register หลัง QFT คือ DFT ของ square wave ที่เก็บอยู่ใน magnitude + relative phase · โอกาส READ ได้ค่าไหน = ความถี่นั้นมีส่วนในสัญญาณแรงแค่ไหน (p39)
รันโค้ด qubyte นี้แล้ว READ ครั้งเดียว · ข้อไหนบรรยายผลได้ถูกที่สุด?
ถูกค่ะ! 40.7 + 40.7 ≈ 81% · ที่เหลือ ~19% อาจได้ฮาร์มอนิกอื่น (24, 232, …) · READ ได้ค่าเดียวเสมอ ไม่ได้ทั้ง spectrum
ยังไม่ใช่ค่ะ: READ ได้ค่าเดียวเสมอ (ไม่ได้ทั้งกราฟ) และค่าที่ได้สุ่มตามน้ำหนักของกราฟ → 8 หรือ 248 รวม ~81% · ฮาร์มอนิกอื่นยังมีโอกาสออก

ข้อสุดท้ายนี้แหละคือปัญหาใหญ่ที่บทหน้าจะคุยกัน: DFT คลาสสิกให้ทั้งกราฟ แต่ QFT ให้เรา “จับฉลาก” ได้แค่ความถี่เดียวต่อการรันหนึ่งครั้ง แล้วแบบนี้ QFT จะเอาไปใช้ทำอะไรได้บ้าง?

ทดสอบความจำ: ปิดหน้าจอแล้วลองตอบก่อนกดเปิด
  1. DFT/QFT บอกอะไรเกี่ยวกับสัญญาณ 3 อย่าง?
    ความถี่ · สัดส่วน · offset ของ sine ที่บวกกันเป็นสัญญาณ
  2. DC bias คืออะไร อยู่ช่องไหน?
    เส้นฐานที่สัญญาณแกว่งรอบ · ช่องความถี่ 0
  3. square wave ความถี่ f ได้ peak ที่ไหน สูงเท่าไร?
    f, 3f, 5f, … สูง 1, ⅓, ⅕ (+ภาพสะท้อน)
  4. qc.phase(180, 4) บน register 4 qubit (หลัง had) → ความถี่เท่าไร?
    mask 4 → พลิกทุก 4 → คาบ 8 → ความถี่ 2
  5. ทำไมความน่าจะเป็นตอน READ ลดแบบ 1/k² แทนที่จะเป็น 1/k?
    ความน่าจะเป็น = |amplitude|²

สรุปบทนี้

  • DFT/QFT แยกสัญญาณเป็น sine หลายตัว: ความถี่ + สัดส่วน (ความสูง peak) + offset (เฟส) · สัญญาณจริงตัดครึ่งขวาทิ้งได้
  • ช่องความถี่ 0 = DC bias (เส้นฐาน) · เช็คทุกครั้ง
  • square wave → ฮาร์มอนิกคี่ f, 3f, 5f … สูง 1, ⅓, ⅕ · 8 รอบใน 256 → 16 peak ห่างกัน 16
  • ใน QPU: had + phase(180, mask) = square wave · mask p → ความถี่ 2ⁿ/(2p) · เฟส 180° = ลบ = สัญญาณจริง → peak คู่ k กับ 2ⁿ − k
  • qubyte: หลัง QFT READ ได้ 8 หรือ 248 ~81% · ความน่าจะเป็น = |amp|² → ลด ~1/k² · ผล QFT = DFT เป๊ะ แต่อ่านได้ค่าเดียว
