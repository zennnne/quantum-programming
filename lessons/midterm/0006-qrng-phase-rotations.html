Lesson 06 + 07 · QPU Instructions

โปรแกรมควอนตัมตัวแรกของพี่ (QRNG) แล้วต่อด้วย การหมุน: PHASE, ROTX, ROTY

บทที่ 5 พี่ได้วงจร WRITE→[H]→READ มาแล้ว บทนี้ครึ่งแรกเราจะเอามัน ไปทำงานจริง เป็นเครื่องสุ่มที่คอมทั่วไปทำไม่ได้ ส่วนครึ่งหลังคือ gate ตระกูลใหม่ที่ หมุน qubit — และเครื่องมือใหม่ที่ชื่อ Bloch sphere ค่ะ

บทนี้ยาว (รวม 2 บท) — จับหลัก 4 อย่างพอ
  1. PRNG ทำนายได้ / QRNG ทำนายไม่ได้ — ต่างกันที่ "ต้นตอของความสุ่ม"
  2. QRNG = WRITE|0⟩ → [H] → READ จบ แค่นั้นจริงๆ
  3. PHASE(θ) หมุนเข็มของวง |1⟩ เท่านั้น — ไม่แตะโอกาสวัดเลย
  4. Bloch sphere = ลูกศร 1 อัน · ROTX/ROTY เปลี่ยน magnitude · PHASE เปลี่ยน phase
ครึ่งแรก · บทที่ 6

QRNG — โปรแกรมควอนตัมตัวแรกที่ใช้งานได้จริง

1. ทำไมต้องมี "สุ่มแท้" ในเมื่อคอมสุ่มเลขได้อยู่แล้ว?

เวลาพี่เรียก Math.random() หรือ random.randint() คอมไม่ได้ "สุ่ม" จริงๆ นะคะ มันรัน PRNG (Pseudo-Random Number Generator — ตัวสร้างเลขสุ่มเทียม) ซึ่งเป็น สูตรคณิตศาสตร์ธรรมดา ที่ผลลัพธ์ถูกกำหนดโดยของสองอย่างเท่านั้น: ตัวอัลกอริทึม กับ seed (ค่าตั้งต้น)

สไลด์ยกตัวอย่าง PRNG ที่ง่ายที่สุดตัวหนึ่งมาให้ดู — ลองไล่มือตามนะคะ สูตรคือ xn+1 = (a · xn + c) mod m โดยกำหนด a = 5, c = 1, m = 16, seed x0 = 3

1) x₁ = (5 × 3 + 1) mod 16 = 16 mod 16 = 0
2) x₂ = (5 × 0 + 1) mod 16 = 1 mod 16 = 1
3) x₃ = (5 × 1 + 1) mod 16 = 6 mod 16 = 6
4) x₄ = (5 × 6 + 1) mod 16 = 31 mod 16 = 15
ได้ลำดับ 0, 1, 6, 15, … ดู "มั่ว" ดีใช่ไหมคะ? แต่พี่เพิ่งคำนวณมันด้วยมือเองกับตา — มันไม่มีอะไรสุ่มเลยสักนิด
แก่นของคำว่า pseudo

PRNG เรียกว่า pseudo (เทียม/ปลอม) เพราะ ถ้ารู้อัลกอริทึม + รู้ seed → ทำนายทุกเลขในอนาคตได้หมด ความสุ่มของมันคือ "ความไม่รู้ของคนดู" ไม่ใช่ความสุ่มของตัวเลข พูดอีกแบบ: ผลลัพธ์ถูกกำหนดไว้แล้วตั้งแต่วินาทีที่เลือก seed

อย่าเพิ่งเข้าใจผิดว่า PRNG แย่นะคะ — มันดีมากและใช้กันทุกที่: simulation (พยากรณ์อากาศ ฟิสิกส์), cryptography, เกม, machine learning, สถิติแบบ Monte Carlo แต่พอถึงงานที่ ทำนายไม่ได้ คือข้อกำหนดด้านความปลอดภัย (เช่น สร้างกุญแจเข้ารหัส) การที่ "มี seed ให้เดา" คือจุดอ่อนโดยธรรมชาติ

2. QRNG — เอาวงจรบทที่แล้วมาแก้ปัญหานี้เลย

ทีนี้ของสวยงามมาแล้วค่ะ ผลของการวัด qubit ที่อยู่ใน superposition นั้น ทำนายไม่ได้ตามกฎของฟิสิกส์ (ไม่ใช่ "เรายังไม่รู้พอ" แต่คือ ไม่มีอะไรให้รู้) เอาข้อเท็จจริงนี้มาทำเครื่องสุ่มได้ตรงๆ 3 ขั้น:

1. WRITE |0⟩เตรียม qubit ให้แน่นอน
2. HADสร้าง superposition 50/50
3. READวัด → ได้ 0 หรือ 1 สุ่มแท้

ในรูปวงจร (สไตล์ QCEngine ที่ออกสอบ) อ่านจากซ้ายไปขวาตามเวลา หน้าตาแบบนี้เป๊ะ:

นี่คือโปรแกรม QPU เต็มๆ ตัวแรกที่พี่เห็นในวิชานี้ (slide 58)

ไล่ด้วย circle notation ให้เห็นภาพทีละสเต็ป:

หลัง WRITE: |0⟩ แน่นอน 100%
—[H]→
หลัง HAD: โอกาส 50/50
—READ→
หลัง READ: ยุบไปวงเดียว
(รอบนี้ได้ 0 — รอบหน้าไม่รู้)

โค้ด QCEngine ก็สั้นพอๆ กับวงจรเลยค่ะ (slide 58–60) — สังเกตว่า 1 บรรทัด = 1 สัญลักษณ์บนวงจร:

qc.reset(1); // ขอ qubit 1 ตัวจาก QPU (ทุกโปรแกรมเริ่มด้วยบรรทัดนี้)
qc.write(0); // ตั้งค่าเป็น |0⟩ เหมือน bit ธรรมดาที่เซ็ตเป็น 0
qc.had(); // [H] → superposition ของ 0 กับ 1
var result = qc.read(); // วัดออกมาเป็น bit สุ่ม เก็บใส่ตัวแปร

แล้วมันต่างจากโยนเหรียญตรงไหน?

นี่คือประเด็นที่สไลด์ (หน้า 61) ย้ำหนักมาก และหนูว่าเป็นหัวใจของทั้งบท: ข้างใน HAD gate ไม่มีอัลกอริทึมสุ่ม ไม่มี seed ไม่มีวงจร RNG ฮาร์ดแวร์อะไรเลย ความสุ่มไม่ได้ถูก "คำนวณ" ขึ้นมา — มันรับประกันโดยฟิสิกส์ควอนตัม ไม่ใช่โดยการคำนวณ

PRNGสุ่มเพราะ "เรายังไม่รู้"
รู้ seed เมื่อไหร่ = ทำนายได้หมด
≠
QRNGสุ่มเพราะ "ไม่มีอะไรให้รู้"

ประโยคที่ควรจำไปสอบ: ไม่มีใคร — ไม่ว่าจะรู้เรื่องระบบนั้นมากแค่ไหน — ทำนายได้ว่า READ หลัง HAD จะออก 0 หรือ 1 ความทำนายไม่ได้นี้ สมบูรณ์แบบ ต่างจาก PRNG โดยสิ้นเชิง

กับดักที่ออกสอบง่ายมาก 🪤

ถ้าพี่รันโค้ดข้างบนบน QCEngine (simulator) — ความสุ่มที่ได้ ยังเป็น PRNG อยู่! เพราะ simulator ก็คือโปรแกรมที่รันบนคอมพิวเตอร์ธรรมดา มันได้แค่ เลียนแบบ ความสุ่ม ต้องเอาโปรแกรมเดิมนี้ไปรันบน QPU จริง ผลลัพธ์ถึงจะมาจากพฤติกรรมควอนตัมจริง และเป็น สุ่มแท้ (slide 57)

สรุปสั้นๆ: โปรแกรมเดียวกัน แต่ "สุ่มแท้หรือไม่" ขึ้นกับว่ารันบนอะไร

เช็คความเข้าใจ ① — เพื่อนบอกว่า "เขียน QRNG บน QCEngine แล้ว ได้เลขสุ่มแท้แล้ว!" ข้อไหนคือคำท้วงที่ถูกต้อง?
ใช่เลยค่ะ! วงจรถูกทุกอย่าง แต่ต้นตอความสุ่มผิด — simulator ไม่มีฟิสิกส์ควอนตัมจริงให้ใช้ มันคำนวณเอา ก็เลยต้องพึ่ง PRNG อยู่ดี ต้องรันบน QPU จริงเท่านั้น
ยังไม่ใช่ค่ะ — โค้ดกับวงจรถูกหมดแล้ว ปัญหาอยู่ที่ ที่รัน: QCEngine เป็น simulator บนคอมธรรมดา จึงเลียนแบบความสุ่มด้วย PRNG ต้องเอาไปรันบน QPU จริง ผลถึงจะสุ่มแท้ (slide 57)

3. อยากได้ 1 ไบต์ ไม่ใช่ 1 บิต ล่ะ?

ทำ 8 ตัวขนานกันไปเลยค่ะ! ถึงเรื่อง multi-qubit จะยังไม่สอน แต่ QRNG มันง่ายพอที่จะเอา วงจรเดิม วางซ้อน 8 เส้น แล้วได้ random byte ในรอบเดียว (slide 62–63):

qc.reset(8); // ขอ 8 qubit
qc.write(0); // ← ไม่ได้ระบุตัวไหน = เขียนให้ "ทุกตัว"
qc.had(); // ← ไม่ได้ระบุตัวไหน = HAD ให้ "ทุกตัว"
var result = qc.read(); // อ่านทั้ง 8 → ได้เลข 0–255
qc.print(result);

จุดที่สไลด์อยากให้สังเกตคือกติกาของ QCEngine: ถ้าไม่ระบุ qubit เจาะจง คำสั่งอย่าง WRITE และ HAD จะกระทำกับ qubit ทุกตัวที่ initialize ไว้ — โค้ดเลยแทบไม่ต่างจากตัวเดียวเลย เปลี่ยนแค่ reset(1) เป็น reset(8)

เก็บไว้คิดเล่นๆ

ในวงจร 8 เส้นของสไลด์ ทุกเส้น "ไม่คุยกันเลย" — ต่างคนต่างสุ่มของตัวเอง นี่ยัง ไม่ใช่ พลังจริงของ multi-qubit นะคะ พลังจริง (entanglement) จะโผล่ตอน qubit เริ่มมีอิทธิพลต่อกัน ซึ่งรอบทหลังค่ะ ตอนนี้มันแค่ "8 โปรแกรมเดี่ยวรันพร้อมกัน"

PHASE, ROTX, ROTY — gate ที่ "หมุน" qubit

4. PHASE(θ) — คำสั่งที่จับ relative phase ได้ตรงๆ

ตั้งแต่บทที่ 3 พี่รู้ว่า qubit มี 2 อย่าง: magnitude (คุมโอกาสวัด) กับ relative phase (เฟสสัมพัทธ์ = ทิศเข็มนาฬิกาในวง) แต่ gate ที่เจอมา (NOT, HAD) ยังไม่มีตัวไหน "จับ phase หมุนเล่นตรงๆ" ได้เลย — PHASE(θ) คือตัวนั้นค่ะ และมัน ไม่มีคู่เทียบในคอมพิวเตอร์ธรรมดา เลยแม้แต่นิดเดียว (slide 64)

สิ่งที่ทำให้ PHASE แปลกกว่า gate ที่ผ่านมา: มัน กินพารามิเตอร์เพิ่ม คือ มุมที่จะหมุน เช่น PHASE(45) = หมุน 45 องศา ส่วน NOT/HAD ไม่ต้องบอกอะไรเลย

PHASE(θ) — วงกลมมี φ
เขียนมุมกำกับไว้ข้างบน

มันทำอะไรกับวง (นี่แหละของจริง)

PHASE หมุนเข็มของวง |1⟩ เท่านั้น — วง |0⟩ ไม่แตะเลย ดูตัวอย่าง PHASE(45°) จาก slide 64:

ก่อน: เข็มขึ้นทั้งคู่
—(φ 45°)→
หลัง: วง |1⟩ เข็มหมุนไป 45°
วง |0⟩ เหมือนเดิมเป๊ะ
ทิศการหมุน — จุดที่พลาดกันเยอะตอนวาดวงจร

ในหนังสือ/สไลด์เล่มนี้ มุมบวก = หมุนทวนเข็มนาฬิกา (สังเกตลูกศรแดง 45° ในสไลด์ มันวิ่งจาก 12 นาฬิกาไปทาง ซ้าย) ดังนั้น PHASE(45) จะได้เข็มชี้ไป บน-ซ้าย ไม่ใช่บน-ขวา — เวลาสอบวาดรูป ระวังตรงนี้ให้ดีค่ะ

ผลข้างเคียงที่ตามมาทันที และเป็นข้อสอบชั้นดี: PHASE ไม่มีผลใดๆ กับ qubit ที่อยู่ในสถานะ |0⟩ เพราะ |0⟩ แปลว่า "วง |1⟩ ว่างเปล่า" (amplitude = 0) — ก็ไม่มีเข็มให้หมุนไงคะ หมุนศูนย์ไปกี่องศาก็ยังเป็นศูนย์ นี่คือเหตุผลว่าทำไมแทบทุกครั้งพี่จะเห็น HAD มาก่อน PHASE เสมอ — ต้องสร้าง superposition ให้วง |1⟩ มีของก่อน PHASE ถึงจะมีความหมาย

Reversibility — เจอ "ข้อยกเว้น" ตัวแรกแล้ว!

ตั้งแต่บท 4 พี่เจอแต่ gate ที่เป็น its own inverse (ทำสองครั้ง = กลับที่เดิม): NOT ทำสองที กลับที่เดิม, HAD ทำสองที กลับที่เดิม จนอาจเผลอคิดว่า "gate ควอนตัมมันเป็นแบบนี้ทุกตัว" PHASE คือตัวที่หักล้างความคิดนั้นค่ะ

✔ Reversibleย้อนกลับได้แน่นอน (ไม่ทำลายข้อมูลเหมือน READ)
✘ ไม่ใช่ its own inversePHASE(45) สองที ≠ เดิม — ได้ 90° ต่างหาก!
วิธีย้อน = PHASE(−θ)หมุนกลับทางเดิม เช่น PHASE(45) แก้ด้วย PHASE(−45)

เกร็ด: มีมุมพิเศษที่บังเอิญเป็น its own inverse อยู่นะคะ — PHASE(180) เพราะหมุน 180° สองครั้ง = 360° = ครบรอบพอดี (gate ตัวนี้มีชื่อเล่นว่า Z และจะกลับมาเป็นพระเอกในบท 8 ตอนเราสร้าง NOT จาก HAD กับ PHASE(180) — slide 75)

เช็คความเข้าใจ ② — WRITE |0⟩ → PHASE(90) → READ ผลลัพธ์ที่วัดได้คือ?
เป๊ะค่ะ! เหตุผล ซ้อนกันสองชั้น: (1) |0⟩ มีวง |1⟩ ว่าง PHASE เลยไม่มีเข็มให้หมุน → state ไม่เปลี่ยนเลย และ (2) ต่อให้มีเข็มให้หมุน phase ก็ไม่กระทบ magnitude² อยู่ดี (บท 5)
ยังไม่ใช่ค่ะ — กับดักคือ PHASE ไม่ได้สร้าง superposition และ ไม่ย้ายพื้นที่ทึบ (นั่นคืองานของ HAD กับ NOT) พอ qubit เป็น |0⟩ วง |1⟩ ว่าง = ไม่มีเข็มให้หมุน state จึงไม่ขยับเลย → วัดได้ 0 แน่นอน 100%

5. สถานะที่ใช้บ่อยจนได้ชื่อ: |+⟩, |−⟩, |+Y⟩, |−Y⟩

พอมี HAD + PHASE ครบ พี่สร้าง superposition ได้ทุกแบบที่ magnitude เท่ากัน (50/50) แต่ phase ต่างกัน — และมี 4 ตัวที่ใช้บ่อยจนคนตั้งชื่อให้ (slide 65–66) ทั้ง 4 ตัว วัดแล้วได้ 50/50 เหมือนกันหมด ต่างกันแค่ทิศเข็มของวง |1⟩ เท่านั้น:

|+⟩
เข็มขึ้นทั้งคู่ (0°)
HAD เฉยๆ
|−⟩
เข็มวง |1⟩ ชี้ลง (180°)
HAD → PHASE(180)
|+Y⟩
เข็มวง |1⟩ ชี้ซ้าย (90°)
HAD → PHASE(90)
|−Y⟩
เข็มวง |1⟩ ชี้ขวา (−90°)
HAD → PHASE(−90)

สไลด์ 65 ท้าให้พี่ลองหาเองว่าสร้างยังไง ("see whether you can determine how to produce these states") — เฉลยอยู่ในการ์ดข้างบนแล้วค่ะ สูตรคิดง่ายๆ คือ HAD ก่อนเสมอ (เพื่อให้วง |1⟩ มีของ) แล้วค่อย PHASE ตามมุมที่อยากได้ ส่วน |+⟩ ไม่ต้อง PHASE เลยเพราะ HAD ให้เข็มขึ้นอยู่แล้ว

โยงกลับบท 5

จำได้ไหมคะว่า H|1⟩ = (|0⟩ − |1⟩)/√2 คือ "เข็มวง |1⟩ ชี้ลง" — นั่นแหละคือ |−⟩ พอดีเป๊ะ! แปลว่าพี่สร้าง |−⟩ ได้สองทาง: WRITE|1⟩ → HAD หรือ WRITE|0⟩ → HAD → PHASE(180) — คนละเส้นทาง ปลายทางเดียวกัน

6. Bloch sphere — เครื่องมือมองภาพอันที่สอง

circle notation ดีมากตรงที่เห็น magnitude กับ phase แยกกันชัด แต่มันมี 2 วง ทำให้ตอบคำถามอย่าง "หมุนรอบแกน" ไม่ค่อยได้ Bloch sphere (ทรงกลมบล็อค) คือวิธีมองอีกแบบ: ยุบข้อมูลทั้งหมดของ qubit 1 ตัวเหลือเป็น ลูกศร 1 อันบนผิวทรงกลม ทีนี้ gate ทุกตัวก็กลายเป็นแค่ "หมุนลูกศรรอบแกนใดแกนหนึ่ง"

|1⟩ลูกศรชี้ลงตรงๆ (ขั้วใต้)
superpositionลูกศรชี้ข้างๆ หรือเฉียงๆ

ตำแหน่งลูกศรบอกด้วยมุม 2 ตัว: θ (เอียงจากขั้วเหนือลงมาเท่าไหร่ — คุม magnitude) และ φ (หมุนรอบแกนตั้งไปทางไหน — คุม relative phase) เขียนเป็นสูตรตามสไลด์ 68 ได้ว่า

|ψ⟩ = cos(θ/2) |0⟩  +  eiφ sin(θ/2) |1⟩
Refresher — อ่านสูตรนี้ยังไงไม่ให้กลัว

cos(θ/2) กับ sin(θ/2) ก็คือ magnitude ของสองวงนั่นแหละค่ะ (θ=0 → cos0=1, sin0=0 → เป็น |0⟩ เต็ม ✔ · θ=180° → เป็น |1⟩ เต็ม ✔ · θ=90° → cos45°=sin45°=1/√2 → 50/50 พอดี ✔)

eiφ คือ "ตัวหมุนเข็ม" — มันมีขนาดเท่ากับ 1 เสมอ เลยไม่ไปแตะ magnitude เด็ดขาด ทำได้อย่างเดียวคือหมุน phase ไป φ องศา นี่คือเหตุผลทางคณิตศาสตร์ว่าทำไม PHASE ถึงไม่เปลี่ยนโอกาสวัด — ส่วน "ทำไม θ ถึงหาร 2" ยังไม่ต้องสนตอนนี้ค่ะ (มันมาจากเรขาคณิตของทรงกลม)

7. ROTX / ROTY / PHASE = หมุนรอบ 3 แกน

พอมองเป็นลูกศรบนทรงกลมแล้ว gate ตระกูลหมุนก็เข้าใจง่ายขึ้นเยอะ — มันคือ คำสั่งเดียวกันหมด ต่างกันแค่ "หมุนรอบแกนไหน" นี่คือตารางที่สรุปทั้งบทที่ 7 ไว้ (slide 68):

คำสั่งหมุนรอบแกนเปลี่ยนโอกาสวัด?หน้าที่
ROTX(θ)แกน X (แกนนอน)เปลี่ยนเปลี่ยน magnitude
ROTY(θ)แกน Y (แกนนอน อีกทิศ)เปลี่ยนเปลี่ยน magnitude
PHASE(θ)
= ROTZ(θ)		แกน Z (แกนตั้ง |0⟩→|1⟩)ไม่เปลี่ยนเปลี่ยน phase อย่างเดียว

ทำไม PHASE ถึงไม่เปลี่ยนโอกาสวัด — พอมองบนทรงกลมแล้วเห็นด้วยตาเลยค่ะ: แกน Z คือแกนตั้งที่ลากจาก |0⟩ ลงไป |1⟩ พอดี การหมุนรอบแกนนี้ทำให้ลูกศร อยู่ที่ละติจูดเดิมเสมอ (สูงเท่าเดิม) — สูงเท่าเดิม = θ เท่าเดิม = magnitude เท่าเดิม = โอกาสวัดเท่าเดิม เปลี่ยนแค่ว่ามันหันไปทางไหน (= φ = phase) ส่วน ROTX/ROTY หมุนรอบแกนนอน ลูกศรเลย ขึ้นๆ ลงๆ ระหว่างขั้ว → magnitude เปลี่ยน → โอกาสวัดเปลี่ยน

Analogy ของอาจารย์ — ใช้มือเลย ทำตามได้ (slide 72)

กางมือออกมาข้างหน้า แล้วลอง:

  • ROTX(θ) → เอียงมือ ไปหน้า/มาหลัง
  • ROTY(θ) → เอียงมือ ซ้าย/ขวา
  • PHASE(θ) → หมุนมือ รอบตัวเอง เหมือนเข็มนาฬิกา (มืออยู่ที่เดิม แค่หันคนละทาง)

และเพราะ ROTX/ROTY เปลี่ยน magnitude ได้ มันจึง สร้าง superposition จาก |0⟩ ได้เอง โดยไม่ต้องพึ่ง HAD เลย! เช่น ROTX(π/2) หรือ ROTY(π/2) ยิงใส่ |0⟩ ก็ได้ superposition 50/50 ออกมาทั้งคู่ — แต่เป็น คนละตัวกัน (phase ต่างกัน) ซึ่งจะให้ผล interference ต่างกันตอนไปเจอ gate ถัดไป นี่คือมุมมองที่สไลด์ 66 บอกว่า 4 สถานะเมื่อกี้ "มองเป็นผลของ rotation ก็ได้"

จุดที่สไลด์เขียนพลาดนิดนึง — รู้ไว้กันงง

1) สไลด์ 71 เขียนว่า "The Z-axis is a horizontal axis" — ตรงนี้พิมพ์ผิดค่ะ แกน Z คือแกนตั้ง (ลากจาก |0⟩ ขั้วเหนือ ลงไป |1⟩ ขั้วใต้) มีแค่ X กับ Y ที่เป็นแกนนอน ถ้า Z เป็นแกนนอน ประโยคถัดไปในสไลด์เอง ("ลูกศรอยู่ละติจูดเดิม → magnitude ไม่เปลี่ยน") จะขัดแย้งกันทันที

2) สไลด์ 69 เขียนว่า ROTX(π/2) เอียง |0⟩ ไปเป็น |+⟩ — จริงๆ ตัวที่พา |0⟩ ไป |+⟩ คือ ROTY(π/2) ส่วน ROTX(π/2) พาไป |−Y⟩ แต่ใจความที่ออกสอบไม่ได้เปลี่ยน: ทั้งคู่สร้าง superposition 50/50 เหมือนกัน ต่างกันที่ phase เท่านั้น (ถ้าข้อสอบถามตามสไลด์ ตอบตามสไลด์ไปก่อน แล้วรู้ไว้ในใจว่าของจริงเป็นแบบนี้ค่ะ)

เช็คความเข้าใจรอบสุดท้าย

① เพื่อนบอกว่า "PHASE(90) ทำสองครั้งติดกัน ก็เหมือนไม่ได้ทำอะไร เพราะ gate ควอนตัมย้อนตัวเองได้" — ผิดตรงไหน?
ถูกต้องค่ะ! PHASE reversible (ย้อนได้) แต่ ไม่ใช่ its own inverse หมุน 90° สองที = หมุน 180° ต่างหาก ต้องย้อนด้วย PHASE(−90) — นี่คือ gate ตัวแรกที่หักกฎ "ทำสองทีกลับที่เดิม" ที่ NOT กับ HAD ทำให้เราชิน
ยังไม่ใช่ค่ะ — PHASE ย้อนกลับได้แน่นอน (ไม่ทำลายอะไรเหมือน READ) ที่เพื่อนผิดคือคำว่า "ย้อนตัวเอง": หมุน 90° สองครั้งได้ 180° ไม่ใช่ 0° ต้องแก้ด้วย PHASE(−90) ต่างหาก (ที่ NOT/HAD ทำสองทีแล้วกลับที่เดิม เป็นคุณสมบัติเฉพาะตัวมัน ไม่ใช่กฎทั่วไป)
② qubit ตัวหนึ่งอยู่ในสถานะ |+Y⟩ ถ้าเอาไป READ เลย โอกาสได้ 0 เท่าไหร่?
ใช่เลยค่ะ 50% — ทั้ง |+⟩, |−⟩, |+Y⟩, |−Y⟩ วัดแล้วได้ 50/50 เหมือนกันหมด ต่างกันแค่ phase ซึ่ง READ มองไม่เห็น phase มีความหมายก็ต่อเมื่อมี gate มาทำ interference ทีหลัง
ยังไม่ใช่ค่ะ — นี่คือกับดักใหญ่ที่สุดของบท 5–7: phase (ทิศเข็ม) ไม่กระทบโอกาสวัดเลย โอกาสมาจาก magnitude² อย่างเดียว |+Y⟩ มีสองวงทึบเท่ากัน → 50/50 เป๊ะ เหมือน |+⟩ ทุกประการ
③ ถ้าอยากเปลี่ยนโอกาสวัดของ qubit ต้องใช้คำสั่งไหนได้บ้าง?
ถูกค่ะ! กลุ่มที่ "ขยับพื้นที่ทึบ" = เปลี่ยน magnitude = เปลี่ยนโอกาส ได้แก่ HAD, NOT, ROTX, ROTY ส่วน PHASE/ROTZ หมุนรอบแกนตั้ง ลูกศรอยู่ละติจูดเดิม → โอกาสเท่าเดิม
ยังไม่ใช่ค่ะ — PHASE = ROTZ เป็นตัวเดียวกัน และหมุนรอบ แกนตั้ง ลูกศรจึงอยู่ระดับเดิม → โอกาสไม่ขยับเลย ตัวที่เปลี่ยนโอกาสจริงคือพวกที่ย้ายพื้นที่ทึบ: HAD, NOT, ROTX, ROTY (ส่วน READ ไม่ได้เปลี่ยนโอกาส แต่มันจบเกม = ยุบ state ไปเลย)
🧠 ลองเล่าเองก่อนเปิด — "ทำไม PHASE ถึงเปลี่ยนโอกาสวัดไม่ได้ ทั้งที่ ROTX เปลี่ยนได้ ทั้งที่มันหมุนเหมือนกัน?"

ตัวอย่างคำตอบที่ดี: "บน Bloch sphere qubit คือลูกศร 1 อัน โดย 'ความสูง' ของลูกศร (มุม θ) เป็นตัวคุม magnitude ของ |0⟩ กับ |1⟩ ซึ่งคุมโอกาสวัดอีกที — PHASE หมุนรอบ แกน Z ซึ่งเป็นแกนตั้ง ลูกศรเลยอยู่ละติจูดเดิมตลอด ความสูงไม่ขยับ = โอกาสไม่ขยับ เปลี่ยนแค่ทิศที่มันหัน (φ = relative phase) ส่วน ROTX/ROTY หมุนรอบแกนนอน ลูกศรเลยไต่ขึ้นลงระหว่างขั้วเหนือ (|0⟩) กับขั้วใต้ (|1⟩) ความสูงเปลี่ยน = magnitude เปลี่ยน = โอกาสวัดเปลี่ยน ในภาษา circle notation ก็คือ PHASE หมุนเข็มของวง |1⟩ เฉยๆ แต่ไม่ย้ายพื้นที่ทึบ ส่วน ROTX/ROTY ย้ายพื้นที่ทึบระหว่างสองวง"

นึกเองก่อนเปิดเฉลย (retrieval practice) จำได้นานกว่าอ่านซ้ำเยอะค่ะ
