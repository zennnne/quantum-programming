Quantum Programming · Lec 04 · บทที่ 0015

★ เดินโปรแกรม teleportation ทีละ step

บท 0014 สอน “ภาษา” สองภาษาไว้แล้ว — วงจร 5 กล่อง กับ ผัง 8 วง · บทนี้คือการเอาสองภาษานั้นมาใช้พร้อมกัน: เลื่อนเส้นประสีแดงไปทีละ step แล้วดูว่าผัง 8 วงเปลี่ยนหน้าตายังไง จนเห็นกับตาว่า payload ของ Alice ไปโผล่ที่ Bob ได้จริงค่ะ

ทำไมบทนี้คือหัวใจของ Lec 04

สไลด์ ครึ่งบท (หน้า 27–43) เป็นเรื่องนี้เรื่องเดียว — เพราะนี่คือจุดที่ teleportation เลิกเป็น “เรื่องเล่า” แล้วกลายเป็นสิ่งที่ตรวจสอบได้ทีละบรรทัด · ถ้าพี่ Zen เดินผัง 8 วงตามได้ครบทั้ง 6 ภาพ ก็แปลว่าเข้าใจ teleportation จริง ไม่ใช่ท่องจำค่ะ

บทนี้จับ 3 อย่าง: ① Alice ค่อยๆ “ผูก” payload เข้ากับ Bob ยังไง (Step 1→3.2) ② READ = เลือกคอลัมน์มา 1 คอลัมน์ ③ ทำไม 2 บิตถึงบอก Bob ได้พอดีว่าต้องแก้อะไร (Step 4–5)

ตลอดบทนี้ ผัง 8 วงจะใช้ผังมาตรฐานเดิมของบท 0014 เป๊ะ — แถวบน = bob 0 · แถวล่าง = bob 1 · สองคอลัมน์ซ้าย = ep 0 · สองคอลัมน์ขวา = ep 1 · คอลัมน์สลับกัน = alice 0/1 (น้ำหนักบิต alice = 1, ep = 2, bob = 4)

จุดตั้งต้น (สไลด์หน้า 22) — ทุก qubit เป็น |0⟩ → วง |0⟩ เต็มวง เข็มชี้ขึ้น อีก 7 วงว่าง · ตัวเลขใต้วงคือบิตเรียง bob · ep · alice
ส่วนที่ 1

ฝั่ง Alice — Step 1 → 3.2 (ผูก payload เข้ากับ Bob)

1.1 Step 1 — สร้างคู่ entangled

งานแรกของ teleportation คือปูสายเชื่อมไว้ก่อน · HAD แล้วตามด้วย CNOT บน ep กับ bob = สูตรสร้าง Bell pair ตัวเดิมจากบท 0009 เป๊ะๆ ค่ะ

หลัง Step 1 (สไลด์หน้า 27) — เหลือ |0⟩ กับ |6⟩ ครึ่งวงเท่ากัน เข็มชี้ขึ้นทั้งคู่ · |0⟩ = ep 0, bob 0 · |6⟩ = ep 1, bob 1 → ep กับ bob เท่ากันเสมอ แต่จะได้ 0 หรือ 1 สุ่ม 50/50
อ่านผังให้เป็นนิสัย

“ทำไมถึงรู้ว่า entangled?” — เพราะมีแค่วงที่ ep = bob เท่านั้นที่ไม่ว่าง · วงที่ ep ≠ bob (|2⟩ |3⟩ |4⟩ |5⟩) ว่างหมด แปลว่ากรณีที่ทั้งสองไม่ตรงกันเกิดไม่ได้เลย นี่คือหน้าตาของ entanglement ในผัง circle notation ค่ะ

1.2 Step 2 — เตรียม payload

ทีนี้ Alice ค่อยปั้นของที่จะส่ง · ในตัวอย่างของบทนี้ payload ถูกปั้นด้วย HAD → PHASE(45°) → HAD บนสาย alice (ในงานจริง payload จะมาจากไหนก็ได้ — จะ write ค่าลงไป หรือรับมาจากการคำนวณส่วนอื่นของ QPU ก็ได้ทั้งนั้น)

หลัง Step 2 (สไลด์หน้า 28–30) — 4 วงมีค่า · วงที่ alice = 0 (|0⟩ |6⟩) ใหญ่ เข็มชี้ขึ้น = มุมอ้างอิง · วงที่ alice = 1 (|1⟩ |7⟩) เล็ก เข็มชี้ 3 นาฬิกา = หมุนตามเข็ม 90° → phase −90°

อ่านเฉพาะ qubit alice ออกมา จะได้ payload = 85.4% |0⟩ + 14.6% |1⟩ ที่ relative phase −90° (เพราะ 42.7% + 42.7% = 85.4% และ 7.3% + 7.3% = 14.6%) — นี่คือ “ของ” ที่เราจะตามดูไปจนจบบทค่ะ

เช็กตัวเลขเองได้

HAD → PHASE(45°) → HAD บน |0⟩ ให้ amplitude 1 + ei45°2 บน |0⟩ และ 1 − ei45°2 บน |1⟩ → ขนาดยกกำลังสอง = 0.854 และ 0.146 พอดี · ส่วนต่างมุมของสองก้อนนี้ = −90° (สังเกตว่าครึ่งหนึ่งของ 45° ไม่ใช่คำตอบ — ต้องคิดเป็นการบวกเวกเตอร์เชิงซ้อน)

1.3 Step 3.1 — เชื่อม payload เข้ากับคู่ entangled

ตอนนี้ในเครื่องมี “ของ” (alice) กับ “สาย” (ep–bob) แต่ยังไม่ต่อกัน · Alice ต่อมันด้วย CNOT ตัวเดียว โดยให้ alice เป็น control · ep เป็น target

หลัง Step 3.1 (สไลด์หน้า 31–32) — CNOT สลับวงในคู่ที่ alice = 1: วงที่ไฮไลต์ส้ม |1⟩↔|3⟩ และ |5⟩↔|7⟩ · ของที่เคยอยู่ |1⟩ ย้ายไป |3⟩ · ที่เคยอยู่ |7⟩ ย้ายไป |5⟩

ทำไมสลับแบบนี้? เพราะ CNOT “พลิก ep เมื่อ alice = 1” → วงที่ alice = 1 จะย้ายไปวงที่ค่า ep ตรงข้าม (ต่างกัน 2 ในเลขวง) ส่วนวงที่ alice = 0 อยู่นิ่ง · ผลลัพธ์คือวงที่รอดมีแต่วงที่ XOR ทั้งสามบิต = 0 (|0⟩ = 000, |3⟩ = 011, |5⟩ = 101, |6⟩ = 110) — กติกาข้อเดียวกับที่พี่ Zen เจอในควิซบท 0014 ค่ะ

ประโยคทองของ Step 3.1

เดิม “ep = bob เสมอ” (สองตัวพัวพันกัน) · ตอนนี้กลายเป็น “alice ⊕ ep ⊕ bob = 0 เสมอ” = พัวพันกันครบทั้งสามตัว · แปลว่า payload ของ Alice ผูกเข้ากับ qubit ของ Bob ทางอ้อมแล้ว ทั้งที่ยังไม่มีอะไรวิ่งไปหา Bob เลย

สมมติก่อนทำ Step 3.1 มีของอยู่ที่วง |5⟩ (bob 1, ep 0, alice 1) · หลัง ep.cnot(alice); ของก้อนนี้จะไปอยู่วงไหน?
ถูกต้องค่ะ! alice = 1 → CNOT พลิกบิต ep จาก 0 เป็น 1 · ep มีน้ำหนัก 2 → 5 + 2 = 7 · สังเกตว่า bob กับ alice ไม่ขยับเลย
ยังไม่ใช่ค่ะ — CNOT ตัวนี้แตะแค่ ep ตัวเดียว (alice เป็นแค่ control) · alice = 1 จึงพลิก ep 0→1 = บวกน้ำหนักของ ep เข้าไป 2 → 5 → 7 · ถ้าตอบ |1⟩ แปลว่าไปพลิก bob (น้ำหนัก 4) แทน ค่ะ

1.4 Step 3.2 — HAD ปิดท้ายฝั่ง Alice

จังหวะสุดท้ายก่อนวัด Alice ทำ HAD บน alice · หลัง HAD วงทั้ง 8 มีค่าหมด ซึ่งดูเหมือนยุ่งขึ้น แต่ที่จริงคือจังหวะที่ทุกอย่างเข้าที่ค่ะ

หลัง Step 3.2 (สไลด์หน้า 33–35) — ทั้ง 8 วงมีค่า · วงใหญ่ 4 วง (|0⟩ |1⟩ |6⟩ |7⟩) เท่ากันหมด ที่ 21.35% · วงเล็ก 4 วงเท่ากันหมดที่ 3.65% · เข็มของวงเล็กชี้คนละทางกันเป็นคู่ ๆ (−90° กับ +90°)

เคล็ดลับการอ่าน: อ่านเป็นคอลัมน์ — หนึ่งคอลัมน์คือ (alice, ep) หนึ่งค่า โดยวงบน = bob 0 และวงล่าง = bob 1 · เพราะฉะนั้นหนึ่งคอลัมน์ = สถานะหนึ่งแบบของ qubit ของ Bob และเมื่อดูทั้ง 4 คอลัมน์ จะพบว่าทุกคอลัมน์คือ payload เดิมของ Alice ที่ถูกดัดแปลงต่างกันแค่นั้นเองค่ะ

กฎที่ต้องจำให้ได้ (เรื่องสอบ)

บิตจาก ep คุม NOT · บิตจาก alice คุม PHASE(180°) — ตรงกับลูกศรประฟ้าสองเส้นในวงจรหน้า 15 เป๊ะ (ep → ⊕ · alice → φ) · ตารางข้างบนนี้คือที่มาของลูกศรสองเส้นนั้นค่ะ

แล้วทำไมต้องมี HAD ตัวนี้ด้วย? สไลด์หน้า 35 ตอบสั้นๆ ว่า — ถ้า Alice ไม่ทำ HAD ก่อน เธอจะทำลายข้อมูล magnitude กับ phase ทิ้งไปตอน READ · HAD คือตัวที่แปลงข้อมูลใน payload ให้ไปฝากไว้ในความสัมพันธ์ระหว่างคอลัมน์ก่อน แล้วค่อยวัดค่ะ

ส่วนที่ 2

จุดพลิก — READ แล้วส่งไม้ต่อให้ Bob (Step 3.3 → 5)

2.1 Step 3.3 — Alice READ ทั้งสองตัว

Alice วัด qubit ของเธอสองตัว: payload (alice) และครึ่งของเธอในคู่ entangled (ep)

หลัง Step 3.3 (สไลด์หน้า 36–37) — รูปในสไลด์วาดกรณีที่สุ่มได้ bit_p = 1, bit_n = 1 → คอลัมน์ที่ 4 · วงนอกคอลัมน์นั้นกลายเป็นศูนย์หมด แล้วสองวงที่เหลือถูก normalize ใหม่ จนกลับมาเป็น 14.6% / 85.4%
ประโยคทองของทั้งบท

READ ของ Alice = การเลือกคอลัมน์มา 1 คอลัมน์ · ได้คอลัมน์ไหนเป็นเรื่องสุ่มล้วน (โอกาสเท่ากันคอลัมน์ละ 25%) และสั่งไม่ได้ — นี่คือเหตุผลที่ teleportation ยังไม่ละเมิด no-signaling ของบท 0012 ค่ะ

สังเกตว่าคอลัมน์ที่ 4 คือกรณี “โดนทั้ง NOT และ PHASE(180°)” → ของใหญ่ที่เคยอยู่ bob = 0 ถูกสลับไปอยู่ bob = 1 (|7⟩ เต็มวง) และวงเล็ก |3⟩ เข็มพลิกไปที่ +90° แทนที่จะเป็น −90° เดิม · payload ยังอยู่ครบ แค่ถูกดัดแปลงไป 2 ชั้น

และราคาที่จ่ายคือ: qubit สองตัวของ Alice ถูกทำลายถาวร — ในวงจรคือเส้นสายที่กลายเป็นเส้นจาง หลัง detector · นี่คือหน้าตาของ no-cloning ในวงจร ไม่ใช่ผลข้างเคียงที่น่ารำคาญ แต่เป็นสิ่งที่โปรโตคอลต้องการค่ะ

รอบนี้ Alice อ่านได้ bit_p = 0 (จาก alice) และ bit_n = 1 (จาก ep) · Bob ต้องทำอะไรกับ qubit ของเขา?
ถูกต้องค่ะ! bit_n (จาก ep) = 1 → ทำ NOT · bit_p (จาก alice) = 0 → ไม่ต้อง PHASE · ตรงกับคอลัมน์ที่ 3 (alice 0, ep 1) ในตารางส่วนที่ 1 พอดี
ยังไม่ใช่ค่ะ — ยึดกฎ ep คุม NOT · alice คุม PHASE · ที่นี่ ep = 1 (ทำ NOT) และ alice = 0 (ไม่ทำ PHASE) → NOT อย่างเดียว · ระวังอย่าสลับสองบิตนี้กันนะคะ เป็นจุดที่พลาดกันบ่อยที่สุดของบท

2.2 Step 4 — Bob รับ 2 บิตแล้วแก้

Alice ยกหูโทรศัพท์ (ช่องทางคลาสสิก) ส่ง 2 บิตให้ Bob · Bob เอาสองบิตนั้นมาเปิดตารางในส่วนที่ 1 แล้วทำ inverse operation ตามนั้น จบเลย

หลัง Step 4 (สไลด์หน้า 38–39) — สองวงเดิมสลับขนาดกัน และเข็มกลับที่: bob = 0 เต็มวงเข็มขึ้น · bob = 1 วงเล็กที่ −90° → อ่าน qubit ของ Bob ได้ 85.4% |0⟩ + 14.6% |1⟩ ที่ phase −90° = payload เดิมของ Alice เป๊ะ ✓

ลองเทียบผังนี้กับผังหลัง Step 2 ดูนะคะ — รูปทรงเหมือนกันเป๊ะ ต่างแค่ตอนนี้มันอยู่คนละคอลัมน์ (เพราะ alice กับ ep ถูกวัดค่าไปแล้ว) และที่สำคัญมันอยู่บนสายของ Bob แล้ว · นี่คือช่วงเวลาที่ payload “ย้ายบ้าน” สำเร็จค่ะ

⚠️ สไลด์เขียนผิด · จุดที่ 8 ของคอร์ส

หน้า 38 เขียนว่า Bob แก้ด้วย “HAD และ/หรือ PHASE(180)” — ผิดค่ะ ของจริงคือ NOT และ/หรือ PHASE(180) · หน้า 39 ของสไลด์เอง กับโค้ดในรูป (bob.not()) ก็เขียนว่า NOT ทั้งคู่

หน้า 39 ยังเขียนกำกวมอีกจุด: “ถ้าบิตแรกเป็น 1 → NOT · บิตที่สอง → PHASE(180)” โดยไม่บอกว่าบิตไหนคือบิตแรก — และโค้ดอ่าน bit_p ก่อน bit_n ด้วย เพราะฉะนั้น “บิตแรก” ในประโยคนั้น ≠ bit_p · ให้ยึดโค้ดเสมอ: bit_n (ep) คุม NOT · bit_p (alice) คุม PHASE(180)

2.3 Step 5 — verify (prep แบบย้อนกลับ)

ถ้าใช้งานจริง โปรโตคอลจบไปแล้วตั้งแต่ Step 4 — Bob เอา qubit ไปใช้ต่อได้เลย · แต่ถ้าอยากตรวจว่าฮาร์ดแวร์ทำถูกจริงไหม ต้องยอมทำลาย qubit นั้นทิ้งเพื่อดูค่ะ

วิธีที่ง่ายที่สุดคือให้ Bob รันขั้นตอน prep payload ย้อนกลับ — เดิม Alice ทำ HAD → φ(+45°) → HAD บน |0⟩ · Bob ก็ทำ HAD → φ(−45°) → HAD แล้ววัด · ถ้าของที่ Bob ถืออยู่คือ payload จริง ผลต้องย้อนกลับไปเป็น |0⟩ เป๊ะ → อ่านได้ 0 เสมอ

หลัง Step 5 (สไลด์หน้า 40–43) — เหลือวงเดียวคือ |3⟩ เต็มวงพอดี เข็มชี้ขึ้น → bob เป็น |0⟩ แน่นอน 100% → check ต้องได้ 0 เสมอ = teleport สำเร็จ · (ยังอยู่คอลัมน์ 4 เพราะ alice กับ ep ถูกตรึงค่าไว้ตั้งแต่ Step 3.3 แล้ว)
ทำไมต้อง verify แบบนี้ ไม่ใช่ “เปิดดู”

เพราะ READ ครั้งเดียวบอกสถานะ qubit ไม่ได้ — อ่าน payload ตรงๆ ก็ได้แค่ 0 หรือ 1 หนึ่งค่า ซึ่งบอกอะไรเรื่อง 85.4/14.6 กับ phase −90° ไม่ได้เลย · แต่พอทำ prep ย้อนกลับก่อน คำตอบที่ถูกต้องจะกลายเป็น “0 เท่านั้น” ซึ่งตรวจได้ ถ้าเจอ 1 เมื่อไรแปลว่าพัง · ในงานจริงควรแทรกรอบ verify สลับกับรอบ teleport จริงเป็นระยะๆ ค่ะ

ถ้า Bob ข้าม Step 4 (ไม่แก้ตาม 2 บิตเลย) แล้วรัน Step 5 ต่อทันที · ค่า check ที่ได้จะเป็นยังไง?
ถูกต้องค่ะ! Alice สุ่มได้คอลัมน์ไหนก็ได้ (คอลัมน์ละ 25%) · เฉพาะคอลัมน์ที่ 1 เท่านั้นที่ payload ตรงอยู่แล้ว → verify ผ่าน · อีก 3 คอลัมน์ payload ถูกดัดแปลงค้างไว้ → มีโอกาสอ่านได้ 1 · นี่คือเหตุผลที่การรันบน IBM QX ต้องทำ post-selection ซึ่งเราจะเจอในบทหน้าค่ะ
ลองคิดใหม่นะคะ — 2 บิตของ Alice สุ่มล้วน แปลว่า Bob อาจตกอยู่ใน คอลัมน์ไหนก็ได้ใน 4 คอลัมน์ · คอลัมน์ที่ 1 ผ่านอยู่แล้ว ที่เหลือยังโดน NOT/PHASE ค้างอยู่ → ผลจึงไม่คงที่ · ไม่ใช่ 0 เสมอ และไม่ใช่ 1 เสมอค่ะ

  2. payload ของบทนี้คืออะไร? → 85.4% |0⟩ + 14.6% |1⟩ ที่ relative phase −90° ปั้นด้วย HAD → φ(45°) → HAD
  3. CNOT ใน Step 3.1 สลับวงคู่ไหน? → คู่ที่ alice = 1 คือ |1⟩↔|3⟩ และ |5⟩↔|7⟩ · เหลือเฉพาะวงที่ XOR ทั้งสามบิต = 0
  4. ทำไม Alice ต้อง HAD ก่อน READ? → ถ้าไม่ทำ จะทำลาย magnitude กับ phase ของ payload ทิ้ง ตอน READ · HAD ย้ายข้อมูลไปฝากไว้ในความสัมพันธ์ระหว่างคอลัมน์ก่อน
  5. READ ของ Alice ทำอะไรกับผัง 8 วง? → เลือกมา 1 คอลัมน์ (สุ่ม 25% เท่ากัน) วงนอกคอลัมน์เป็นศูนย์ แล้ว normalize ใหม่
  6. บิตไหนคุมอะไร? → bit_n (จาก ep) คุม NOT · bit_p (จาก alice) คุม PHASE(180°)
  7. Step 5 ทำอะไร แล้วต้องได้อะไร? → prep ย้อนกลับ (HAD → φ(−45°) → HAD) แล้ววัด → ต้องได้ 0 เสมอ · ผังเหลือ |3⟩ เต็มวงเข็มขึ้น
  8. สไลด์หน้า 38 ผิดตรงไหน? → เขียน “HAD และ/หรือ PHASE(180)” ที่ถูกคือ NOT
