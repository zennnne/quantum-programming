บทนี้คือ 2 บทสุดท้ายของ Lec 02 ค่ะ ครึ่งแรกพี่จะเห็นว่า gate ที่เรียนมา เอามาต่อกันเป็น gate ตัวใหม่ได้ (และมีคำสั่งนึงที่ควอนตัม ทำไม่ได้เลย) ส่วนครึ่งหลัง เราจะเอาทุกอย่างที่สะสมมาทั้งคอร์ส ไปประกอบเป็นโปรแกรมจริงที่ ตรวจจับคนดักฟังได้ค่ะ

บทนี้ยาว (รวม 2 บท) — จับหลัก 5 อย่างพอ
  1. No-cloning — ก๊อป qubit ที่ไม่รู้ค่าไม่ได้ นี่คือ "ข้อจำกัด" ที่กลายเป็น "อาวุธ"
  2. gate ต่อกันได้ — X = HZH, Z = HXH (เอา H กับ Z มาสลับที่กันเฉยๆ)
  3. RNOT (√NOT) — ครึ่งหนึ่งของ NOT · ทำสองที = NOT เต็ม · ไม่ใช่ its own inverse
  4. สัญลักษณ์ RNOT = กล่องมี √ (เรื่องสอบ! ตัวสุดท้ายที่ต้องท่อง)
  5. Spy Hunter — เจอ HAD ตรงกันแต่ค่าไม่ตรง = มีสปาย เพราะ no-cloning บังคับให้สปายเดา

ประกอบ gate + คำสั่งที่หายไป (COPY) + RNOT

1. คำสั่งที่ควอนตัม "ทำไม่ได้": COPY

ตั้งแต่เรียนคอมมา พี่ก๊อปข้อมูลจนเป็นเรื่องธรรมดา — b = a ก็ได้ค่าซ้ำมาแล้ว แต่กับ qubit มีเรื่องน่าตกใจค่ะ: เราก๊อป qubit ที่ไม่รู้ค่าของมันไม่ได้เลย ข้อเท็จจริงนี้มีชื่อเป็นทางการว่า no-cloning theorem (ทฤษฎีบทห้ามโคลน) (slide 73)

ก๊อปได้ค่าที่รู้อยู่แล้วว่าเป็น |0⟩ หรือ |1⟩ — ใช้ WRITE เขียนขึ้นใหม่เอาก็ได้
ก๊อปไม่ได้ ①qubit ที่อยู่ใน superposition
ก๊อปไม่ได้ ②qubit ที่กำลังคำนวณอยู่ (ยังไม่รู้ค่า)

ทำไมล่ะ? เพราะวิธีเดียวที่จะ "ดึงค่า" ออกจาก qubit คือ READ — แต่จากบท 5 พี่รู้แล้วว่า READ มันยุบ superposition ทิ้ง (collapse) พอพยายามจะก๊อป ก็เท่ากับบังคับให้วัด ตัวต้นฉบับก็พังไปพร้อมกัน ได้มาแค่ 0 หรือ 1 ธรรมดา ไม่ใช่ตัว qubit จริง เหมือนจะถ่ายเอกสารรูปสามมิติ แต่เครื่องถ่ายฉายได้แค่เงาแบนๆ ออกมา ตัวจริงก็ถูกทุบทิ้งด้วย

ข้อจำกัด → อาวุธ (เก็บประโยคนี้ไว้ เดี๋ยวได้ใช้ในครึ่งหลัง)

ฟังดูเหมือนเป็นข้อเสียใช่ไหมคะ แต่เดี๋ยวในบท 9 พี่จะเห็นว่า เพราะสปายก๊อป qubit ไม่ได้นี่แหละ เราถึงจับสปายได้ — ข้อจำกัดของฟิสิกส์กลายเป็นระบบความปลอดภัยที่แฮกไม่ได้ สไลด์ 73 ปิดท้ายว่า ควอนตัมมีคำสั่งทรงพลังอื่นๆ ที่ชดเชยการไม่มี COPY ได้สบายมาก

เช็คความเข้าใจ ① — ทำไมเราถึงก๊อป qubit ที่อยู่ใน superposition ไม่ได้?
ใช่เลยค่ะ! นี่คือหัวใจของ no-cloning: จะก๊อปต้องอ่านค่า จะอ่านต้อง READ และ READ ก็ยุบ superposition ทิ้ง ตัวจริงเลยพังคามือ ได้มาแค่ bit ธรรมดา ไม่ใช่ qubit
ยังไม่ใช่ค่ะ — ไม่ใช่เรื่องหน่วยความจำหรือคำสั่งที่ยังไม่มา แต่เป็น กฎของฟิสิกส์: วิธีเดียวที่จะดึงค่าออกมาก๊อปคือ READ ซึ่งยุบ superposition ตัวต้นฉบับทิ้ง จึงก๊อปไม่ได้โดยหลักการ ไม่ใช่แค่ยังทำไม่ได้

2. ประกอบ gate — เอา H กับ Z มาต่อกันได้ NOT!

เหมือน logic gate ธรรมดาที่เอา NAND มาต่อกันเป็นอะไรก็ได้ quantum gate ก็เอามาต่อกันได้ เพื่อสร้าง (ก) gate ที่มีอยู่แล้วตัวอื่น หรือ (ข) gate ใหม่ที่ไม่เคยมี (slide 74) ตอนนี้พี่มีของเล่นในมือ 5 ตัว: NOT, HAD, PHASE, READ, WRITE

สไลด์เริ่มด้วยกรณีสวยๆ: ถ้า QPU ไม่มีปุ่ม NOT ให้ เราสร้างเองได้จาก HAD กับ PHASE(180) หรือเขียนสั้นๆ ด้วยชื่อเล่นของ gate ว่า

X = H Z H

(จำไว้จากบท 7 นะคะ: Z ก็คือ PHASE(180) ส่วน X ก็คือ NOT — สไลด์แค่ใช้ชื่อสั้น) ในรูปวงจร อ่านซ้าย→ขวาก็คือ ยิง H ก่อน แล้ว Z แล้ว H อีกที:

H → PHASE(180) → H = NOT เป๊ะ (slide 75–85)

อยากเชื่อว่ามันเท่ากับ NOT จริงๆ ก็คูณเมทริกซ์ตามได้เลยค่ะ สไลด์ไล่ทีละสเต็ป — หนูสรุปให้ (คูณจากขวาไปซ้าย ตามกติกาเมทริกซ์ แต่ผลก็คือ HZH):

1) จับคู่ในสุดก่อน: ZH = 100−1 · 1√2 111−1 = 1√2 11−11 (แถวล่างโดน −1 คูณ เลยเปลี่ยนเครื่องหมาย)
2) แล้วคูณ H เข้าไปอีกที: H(ZH) = 1√2 111−1 · 1√2 11−11 = 12 0220
3) ดึง ½ เข้าไป = 0110 — นี่คือเมทริกซ์ของ NOT (X) เป๊ะ! ✔

และมันทำงานทั้งสองทางค่ะ — สลับที่ H กับ Z กันเฉยๆ ก็ได้อีกสมการ (slide 86–90):

Z = H X H

อ่านเป็นภาษาคนว่า "PHASE(180) ก็สร้างได้จาก HAD กับ NOT" คู่กันสวยงามมาก จำง่ายๆ ว่า H เป็นตัว "สลับมุมมอง" — พอเอา H ประกบหน้า-หลัง gate ตัวนึง มันจะกลายเป็น gate อีกตัวที่ทำหน้าที่คล้ายกันแต่คนละแกน (X↔Z สลับกันได้ด้วย H)

โยงกับ Bloch sphere (บท 7)

ทำไม H ถึงสลับ X กับ Z ได้? เพราะบนทรงกลม Bloch HAD คือการหมุนที่สลับแกน X กับแกน Z เข้าหากัน พอสลับแกนแล้ว "หมุนรอบ Z" (=Z gate) ก็เลยกลายเป็น "หมุนรอบ X" (=X gate) พอเอา H มาเลิกสลับตอนท้าย ทุกอย่างก็ลงตัว — ไม่ต้องท่องเมทริกซ์ก็เห็นภาพได้ค่ะ

เช็คความเข้าใจ ② — QPU ตัวหนึ่งมีปุ่ม HAD กับ PHASE ให้ แต่ไม่มีปุ่ม NOT พี่จะพลิก |0⟩ ให้เป็น |1⟩ ได้ยังไง?
ถูกต้องค่ะ! X = HZH ก็คือ had() → phase(180) → had() ได้ NOT เต็มตัว — นี่คือพลังของการประกอบ gate: ขาดปุ่มไหนก็สร้างเองจากปุ่มที่มีได้
ยังไม่ใช่ค่ะ — PHASE(180) ตัวเดียวไม่พลิกบิต (มันแค่หมุนเข็มของวง |1⟩ และไม่มีผลกับ |0⟩ เลยด้วยซ้ำ) ส่วน HAD สองทีก็กลับที่เดิม สูตรที่ถูกคือ X = HZH: HAD → PHASE(180) → HAD

3. RNOT (√NOT) — "รากที่สองของ NOT" ที่คอมธรรมดาไม่มีวันมี

ทีนี้ของแปลกจริงๆ มาแล้วค่ะ การประกอบ gate ไม่ได้สร้างแค่ของเดิม แต่สร้าง ของใหม่ที่ไม่มีในโลกลอจิกปกติ ได้ด้วย ตัวอย่างเด็ดคือ RNOT — Root-of-NOT (รากที่สองของ NOT) หรือเขียน √NOT ความหมายตรงตัวเลยค่ะ: ทำมันสองครั้ง = ได้ NOT หนึ่งที (slide 91)

√NOT · √NOT = NOT

ลองคิดดูนะคะ ในโลกคอมธรรมดา "ครึ่งหนึ่งของการพลิกบิต" มันคืออะไร? พลิกครึ่งนึงเนี่ย? มันไม่มีความหมายเลย บิตมีแค่ 0 กับ 1 จะครึ่งๆ กลางๆ ได้ไง — แต่ในควอนตัมมันมีจริง เพราะ qubit เดินทางผ่าน superposition ได้ RNOT ก็คือ "พาไปหยุดครึ่งทาง" ระหว่าง |0⟩ กับ |1⟩ พอดี

หน้าตาสัญลักษณ์ (ตัวสุดท้ายที่ต้องท่องสอบ!)

สไลด์ 92 โชว์สัญลักษณ์ชัดเจน: กล่องสี่เหลี่ยมที่มีเครื่องหมาย √ (รากที่สอง) ข้างใน และโชว์ 2 เอกลักษณ์สำคัญของมันด้วย:

RNOT (√NOT)
กล่องมี √
RNOT ต่อกัน 2 ตัว = NOT (⊕)
RNOT = H → PHASE(90°) → H

เมทริกซ์ของมันตามสไลด์ 94 (ต่างจาก gate อื่นตรงมี i = จำนวนเชิงซ้อนโผล่มาเต็มๆ):

√NOT = 12 1+i1−i1−i1+i
Refresher — ตรวจว่า "ทำสองที = NOT" ได้ยังไง

เอา √NOT มาคูณตัวเอง (A·A) แล้วดูว่าได้ NOT ไหม สไลด์ไล่ทีละช่อง (slide 96–101) ยกช่องบนซ้ายมาให้ดู: (1+i)(1+i) + (1−i)(1−i). กุญแจคือ i² = −1 ค่ะ:

(1+i)² = 1 + 2i + i² = 1 + 2i − 1 = 2i · และ (1−i)² = 1 − 2i − 1 = −2i → รวมกัน = 2i + (−2i) = 0 พอทำครบทุกช่องด้วย ½·½ = ¼ จะได้ 0110 = NOT เป๊ะ ✔

ไล่ด้วย circle notation ให้เห็นภาพว่า "ครึ่งทาง" หน้าตาเป็นไง — ยิง RNOT ใส่ |0⟩ ได้ superposition ที่เข็มเอียง (มี i อยู่ในนั้น) พอยิงอีกที ก็ไปถึง |1⟩ พอดี:

—√—→
ครึ่งทาง: 50/50
(เข็มเอียง — มี i)
—√—→
ถึง |1⟩ พอดี
= NOT เต็ม

ทำไม RNOT = H–PHASE(90)–H (เกร็ดสวยๆ ที่สไลด์พิสูจน์ให้)

จำ X = HZH = H–PHASE(180)–H ได้ไหมคะ? RNOT ก็หน้าตาเดียวกันเป๊ะ แค่ เปลี่ยน 180 เป็น 90 (ครึ่งนึงพอดี!): RNOT = H–PHASE(90)–H เพราะงั้นทำ RNOT สองที ก็คือ (slide 104–105):

RNOT · RNOT = H · P(90) · H · H · P(90) · H
ตรงกลาง H·H = ตัวตน (HAD ย้อนตัวเอง) → หายไป!
= H · P(90) · P(90) · H = H · P(180) · H = HZH = NOT ✔

เห็นความสวยไหมคะ — "ครึ่งหนึ่งของ NOT" ก็คือ "ครึ่งหนึ่งของมุม PHASE ตรงกลาง" พอดี 180 หารสอง = 90 เป๊ะ เพราะ P(90) สองทีเท่ากับ P(180) นั่นเอง

จุดที่ต่างจาก NOT — ออกสอบได้ 🪤

NOT เป็น its own inverse (ทำสองทีกลับที่เดิม) แต่ RNOT ไม่ใช่! — เพราะทำสองที ของ RNOT กลายเป็น NOT (ไม่ใช่กลับที่เดิม) จะย้อน RNOT ต้องใช้ เฟสลบ: RNOT⁻¹ = H–PHASE(−90)–H (slide 106) เหมือน PHASE ในบท 7 เลยที่ต้องย้อนด้วยมุมลบ

เช็คความเข้าใจ ③ — qubit อยู่ที่ |0⟩ พี่ยิง RNOT ใส่หนึ่งครั้ง แล้ว READ เลย โอกาสได้ 1 เท่าไหร่?
เป๊ะค่ะ! RNOT ทีเดียว = พาไป "ครึ่งทาง" = superposition 50/50 พอดี (เหมือน HAD แต่ phase ต่างกัน มี i) ต้องทำสองทีถึงจะถึง |1⟩ เต็ม แล้วได้ 1 แน่นอน 100%
ยังไม่ใช่ค่ะ — RNOT ทีเดียวคือ "ครึ่งทาง" ระหว่าง |0⟩ กับ |1⟩ = superposition 50/50 ดังนั้น READ ได้ 1 ที่ 50% ไม่ใช่ 0% หรือ 100% (ต้องทำสองทีถึงจะเป็น NOT เต็มแล้วได้ 1 แน่นอน)

Quantum Spy Hunter — เอา no-cloning มาจับคนดักฟัง

4. ปัญหา: จะรู้ได้ยังไงว่ามีคนแอบฟังสายอยู่?

ครึ่งหลังนี้คือ capstone ของทั้ง Lec 02 ค่ะ — เอาทุกอย่างที่เรียนมา (WRITE, HAD, READ, no-cloning) มาประกอบเป็นโปรแกรมจริงที่ทำเรื่องที่คอมธรรมดาทำไม่ได้: QKD — Quantum Key Distribution (การแจกกุญแจเชิงควอนตัม) ระบบส่งข้อมูลที่ พิสูจน์ได้ทางฟิสิกส์ว่าปลอดภัย (slide 107)

ตัวละครมาตรฐานของวงการเข้ารหัส: Alice อยากส่งข้อมูลลับให้ Bob ผ่านสายควอนตัม แต่กลัวมี สปาย (eavesdropper) แอบดักฟังกลางทาง คำถามคือ — จะรู้ตัวได้ยังไงว่าโดนดักฟัง?

ต้นทาง-ปลายทางไม่มีทางรู้
≠
สายควอนตัม (qubit)สปายก๊อปไม่ได้ (no-cloning!)
ต้อง READ = ทิ้งร่องรอย
นี่แหละ "ข้อจำกัดกลายเป็นอาวุธ" ที่พูดไว้ตอนต้นบท

บนสายบิตธรรมดา สปายแค่ก๊อปบิตผ่านไป ไม่มีใครรู้ แต่บนสายควอนตัม no-cloning บังคับว่าสปายก๊อปไม่ได้ สิ่งเดียวที่สปายทำได้คือ READ qubit แล้วพยายามส่งตัวใหม่ให้ Bob — แต่ READ มันยุบ state และสปายไม่รู้ว่า Alice ใส่ HAD มาหรือเปล่า เลยเดาผิดบ่อยๆ แล้วส่งของผิดต่อไป = ทิ้งร่องรอยให้จับได้

  3. ส่งข้ามสายไป Bob — fiber.exchange(a)
  4. สปาย (ถ้ามี) ดักกลางทาง — ก๊อปไม่ได้ ทำได้แค่ READ แล้วส่งตัวใหม่ต่อ แต่สปายไม่รู้ว่า Alice ใส่ HAD ไหม เลยไม่รู้ว่าควร READ ในฐานไหน → เดามั่ว
  5. Bob สุ่มบิต recv_had ของตัวเอง — ถ้า recv_had=1 ก็ใส่ HAD ก่อน READ (เพื่อ "ถอด" HAD ของ Alice) แล้ว READ ออกมาเป็น recv_val

6. หัวใจ: กติกาจับสปาย

หลังส่งเสร็จ Alice กับ Bob คุยกันเปิดเผยผ่านสายธรรมดาได้เลย (ไม่ต้องเข้ารหัส!) — แต่คุยแค่ว่า "ตาไหนบ้างที่เราบังเอิญเลือก HAD ตรงกัน" ไม่บอกค่าจริง เฉพาะตาที่ HAD ตรงกัน (send_had = recv_had, เกิดประมาณครึ่งนึง) ค่าที่ได้ต้องตรงกันถ้าไม่มีใครยุ่ง กติกาคือ (slide 120):

ประโยคที่ต้องจำไปสอบ 🎯

ถ้า HAD ตรงกัน แต่ค่าไม่ตรงกัน → มีสปาย!

if (send_had == recv_had) // เลือก HAD เหมือนกัน
if (send_val != recv_val) // แต่ค่าดันไม่ตรง
qc.print('Caught a spy!');

ทำไมกฎนี้ถึงจับได้? เพราะถ้า HAD ตรงกันแล้วไม่มีสปาย ค่าต้องตรงกัน 100% (Bob ถอดรหัสถูกพอดี) การที่มันไม่ตรง แปลว่ามีบางอย่างไปยุ่ง state ระหว่างทาง — ก็คือสปายที่ READ แล้วส่งของผิดมาให้ Bob นั่นเอง สปายมีโอกาส 25% ที่จะถูกจับได้ต่อ qubit หนึ่งตัวที่เอามาตรวจ (slide 107) ยิ่งตรวจหลายตัว โอกาสรอดของสปายยิ่งเข้าใกล้ศูนย์

25% มาจากไหน (เกร็ด ไม่ออกสอบลึก)

สปายจะถูกจับได้เมื่อของ 2 อย่างเกิดพร้อมกัน: (1) ตานั้น Alice-Bob เลือก HAD ตรงกัน (โอกาส ½) และ (2) การที่สปายเดา HAD ผิดแล้ว READ ทำให้ค่าเพี้ยน (โอกาส ½ ในตาที่ HAD ตรงกัน) → ½ × ½ = ¼ = 25% ต่อ qubit หนึ่งตัว

เช็คความเข้าใจ ④ — ทำไมสปายที่ฉลาดมากๆ ถึงยัง "ก๊อป qubit เก็บไว้ แล้วส่งตัวจริงต่อ" ไม่ได้?
ใช่เลยค่ะ! นี่คือจุดที่บท 8 (no-cloning) กับบท 9 มาบรรจบกัน: ก๊อปไม่ได้ = ต้อง READ = ยุบ state + สปายไม่รู้ฐาน HAD ของ Alice เลยเดาผิด ส่งของเพี้ยนต่อ = โดนจับ
ยังไม่ใช่ค่ะ — ไม่เกี่ยวกับความเร็ว น้ำหนักสาย หรือรหัสผ่าน แต่เป็น no-cloning theorem จากบท 8: ก๊อป qubit ที่ไม่รู้ค่าไม่ได้เลย สปายเลยทำได้แค่ READ ซึ่งยุบ state และเดาฐานผิด → ทิ้งร่องรอย
เช็คความเข้าใจ ⑤ — ในตาหนึ่ง Alice ส่งมาโดย ไม่ใส่ HAD (send_had=0) แต่ Bob ใส่ HAD ก่อน READ (recv_had=1) แล้วค่าที่ได้ไม่ตรงกัน สรุปว่ามีสปายไหม?
ถูกต้องค่ะ! กฎจับสปายใช้ได้เฉพาะตาที่ HAD ตรงกันเท่านั้น ตานี้ HAD ไม่ตรง (0 vs 1) ค่าที่เพี้ยนจึงเป็นเรื่อง "ปกติ" ของ superposition ไม่ใช่หลักฐานสปาย — ทิ้งตานี้ไป
ยังไม่ใช่ค่ะ — กับดักคือกฎจับสปายใช้ได้เฉพาะเมื่อ send_had == recv_had ตานี้ HAD ไม่ตรงกัน (0 vs 1) ค่าที่ไม่ตรงจึงอธิบายได้ด้วย superposition ธรรมดา ไม่ใช่หลักฐานสปาย ตาแบบนี้ต้องโยนทิ้ง
🧠 ลองเล่าเองก่อนเปิด — "no-cloning ทำให้ระบบจับสปายทำงานได้ยังไง เล่าเป็นขั้นๆ"

ตัวอย่างคำตอบที่ดี: "บนสายบิตธรรมดา สปายก๊อปบิตผ่านไปเงียบๆ ได้ ไม่มีใครรู้ แต่บนสายควอนตัม no-cloning ห้ามก๊อป qubit ที่ไม่รู้ค่า สปายเลยทำได้แค่ READ — ซึ่ง (1) ยุบ superposition ทิ้ง และ (2) สปายไม่รู้ว่า Alice ใส่ HAD มาหรือเปล่า เลยไม่รู้ว่าต้อง READ ในฐานไหน → เดาผิดประมาณครึ่งนึง พอเดาผิดแล้วส่ง qubit ตัวใหม่ต่อให้ Bob มันก็เป็นสถานะที่เพี้ยน ทีนี้ Alice กับ Bob เอาเฉพาะตาที่ เลือก HAD ตรงกัน มาเทียบค่า ถ้าไม่มีสปายค่าต้องตรง 100% ถ้าเจอค่าไม่ตรงในตาพวกนี้ = มีสปายแน่นอน โอกาสจับได้ 25% ต่อ qubit ยิ่งตรวจเยอะยิ่งหนีไม่รอด"

นึกเองก่อนเปิดเฉลย (retrieval practice) จำได้นานกว่าอ่านซ้ำเยอะค่ะ

ทำไมเรื่องนี้ถึงสำคัญในโลกจริง (slide 114)

QKD ใช้ QPU เล็กมาก (qubit ตัวเดียวก็พอ!) ไม่ต้องรอ quantum computer ยักษ์ที่รัน Shor ได้ เพราะงั้น quantum cryptography เลยเริ่มมีขายเชิงพาณิชย์แล้วจริงๆ ตั้งแต่ตอนที่ QPU ทั่วไปยังทำอะไรใหญ่ๆ ไม่ได้ — เป็นการประยุกต์ควอนตัมตัวแรกๆ ที่ออกจากห้องแล็บมาสู่ตลาดค่ะ
