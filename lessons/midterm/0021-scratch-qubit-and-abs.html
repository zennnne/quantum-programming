Quantum Programming · Lec 05 · บทที่ 0021

scratch qubit — ที่พักของข้อมูลที่กำลังจะหาย

ตั้งแต่ บท 0017 เราท่องกฎเหล็กสองข้อของ QPU มาตลอด: ห้ามคัดลอก กับ ต้องย้อนกลับได้ ที่ผ่านมากฎพวกนี้ยังไม่เคยขวางเราจริงๆ เพราะโจทย์ที่เจอ (+1, a += b, negate) บังเอิญย้อนกลับได้อยู่แล้ว บทนี้เราจะเจอโจทย์แรกที่ชนกำแพงเต็มๆ — ฟังก์ชันง่ายที่สุดในโลกอย่าง abs(a) (ค่าสัมบูรณ์) ที่ไม่ว่าจะเรียง gate ยังไงก็ทำไม่ได้ แล้วเราจะแก้มันด้วยของชิ้นเดียว: qubit เปล่าๆ อีกหนึ่งตัวที่เรียกว่า scratch qubit (คิวบิตทด) ค่ะ

บทนี้จับ 3 อย่าง
  1. ทำไม abs(a) ถึงทำไม่ได้ — และทำไมมันไม่ใช่ปัญหาที่แก้ด้วย “หา gate ให้เก่งขึ้น” แต่เป็นปัญหาระดับทฤษฎีสารสนเทศ
  2. scratch qubit คืออะไร — และทำไมการเอาบิตเครื่องหมายไป “พัก” ไว้ที่มัน ถึงทำให้วงจรทั้งชุดย้อนกลับได้ทันที
  3. อ่าน circle notation 3 สแนปช็อต — เห็นด้วยตาว่าการมี “แถวที่สอง” ช่วยยังไง

ส่วนที่ 1 — โจทย์ที่ทำไม่ได้: abs(a)

สไลด์ตั้งโจทย์ไว้ตรงๆ เลยค่ะ: มี a เป็น quantum integer 3 qubit (เก็บเลขติดลบแบบ two’s complement ตาม บท 0019) จะใส่ gate อะไรลงในกล่องนี้ ให้ผลลัพธ์เป็น abs(a)?

ตอนแรกมันดูง่ายมาก เพราะเราทำ negate (a = -a) เป็นแล้วตั้งแต่บท 0019 — พลิกทุกบิตแล้ว +1 ส่วน abs ก็แค่ “negate ถ้า a ติดลบ” แล้วเรารู้ด้วยว่า a ติดลบเมื่อไหร่: ดูที่บิตเครื่องหมาย คือ qubit 0x4 นั่นเอง งั้นก็เอาบิตนั้นมาเป็น control ของ negate สิ จบ!

…แต่มันพังค่ะ ลองไล่ดู: สมมติ a = −1 = 111₂ บิตเครื่องหมายเป็น 1 → negate ทำงาน → ได้ 001₂ = 1 ถูกต้อง
ทีนี้ลอง a = 1 = 001₂ อยู่แล้ว → บิตเครื่องหมายเป็น 0 → negate ไม่ทำงาน → ได้ 001₂ = 1 ก็ถูกต้องอีก
สังเกตอะไรไหมคะ — อินพุตสองตัวที่ต่างกัน (−1 กับ 1) ให้เอาต์พุตตัวเดียวกัน พอวงจรจบแล้ว บิตเครื่องหมายกลายเป็น 0 ไปแล้ว ต่อให้ย้อนวงจรกลับ ก็ไม่มีทางรู้ว่าตอนแรกมันคือ −1 หรือ 1 → ข้อมูลหาย = ไม่ reversible

และนี่คือประโยคที่สไลด์เน้นมากที่สุดของหน้านี้:

“It’s not that we’ll receive a QPU compile or runtime error; the problem is that no matter how hard we try, we won’t ever find a configuration of reversible QPU operations able to produce the desired results.” — สไลด์ p41

แปลไทย: ไม่ใช่ว่าจะได้ error ตอน compile หรือตอน run — แต่คือไม่ว่าจะพยายามแค่ไหน ก็หาชุด gate ที่ให้ผลลัพธ์นี้ไม่เจอเลย เพราะตัวฟังก์ชัน abs ทางคณิตศาสตร์เองทำลายข้อมูลเรื่องเครื่องหมายทิ้ง ปัญหาอยู่ที่ตัวโจทย์ ไม่ใช่ที่ฝีมือเรา
ฟังก์ชันที่ QPU ทำได้ต้องเป็น 1-ต่อ-1 — อินพุตต่างกัน ต้องได้เอาต์พุตต่างกันเสมอ ถึงจะเดินย้อนกลับได้
✗
abs ไม่ใช่ 1-ต่อ-1−1 กับ 1 ยุบมาเป็น 1 เหมือนกัน · −3 กับ 3 ยุบเป็น 3 · อินพุต 2 ตัว → เอาต์พุต 1 ตัว
① สมมติพี่ Zen ดื้อ ลองทำ negate โดยใช้บิตเครื่องหมายของ a เองเป็น control จริงๆ แล้วป้อน a = −3 (101₂) เข้าไป · หลังวงจรจบจะได้ 011₂ = 3 · ทีนี้ถ้าเอา 011₂ เดินย้อนวงจรกลับ จะเกิดอะไรขึ้น
ถูกต้องค่ะ! วงจรย้อนก็ต้องดูบิตเครื่องหมายเหมือนกัน แต่ตอนนี้บิตนั้นเป็น 0 ไปแล้ว มันเลย “ไม่ negate” → ได้ 3 กลับมา ไม่ใช่ −3 อินพุตเดิมหายไปแล้วจริงๆ · ส่วนตัวเลือกที่บอกว่า gate เป็น unitary ก็ไม่ผิดนะคะ — แต่นั่นแหละคือประเด็น: เราหาชุด unitary ที่ทำงานนี้ไม่ได้ตั้งแต่แรก ไม่ใช่ว่ามีแล้วย้อนไม่ได้
ยังไม่ใช่ค่ะ ลองนึกว่า “วงจรย้อน” ก็ใช้บิตเครื่องหมายเป็น control เหมือนกัน แล้วตอนนี้บิตเครื่องหมายของ 011₂ เป็นอะไรคะ?

ส่วนที่ 2 — ทางออก: เอาเครื่องหมายไป “พัก” ไว้ที่ scratch qubit

“Scratch qubits are not necessary for encoding the input or output we’re interested in, but rather play a temporary role enabling the quantum logic connecting them.” — สไลด์ p39

แปลไทย: scratch qubit (คิวบิตทด) ไม่ได้ใช้เก็บอินพุตหรือเอาต์พุตที่เราสนใจ แต่ทำหน้าที่ชั่วคราว เพื่อให้ตรรกะที่เชื่อมอินพุต → เอาต์พุตเป็นไปได้

ไอเดียแก้ปัญหาสั้นมากค่ะ: ปัญหาคือข้อมูล “เดิมติดลบไหม” หายไป — งั้นก็อย่าให้มันหายสิ เอาไปพักไว้ที่อื่นก่อน เพิ่ม qubit เปล่าๆ (เริ่มที่ ∣0⟩) มาอีก 1 ตัว แล้วใช้ CNOT ก๊อบ… เอ๊ย พ่วง บิตเครื่องหมายไปไว้ที่มัน จากนั้นค่อย negate โดยใช้ scratch เป็น control แทนที่จะใช้บิตเครื่องหมายของ a เอง

ดูเผินๆ เหมือนวงจรใหม่ทั้งยวง แต่จริงๆ แล้วของใหม่มีแค่ gate เดียวค่ะ — ที่เหลือคือวงจร negate จาก บท 0019 แบบเป๊ะๆ ที่เอา ● ของ scratch ไปแปะเพิ่มในทุก gate เท่านั้นเอง (เป็นท่าเดียวกับที่เราทำ conditional increment ใน บท 0020 เลย):

ขั้นnegate ธรรมดา (บท 0019)negate ใน abs (บทนี้)
พลิกทุกบิตX:0 + X:1 + X:2 CTRL:3 + X:0,1,2
+1 (บิต 0x4)CCNOT:0,1,2 CTRL:0,1,3 + X:2
+1 (บิต 0x2)CNOT:0,1 CCNOT:0,3,1
+1 (บิต 0x1)X:0 CNOT:3,0

เห็นแพตเทิร์นไหมคะ — ทุกแถวคือ gate เดิม + จุด ● ที่สาย scratch เพิ่มมาหนึ่งจุด ไม่มีอะไรใหม่ในเชิงสัญลักษณ์เลย ของใหม่จริงๆ คือ CNOT:2,3 ตัวแรกสุด ที่ทำหน้าที่ “พักเครื่องหมาย” — และเจ้านี่แหละคือหัวใจของทั้งบท

⚠️ CNOT ตัวนั้น “ไม่ได้ copy” บิตเครื่องหมายนะคะ — สไลด์ p43 ย้ำเรื่องนี้ตรงๆ เพราะ QPU copy qubit ไม่ได้ (no-cloning ตั้งแต่บท 0017)
สิ่งที่ CNOT ทำคือ entangle scratch เข้ากับบิตเครื่องหมายของ a ต่างหาก
ผลลัพธ์ดูเหมือนการ copy ก็ต่อเมื่อ a อยู่ในสถานะฐานตัวเดียว (เช่น a = −3 เป๊ะๆ) แต่ถ้า a อยู่ใน superposition มันจะกลายเป็น สถานะพัวพัน ไม่ใช่สำเนาสองชุด

และนี่คือเอาต์พุตที่ควรจำ (ดูป้ายฝั่งขวาของวงจร): สาย a กลายเป็น abs(a) ส่วน scratch กลายเป็น sign(a) เครื่องหมายไม่ได้หายไปไหน — มันย้ายที่ วงจรทั้งชุดจึงย้อนกลับได้ นี่คือหัวใจของเทคนิค scratch qubit ค่ะ

② ทำไมการเอา sign(a) ไปไว้ที่ scratch ถึงทำให้วงจรกลายเป็น reversible ทั้งที่ abs เองยังทำลายข้อมูลอยู่ดี
ใช่เลยค่ะ! กุญแจอยู่ที่คำว่า เอาต์พุตรวม — ถ้าดูแค่สาย a อย่างเดียวมันยังทำลายข้อมูลอยู่จริง (−3 กับ 3 ได้ 3 เหมือนกัน) แต่พอนับ scratch ด้วย เอาต์พุตคือคู่ (3, ลบ) กับ (3, บวก) ซึ่งต่างกัน → กลับมาเป็น 1-ต่อ-1 → ย้อนกลับได้
ยังไม่ใช่ค่ะ ลองถามตัวเองว่า “ถ้าหนูเห็นเอาต์พุตทั้งหมด (ทั้งสาย a และสาย scratch) หนูบอกได้ไหมว่าอินพุตเดิมคืออะไร?”

ส่วนที่ 3 — ดูด้วยตา: circle notation 3 สแนปช็อต

ส่วนนี้คือของดีของบทค่ะ สไลด์ p44–45 เอาสถานะตัวอย่างที่จงใจใส่เฟสต่างกันทุกวง (0°, −45°, 180°, −90°, 135°) มาไล่ทีละขั้น จะได้ตามได้ว่าวงไหนย้ายไปไหน ตอนนี้ผังไม่ใช่แถวเดียวแล้ว แต่เป็น 2 แถว × 8 คอลัมน์ = 16 วง เพราะเรามี 4 qubit — คอลัมน์ = ค่าของ a (two’s complement) และ แถว = ค่าของ scratch

① ก่อนเริ่ม — 6 วงเท่าๆ กัน อยู่แถวบนหมด (scratch = ∣0⟩) · แถวล่างว่างเปล่าทั้งแถว คือที่ว่างที่เรายังไม่ได้ใช้

② หลัง CNOT:2,3 (XOR บิตเครื่องหมายเข้า scratch) — ทุกวงที่ a ติดลบตกลงมาแถวล่าง ตรงคอลัมน์เดิมเป๊ะ · magnitude และเฟสติดตัวลงมาครบ ไม่มีอะไรเปลี่ยน

③ หลังจบวงจร (negate โดยมี scratch เป็น control) — วงในแถวล่างเลื่อนตามแนวนอนไปช่องค่าบวกที่คู่กัน: −1 → 1 · −3 → 3 · แถวบนไม่ถูกแตะเลยสักวง

ทีนี้อ่านผลออกมาเป็นภาษาคน — 3 ประเด็นที่ต้องเห็นให้ได้:

① ค่าบวกไม่ถูกแตะเลย วงที่ a ≥ 0 (∣0⟩, ∣1⟩, ∣3⟩) อยู่นิ่งสนิททั้ง 3 ขั้น เพราะ scratch ของมันเป็น 0 → gate ที่มี ● ที่สาย scratch ไม่ทำงานกับมันเลย
② นี่คือเหตุผลที่ scratch แก้ปัญหาได้ ถ้าไม่มี scratch ผังจะมีแถวเดียว วงของ a = −1 ต้องเลื่อนไปทับช่อง a = 1 ที่มีของอยู่แล้ว → magnitude และเฟสของเดิมโดนทำลาย กู้ไม่ได้อีกเลย
③ scratch = “ชั้นที่สอง” ให้ย้ายลงไปก่อน พอลงไปแถวล่างแล้วค่อยเลื่อนแนวนอน ก็ไม่ชนกับใคร — ของเดิมอยู่ครบ สถานะทั้งหมดจึงกู้คืนได้ = reversible
สังเกตวงที่ช่อง a = −4 (ket ∣12⟩) สิคะ — มันไม่ขยับไปไหนเลย ทั้งที่มันเป็นค่าลบและถูกย้ายลงแถวล่างเรียบร้อยแล้ว
เพราะ abs(−4) = 4 แต่ register 3 บิตแบบ two’s complement เก็บได้แค่ −4 ถึง 3 — ไม่มีเลข 4 ให้ไปอยู่
วงจร negate ก็เลยพา −4 วนกลับมาเป็น −4 ตัวเดิม (พลิกบิต 100 → 011 แล้ว +1 → 100) · นี่ไม่ใช่บั๊ก แต่เป็นข้อจำกัดเดียวกับ abs(INT_MIN) ในภาษา C ที่พี่ Zen อาจเคยเจอมาแล้วค่ะ
③ ถ้าเราดื้อทำ abs โดยไม่มี scratch qubit (ผังเหลือแถวเดียว 8 วง) · จากสแนปช็อต ① วงที่ช่อง a = −1 (เข็ม 135°) ต้องเลื่อนไปช่อง a = 1 · แล้วจะเกิดอะไรขึ้น
ถูกต้องค่ะ! ช่อง a = 1 มีของอยู่แล้ว (เข็ม −45°) พอวง 135° เลื่อนมาทับ ทั้ง magnitude และเฟสของเดิมก็หายไป → ย้อนกลับไม่ได้อีกเลย · scratch qubit คือการเปิด “แถวที่สอง” ให้ย้ายลงไปเลื่อนโดยไม่ชนใคร นั่นเองค่ะ
ลองดูสแนปช็อต ① อีกทีนะคะ — ช่อง a = 1 ในแถวนั้น ว่างอยู่หรือมีวงอยู่แล้ว? · และอย่าลืมว่า “error ตอนรัน” คือสิ่งที่สไลด์ p41 บอกชัดว่าไม่เกิดค่ะ
④ จากสแนปช็อต ③ ถ้าตอนนี้เราเอาสาย scratch ไป READ เลย (เพราะอยากรู้ว่าเดิมติดลบหรือเปล่า) จะเกิดอะไรขึ้นกับสถานะที่เหลือ
ใช่ค่ะ และนี่คือปัญหาที่บทนี้ทิ้งไว้ — scratch ไม่ได้กลับไปเป็น ∣0⟩ เอง และมันยัง entangled กับ a อยู่ (ดูสแนปช็อต ③: วงกระจายอยู่ทั้งสองแถว) · READ มันเมื่อไหร่ superposition ที่เราอุตส่าห์สร้างมาก็พังทันที · ทางแก้ชื่อว่า uncomputing — อยู่ในบทหน้าค่ะ
ลองดูสแนปช็อต ③ ดีๆ นะคะ — ตอนนี้วงกระจายอยู่ ทั้งแถวบนและแถวล่าง แปลว่าค่าของ scratch กับค่าของ a ผูกกันอยู่ การอ่านตัวหนึ่งจะไปกระทบอีกตัวไหมคะ?

สรุป + ปัญหาที่ยังค้าง

สูตรของบทนี้ 3 บรรทัด
  1. เจอ operation ที่ทำลายข้อมูล (ไม่ใช่ 1-ต่อ-1) → QPU ทำตรงๆ ไม่ได้เด็ดขาด
  2. เพิ่ม scratch qubit เริ่มที่ ∣0⟩ แล้วใช้ CNOT พ่วง (ไม่ใช่ copy) ข้อมูลที่กำลังจะหายไปเก็บไว้
  3. ทำ operation จริงโดยใช้ scratch เป็น control → เอาต์พุตรวมกลับมาเป็น 1-ต่อ-1 → reversible

แต่บทนี้จบแบบยังไม่จบค่ะ — ดูสแนปช็อต ③ อีกที: scratch qubit ของเรา ไม่ได้กลับไปเป็น ∣0⟩ และมัน entangled กับ a อยู่ ทำให้เกิดปัญหา 2 ข้อ ที่สไลด์ p46 ยกมาเลย:

① เอาไปใช้ต่อไม่ได้
scratch qubit มีจำกัดมากบน QPU จริง ถ้าใช้แล้วทิ้งเลย โปรแกรมใหญ่ๆ จะกิน qubit ไม่ไหว เราอยากได้มันคืนมาเป็น ∣0⟩ เพื่อใช้ซ้ำ
② จะรีเซ็ตก็ไม่ได้
จะ READ แล้วเซ็ตกลับ ∣0⟩ ก็ไม่ได้ เพราะมันพัวพันกับ a อยู่ — อ่านเมื่อไหร่ superposition ของ a พังทันที (ตรงกับข้อ ④ ที่เพิ่งทำไป)

ทางออกของทั้งสองข้อคือเทคนิคชื่อ uncomputing (การย้อนคำนวณ) และสูตรใช้งานจริง ที่เรียกว่า compute → use → uncompute ซึ่งสไลด์บอกว่าเจอบ่อยมากในโปรแกรมควอนตัม — เก็บไว้บทหน้าค่ะ (สไลด์ p46–54)

🧠 ทดสอบความจำก่อนปิด (ตอบในใจก่อนกดดู)
  1. ทำไม abs(a) ถึงทำบน QPU ตรงๆ ไม่ได้?
    เพราะไม่ใช่ 1-ต่อ-1 — อินพุตสองตัว (−3 กับ 3) ให้เอาต์พุตตัวเดียวกัน = ข้อมูลหาย = ไม่ reversible
  2. สไลด์ย้ำว่าปัญหานี้แสดงตัวออกมายังไง?
    ไม่ใช่ error ตอน compile/run — แต่คือหาชุด gate ที่ทำได้ไม่เจอเลย เป็นปัญหาระดับทฤษฎีสารสนเทศ
  3. scratch qubit นิยามว่าอะไร?
    qubit ที่ไม่ได้เก็บอินพุตหรือเอาต์พุตที่เราสนใจ แต่ทำหน้าที่ชั่วคราว ให้ตรรกะที่เชื่อมสองอย่างนั้นเป็นไปได้
  4. gate ตัวแรกของวงจร abs คืออะไร ทำอะไร?
    CNOT จาก a0x4 (บิตเครื่องหมาย) → scratch = XOR บิตเครื่องหมายเข้า scratch
  5. CNOT ตัวนั้น copy บิตเครื่องหมายหรือเปล่า?
    ไม่ใช่ — QPU copy qubit ไม่ได้ (no-cloning) สิ่งที่มันทำคือ entangle scratch กับบิตเครื่องหมาย
  6. เอาต์พุตของวงจรทั้งชุดคืออะไรบ้าง?
    สาย a → abs(a) · สาย scratch → sign(a)
  7. ในผัง circle notation แถวกับคอลัมน์แทนอะไร?
    คอลัมน์ = ค่าของ a (0,1,2,3,−4,−3,−2,−1) · แถว = ค่าของ scratch (0 บน / 1 ล่าง)
  8. ทำไม abs(−4) ถึงยังเป็น −4?
    register 3 บิตเก็บได้แค่ −4 ถึง 3 ไม่มีเลข 4 ให้ไปอยู่ (เหมือน abs(INT_MIN) ในภาษา C)
  9. ปัญหา 2 ข้อที่ scratch ทิ้งไว้คืออะไร?
    ① ไม่กลับเป็น ∣0⟩ จึงใช้ซ้ำไม่ได้ ② รีเซ็ตด้วยการ READ ก็ไม่ได้เพราะ entangled กับ a
