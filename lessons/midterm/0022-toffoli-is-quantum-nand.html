Quantum Programming · Lec 05 · บทที่ 0022 (ปิดคาบ)

Toffoli คือ NAND ของโลกควอนตัม

ตลอด Lec 05 เราเห็น multi-condition CNOT (● หลายจุด + ⊕) โผล่ในทุกวงจร ตั้งแต่ increment ยัน abs(a) — เหมือนมันเป็นอิฐก้อนเดียวที่ใช้ก่อทุกอย่าง บทนี้คือคำอธิบายว่าทำไมถึงเป็นแบบนั้น และเราจะเอามันมาสร้างประตูลอจิกดิจิทัลครบทั้ง 6 ตัว พร้อมกับเจอบิลค่าใช้จ่ายที่ตามมา: scratch qubit

ทำไมต้องเรียนบทนี้ — ในโลกดิจิทัล ทุกอย่างที่คอมพิวเตอร์ทำได้ ย่อยลงไปสุดทางแล้ว เป็น NAND ต่อกันเป็นล้านๆ ตัว · บทนี้ตอบว่าฝั่งควอนตัมอิฐก้อนนั้นคือตัวไหน ซึ่งแปลว่าถ้าเข้าใจ gate ตัวเดียวนี้ เราจะอ่านวงจรลอจิกควอนตัมอะไรก็ได้ออก · และเป็นเรื่องที่ออกสอบได้ตรงๆ เพราะมันคือตารางสัญลักษณ์ 6 ช่อง

ส่วนที่ 1 · gate สารพัดประโยชน์: จาก NAND สู่ Toffoli

1.1 ฝั่งดิจิทัล — NAND ตัวเดียวสร้างได้ทั้งโลก

ในลอจิกดิจิทัล มีข้อเท็จจริงที่สวยมากอยู่ข้อหนึ่ง: มี logic gate พื้นฐานไม่กี่ตัว ที่เอาไปสร้างตัวอื่นทั้งหมดได้ · สุดขั้วคือ NAND — ถ้ามีแต่ NAND อย่างเดียว ก็สร้าง AND, OR, NOT, XOR ได้ครบ แล้วประกอบเป็นฟังก์ชันลอจิกอะไรก็ได้ที่เราต้องการ เราเรียกเกตแบบนี้ว่า universal gate (เกตครบชุด)

และ NAND ในรูปจะมี input กี่ขาก็ได้ — กรณีง่ายที่สุดคือขาเดียว ซึ่งมันจะทำหน้าที่เป็น NOT พอดี:

จำสัญลักษณ์: ทรง AND = ด้านซ้ายตรง ด้านขวาโค้งเป็นครึ่งวงกลม (ทรงตัว D) · วงกลมเล็กที่ขา output (inverting bubble) แปลว่า “แล้ว NOT ทับอีกที” → AND + bubble = NAND เสมอ · ดูครบทั้ง 6 ตัวได้ที่ ชีตสัญลักษณ์วงจร

สไลด์พิมพ์ตก — p56 เขียนว่า “the NAND gates in Figure an have any number of inputs” ที่ถูกคือ “can have” · ความหมายไม่เปลี่ยน แต่ถ้าเจอในข้อสอบให้อ่านว่า “NAND จะมีขาเข้ากี่ขาก็ได้”

1.2 ฝั่งควอนตัม — เกตอเนกประสงค์คือ multi-condition CNOT

ฝั่งควอนตัมก็เล่นท่าเดียวกันเป๊ะ: เริ่มจากเกตอเนกประสงค์ตัวเดียวแล้วต่อยอดเป็นลอจิกทั้งหมด · เกตตัวนั้นคือ multiple-condition CNOT หรือชื่อที่คุ้นกว่าคือ Toffoli gate — และมันเปลี่ยนจำนวน condition ได้เหมือน NAND เปลี่ยนจำนวนขาเข้าได้เลย:

โค้ด QCEngine ของทั้งสามอันนี้ (a = บิต 0x1, b = 0x2, c = 0x4):

// c = ~c
c.write(0);  c.not();  c.read();

// if (b) then c = ~c
qc.write(2, 2|4);  c.cnot(b);  qc.read(2|4);

// if (a and b) then c = ~c
qc.write(1|2);  qc.cnot(4, 1|2);  qc.read(1|2|4);

อ่านโค้ดให้ถูก: qc.cnot(target_mask, condition_mask) — ตัวแรกคือเป้า ตัวหลังคือเงื่อนไข · ดังนั้น qc.cnot(4, 1|2) = พลิกบิต 0x4 (c) เมื่อ 0x1 และ 0x2 (a และ b) เป็น 1 ทั้งคู่ = Toffoli

1.3 ตัวเทียบเท่าฝั่งดิจิทัลแบบเป๊ะๆ

Toffoli ทำงาน “เกือบ” เหมือน NAND — คำว่าเกือบสำคัญมาก เพราะถ้าเขียนตัวเทียบเท่าฝั่งดิจิทัลออกมาจริงๆ จะได้แบบนี้:

c = c XOR (a AND b)

การเดินสายฝั่งขวาตามสไลด์ p58 (ข้อนี้ออกสอบได้ — จำผังไว้): เส้น a และ b วิ่งผ่านออกไปเป็น output ชื่อเดิม โดยมีจุดแยกสัญญาณ ● บนเส้น · สัญญาณที่แยกออกมาจาก a และ b เข้า AND gate → เอาต์พุตของ AND เข้า XOR gate พร้อมกับเส้น c → เอาต์พุตของ XOR คือ c ตัวใหม่

ประโยคทองของบท — NAND เขียนทับ output ทิ้ง ของเดิมหายไปเลย จึงย้อนกลับไม่ได้ · แต่ Toffoli เอาผล a AND b ไป XOR ใส่ c ที่มีอยู่เดิม และ a, b ยังอยู่ครบ → ย้อนกลับได้ (รัน Toffoli ซ้ำอีกรอบก็กลับที่เดิมพอดี)
① เพราะอะไร Toffoli ถึงย้อนกลับได้ แต่ NAND ย้อนกลับไม่ได้?
ถูกต้องค่ะ · เงื่อนไข ย้อนกลับได้ ต้องการสองอย่างพร้อมกัน: ข้อมูลเข้า (a, b) ไม่หาย และการเขียนผลต้องเป็นการ XOR ไม่ใช่การทับ — เพราะ XOR ตัวเดิมซ้ำสองครั้งได้ค่าเดิมคืน
ยังไม่ใช่ค่ะ · ลองนึกว่าจะ “ถอย” ยังไง — ถ้าเขียนทับ ของเดิมหายถาวร ย้อนไม่ได้ · ถ้า a, b หาย ก็คำนวณ a AND b ซ้ำไม่ได้ → คำตอบต้องเป็นข้อที่เก็บ a, b ไว้ครบ + ใช้ XOR
② ตั้งค่าเริ่มต้น a = 1, b = 0, c = 1 แล้วรัน Toffoli หนึ่งครั้ง ได้อะไรออกมา? (ลองแทนในสูตร c = c XOR (a AND b) ก่อนเลือก)
ถูกค่ะ · a AND b = 1 AND 0 = 0 → c = 1 XOR 0 = 1 ไม่ขยับ · เงื่อนไขไม่ครบ Toffoli ก็ไม่ทำอะไร และ a, b ไม่เคยถูกแตะอยู่แล้ว
ยังไม่ใช่ค่ะ · Toffoli พลิก c ก็ต่อเมื่อ control ครบทุกตัวเป็น 1 · ที่นี่ b = 0 → a AND b = 0 → c XOR 0 = c เท่าเดิม · และสาย control ไม่มีวันเปลี่ยนค่า ไม่ว่าจะกรณีไหน

ส่วนที่ 2 · สร้างประตูลอจิกครบ 6 ตัว + บิลค่า scratch

2.1 ตาราง 6 ช่องที่ต้องจำ

มีเกตตัวเดียวนี้ในมือ เราสร้าง QPU เวอร์ชันของฟังก์ชันลอจิกได้เพียบ · สไลด์ p59–60 ให้มาครบ 6 ช่อง · ทุกช่องเรียงสายบนลงล่างเป็น a, b, c เหมือนกันหมด และ a กับ b ออกมาเหมือนเดิมทุกช่อง:

a = (NOT a) · ops="X:0" — ⊕ เดี่ยวไม่มี control บนสาย a · ไม่ใช้ scratch

b = (a XOR b) · ops="CNOT:0,1" — ● บน a, ⊕ บน b · ไม่ใช้ scratch

c = (a AND b) · ops="WRITE:2; CCNOT:0,1,2" — Toffoli ตรงๆ · ต้องมี scratch c = |0⟩

c = (a OR b) · X:0 + X:1; CCNOT:0,1,2; X:0 + X:1 + X:2 — คอลัมน์สุดท้ายมี ⊕ ครบทั้ง 3 สาย

c = (a NAND b) · CCNOT:0,1,2; X:2 — Toffoli แล้วต่อด้วย ⊕ เดี่ยวบนสาย c (ไม่มีเส้นตั้ง)

c = (a NOR b) · X:0 + X:1; CCNOT:0,1,2; X:0 + X:1 — คอลัมน์สุดท้าย ไม่มี ⊕ บนสาย c

2.2 OR กับ NOR ต่างกันแค่ ⊕ ตัวเดียว — เพราะ De Morgan

สองช่องล่างขวาคือช่องที่คนงงบ่อยที่สุด และมันต่างกันแค่ ⊕ หนึ่งตัวบนสาย c · หลักคิดคือกฎ De Morgan:

NOT a AND NOT b  =  NOT (a OR b)
① พลิก a และ b (X:0 + X:1) — ตอนนี้เส้นทั้งสองถือค่า NOT a กับ NOT b
② Toffoli — ได้ c = NOT a AND NOT b ซึ่งตามสูตร De Morgan ก็คือ NOT (a OR b) = NOR พอดี
③ พลิก a และ b กลับคืน — เพราะ a, b ต้องออกมาเหมือนเดิม (ไม่งั้นเอาไปใช้ต่อไม่ได้) · ถึงตรงนี้เราได้ NOR แล้ว
④ ถ้าอยากได้ OR ก็แค่ พลิก c เพิ่มอีกที (X:2 ในคอลัมน์เดียวกัน) — เพราะ NOT ของ NOR คือ OR

เห็นไหมคะว่าทำไมสไลด์วาดคอลัมน์สุดท้ายของ OR เป็น ⊕ สามตัว แต่ของ NOR เป็น ⊕ สองตัว — สองตัวแรกคือ “คืน a, b” (มีเหมือนกันทั้งคู่) ตัวที่สามบนสาย c คือ “พลิกจาก NOR เป็น OR” ที่มีเฉพาะฝั่ง OR

③ ในวงจร c = (a OR b) ถ้าลบ ⊕ ที่อยู่บนสาย c ในคอลัมน์สุดท้ายทิ้ง จะได้วงจรอะไร? (ไล่ตาม 4 สเต็ปข้างบนก่อนตอบ)
ใช่เลยค่ะ · สเต็ป ①–③ ผลิต NOR ออกมาอยู่แล้ว ⊕ บนสาย c คือสเต็ป ④ ที่พลิกให้เป็น OR · ตัดทิ้ง = หยุดที่ NOR · เทียบกับตารางช่อง NOR ในหัวข้อ 2.1 ได้เลย ops เหมือนกันเป๊ะ
ยังไม่ใช่ค่ะ · ⊕ สองตัวบน a และ b ต่างหากที่ทำหน้าที่คืนค่า — ตัวที่อยู่บนสาย c ทำงานคนละอย่าง คือพลิกผลลัพธ์ · Toffoli หลังจากพลิก a, b แล้ว ให้ NOT a AND NOT b = NOR ดังนั้นการตัด ⊕ บน c คือการหยุดไว้ที่ NOR

2.3 กับดักสำคัญ: ป้าย “c = a AND b” จริงแค่ตอน c เริ่มที่ |0⟩

วงจรควอนตัมพวกนี้ทำ c = c XOR f(a,b) เสมอ ไม่มีทางเลือกอื่น เพราะนั่นคือสิ่งที่ Toffoli ทำ · มันจะกลายเป็น c = f(a,b) ตามป้าย ก็ต่อเมื่อ 0 XOR f = f คือ c ต้องเริ่มที่ |0⟩

นี่คือเหตุผลที่ 4 ช่องล่างมี ▷ ที่หัวสาย c — สัญลักษณ์ WRITE ที่เขียนค่า |0⟩ ลงไปก่อน · ช่อง NOT กับ XOR ไม่มี เพราะมันเขียนผลทับสาย input ได้เลย โดยที่ยังย้อนกลับได้ (a หรือ b ตัวเดิมเอากลับคืนได้จากผลลัพธ์) จึงไม่ต้องยืมสายที่สาม
④ ในวงจรช่อง AND ถ้าเผลอให้ c เริ่มที่ |1⟩ แทน |0⟩ ท้ายวงจร c จะเป็นฟังก์ชันอะไร?
เยี่ยมค่ะ · XOR กับ 1 = พลิกบิต ดังนั้น c เริ่มที่ |1⟩ ก็เท่ากับได้ NAND มาฟรีๆ — ซึ่งเป็นวิธีสร้าง NAND ที่ประหยัดกว่าช่อง NAND ในตาราง (ที่ต้องเสีย ⊕ เพิ่มอีกตัว) · จุดนี้ย้ำว่าป้ายบนวงจรขึ้นกับค่าเริ่มต้นของ scratch
ยังไม่ใช่ค่ะ · แทนค่าตรงๆ: c = 1 XOR (a AND b) · ถ้า a AND b = 0 → c = 1 · ถ้า a AND b = 1 → c = 0 · กลับด้านกับ AND ทุกกรณี = NAND · (Toffoli ไม่ได้บังคับค่าเริ่มต้นอะไรเลย คนที่บังคับคือ WRITE)

2.4 บิลที่ตามมา — scratch qubit เป็นของแพง

สังเกตว่าใน 6 ช่องนั้น มี 4 ช่อง (AND, OR, NAND, NOR) ที่ต้องขอ qubit เพิ่มอีกตัว ที่ตั้งต้นด้วย |0⟩ มารับผล · นี่คือ scratch qubit ตัวเดียวกับที่เรารู้จัก ใน บท 0021 เลย · และสไลด์ p60 พูดตรงๆ ว่า:

“หนึ่งในความท้าทายใหญ่ของ quantum computation คือการลดจำนวน scratch qubit ที่ต้องใช้ในการคำนวณหนึ่งๆ” — เพราะบน QPU จริง qubit เป็นทรัพยากรที่แพงมาก และมีจำนวนจำกัดสุดๆ · ลอจิกที่กินสายเยอะ = รันบนเครื่องจริงไม่ได้

ตรงนี้ต่อกับ บท 0021b พอดีเป๊ะ: uncomputing ไม่ได้มีไว้แค่ให้วงจรถูกต้อง — มันคือวิธีคืน scratch qubit กลับเข้าคลังเพื่อเอาไปใช้ซ้ำ · ยิ่งเราคืนเก่ง เราก็ยิ่งคำนวณเรื่องใหญ่ได้ด้วย qubit เท่าเดิม

ลอจิกดิจิทัลทรานซิสเตอร์ราคาเศษสตางค์ ใส่เพิ่มเป็นล้านตัวก็ยังไหว — ไม่มีใครนับ gate
≠
ลอจิกควอนตัมqubit ทุกตัวมีราคา การเพิ่ม scratch หนึ่งตัวคือการตัดสินใจเชิงออกแบบ — ต้องนับทุกตัว

2.5 ปิด Lec 05 — แล้วบทหน้าจะไปไหนต่อ

สไลด์สรุปคาบไว้ 3 ข้อ:

  • ความสามารถทำลอจิกดิจิทัลบน superposition คือแกนกลางของอัลกอริทึม QPU ส่วนใหญ่ — ตลอดคาบนี้เราเห็นวิธีจัดการข้อมูลควอนตัมและทำ conditional operation ภายใน superposition
  • แต่ทำได้อย่างเดียวยังใช้ประโยชน์ได้จำกัด ถ้าดึงข้อมูลออกมาไม่เป็น — ถ้าเรา READ superposition ของคำตอบทั้งหมด เราจะได้คำตอบเดียวแบบสุ่ม เหมือนเดิม
  • บทหน้าคือเครื่องมือที่แก้ปัญหานั้น: QPU primitive ที่ดึงผลลัพธ์ออกจาก superposition ได้อย่างเชื่อถือได้ ชื่อ amplitude amplification (การขยายแอมพลิจูด)
เชื่อมกับสิ่งที่เพิ่งเรียน — จำวงจรปิดท้ายบท 0021b ได้ไหมคะ ที่ phase(180) if abs(a)==1 — คำตอบถูกซ่อนไว้ในเฟสซึ่ง READ ไม่เห็น · amplitude amplification คือเครื่องมือที่แปลงเฟสนั้นให้กลายเป็นความน่าจะเป็นที่วัดได้ · นั่นแปลว่าทุกอย่างที่เราสร้างมาทั้งคาบนี้กำลังจะได้ใช้งานจริงในบทหน้า
ทบทวนความจำ 10 ข้อ (ลองตอบในใจก่อนกดดู)
  1. universal gate ของลอจิกดิจิทัลคือตัวไหน — และมันมีขาเข้าได้กี่ขา?
    NAND · กี่ขาก็ได้ · ขาเดียว = NOT
  2. universal gate ฝั่งควอนตัมชื่ออะไร?
    multiple-condition CNOT = Toffoli gate · เปลี่ยนจำนวน condition ได้
  3. สมการที่ Toffoli ทำจริงๆ คือ?
    c = c XOR (a AND b)
  4. Toffoli ต่างจาก NAND ตรงไหน?
    NAND เขียนทับ output ทิ้ง · Toffoli XOR ใส่ c เดิม + เก็บ a, b ไว้ → ย้อนกลับได้
  5. ผังลอจิกเทียบเท่าของ Toffoli เดินสายยังไง?
    a, b แยกจุด ● เข้า AND → ผล AND เข้า XOR พร้อม c → ได้ c ใหม่ · a, b ผ่านออกไปเหมือนเดิม
  6. ในตาราง 6 ช่อง ช่องไหนบ้างที่ไม่ต้องใช้ scratch qubit — เพราะอะไร?
    NOT กับ XOR · เพราะเขียนผลทับสาย input ได้เลยโดยยังย้อนกลับได้
  7. ops ของช่อง OR คืออะไร?
    X:0 + X:1; CCNOT:0,1,2; X:0 + X:1 + X:2 (คอลัมน์สุดท้าย ⊕ ครบ 3 สาย)
  8. ops ของช่อง NOR ต่างจาก OR ตรงไหน?
    คอลัมน์สุดท้ายมีแค่ X:0 + X:1 — ไม่มี ⊕ บนสาย c
  9. ทำไม OR/NOR ต้องพลิก a, b ก่อนแล้วพลิกกลับ?
    De Morgan: NOT a AND NOT b = NOT(a OR b) · พลิกกลับเพื่อคืนค่า a, b
  10. สไลด์บอกว่าความท้าทายใหญ่ของ quantum computation คืออะไร?
    การลดจำนวน scratch qubit ที่ต้องใช้ — qubit เป็นทรัพยากรที่แพงและมีจำกัด

สรุปบทนี้

  • ดิจิทัลมี NAND เป็นเกตครบชุด · ควอนตัมมี multi-condition CNOT (Toffoli) — ทั้งคู่ขยายจำนวนขาเข้า/เงื่อนไขได้ เหมือนกัน
  • Toffoli ทำ c = c XOR (a AND b) — คือ AND ที่ตามด้วย XOR ไม่ใช่การเขียนทับ นั่นแหละที่ทำให้มันย้อนกลับได้ ต่างจาก NAND
  • ประกอบ Toffoli กับ ⊕ ไม่กี่ตัว ได้ประตูลอจิกครบ 6 ตัว: NOT · XOR · AND · OR · NAND · NOR → ท่องตารางนี้ให้ได้ ออกสอบแน่
  • ป้าย “c = a AND b” จริงเฉพาะเมื่อ c เริ่มที่ |0⟩ — เพราะวงจรทำ c = c XOR f(a,b) เสมอ
  • 4 ใน 6 ช่องต้องเสีย scratch qubit → การลดจำนวน scratch คือโจทย์ใหญ่ของวงการ และ uncomputing คือเครื่องมือหลักที่ใช้แก้
  • จบ Lec 05 · บทหน้า Lec 06 = amplitude amplification — วิธีดึงคำตอบออกจาก superposition ให้ได้จริง
