Quantum Programming · Lec 05 · บทที่ 0019

บวกควอนตัมสองตัว (a += b) และเลขติดลบ

บท 0018 จบลงที่ข้อจำกัดหนึ่ง — เราบวกได้แค่ ค่าดิจิทัลคงที่ ที่เรารู้ล่วงหน้า และเปลี่ยนตัวเลขทีก็ต้องรื้อวงจรใหม่ทุกที บทนี้เราจะปลดล็อกไปสู่ “บวก quantum register สองตัวเข้าด้วยกัน” — วงจรเดียว ใช้ได้กับทุกค่าของ input · แล้วต่อด้วย เลขติดลบ และ การกลับเครื่องหมาย ปิดท้ายด้วยของยาก a += b*b ค่ะ

บทนี้จับ 4 อย่าง
① ทำไม c = a + b แบบที่ CPU ทำ ผิดกติกา QPU ทั้งสองข้อ — และทางออกคือ +=
② วงจร a += b = increment chain ของบท 0018 ที่พ่วง control จากบิตของ b ทำซ้ำ 1 รอบต่อ 1 บิต
③ two's complement — วิธีใส่เลขติดลบลง register โดยไม่ต้องแก้วงจรเลขคณิตเลยสักตัว
④ a = -a (พลิกบิตแล้ว +1) และ a += b*b ที่คูณแบบย้อนกลับได้

ส่วนที่ 1 — บวก quantum integer สองตัว

ปูพื้นก่อน: ทำไมสิ่งที่ CPU ทำทุกวัน ถึงทำบน QPU ไม่ได้

บน CPU เวลาบวกเลข เราเขียนกันจนชิน:

c = a + b

อ่าน a · อ่าน b · บวก · เขียนผลลง c จบ · แต่พอย้ายมาอยู่บน QPU บรรทัดเดียวนี้ละเมิดกติกาทั้งสองข้อที่เราวางไว้ในบท 0017 พร้อมกันเลยค่ะ

① ละเมิด reversibility
ของเดิมที่อยู่ใน register c ถูกทับหายไป เมื่อดูผลลัพธ์ปลายทางแล้ว เราย้อนกลับไม่ได้ว่า c เคยเป็นอะไร — operation ที่ไม่ใช่ READ ทุกตัวต้องย้อนกลับได้ ข้อนี้จึงตกทันที
② ละเมิด no-copying
สมมติทำได้จริง เราจะแอบคำนวณ b = c − a ต่อได้ ผลคือได้ สำเนาของ superposition ใน a สองชุด — ซึ่งทฤษฎี no-cloning บอกว่าเป็นไปไม่ได้
ทางออกของสไลด์: เลิกใช้ + ที่ต้องมี register ที่สาม แล้วหันไปสร้าง operator += แทน — บวกเลขตัวหนึ่งลงไปบนอีกตัวโดยตรง · a กลายเป็น a+b ส่วน b ยังอยู่ครบไม่ขยับ (slide 24)

+= ผ่านกติกาสบายๆ ทั้งสองข้อ: ย้อนกลับได้ (ก็แค่ a -= b โดยที่ b ยังอยู่ให้ลบ) และไม่มีการคัดลอกอะไรเกิดขึ้นเลย เพราะข้อมูลเก่าของ a ไม่ได้ถูกทับทิ้ง แต่ถูกแปลงเป็นค่าใหม่

วงจร a += b — increment chain ที่มี b เป็นเจ้านาย

เคล็ดลับของวงจรนี้เรียบง่ายอย่างน่าตกใจ: เอา increment chain ของบท 0018 มาทั้งดุ้น แล้วพ่วง control เพิ่มอีกจุดหนึ่งจากบิตของ b เข้าไปในทุก gate

บท 0018: a.add(1) increment chain วิ่งเสมอ — บวก 1 ทุกครั้งที่รันวงจร

บทนี้: a.add(b) increment chain วิ่งก็ต่อเมื่อบิตของ b เป็น 1 — ตัว b เองเป็นคนสั่ง

b มีกี่บิต ก็ทำ increment chain แบบมีเงื่อนไขซ้ำเท่านั้นรอบ · ตัวอย่างจากสไลด์คือ a เป็น qunibble 4 qubit และ b เป็น 2 qubit → จึงมี 2 รอบ:

อ่านทีละรอบนะคะ — ให้มองกล่อง a += b เป็นสองก้อน:

รอบ 1 4 คอลัมน์แรก = “ถ้า b·0x1 เป็น 1 ให้ a += 1”
คือ increment chain ตัวเดิมเป๊ะ (0x8 → 0x4 → 0x2 → 0x1 ไล่จาก control เยอะไปน้อย) แต่ทุก gate มี ● ที่สาย b·0x1 เพิ่มเข้ามา · b·0x1 เป็น 0 เมื่อไหร่ ทั้งก้อนนี้ไม่ทำอะไรเลย
รอบ 2 3 คอลัมน์หลัง = “ถ้า b·0x2 เป็น 1 ให้ a += 2”
chain เดิมอีกครั้ง แต่คราวนี้ เริ่มที่บิต a·0x2 แทนที่จะเป็น a·0x1 — เพราะ b·0x2 มีน้ำหนัก 2 การบวก 2 ก็คือการบวก 1 ที่ตำแหน่งบิตสูงขึ้นหนึ่งขั้นนั่นเอง (chain จึงสั้นลงหนึ่ง gate)
b·0x1 สั่งบวก 1 · b·0x2 สั่งบวก 2 · รวมกันได้ b พอดี ทุกค่าที่ b เป็นไปได้ — และเพราะเงื่อนไขทั้งหมดอ่านมาจากสาย ไม่ใช่จากตัวเลขที่เรารู้ล่วงหน้า วงจรนี้จึงไม่ต้องเปลี่ยน gate เลยเมื่อ input เปลี่ยน — ต่างจาก add(12) ของบทที่แล้วอย่างสิ้นเชิง (slide 25)

เปลี่ยนค่า inputต้องรื้อวงจรใหม่ (12 ใช้ 2 gate, 7 ใช้อีกแบบ)วงจรเดิม ไม่ต้องแตะอะไรเลย
จำนวน gateขึ้นกับว่าเลขนั้นมีบิต 1 กี่ตัวคงที่ = chain ยาว ๆ 1 ชุดต่อ 1 บิตของ b

worked example — วงจรเดียว บวกสี่โจทย์พร้อมกัน

กล่อง prepare ในวงจรข้างบนเตรียม input ไว้แบบนี้ (มันมีไว้ป้อนค่าทดสอบเฉยๆ ไม่ใช่ส่วนหนึ่งของ operation นะคะ):

a = ∣1⟩ + ei45°∣5⟩√2  ·  b = ∣1⟩ + ei90°∣3⟩√2

a มี 2 กิ่ง · b มี 2 กิ่ง → รวมกันเป็น 4 กิ่ง ที่วงจรต้องทำงานให้ครบในการรันครั้งเดียว:

กิ่งa เดิมba หลัง a += bเฟสของกิ่ง
①∣1⟩∣1⟩∣2⟩0°
②∣1⟩∣3⟩∣4⟩90°
③∣5⟩∣1⟩∣6⟩45°
④∣5⟩∣3⟩∣8⟩135°

เฟสของแต่ละกิ่ง = เฟสของกิ่ง a บวก เฟสของกิ่ง b (เพราะแอมพลิจูดคูณกัน เฟสจึงบวกกัน — หลักเดิมจากบท 0003) · ส่วน b ไม่ขยับเลย ตลอดวงจร ทำหน้าที่เป็น control อย่างเดียว

นี่คือหัวใจของทั้งคาบเลยค่ะ — วงจรเดียว 7 คอลัมน์ ทำการบวกสี่โจทย์พร้อมกัน และถ้า b เป็น register 8 qubit เต็มๆ ที่อยู่ใน superposition ครบทุกค่า วงจรเดิมนี้ก็จะบวกทั้ง 256 โจทย์พร้อมกันโดยไม่เพิ่ม gate สักตัว

แล้ว a -= b ล่ะ?

เหมือนบทที่แล้วเป๊ะ — รัน gate ชุดเดิมย้อนลำดับ (⑦⑥⑤④③②①) จบ ไม่ต้องออกแบบวงจรใหม่ เพราะทุก gate ในนี้เป็น NOT แบบมีเงื่อนไข ซึ่งเป็น inverse ของตัวเอง (slide 26)

// บวก register b เข้าไปใน register a
a.add(b);        // a += b
a.subtract(b);   // a -= b  (วงจรเดิม เรียงกลับหลัง)
quiz ① ในวงจร a += b ข้างบน รอบที่สอง (ที่มี b·0x2 เป็น control) เริ่มบวกที่บิต a·0x2 ไม่ใช่ a·0x1 — เพราะอะไร?
ถูกต้องค่ะ · บิตของ b บอก “น้ำหนัก” ว่าต้องบวกเท่าไหร่ — น้ำหนัก 1 → chain เริ่มที่ 0x1 · น้ำหนัก 2 → chain เริ่มที่ 0x2 (สั้นลง 1 gate) · ถ้า b มีบิต 0x4 ด้วย รอบที่สามจะเริ่มที่ a·0x4 และเหลือแค่ 2 gate
ยังไม่ใช่ค่ะ · ลองคิดแบบนี้: บวก 2 = บวก 1 สองครั้ง = บวก 1 ที่ตำแหน่งบิตถัดขึ้นไป · จุดเริ่มของ chain จึงเลื่อนตามน้ำหนักของบิต b ที่เป็น control อยู่ ไม่เกี่ยวกับว่าสายไหนเคยถูกใช้ไปแล้ว

ส่วนที่ 2 — เลขติดลบ, negate และ a += b*b

two's complement — ใส่เลขลบโดยไม่แก้วงจรสักตัว

ถึงตรงนี้เราบวกลบได้แล้ว แต่ยังเป็นจำนวนเต็มบวกล้วนๆ · คำถามคือ จะเก็บ −3 ลง register ยังไง? สไลด์ตอบว่า: ใช้วิธีเดียวกับที่ CPU และภาษาโปรแกรมสมัยใหม่ ทุกตัวใช้กันอยู่แล้ว คือ two's complement (ทูส์คอมพลีเมนต์ / เลขเติมเต็มฐานสอง)

หลักการ: register n บิตเก็บค่าได้ 2n แบบ → ยกครึ่งแรกให้จำนวนบวก ครึ่งหลังให้จำนวนลบ · register 3 บิตจึงแทน −4, −3, −2, −1, 0, +1, +2, +3 ได้พอดี:

ค่า0123−4−3−2−1
เลขฐานสอง000001010011100101110111

Two's complement for binary representation of negative integers (slide 28)

ตอนแรกที่เห็นตารางนี้อาจรู้สึกว่าจับคู่กันมั่วๆ ทำไม 111 ถึงเป็น −1 ไม่ใช่ −7? แต่การเลือกแบบนี้มีข้อดี 2 อย่างที่สำคัญมากกับเราตอนนี้:

① เลขคณิตเดิมใช้ได้ทันที
วงจร increment / a += b ที่เราสร้างมาไม่ต้องแก้อะไรเลยสักบิต · ลองดู: −1 คือ 111 · บวก 1 → ทดจนล้นหมด เหลือ 000 = 0 ✓ ถูกต้องเป๊ะ · การ wrap ที่เราเคยมองว่าเป็น “bug ของ overflow” กลายเป็นสิ่งที่ทำให้เลขลบทำงานได้
② บิตสูงสุดกลายเป็นบิตเครื่องหมาย
สังเกตแถวล่าง: 000–011 (บวกและศูนย์) บิตซ้ายสุดเป็น 0 เสมอ · 100–111 (ลบ) บิตซ้ายสุดเป็น 1 เสมอ · sign bit (บิตเครื่องหมาย) จึงมาฟรีๆ ไม่ต้องเก็บแยก — จำจุดนี้ไว้ให้ดี บทหน้าเราจะเอามันไปใช้ทำของสนุก
ข้อควรระวังจากสไลด์: two's complement เป็นแค่ ข้อตกลงในการตีความ ไม่ใช่สิ่งที่ฝังอยู่ในตัว qubit · register ที่อ่านได้ 111 จะแปลว่า 7 หรือ −1 ขึ้นกับว่าเราตกลงกันไว้แบบไหน · จึงต้องรู้ตัวตลอดว่าตอนนี้เข้ารหัสแบบไหนอยู่ ไม่งั้นอ่านผลลัพธ์ผิดความหมายทั้งหมด (slide 29)

วงจร a = -a — พลิกทุกบิตแล้วบวกหนึ่ง

กฎการกลับเครื่องหมายใน two's complement มีแค่สองขั้น: พลิกทุกบิต แล้วบวก 1 · แปลเป็นวงจรควอนตัมได้ตรงๆ แบบนี้เลยค่ะ — และจะเห็นว่ามันคือ increment chain ตัวเดิมอีกแล้ว:

① a = 3 → เลขฐานสอง (0x8→0x1) = 0011
② พลิกทุกบิต (NOT พร้อมกัน 4 สาย) → 1100
③ +1 ด้วย increment chain → 1101
④ อ่านแบบ two's complement 4 บิต: 1101 = −3 ✓

ลองกับ 0 ดูก็ได้ค่ะ: 0000 → พลิก → 1111 → +1 → ทดจนล้น → 0000 = 0 ✓ (−0 ก็คือ 0 นั่นแหละ ไม่มีปัญหา)

quiz ② เอาวงจร a = -a ไปใช้กับ register 3 บิต ที่เก็บค่า 100 (= −4 ในตาราง) — ผลลัพธ์คืออะไร?
ถูกต้องค่ะ · ไล่ดู: 100 → พลิก → 011 → +1 → 100 กลับมาที่เดิม! เพราะช่วง 3 บิตคือ −4 ถึง +3 · +4 ไม่มีที่อยู่ ค่า −4 จึงเป็นจุดที่ negate แล้วค้าง — เป็นข้อจำกัดเดียวกับ INT_MIN ในภาษา C/Java ทุกภาษาเลย
ลองไล่มือดูนะคะ: 100 พลิกทุกบิตได้ 011 แล้วบวก 1 ได้ 100 — กลับมาที่เดิมเป๊ะ · เหตุผลคือ 3 บิตแทนได้แค่ −4 ถึง +3 ดังนั้น +4 ไม่มีรหัสให้อยู่

ของยากปิดท้าย: a += b*b

ไม่ใช่ว่าเลขคณิตทุกอย่างจะยัดลงกติกา QPU ได้ง่ายๆ · การคูณเป็นตัวที่ทำแบบย้อนกลับได้ยาก ลองดูตัวอย่างชัดๆ:

ทำไม b = b*b ถึงเป็นไปไม่ได้เลย
ถ้า b เป็น 3 → ได้ 9 · ถ้า b เป็น −3 → ก็ได้ 9 เหมือนกัน · เมื่อผลลัพธ์คือ 9 เราไม่มีทางรู้ว่า b เดิมเป็น 3 หรือ −3 — sign bit หายไปตลอดกาล · ไม่ใช่ว่า “หา gate ที่เก่งพอไม่เจอ” แต่มันเป็นไปไม่ได้ในเชิงทฤษฎีสารสนเทศ เพราะสองอินพุตแมปไปที่เอาต์พุตเดียวกัน (slide 32)

แต่ a += b*b ทำได้สบายมาก — เพราะ b ยังอยู่ครบไม่ถูกแตะ การย้อนกลับก็แค่ a -= b*b เท่านั้นเอง · นี่เป็นแพตเทิร์นที่จะเจอซ้ำๆ ตลอดทั้งวิชา: อะไรที่ทำ “ทับตัวเอง” ไม่ได้ ให้เปลี่ยนไป “บวกสะสมลง register อื่น” แทน

วิธีสร้างวงจร ใช้เลขคณิตประถมค่ะ · b เป็น 2 บิต เขียนได้ว่า b = b₀ + 2b₁ ดังนั้น:

b² = (b₀ + 2b₁)² = b₀² + 4b₀b₁ + 4b₁² = b₀ + 4·b₀b₁ + 4·b₁

ที่ b₀² กลายเป็น b₀ ได้เพราะบิตมีค่าแค่ 0 หรือ 1 → ยกกำลังสองแล้วได้ตัวเดิมเสมอ (0²=0, 1²=1)

สามพจน์ทางขวาบอกวงจรมาให้เสร็จสรรพ — บวก 1 ถ้า b₀ · บวก 4 ถ้า b₀ และ b₁ · บวก 4 ถ้า b₁ แต่ละพจน์ก็คือ increment chain แบบมีเงื่อนไขอีกนั่นแหละ (พจน์ +4 ตัวกลาง สไลด์ทำเป็น “+2 สองรอบ” ซึ่งได้ผลเท่ากัน):

// a += b * b
a.addSquared(b);

ลองตรวจกับ b = 3 (b₀=1, b₁=1): บวก 1 + 2 + 2 + 4 = 9 = 3² ✓ · ลองกับ b = 2 (b₀=0, b₁=1): กล่องแรกสามกล่องไม่ทำงานเลย เหลือแค่ +4 = 2² ✓

quiz ③ รันวงจร a += (b*b) ข้างบนโดยที่ a = ∣1⟩ และ b = ∣3⟩ (a เป็น qunibble 4 บิต) — จบแล้ว a เป็นเท่าไหร่?
ถูกต้องค่ะ · b=3 ทำให้ b₀=1 และ b₁=1 → ทั้งสี่กล่องทำงานหมด = +1+2+2+4 = 9 · a จึงเป็น 1+9 = 10 · ย้ำจุดสำคัญ: มันคือ += ค่าเดิมของ a ถูกบวกเพิ่ม ไม่ได้ถูกทับ — ถ้าทับเมื่อไหร่คือละเมิด reversibility ทันที
ยังไม่ใช่ค่ะ · จำสองอย่าง: (๑) วงจรนี้บวก b² ไม่ใช่ b → b=3 จึงบวก 9 · (๒) มันคือ += ไม่ใช่ = → ค่าเดิม 1 ยังอยู่ ผลจึงเป็น 1 + 9 = 10
ทดสอบความจำก่อนปิดบท — ตอบในใจให้ครบก่อนกดดูคำตอบนะคะ
  1. c = a + b ละเมิดกติกา QPU ข้อไหนบ้าง และละเมิดยังไง?
  2. ทำไม += ถึงรอด ทั้งที่ + ไม่รอด?
  3. วงจร a += b สร้างจากอะไร และทำซ้ำกี่รอบ?
  4. ถ้า b เป็น register 3 บิต รอบที่สามจะเริ่มบวกที่บิตไหนของ a?
  5. ข้อได้เปรียบใหญ่ที่สุดของ a.add(b) เหนือ a.add(12) คืออะไร?
  6. ใน two's complement 3 บิต 101 คือค่าอะไร และบิตไหนบอกเครื่องหมาย?
  7. วงจร a = -a มีกี่ขั้น และแต่ละขั้นทำอะไร?
  8. ทำไม b = b*b ทำไม่ได้ แต่ a += b*b ทำได้?

คำตอบย่อ ① reversibility (ทับของเดิมใน c) + no-copying (แอบทำ b = c−a ได้ = สำเนา a สองชุด) ② เพราะ b ยังอยู่ครบ ย้อนด้วย a -= b ได้ และไม่มีการทับข้อมูล ③ increment chain ของบท 0018 ที่พ่วง ● จากบิตของ b เข้าไปทุก gate · ทำ 1 รอบต่อ 1 บิตของ b ④ a·0x4 (ตามน้ำหนักของบิต b·0x4) และ chain รอบนั้นจะเหลือแค่ 2 gate ⑤ วงจรเดิมใช้ได้กับทุกค่าของ input โดยไม่ต้องเปลี่ยน gate — และ input เป็น superposition ได้ ⑥ −3 · บิตสูงสุด (ซ้ายสุด) เป็น sign bit ⑦ 2 ขั้น — พลิกทุกบิตพร้อมกัน แล้ว +1 ด้วย increment chain ⑧ b และ −b ยกกำลังสองได้ค่าเดียวกัน → เสีย sign bit ย้อนไม่ได้ · แต่ += ไม่ทับ b จึงย้อนด้วย a -= b*b ได้

สรุปบทนี้
① c = a + b ผิดกติกาทั้งสองข้อ → เราจึงมี += แทน
② a += b = increment chain เดิม + control จากบิตของ b · 1 รอบต่อ 1 บิต · วงจรเดียวใช้ได้กับทุก input รวมทั้ง superposition
③ two's complement ให้เลขลบมาฟรีๆ โดยไม่ต้องแก้วงจรเลขคณิตเลย และแถม sign bit มาให้ที่บิตสูงสุด
④ a = -a = พลิกทุกบิต + increment · a += b*b ทำได้เพราะไม่ทับ b (ต่างจาก b = b*b ที่เป็นไปไม่ได้)
บทหน้า (0020): เอา sign bit ที่เพิ่งเจอ ไปทำ เงื่อนไข if แบบควอนตัม — logic ที่ทั้งรันและไม่รันพร้อมกัน แล้วเก็บคำตอบไว้ใน เฟส
