Quantum Programming · Lec 03 · บทที่ 0012 (ปิดคอร์ส Lec 03)

สร้าง conditional op เองได้ทุกตัว + capstone: remote-controlled randomness

ตลอด Lec 03 เราได้ conditional gate มาเป็นตัวๆ (CNOT, CPHASE, CCNOT…) แต่ถ้า QPU ที่เราใช้ ไม่มี gate ที่ต้องการล่ะ? บทนี้เรียนหลักการ “ประกอบ conditional op เองจากของที่มี” แล้วปิดท้ายด้วยโปรแกรมจริง — remote-controlled randomness ที่เอา entanglement มาโชว์ว่าทำไมมัน “เปลี่ยนสถานะข้ามระยะทางได้ทันที แต่ส่งข้อมูลเร็วกว่าแสงไม่ได้”

บทนี้จับ 3 อย่าง

① หลักการทั่วไป: แตก single-qubit op เป็นสเต็ป แล้วใช้ CNOT “ยกเลิกแบบมีเงื่อนไข” · ② ตัวอย่างเป๊ะ: ประกอบ CPHASE จาก 2 CNOT + 3 PHASE (ไล่ทีละ input พิสูจน์ว่าเวิร์ก) · ③ capstone: remote-controlled randomness — entanglement + ทำไมส่งข้อมูลเร็วกว่าแสงไม่ได้

ส่วนที่ 1 · ประกอบ conditional op เอง

สร้าง CPHASE จาก CNOT + PHASE

1. ปัญหา: ถ้า QPU ไม่มี gate ที่เราต้องการ?

ในสไลด์ (หน้า 105) ตั้งคำถามน่ารักว่า — มี CNOT, CPHASE แล้ว มี “CHAD” (conditional HAD) หรือ “CRNOT” (conditional RNOT) ด้วยไหม? คำตอบคือ เราสร้างเองได้ทุกตัว แม้ QPU จริง จะไม่มี gate เวอร์ชัน conditional ของ op นั้นในชุดคำสั่ง

หลักการทั่วไป (หน้า 105)

แตก single-qubit op ออกเป็น สเต็ปย่อยๆ โดยจัดให้สามารถใช้ CNOT “ยกเลิก (undo)” op นั้นแบบมีเงื่อนไข ได้ — ผลลัพธ์คือเราเลือกได้ว่าจะให้ op ทำงานหรือไม่ ขึ้นกับ qubit เงื่อนไข

ฟังลอยๆ อาจงง แต่พอดูตัวอย่างจริงจะเข้าใจทันที สไลด์ยกเคสที่เจอบ่อยมากกับ QPU ปัจจุบัน: มี CNOT, CZ, PHASE แต่ไม่มี CPHASE — เราจะประกอบ CPHASE ขึ้นเองจาก 3 อย่างนี้

2. กุญแจสองดอกที่ทำให้ทริคนี้เวิร์ก

① PHASE แตกเป็นครึ่งได้ + ถอยกลับได้
PHASE(90) = PHASE(45)·PHASE(45) และ PHASE(45)·PHASE(−45) = ไม่ทำอะไรเลย (หมุนไปแล้วหมุนกลับ = ศูนย์)
② PHASE ไม่มีผลกับ |0⟩
จำจากบท 0006 — PHASE หมุนเฉพาะ amplitude ของสถานะ |1⟩ เท่านั้น ถ้า qubit เป็น |0⟩ อยู่ PHASE จะเฉยๆ ไม่เกิดอะไร

ไอเดียคือ: เอา CNOT มา “พลิก target ตอนที่ control = 1” คั่นกลางระหว่าง PHASE ครึ่งแรก กับครึ่งหลัง เพื่อให้สองครึ่งนั้น หักล้างกันพอดี เมื่อ control = 0 แต่ ไม่หักล้าง เมื่อ control = 1 → กลายเป็นเงื่อนไขขึ้นมา

3. วงจรจริง (หน้า 107–108)

ประกอบเอง: PHASE(45) บน b → CNOT → PHASE(−45) บน b → CNOT → PHASE(45) บน a
= CPHASE(90) — หมุน phase เฉพาะสถานะ |11⟩ เท่านั้น
var theta = 90;
qc.reset(2); qc.write(0); qc.hadamard();
// ประกอบ CPHASE ด้วย 2 CNOT + 3 PHASE
qc.phase( theta / 2, 0x2);   // PHASE(45) บน b
qc.cnot(0x2, 0x1);           // CNOT: a คุม, พลิก b
qc.phase(-theta / 2, 0x2);   // PHASE(-45) บน b
qc.cnot(0x2, 0x1);           // CNOT: a คุม, พลิก b
qc.phase( theta / 2, 0x1);   // PHASE(45) บน a
// ได้ผลเท่ากับ CPHASE(90) เป๊ะ:
qc.phase(theta, 0x1, 0x2);
อ่านโค้ด QCEngine

qc.cnot(0x2, 0x1) = target คือ 0x2 (b), condition/control คือ 0x1 (a) → “ถ้า a=1 ค่อยพลิก b” · qc.phase(θ, 0x1, 0x2) ที่มี 2 mask = CPHASE เต็มตัว (ไว้เทียบผล)

4. ไล่พิสูจน์ทีละ input — ทำไมมันเวิร์ก

ไล่สถานะฐานทั้ง 4 แบบ (a,b) ผ่าน 5 สเต็ป จำไว้ว่า PHASE เฉยกับ |0⟩ และ CNOT พลิก b เฉพาะตอน a=1:

input (a,b)P(45) บน bCNOTP(−45) บน bCNOTP(45) บน aphase รวม
0,0b=0 เฉยa=0 ไม่พลิกb=0 เฉยไม่พลิกa=0 เฉย0°
0,1+45°a=0 ไม่พลิก−45° (b ยัง=1)ไม่พลิกa=0 เฉย0°
1,0b=0 เฉยa=1 พลิก b→1−45° (b=1 แล้ว)พลิก b→0+45°0°
1,1+45°a=1 พลิก b→0b=0 เฉยพลิก b→1+45°+90°

เห็นความสวยไหมคะ — มีแค่ input (1,1) เท่านั้นที่ phase ไม่หักล้าง (ได้ +90°) ตรงกับนิยาม CPHASE เป๊ะ: หมุน phase เฉพาะเมื่อทั้งสอง qubit เป็น 1

ข้อควรระวัง (หน้า 110)

ตัวอย่างนี้ประกอบ CPHASE ได้ง่ายเพราะ PHASE สลับที่กับ CNOT ได้สวยๆ การประกอบ conditional ของ op ทั่วไป (เช่น CHAD, CRNOT) ใช้หลักการเดียวกัน — “แตกเป็นสเต็ป + ใช้ CNOT ยกเลิกแบบมีเงื่อนไข” — แต่รายละเอียดคณิตซับซ้อนกว่านี้เล็กน้อย ไม่ต้องจำสูตร จำแค่หลักการ พอค่ะ

ลองเอง: ไล่ input (a=1, b=0) หรือ |01⟩ ผ่านวงจร 5 สเต็ปข้างบน phase สุทธิที่ได้คือเท่าไร?
ใช่เลยค่ะ! (1,0): CNOT พลิก b เป็น 1 → PHASE(−45) เลยโดน b → พอ PHASE(+45) บน a ตัวสุดท้าย +45 กับ −45 หักล้าง = 0° · CPHASE จะแตะเฉพาะ |11⟩ เท่านั้น
ลองไล่ตามตารางแถว “1,0”: b=0 ตอนแรก PHASE เฉย → CNOT พลิก b→1 → PHASE(−45) โดน b (=−45°) → CNOT พลิกกลับ → PHASE(+45) บน a (=+45°) → รวม −45+45 = 0°
ส่วนที่ 2 · capstone

Remote-controlled randomness

5. โจทย์: “รีโมตสุ่ม” ข้ามระยะทาง (หน้า 112)

เราจะเขียนโปรแกรมสร้าง 2 qubit (a และ b) ที่พัวพันกัน (entangled) โดยมีสมบัติพิลึกว่า — อ่าน qubit ตัวไหนก็ได้ ได้ 50/50 แต่ผลที่ออก เปลี่ยนความน่าจะเป็นของอีกตัวทันที ไม่ว่าจะอยู่ห่างกันแค่ไหน:

กติกาของรีโมต (หน้า 112)

อ่านตัวหนึ่งได้ 0 → อีกตัวมีโอกาสอ่านได้ 1 แค่ 15% · อ่านได้ 1 → อีกตัวมีโอกาสอ่านได้ 1 ถึง 85%

6. โปรแกรม (หน้า 113)

a.had() · b.had() · b.phase(45) · b.had() · b.cnot(a) · อ่านทั้งคู่
qc.reset(2);
var a = qint.new(1, 'a');
var b = qint.new(1, 'b'); qc.write(0);
a.had();          // prob ของ a = 50%
b.had();
b.phase(45);
b.had();          // prob ของ b = 15%
b.cnot(a);        // พัวพัน a กับ b เข้าด้วยกัน
var a_result = a.read();
var b_result = b.read();
ทำไม b ถึงได้ prob 15%

ท่า HAD → PHASE(45) → HAD บน b: prob ที่ b เป็น 1 = |1 − ei45°|² ⁄ 4 = (2 − 2cos45°)/4 ≈ 0.146 = 15% · ถ้าไม่มี PHASE(45) คั่น (HAD→HAD เฉยๆ) จะกลับเป็น |0⟩ 100% — เจ้า PHASE(45) คือตัวเอียงให้ได้ 15% พอดี

7. ก่อน READ: สถานะพัวพัน (หน้า 114)

หลัง b.cnot(a) เราได้สถานะพัวพันที่ amplitude ไปกองที่ |00⟩ กับ |11⟩ เป็นหลัก (a เป็น bit ล่าง = 0x1):

ยังไม่อ่าน → a เป็น 50/50, b ก็ 50/50 (แยกกันดูเหมือนสุ่มธรรมดา) แต่มันผูกกันอยู่

8. READ a แล้วเกิดอะไรกับ b (หน้า 115–116)

ถ้าอ่าน a ได้ 0 (โอกาส 50%)
เหลือเฉพาะวงที่ a=0 คือ |00⟩ กับ |10⟩ แล้ว renormalize:
→ b อ่านได้ 1 แค่ 15%
ถ้าอ่าน a ได้ 1 (โอกาส 50%)
เหลือเฉพาะวงที่ a=1 คือ |01⟩ กับ |11⟩ แล้ว renormalize:
→ b อ่านได้ 1 ถึง 85%

เห็น “รีโมต” ทำงานแล้วค่ะ — แค่อ่าน a ผลของ b ก็เปลี่ยนความน่าจะเป็นทันที (15% ↔ 85%)

🔴 จุดสไลด์ผิด (จุดที่ 5 ของคอร์ส) — ตัวเลข prose หน้า 115/116

ตัว prose หน้า 115/116 เขียนว่า b เป็น 70%/30% (และ 30%/70%) — ผิด เพราะขัดกับ (ก) โจทย์หน้า 112, (ข) คอมเมนต์โค้ด “prob ของ b = 15%”, (ค) การคำนวณจริง ของ PHASE(45), และ (ง) ขนาดวงในรูปหน้าเดียวกัน (ซึ่งวาดถูกที่ 85/15!) · ค่าที่ถูกคือ 85%/15% · เลข 70/30 จะถูกก็ต่อเมื่อมุมเป็น ~66° ไม่ใช่ 45° · ตอนสอบถ้าอาจารย์ยึด prose ให้ตอบตามสไลด์ไปก่อน แต่รู้ของจริงไว้ (แล้วลองทักอาจารย์ดูได้ค่ะ)

9. ทำไมส่งข้อมูลเร็วกว่าแสงไม่ได้ (หน้า 117)

ถึง b จะเปลี่ยน “ทันที” เมื่ออ่าน a — เรากลับ สั่งทิศทางไม่ได้ เพราะ ผลของ a ออกมาแบบสุ่ม 50/50 เราเลือกไม่ได้ว่าจะให้ b เป็น 15%/85% ทางไหน

ประโยคทองจากสไลด์ (หน้า 117)

entanglement เปลี่ยนสถานะ qubit ข้ามระยะทางได้ทันทีก็จริง แต่มัน “สมคบคิด” ที่จะทำในแบบที่ เราส่งข้อมูลที่ตั้งใจไว้ล่วงหน้าไปไม่ได้ — ถ้าเลือกทิศได้เมื่อไร ก็จะส่งสัญญาณเร็วกว่าแสงได้ ซึ่งจักรวาลไม่ยอม (จักรวาลไม่ปลื้มหนัง sci-fi 😆)

เชื่อมกับบท 0009: Bell pair = “ความสุ่มที่แชร์กัน” (shared randomness) — เห็นค่าตรงกันข้ามฝั่ง แต่สั่งค่าไม่ได้ นี่คือเหตุผลเดียวกัน

ต่อยอด: ในโปรแกรมนี้ ถ้าเราอ่าน a ได้ค่า 1 โอกาสที่ b จะอ่านได้ 1 คือ?
ถูกต้อง! a=1 → เหลือวง |01⟩,|11⟩ → renormalize แล้ว b อ่านได้ 1 = 85% (ตรงหน้า 112 + คณิต) · ตัวเลือก 70% คือเลข prose ที่สไลด์เขียนผิดค่ะ
a=1 บังคับให้เหลือเฉพาะวง a=1 (|01⟩,|11⟩) · |11⟩ ใหญ่กว่ามาก → หลัง renormalize b อ่านได้ 1 = 85% · (ระวังตัวเลือก 70% เป็นเลข prose สไลด์ที่ผิด)
สลับมุม (interleave บท 0010): โปรแกรม remote-controlled randomness สร้าง entanglement — ต่างจาก phase kickback ตรงไหน?
ใช่ค่ะ! phase kickback ให้สถานะ separable (แยกเป็น 2 qubit อิสระได้ ไม่พัวพัน) — ส่วน remote-controlled randomness มี cnot ตอน control เป็น superposition จึงเกิด entanglement จริง
กลับด้านค่ะ — phase kickback ผลออกมา separable (ไม่พัวพัน, บท 0010) · ส่วนโปรแกรมนี้ cnot ตอน a เป็น superposition → พัวพันจริง
ทดสอบความจำท้ายบท (ปิดหน้าจอแล้วตอบในใจ)
  1. หลักการทั่วไปของการประกอบ conditional op เอง คืออะไร? (ใบ้: แตก…แล้วใช้ CNOT…)
  2. ในวงจรสร้าง CPHASE ทำไม input (1,0) ถึงได้ phase สุทธิ = 0 แต่ (1,1) ได้ 90°? คุณสมบัติ “PHASE เฉยกับ |0⟩” ช่วยยังไง?
  3. ในโปรแกรม remote-controlled randomness: อ่าน a ได้ 0 แล้ว b เป็นกี่เปอร์เซ็นต์? และทำไมเราถึง ส่งข้อมูลผ่านมันไม่ได้?

10. สรุปปิด Lec 03

  • ประกอบ conditional op เองได้ทุกตัว — หลักการ: แตก single-qubit op เป็นสเต็ป + ใช้ CNOT “ยกเลิกแบบมีเงื่อนไข” ให้สองครึ่งหักล้างกันเมื่อ control=0 เท่านั้น
  • ตัวอย่าง: CPHASE = PHASE(45)–CNOT–PHASE(−45)–CNOT–PHASE(45) · เวิร์กเพราะ PHASE เฉยกับ |0⟩ + หมุนไป-กลับหักล้างกัน
  • remote-controlled randomness: had→phase(45)→had→cnot ได้สถานะพัวพัน · อ่านตัวหนึ่งเปลี่ยน prob อีกตัวทันที (15% ↔ 85%)
  • เปลี่ยนได้ทันทีข้ามระยะทาง แต่สั่งทิศไม่ได้ (ผลสุ่ม 50/50) → ส่งข้อมูลเร็วกว่าแสงไม่ได้
  • 🔴 สไลด์ผิดจุดที่ 5: prose หน้า 115/116 เขียน 70/30 — ของจริง 85/15
