Quantum Computer คืออะไรกันแน่ (และ ไม่ใช่ อะไร)

ก่อนจะแตะ qubit, superposition หรือคณิตใดๆ เรามาตอบคำถามที่คาบเรียนข้ามไป ก่อน: ไอเจ้า "คอมพิวเตอร์ควอนตัม" เนี่ย จริงๆ มันคืออะไร แล้วทำไมโลกถึงต้องมีมัน

ทำไมต้องเริ่มตรงนี้

slide คาบแรกเปิดมาด้วยคำว่า Qubits, Superposition, QFT รัวๆ เลย โดยไม่ได้บอกว่า "ภาพใหญ่" คืออะไร พอไม่มีที่แขวนความรู้ สมองเลยจับอะไรไม่ติด บทนี้จะสร้าง ที่แขวน อันนั้นให้ก่อน — 1 ภาพในหัวที่ถูกต้อง มีค่ากว่าท่องศัพท์ 10 คำ

1. ความเข้าใจผิดที่ต้องทิ้งก่อนเลย

พอได้ยินคำว่า "quantum computer" คนส่วนใหญ่จินตนาการถึง เครื่องต่างดาวที่จะมาแทนคอมพิวเตอร์ทุกเครื่อง — เป็นคอมรุ่นใหม่ที่ "เร็วกว่า" ทำทุกอย่างที่คอมเก่าทำได้ แต่ไวขึ้นเป็นล้านเท่า

Misconception ยอดฮิต

❌ "Quantum computer = คอมที่เร็วกว่าเดิม จะมาแทนคอมทุกเครื่อง"
ผิดทั้งสองท่อน. slide เขียนตรงๆ ว่าคำว่า quantum computer นั้น "a bit misleading" — มันชวนให้นึกภาพผิด

ความจริงตาม slide (หน้า 26–27): จุดขายของ quantum computer ไม่ได้มาจากการเป็น "conventional computer killer" (นักฆ่าคอมทั่วไป) แต่มาจาก ความสามารถในการ ขยายชนิดของปัญหาที่ "แก้ไหว" (tractable, ปัญหาที่คำนวณเสร็จในเวลาที่ยอมรับได้)

แก่นของบทนี้

มีปัญหาบางอย่างที่ quantum computer แก้ได้สบายๆ แต่คอมปกติ ทุกเครื่องที่เรา จะสร้างได้ในจักรวาลนี้ แก้ไม่ได้เลย (ไม่ใช่แค่ช้า — คือ เป็นไปไม่ได้). ควอนตัมไม่ได้ "ทำของเดิมให้เร็วขึ้น" แต่ "เปิดประตูปัญหาใหม่ที่เดิมปิดตาย"

2. โมเดลในหัวที่ถูกต้อง: มันคือ "หน่วยประมวลผลร่วม"

slide หน้า 28 ให้มุมมองที่ดีที่สุดสำหรับโปรแกรมเมอร์: quantum computer จริงๆ แล้วคือ co-processor (หน่วยประมวลผลร่วม) ตัวหนึ่ง

คอมพิวเตอร์เคยใช้ co-processor เฉพาะทางมานานแล้ว — ตัวคำนวณทศนิยม, ตัวประมวลสัญญาณ, และที่คุ้นสุดคือ GPU (การ์ดจอ) ที่เก่งงานกราฟิก/งานขนาน เราจึงเรียกอุปกรณ์ควอนตัมนี้ว่า QPU (Quantum Processing Unit) — ล้อกับคำว่า GPU เป๊ะ

CPU + GPUงานทั่วไป + งานกราฟิก/ขนาน
↔
CPU + QPUงานทั่วไป + งานควอนตัมเฉพาะทาง

สังเกตว่าในทั้งสองกรณี CPU ยังเป็นพระเอกที่คุมเกม โปรแกรมส่วนใหญ่รันบน CPU ปกติ แล้ว CPU จะ "สั่ง" QPU เฉพาะตอนเจองานที่เหมาะกับมันเท่านั้น พองานเสร็จ QPU ก็ส่งผลลัพธ์กลับมาให้ CPU (slide หน้า 29, 47)

ภาพการทำงานจริง

โค้ดของเราจะเป็นแบบนี้: รันบน CPU → เจอจุดที่ต้องพึ่งควอนตัม → CPU โยนคำสั่ง ให้ QPU → QPU คำนวณ → คืนผล (projection) กลับมา → CPU ทำงานต่อ
เพราะงั้น "เขียนโปรแกรมควอนตัม" ส่วนใหญ่คือเขียนโค้ดปกติที่ เรียกใช้ QPU เป็นบางจังหวะ ไม่ใช่ทั้งโปรแกรมรันบนควอนตัม

3. ทำไมโลกถึงต้องมีมัน (ตอนนี้)

อีกเหตุผลที่ slide ยกมา (หน้า 21–24) คือฝั่ง hardware: ทรานซิสเตอร์แบบเดิม (CMOS) กำลัง ชนกำแพงฟิสิกส์ ย่อขนาดลงไปเรื่อยๆ จนต่ำกว่า ~20–30 นาโนเมตรแล้วเริ่มมีปัญหา — อิเล็กตรอน "ลอด" (tunneling) ทะลุฉนวนบางๆ, การกระจายตัวของสารเจือ (dopant) แกว่งจนคุมไม่อยู่

พอเล็กถึงระดับนั้น ปรากฏการณ์ควอนตัมกลายเป็นตัวเอกโดยปริยาย ไม่ว่าเราจะ ตั้งใจหรือไม่ก็ตาม — โลกจึงเริ่มคิดว่า "ถ้ายังไงก็หนีควอนตัมไม่พ้น งั้นเรา ใช้ประโยชน์ จากมันไปเลยดีกว่าไหม?"

4. ข่าวดี: ไม่ต้องเก่งฟิสิกส์ก็เขียนได้

จุดที่ปลดล็อกความกลัวได้ดีที่สุดใน slide (หน้า 20):

Analogy ที่ต้องจำ

ฟิสิกส์เบื้องหลังทรานซิสเตอร์ก็คณิตแน่นมาก แต่การเรียน C++ ไม่ต้องแตะ สมการฟิสิกส์สักบรรทัด เช่นเดียวกัน — การเขียนโปรแกรม QPU ไม่ได้แปลว่าต้อง เข้าใจกลศาสตร์ควอนตัมระดับลึก เราเรียน "วิธีสั่งงานมัน" ก่อน ไม่ใช่ "ที่มาของมัน"

สิ่งที่ต้องมีจริงๆ มีแค่ (slide หน้า 25): เข้าใจ control structure (if/while), คณิตระดับโปรแกรมเมอร์ (ฟังก์ชัน, ตรีโกณ, เลขฐานสอง↔ฐานสิบ, ความหมายพื้นฐานของ จำนวนเชิงซ้อน/complex number) และ big-O นิดหน่อย — ของพวกนี้ค่อยรื้อฟื้น ตอนถึงจุดที่ใช้จริง ไม่ต้องกังวลตอนนี้

เช็คความเข้าใจ

1. ข้อไหนอธิบาย "จุดขาย" ของ quantum computer ได้ตรงที่สุด?
ใช่เลยค่ะ! มันเปิดประตูปัญหาใหม่ที่คอมปกติทำไม่ได้ ไม่ใช่แค่ทำของเดิมให้เร็วขึ้น
ยังไม่ใช่นะ — ประเด็นไม่ใช่ "เร็วกว่า" หรือ "มาแทน" แต่คือขยายเซตปัญหาที่ *แก้ไหว* (tractable)
2. โมเดลในหัวที่ถูกต้องของ QPU สำหรับโปรแกรมเมอร์คือ?
ถูกต้อง! เหมือน GPU เลย — CPU คุมเกม แล้วโยนงานเฉพาะทางให้ QPU ทำ
ลองนึกถึง GPU นะ — QPU เป็น co-processor ที่ CPU เรียกใช้เป็นบางจังหวะ ไม่ได้รันทั้งโปรแกรม
3. "เรียน C++ ไม่ต้องรู้สมการฟิสิกส์ของทรานซิสเตอร์" ยกมาเพื่อสื่ออะไร?
ใช่ค่ะ — เราเรียน "วิธีสั่งงาน" ก่อน ไม่ใช่ "ที่มาเชิงฟิสิกส์" ปลดล็อกความกลัวได้เลย
ประเด็นคือ *ระดับความเข้าใจ* — เขียนโปรแกรม QPU ได้โดยไม่ต้องลงลึกฟิสิกส์ควอนตัม เหมือน C++ กับทรานซิสเตอร์
ลองก่อนเปิด: อธิบายด้วยคำพูดตัวเองใน 2 ประโยค — QPU คืออะไร และไม่ใช่อะไร?

ตัวอย่างคำตอบที่ดี: "QPU คือ co-processor เฉพาะทางที่ CPU เรียกใช้เป็นบางจังหวะ คล้าย GPU มันไม่ได้มาแทนคอมปกติหรือแค่ทำงานเดิมให้เร็วขึ้น แต่ช่วยขยายชนิดของ ปัญหาที่แก้ไหวให้กว้างกว่าที่คอมปกติทำได้"

การพยายามนึกเองก่อนเปิดเฉลย (retrieval practice) ช่วยให้จำได้นานกว่าการอ่านซ้ำเยอะเลยค่ะ
