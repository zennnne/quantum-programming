Quantum Programming · Lec 05 · บทที่ 0021b

Uncomputing — ยืม scratch มาแล้วต้องคืนให้เนียน

บทที่แล้วเราสร้าง scratch qubit (คิวบิตทด) ขึ้นมาแก้ปัญหา abs(a) ที่ย้อนกลับไม่ได้ — แล้วจบบทด้วยปัญหาใหม่: scratch ตัวนั้น ค้าง entangled อยู่กับ a เอาไปใช้ต่อไม่ได้ · บทนี้คือคำตอบของปัญหานั้น และมันคือสูตรที่จะใช้ซ้ำไปตลอดวิชานี้

ทำไมต้องเรียนบทนี้ — สูตร compute → use → uncompute คือรูปแบบที่พบบ่อยที่สุด อันหนึ่งใน quantum computation ทั้งวงการ · ตั้งแต่บทหน้าเป็นต้นไป (oracle, amplitude amplification, Grover) ทุกวงจรที่ “ทำอะไรบางอย่างแล้วเก็บผลไว้ในเฟส” ล้วนมีโครงนี้อยู่ข้างใน
จับ 3 อย่าง: ① ทำไม READ scratch ทิ้งไม่ได้ ② ทำไมต้องใช้คำตอบก่อนแล้วค่อยย้อน ③ อ่านวงจร 3 กล่องให้ออก

ส่วนที่ 1 · ปัญหา 2 ข้อของ scratch qubit

สไลด์ p46 บอกตรงๆ ว่า scratch qubit “มักไปพัวพันกับ QPU register ของเรา — พูดให้ตรงคือมัน entangled” แล้วยกปัญหา 2 ข้อที่เกี่ยวโยงกันขึ้นมา:

ปัญหาข้อที่ 1 — scratch ไม่กลับ ∣0⟩ เอง

จบวงจร abs(a) แล้ว scratch ค้างอยู่ที่ “บิตเครื่องหมายของ a” ซึ่งไม่ใช่ ∣0⟩ · แต่ขั้นถัดไปของโปรแกรมต้องการ scratch สะอาดไปใช้ใหม่ (qubit เป็นของหายาก จะเปลืองตัวใหม่ทุกครั้งไม่ได้)

ปัญหาข้อที่ 2 — จะ READ แล้ว NOT ก็ไม่ได้

ทางแก้แบบสัญชาตญาณคือ “ก็ READ มันสิ ได้ 1 ก็ NOT ทิ้ง” — แต่ scratch entangled กับ a อยู่ · การ READ มันจึงยุบ superposition ของ a ไปด้วย สไลด์ p47 ใช้คำว่า “ทำลายครึ่งหนึ่งของ quantum state ของ a”

ย้ำจากบทที่แล้ว: CNOT ตัวแรกที่เอาบิตเครื่องหมายไปพักที่ scratch ไม่ได้ copy — มัน entangle · ถ้ามันเป็นการ copy จริง เราก็คงอ่าน scratch ทิ้งได้สบายๆ แล้วปัญหาข้อที่ 2 จะไม่มีอยู่เลย · ปัญหาทั้งบทนี้เกิดจากคำว่า entangle คำเดียว

ทางออกที่สไลด์เสนอชื่อว่า uncomputing (การย้อนคำนวณ) และแนวคิดมันเรียบง่ายมาก: ย้อน operation ทุกตัวที่ทำให้ scratch entangled เพื่อพามันกลับสู่ ∣0⟩ ที่ไม่ entangled เหมือนตอนเริ่ม — ทำได้เพราะทุก gate ของ QPU (ยกเว้น READ) ย้อนกลับได้อยู่แล้ว รันย้อนลำดับก็จบ

แต่ยังไม่จบ — p48 พูดตรงๆ ว่า: เราได้ scratch กลับมาที่ ∣0⟩ แล้วก็จริง แต่เราก็ล้างงานคำนวณ absolute value ทั้งหมดทิ้งไปด้วย
ก็แน่นอน — “ย้อนทุกอย่าง” ย่อมแปลว่าย้อนคำตอบด้วย นี่คือใจกลางของบทนี้
ข้อ ① ถ้าเราต่อวงจร abs(a) ด้วยวงจรย้อนของมันทันที โดยไม่มีอะไรคั่นกลางเลย — ไล่วงจรในหัวแล้วตอบว่าจบแล้วเราได้อะไร
ถูกต้อง — และนี่คือเหตุผลที่ต้องมีส่วนที่ 2 ของบทนี้ · ถ้า uncompute แล้วคำตอบยังอยู่ นั่นจะเท่ากับเรา copy ข้อมูลควอนตัมได้ ซึ่งผิดกฎ no-copying
ลองไล่ใหม่: ย้อนวงจรทั้งชุด = ย้อนทุกอย่างที่วงจรทำ รวมถึงการ negate ค่า a ด้วย · จะได้สถานะกลับไปเหมือนก่อนเริ่มเป๊ะๆ — คำตอบก็หายไปด้วย

ส่วนที่ 2 · สูตร compute → use → uncompute

ถ้าย้อนแล้วคำตอบหาย ทำไม uncompute ถึงยังมีประโยชน์? สไลด์ p49 ตอบด้วยประโยคเดียว:

เรามัก ใช้คำตอบเสียก่อน แล้วค่อย uncompute

เพราะจริงๆ แล้วเราแทบไม่เคยอยากได้ abs(a) เดี่ยวๆ — เราอยากได้มันเป็นชิ้นส่วนของการคำนวณที่ใหญ่กว่า เช่น “บวกค่าสัมบูรณ์ของ a เข้าไปใน b” · ถ้าเราแทรกการบวกนั้นไว้ตรงกลาง ผลลัพธ์จะไปตกอยู่ที่ b ซึ่งไม่ถูกกล่อง uncompute ย้อนด้วย

ยืมกระดาษทดในห้องสอบทดเลขลงกระดาษ → ลอกคำตอบลงใบตอบ → ลบกระดาษทดจนขาวแล้วคืนครู · คำตอบอยู่ในใบตอบ ไม่ได้หายไปกับกระดาษทด
≈
compute → use → uncomputeคำนวณลง scratch → ใช้ผลไปทำอะไรกับ b → ย้อนจน scratch กลับเป็น ∣0⟩ · คำตอบอยู่ใน b ไม่ได้หายไปกับ scratch

นี่คือวงจรจริงจากสไลด์ p49–p50 — 7 สาย (b 3 บิต, a 3 บิต, scratch 1 บิต) แบ่งเป็น 3 กล่องพอดี:

อ่านวงจรนี้ยังไงให้ไม่ตาลาย — อย่าอ่านทีละ gate ให้อ่านทีละกล่อง แล้วสังเกตว่า กล่องที่ 3 คือกล่องที่ 1 กลับหลัง ตัวต่อตัว:

กล่องทำอะไรแตะสายไหน
① compute abs(a)
5 คอลัมน์		 XOR บิตเครื่องหมายไปพักที่ scratch แล้ว negate a เมื่อ scratch = 1 (= วงจรเดิมของบท 0021 เป๊ะๆ) a + scratch
② b += abs(a)
6 คอลัมน์		 วงจรบวกจากบท 0019 ตรงๆ — ตอนนี้ค่าใน a คือ abs(a) แล้ว จึงบวกได้เลย ไม่แตะ scratch เลยสักคอลัมน์ b + a
③ uncompute abs(a)
5 คอลัมน์		 รันกล่อง ① ย้อนลำดับ → a กลับเป็นค่าเดิม (ติดลบก็กลับไปติดลบ) และ scratch กลับเป็น ∣0⟩ ที่ไม่ entangled a + scratch

ผลรวม: b ได้ค่าใหม่ที่ถูกต้อง · a ไม่เปลี่ยน · scratch คืนสภาพ · และ operation ก้อนใหญ่ทั้งก้อนกลายเป็น reversible ทั้งที่ abs เพียวๆ ไม่ reversible (p51) — นั่นแหละคือทั้งหมดที่เราต้องการ

ข้อ ② ถ้ามีคนลบกล่องที่ 3 ออกจากวงจรข้างบนแล้วรันจริง จะเกิดอะไรขึ้น — คิดจากสิ่งที่แต่ละกล่องแตะ
ใช่ — การบวกจบไปตั้งแต่กล่อง ② แล้ว b ไม่ผิด แต่ที่เสียคือของที่ต้องคืน: a ยังเป็นค่าสัมบูรณ์อยู่ และ scratch ยัง entangled → ขั้นถัดไปของโปรแกรมพัง
ดูคอลัมน์ให้ดี: กล่อง ② ทำการบวกจนจบในตัวเองแล้ว ส่วนกล่อง ③ มีหน้าที่เดียวคือคืนสภาพ a และ scratch · ไม่มีกล่องไหนคืน scratch ให้ฟรีๆ

ส่วนที่ 3 · ทางลัด CNOT และการเก็บผลไว้ในเฟส

สไลด์ p51 เสริมสองอย่าง · อย่างแรก: ถ้าเรารู้ว่า b เริ่มต้นที่ 0 เราไม่ต้องใช้วงจรบวก 6 คอลัมน์เลย — ใช้ CNOT สามตัวก็พอ เพราะ 0 + x = 0 XOR x = x

อย่าเผลอเรียกมันว่า copy — มันดูเหมือน “ก๊อป abs(a) ไปใส่ b” ก็จริง แต่ใช้ได้ เฉพาะตอน b เริ่มที่ 0 เท่านั้น และผลที่ได้คือ b entangled กับ a ไม่ใช่สำเนาอิสระ · กฎ no-copying ยังอยู่ครบไม่มีใครละเมิด

อย่างที่สอง และสำคัญกว่ามาก: เราเอา “ของที่ใช้ตรงกลาง” ไปเป็น phase-encoded result (ผลลัพธ์ที่เข้ารหัสในเฟส) ได้ด้วย — ตราบใดที่กล่อง compute กับ uncompute ไม่ไปยุ่งกับเฟส เฟสที่เรา mark ไว้จะรอดออกมาครบ (p52)

วงจรนี้จากสไลด์ p53 ทำ “กลับเฟส 180° ให้ทุกค่าที่ abs(a) เท่ากับ 1” — สังเกตว่ากล่องกลางเป็นทริกเดิมจากบท 0020: NOT คร่อมหัวท้ายเพื่อแปลงเงื่อนไข a = 001 ให้กลายเป็น “ทุกบิตเป็น 1” แล้วค่อยใช้ CZ 3 ขา

เดินทีละสเต็ปด้วย circle notation (สไลด์ p54)

กริดข้างล่างมี 16 วง = a 3 บิต × scratch 1 บิต · คอลัมน์ = ค่าของ a (two’s complement) · แถวบน = scratch 0 · แถวล่าง = scratch 1 · วงที่หมุนไป 180° คือวงที่ถูก mark ไว้ในเฟส

① หลัง H ทั้ง 3 สาย — a อยู่ในซูเปอร์โพซิชันเท่ากันของ 0…7 · scratch ยังเป็น ∣0⟩ สะอาด แถวล่างจึงว่างทั้งแถว
② หลัง CNOT ตัวแรก (บิตเครื่องหมาย → scratch) · ค่าลบทั้งสี่ (a = −4…−1) ย้ายลงไปแถวล่าง เพราะ scratch ของกิ่งนั้นกลายเป็น 1 · ค่าบวกอยู่แถวบนเหมือนเดิม
③ จบกล่อง compute abs(a) · แถวล่างถูก negate → −1,−2,−3,−4 กลายเป็น 1,2,3,4 (ไปอยู่ที่ ∣9⟩…∣12⟩) · ตอนนี้ “ค่าใน a” ของทุกกิ่งคือค่าสัมบูรณ์แล้ว
④ จบกล่อง Z if abs(a)==1 · ขนาดวงไม่ขยับเลยแม้แต่วงเดียว — เปลี่ยนแค่เฟส · วงที่ abs = 1 คือ ∣1⟩ (แถวบน) กับ ∣9⟩ (แถวล่าง) หมุนไป 180° เข็มชี้ลง
⑤ จบกล่อง uncompute abs(a) · แถวล่างว่างสนิท = scratch กลับเป็น ∣0⟩ ไม่ entangled แล้ว · a กลับมาเป็นค่าเดิมครบทั้ง 8 ค่า · แต่ ∣1⟩ (a = +1) กับ ∣7⟩ (a = −1) ยังเป็น 180° อยู่ — เฟสรอดออกมา นั่นคือคำตอบที่เราต้องการ
ประโยคทองของบท — เราเพิ่งทำสิ่งที่ abs ทำเดี่ยวๆ ไม่ได้ (มันไม่ reversible) โดยที่ไม่มีอะไรเสียหายเลย: a ครบ · scratch สะอาด · คำตอบถูก mark ไว้ในเฟสของวงที่ถูกต้อง · นี่คือรูปร่างของ oracle ที่บทหน้าๆ จะใช้ทั้งบท
ข้อ ③ จากสแนปช็อต ⑤ — ทำไมวงที่เหลือเฟส 180° ถึงเป็น ∣1⟩ กับ ∣7⟩ ไม่ใช่ ∣1⟩ กับ ∣9⟩ เหมือนตอนสแนปช็อต ④
ถูก — เฟสติดไปกับกิ่ง ไม่ได้ติดกับช่องเลข · กิ่งที่มี a = −1 ถูก mark ไว้ตอนที่มันแสดงเป็น abs = 1 พอ uncompute พามันกลับไปเป็น −1 เฟสก็เดินทางไปด้วย · ผลสุดท้ายคือ “ทุกค่าที่ abs(a) = 1 ถูกกลับเฟส” = a = +1 และ a = −1 พอดี
uncompute ไม่ได้ลบหรือสร้างเฟสอะไรเลย มันแค่ย้ายกิ่งกลับที่เดิม · กิ่งที่อยู่ ∣9⟩ ตอน ④ คือกิ่งที่ a จริงๆ เท่ากับ −1 · พามันกลับ ก็ไปโผล่ที่ ∣7⟩ พร้อมเฟสเดิม
ข้อ ④ ในวงจร b ^= abs(a) เงื่อนไข “b ต้องเริ่มที่ 0” จำเป็นเพราะอะไร — ลองแทนตัวเลขจริงดูก่อนตอบ
ใช่ · ลองแทน b = 2, abs(a) = 3 ดู: บวกได้ 5 (101) แต่ XOR ได้ 1 (001) — คนละค่ากันเลย · เงื่อนไข b = 0 คือสิ่งเดียวที่ทำให้ทางลัดนี้ถูกต้อง
ลองแทนตัวเลขจริงดู b = 2, abs(a) = 3 → บวกได้ 5 แต่ XOR ได้ 1 · CNOT ยัง reversible เสมอ (และไม่เกี่ยวกับความเร็ว) แต่มันไม่ใช่การบวก ถ้า b ไม่ได้เริ่มที่ 0
สไลด์พิมพ์ผิด (p46–p54) — หัวเรื่องทุกหน้าเขียนว่า “Upcomputing” แต่คำที่ถูกคือ “Uncomputing” (เนื้อความในหน้าเดียวกันเองก็เขียน uncomputing ถูก) · ตอนสอบให้ตอบตามสไลด์ แต่รู้ไว้ว่าศัพท์จริงในวงการคือ uncomputing
ทดสอบความจำก่อนปิดหน้า — ตอบในใจให้ครบก่อนกดดู

  2. ทำไม “READ scratch แล้ว NOT ทิ้ง” ถึงใช้ไม่ได้
  3. uncomputing แปลว่าทำอะไร ทำได้เพราะคุณสมบัติอะไรของ gate
  4. ถ้า uncompute ทันทีหลัง compute จะได้อะไร เสียอะไร
  5. สูตร 3 ขั้นของบทนี้ชื่อว่าอะไร
  6. ในวงจร b += abs(a) กล่องไหนไม่แตะสาย scratch เลย
  7. กล่อง uncompute เกี่ยวข้องกับกล่อง compute ยังไง
  8. ทำไม CNOT 3 ตัวแทนวงจรบวกได้ และต้องมีเงื่อนไขอะไร
  9. ทำไมเฟสที่ mark ไว้ตรงกลางถึงรอดผ่านกล่อง uncompute ออกมาได้
  10. ท้ายวงจร p53 วงไหนบ้างที่เฟส 180° และเพราะอะไร

สรุปบทนี้

  • scratch qubit ไม่ใช่ของฟรี — ยืมมาแล้วมัน entangled กับ register ของเรา และ READ ทิ้งไม่ได้เพราะจะทำลาย state ครึ่งหนึ่งไปด้วย
  • uncomputing = รัน operation ที่ทำให้มัน entangled ย้อนลำดับ เพื่อคืน scratch สู่ ∣0⟩ ที่ไม่ entangled — ทำได้เพราะ gate ทุกตัว (ยกเว้น READ) reversible
  • ย้อนแล้วคำตอบหายด้วย → จึงต้องเรียงเป็น compute → use → uncompute คือใช้คำตอบให้เสร็จก่อนแล้วค่อยย้อน
  • “use” จะเป็นการบวกลง b · XOR ลง b (ถ้า b เริ่มที่ 0) · หรือกลับเฟสก็ได้ — แบบเฟสคือแบบที่จะใช้บ่อยที่สุดในบทถัดๆ ไป
  • ผลรวม: operation ก้อนใหญ่กลายเป็น reversible ทั้งที่ฟังก์ชันข้างในไม่ reversible
