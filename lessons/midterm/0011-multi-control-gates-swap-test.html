Quantum Programming · Lec 03 · บทที่ 0011

เพิ่มเงื่อนไขให้ NOT: CCNOT, SWAP, CSWAP และ SWAP test

บทที่แล้วเราเพิ่ม “เงื่อนไข” ให้ PHASE จนได้ CPHASE/CZ บทนี้เอาแนวคิดเดิม ไปเพิ่มเงื่อนไขให้ NOT บ้าง → ได้ CCNOT (Toffoli) แล้วต่อยอดเป็น SWAP / CSWAP และปิดท้ายด้วยของเจ๋งเชิงอัลกอริทึม — SWAP test ที่เทียบว่าสองสถานะเหมือนกันแค่ไหน โดยไม่ต้องอ่านทำลายมัน

บทนี้จับ 4 อย่าง

① CCNOT = NOT ที่มี 2 เงื่อนไข (“ถ้า A และ B ค่อยพลิก C”) · ② SWAP = สลับสอง qubit (= 3 CNOT) · ③ CSWAP = SWAP แบบมีเงื่อนไข (= 3 CCNOT) · ④ SWAP test = เอา CSWAP มาเทียบความเหมือนของสองสถานะแบบไม่ทำลาย

ส่วนที่ 1 · gate หลาย control

CCNOT · SWAP · CSWAP

1. CCNOT (Toffoli) — NOT ที่มีสองเงื่อนไข

จำกฎจากบท 0010 ได้ไหมคะ — “ทุกครั้งที่เพิ่ม control หนึ่งตัว จำนวนสิ่งที่ถูกกระทบจะเหลือ ครึ่งเดียว”. CNOT คือ NOT ที่มี 1 เงื่อนไข ถ้าเติมอีกเงื่อนไขเข้าไปก็ได้ CCNOT — พลิก target ก็ต่อเมื่อ control ทั้งสองตัว เป็น |1⟩ พร้อมกัน

ประโยคทองจากสไลด์ (หน้า 87)

CCNOT ตีความได้ว่า “if A AND B then flip C” — สำหรับงาน logic พื้นฐาน CCNOT ถือเป็น QPU operation ที่มีประโยชน์ที่สุดตัวเดียว เพราะเอามาต่อกันสร้าง logic function อะไรก็ได้ (universal สำหรับ logic)

NOT บน 0x1
0 เงื่อนไข → กระทบ 4 คู่
CNOT (control 0x2)
1 เงื่อนไข → กระทบ 2 คู่
CCNOT (control 0x2,0x4)
2 เงื่อนไข → กระทบ 1 คู่

ดูใน circle notation ของทะเบียน 3 qubit (8 วง) จะเห็นชัดว่าเงื่อนไขทำหน้าที่ “กรอง” ว่าจะพลิก วงคู่ไหนบ้าง — ทั้งสามอันข้างบนคือ NOT ที่พลิกบิต 0x1 เหมือนกัน ต่างกันแค่เงื่อนไข:

operationเงื่อนไขคู่วงที่สลับ (บิต 0x1)จำนวนคู่
NOT บน 0x1ไม่มี(0,1)·(2,3)·(4,5)·(6,7)4
CNOT (0x2→0x1)0x2 = 1(2,3)·(6,7)2
CCNOT (0x2,0x4→0x1)0x2 = 1 และ 0x4 = 1(6,7)1

เช็คเอง: |6⟩ = 110₂ (0x2=1, 0x4=1 ✓) และ |7⟩ = 111₂ ต่างกันแค่บิต 0x1 → นี่คือคู่เดียวที่ CCNOT สลับ

① ในทะเบียน 3 qubit เดิม ถ้าใช้ CCNOT ที่มี control = 0x1 กับ 0x2 และ target = 0x4 (คือ “ถ้า 0x1=1 และ 0x2=1 ค่อยพลิก 0x4”) — คู่วงไหนที่ถูกสลับ? (ไล่เลขฐานสองเองก่อนตอบ)
ใช่ค่ะ! เงื่อนไข 0x1=1 และ 0x2=1 เป็นจริงที่ |3⟩=011 และ |7⟩=111 (ทั้งคู่มีบิต 0x1,0x2 ครบ) ต่างกันแค่บิต 0x4 → CCNOT สลับคู่ (3,7) พอดี
ลองใหม่: หาวงที่ 0x1=1 และ 0x2=1 ก่อน (ได้ |3⟩=011 และ |7⟩=111) แล้วดูว่าการพลิกบิต target 0x4 ทำให้ |3⟩↔|7⟩ → คำตอบคือคู่ (3,7)

2. SWAP — สลับสอง qubit

SWAP (หรือ exchange) แค่สลับที่กันของสอง qubit ตรงๆ. ถ้าฮาร์ดแวร์ทำได้ มันอาจย้าย วัตถุจริงสลับตำแหน่งเลยก็ได้ แต่ถ้าไม่ได้ ก็ทำ SWAP โดย “แลกข้อมูล” ผ่าน 3 CNOT สลับหัวท้าย ได้เหมือนกัน (สัญลักษณ์ ×—×)

SWAP = ×—×
= 3 CNOT (สลับหัว-ท้าย-หัว)
เทียบง่ายๆ: จะสลับน้ำสองแก้ว โดยไม่มีแก้วที่สาม — เทไป-เทกลับสามจังหวะก็สลับได้ นี่คือสิ่งที่ 3 CNOT ทำกับข้อมูลใน qubit

“ทำไมไม่แค่เปลี่ยนชื่อ qubit เอาล่ะ?” — คำถามนี้ถูกต้องถ้า SWAP อยู่เดี่ยวๆ. แต่ SWAP จะมีความหมายจริงตอนเราทำให้มัน มีเงื่อนไข → CSWAP

3. CSWAP — SWAP แบบมีเงื่อนไข

CSWAP (conditional exchange) = เติม control ให้ SWAP: “ถ้า control = |1⟩ ค่อยสลับสอง qubit”. สร้างได้จาก 3 CCNOT (คือเอา SWAP = 3 CNOT มาเติมเงื่อนไขให้ทุกตัว) สัญลักษณ์คือจุด control ● เชื่อมกับ ×—×

CSWAP (control 0x4 สลับ 0x1,0x2)
= 3 CCNOT (control กลางกลายเป็นสองจุด)
จุดพีคของ CSWAP (สไลด์หน้า 91)

ถ้า control อยู่ใน superposition เราจะได้ผลเป็น superposition ของ “สลับแล้ว” กับ “ยังไม่สลับ” พร้อมกัน — พฤติกรรมนี้แหละที่ทำให้ SWAP test ในส่วนถัดไปทำงานได้

② ข้อไหนผิดเกี่ยวกับ SWAP / CSWAP?
ถูกต้อง — อันนี้คือข้อที่ผิด. SWAP แค่สลับที่ของสอง qubit ถ้าเริ่มจากสถานะฐาน (เช่น |01⟩) ผลก็ยังเป็นสถานะฐาน (|10⟩) ไม่พัวพันกัน. entanglement ต้องอาศัย superposition ที่ control (เหมือน CNOT ในบท 0009)
ทวนดูอีกที: SWAP=3CNOT ✓, CSWAP=3CCNOT ✓, control superposition ให้ผลซ้อน ✓. เหลือข้อเดียวที่ผิด — SWAP เดี่ยวๆ บนสถานะฐานไม่สร้าง entanglement
ส่วนที่ 2 · เอา CSWAP ไปใช้จริง

SWAP test & fidelity

4. ปัญหา: เทียบสองสถานะยังไงไม่ให้พัง

สมมติมีสองทะเบียนที่เราไม่รู้ว่าข้างในเป็นอะไร (อาจเป็น superposition) — อยากรู้แค่ว่า “มันเหมือนกันไหม”. ปัญหาคือ:

  • READ = การวัดแบบทำลาย → พอวัดปุ๊บ superposition ยุบทันที (บท 0008)
  • เทียบสองสถานะควอนตัมตรงๆ ทำไม่ได้ในกรณีทั่วไป โดยเฉพาะถ้าสถานะไม่รู้/ซ้อนอยู่

SWAP test แก้ปัญหานี้ — มันไม่บอกว่าข้างในเป็นอะไร แต่ใช้ CSWAP ทำให้สองสถานะ แทรกสอด (interfere) กัน แล้วอ่านผลจาก qubit ตัวช่วย (ancilla) ตัวเดียว ได้คำตอบเชิงความน่าจะเป็นว่าเหมือนหรือต่าง

5. หน้าตาวงจร SWAP test

โครง 5 สเต็ป (สไลด์หน้า 93): เตรียม ancilla เป็น |0⟩ → H → CSWAP (ancilla คุมการสลับ input1/input2) → H → READ ancilla

ทำไมมันได้ผล (intuition)

H ตัวแรกทำให้ ancilla เป็น superposition → CSWAP จึงสร้าง “สองเส้นทาง” พร้อมกัน: เส้นที่สลับ input กับเส้นที่ไม่สลับ. H ตัวที่สองเอาสองเส้นทางมาแทรกสอดกัน — ถ้า input เหมือนกัน สลับแล้วก็หน้าตาเดิม สองเส้นทางเหมือนกันเป๊ะ → แทรกสอดเสริมกัน ให้ ancilla กลับไป |0⟩ แน่นอน. ยิ่ง input ต่างกัน สองเส้นทางยิ่งไม่เหมือน → โอกาสได้ |1⟩ ยิ่งมาก

6. อ่านผลยังไง — ⚠️ ระวังจุดที่สไลด์ขัดกันเอง

เวอร์ชัน “5 สเต็ปมาตรฐาน” ข้างบน (และตรงกับตำรา O'Reilly) อ่านผลแบบนี้:

P(อ่าน ancilla ได้ 0) = 1 + |⟨a|b⟩|²2
  • ancilla = |0⟩ → มีโอกาสสูงว่าสองสถานะ เหมือนกัน (ถ้าเหมือนเป๊ะ ได้ 0 แน่ 100%)
  • ancilla = |1⟩ → สองสถานะ ต่างกัน (เจอ 1 เมื่อไร รู้ทันทีว่าไม่เหมือนเป๊ะ)
  • ต่างกันสุดขั้ว (เช่น |0⟩ กับ |1⟩) → ออกมา 50/50
กับดักข้อสอบ — สไลด์สองหน้าขัดกัน

สไลด์หน้า 94 บอกว่า “ancilla = |0⟩ → เหมือน, |1⟩ → ต่าง” (วงจร 5 สเต็ป ตามข้างบน)

แต่ โค้ดหน้า 97–99 เติมบรรทัด output.not() ต่อท้ายก่อน READ → ผลเลยสลับด้าน กลายเป็น “result = 1 ถ้า input เหมือนกัน”. คอมเมนต์ในโค้ดจึงเขียน // result is 1 if inputs are equal

ทั้งสองไม่ผิด — มันคือวงจรคนละอัน (ต่างกันแค่มี NOT ปิดท้ายไหม). เวลาสอบ ดูให้ดีว่าโจทย์ให้วงจรมี output.not() หรือไม่ แล้วค่อยตอบ: มี NOT → 1 = เหมือน · ไม่มี NOT → 0 = เหมือน

โค้ด QCEngine ตามสไลด์ (มี .not() → 1 = เหมือน) ลองรันดูได้เลยค่ะ:

qc.reset(3);
var input1 = qint.new(1, 'input1');
var input2 = qint.new(1, 'input2');
var output = qint.new(1, 'output');   // ancilla
input1.write(0);
input2.write(0);                       // ลองเปลี่ยนเป็น write(1) ดูผลตอน "ต่างกัน"
output.write(0);
output.had();                          // H บน ancilla
input1.exchange(input2, 0x1, output.bits());  // CSWAP: output คุมการสลับ
output.had();                          // H อีกครั้ง
output.not();                          // NOT ปิดท้าย → ทำให้ 1 = เหมือน
var result = output.read();            // result = 1 ถ้า input เหมือนกัน
③ ใช้วงจร SWAP test 5 สเต็ปมาตรฐาน (ไม่มี output.not()) ถ้า input1 กับ input2 เหมือนกันเป๊ะ — อ่าน ancilla ได้อะไร แน่นอนแค่ไหน?
ถูกต้อง — เหมือนเป๊ะ ⟨a|b⟩=1 → P(0) = (1+1)/2 = 1 สองเส้นทางแทรกสอดเสริมกันเต็มที่ ได้ 0 แน่นอน 100% (นี่คือเวอร์ชันไม่มี NOT)
ระวังconvention: เวอร์ชัน 5 สเต็ป (ไม่มี NOT) ให้ 0 = เหมือน. เหมือนเป๊ะ → P(0) = (1+1)/2 = 1 → ได้ 0 แน่นอน. (ถ้ามี .not() ถึงจะกลายเป็น 1)

7. Fidelity — เปลี่ยน “เหมือน/ไม่เหมือน” เป็นตัวเลข

ที่จริง SWAP test บอกได้มากกว่าคำตอบใช่/ไม่ใช่ — ความน่าจะเป็นของผลลัพธ์คือมาตรวัดว่า สองสถานะเหมือนกัน แค่ไหน เรียกว่า fidelity (ความเที่ยงตรง/ความเหมือน)

fidelity = 1 สองสถานะเหมือนกันเป๊ะ
fidelity = 0 ตั้งฉากกัน (ต่างกันสุดขั้ว)

เพราะแต่ละรอบเป็นความน่าจะเป็น รอบเดียวไม่พอ — ต้อง รันซ้ำหลายครั้ง แล้วนับสัดส่วนผล ถึงจะประเมิน fidelity ได้แม่น. กราฟสไลด์หน้า 104 บอกว่า ยิ่งอยากมั่นใจว่าเหมือน “เป๊ะ” ยิ่งต้องรันเยอะ (เส้นพุ่งชันมากเมื่อ fidelity เข้าใกล้ 1) — แต่ทางกลับกัน เจอผลที่แปลว่า “ต่าง” แค่ครั้งเดียว ก็ฟันธงได้ทันทีว่าไม่เหมือนเป๊ะ

เอาไปใช้ตรงไหน

quantum fingerprinting · ตรวจสอบสถานะใน quantum machine learning / quantum communication · เช็คว่า subroutine ทำงานถูก · ตรวจสถานะที่โคลนมา — ทุกงานที่อยาก “เทียบว่าใกล้กันแค่ไหน” โดยไม่ต้องรู้ค่าข้างในจริงๆ

④ รัน SWAP test (เวอร์ชันมาตรฐาน) แล้วบังเอิญได้ผลที่แปลว่า “ต่าง” มาหนึ่งครั้ง สรุปได้อะไรทันที?
ใช่ค่ะ — ถ้าเหมือนเป๊ะ ผลจะต้องออกฝั่ง “เหมือน” เสมอ 100% ดังนั้นพอโผล่ผล “ต่าง” มาแม้ครั้งเดียว ก็รู้แน่นอนว่าสองสถานะไม่เหมือนเป๊ะ (asymmetry ของ SWAP test)
คิดถึง P(เหมือน)=100% ตอน fidelity=1: ถ้าเหมือนเป๊ะจะไม่มีทาง ได้ผล “ต่าง” เลย. ดังนั้นเจอผล “ต่าง” หนึ่งครั้ง = ฟันธงได้ทันทีว่าไม่เหมือนเป๊ะ
🧠 ทดสอบความจำก่อนไปบทหน้า (ลองตอบในใจ/เขียนก่อนกดดู)
  1. วาดสัญลักษณ์วงจรของ CCNOT, SWAP, และ CSWAP จากความจำ
  2. CCNOT บน 3 qubit กระทบกี่คู่วง? แล้ว CNOT / NOT ล่ะ? (คำใบ้: ครึ่งลงเรื่อยๆ)
  3. อธิบายด้วยคำพูดตัวเองว่า SWAP test เทียบสองสถานะได้ยังไง โดยไม่ต้องรู้ค่าข้างใน
  4. วงจร SWAP test 5 สเต็ป: ancilla = |0⟩ แปลว่าอะไร? แล้วถ้าโค้ดมี output.not() ปิดท้าย ความหมายเปลี่ยนยังไง?
  5. fidelity = 1 กับ 0 หมายถึงอะไร? ทำไมต้องรัน SWAP test ซ้ำหลายครั้ง?

8. สรุปก่อนไปบทหน้า

  • CCNOT (Toffoli) = “ถ้า A และ B ค่อยพลิก C” · ●●⊕ · 2 control → กระทบ 1 คู่ (universal สำหรับ logic)
  • SWAP = สลับสอง qubit · ×—× · = 3 CNOT
  • CSWAP = SWAP มีเงื่อนไข · ●+×—× · = 3 CCNOT · control superposition → “สลับ+ไม่สลับ” พร้อมกัน
  • SWAP test: ancilla→H→CSWAP→H→READ · ใช้ interference เทียบสองสถานะโดยไม่ทำลาย
  • อ่านผล: 5 สเต็ป → 0 = เหมือน · ถ้าโค้ดมี .not() → 1 = เหมือน (ระวังตอนสอบ!)
  • fidelity (0..1) = ความเหมือนเชิงตัวเลข · ต้องรันซ้ำหลายรอบ · เจอผล “ต่าง” ครั้งเดียว = ฟันธงว่าไม่เหมือน
