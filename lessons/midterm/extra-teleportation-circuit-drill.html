โจทย์อ่านวงจร Teleportation — 3 ข้อใหญ่ 14 ข้อย่อย

บทซ้อมล้วนๆ ค่ะ ไม่มีเนื้อหาใหม่ · มีวงจร 3 อัน (มาตรฐาน · ถูกดัดแปลงให้ผิด · ถอดป้ายออกหมด) แต่ละอันถาม “กล่องนี้ทำงานอะไร” ควบคู่กับ “ผัง 8 วงหลัง gate นี้หน้าตายังไง” — ข้อย่อยส่วนใหญ่ต้องไล่วงเอง คำนวณเอง ไม่ใช่จำนิยาม · ตอบในใจให้ครบก่อนกดทุกข้อนะคะ

เครื่องมือ 4 อย่างที่ต้องใช้ตลอดทั้งบท — ทวนก่อนเริ่ม
  1. เลขวง = น้ำหนักบิตบวกกัน · alice = 0x1 · ep = 0x2 · bob = 0x4 (เช่นวง 6 = bob 1, ep 1, alice 0)
  2. PHASE บนสาย X = หมุนเข็มเฉพาะวงที่บิต X เป็น 1 · มุมบวก = ทวนเข็ม · ไม่แตะขนาดวง
  3. ⊕ (NOT/CNOT) บนสาย X = สลับของระหว่างคู่วงที่ต่างกันแค่บิต X (เฟสติดไปกับของด้วย)
  4. H บนสาย X = จับคู่วงที่ต่างกันแค่บิต X แล้ว บวก/ลบ: วงที่บิต X = 0 ได้ผลบวก · วงที่บิต X = 1 ได้ผลลบ (ลบ = หมุนเพิ่ม 180°)
ข้อใหญ่ที่ 1 · วงจรมาตรฐาน

ไล่ผัง 8 วงจาก entangle → send

รูปที่ 1 — วงจร teleportation มาตรฐาน (สไตล์ QCEngine · Lec04 หน้า 15) · ชื่อกล่องถูกลบเหลือ ก ข ค ง จ
1.1 หลังจบ กล่อง ก (H บน ep แล้ว CNOT ep→bob) ผัง 8 วงมีของอยู่ที่วงไหน ขนาดเท่าไร (ต้องแปลงเลขฐานสองเป็นเลขวงเอง)
ถูกต้องค่ะ — Bell pair ผูกแค่ ep กับ bob ส่วน alice ยังไม่ถูกแตะเลย (WRITE ของ alice อยู่หลังกล่อง ก ด้วยซ้ำ) → วงที่มีของคือ 0 = 000 กับ 6 = 0x4 + 0x2 = 110 · ถ้าตอบวง 7 คือเผลอให้ alice เป็น 1 ไปด้วย
ไล่ทีละสายค่ะ: bob = 0x4 · ep = 0x2 · alice = 0x1 · กล่อง ก ทำให้ ep กับ bob เป็น 1 พร้อมกัน แล้ว alice ล่ะ ยังเป็นเท่าไรอยู่? → เลขวงที่ได้คือ 4 + 2 + 0 = ?

ผัง A — จุดตั้งต้นของทุกข้อย่อยถัดไปในข้อ 1

1.2 (circle rotation) ในกล่อง ข ลำดับคือ H → φ(45°) → H บนสาย alice · ณ วินาทีที่ φ(45°) ทำงาน เข็มของวงไหนขยับจริง (ไล่ต่อจากผัง A)
เป๊ะค่ะ — H ตัวแรกกระจายของจากวง 0 → {0, 1} และวง 6 → {6, 7} (วงละ 25%) · φ(45°) เล็งวงคี่ทั้งสี่ก็จริง แต่วง 3 กับ 5 ยังว่างเปล่า หมุนไปก็ไม่มีอะไรเปลี่ยน → ที่ขยับจริงคือ วง 1 กับ 7
คำถามนี้แยกสองชั้นค่ะ: (1) φ เล็งวงไหน → วงคี่ (alice = 1) · (2) แต่ตอนนั้นวงคี่วงไหนมีของอยู่จริงบ้าง? — H ตัวแรกเพิ่งกระจายของจากวง 0 กับ 6 ไปได้แค่วง 1 กับ 7 เท่านั้น
1.3 (circle rotation · ขั้นลึก) พอผ่าน H ตัวที่สองของกล่อง ข ผลที่ได้คือ วงคู่ 85.4% ที่ 0° · วงคี่ 14.6% ที่ −90° — เราหมุนไป +45° แท้ๆ ทำไมออกมาเป็น −90°
ใช่ค่ะ — คิดเป็นเวกเตอร์: หลัง φ วงคู่ = 1, วงคี่ = 1∠45° · H ให้ผลรวม (1 + 1∠45°) ยาว 1.85 ชี้ที่ +22.5° และผลลบ (1 − 1∠45°) ยาว 0.77 ชี้ที่ −67.5° · เราสนใจแค่มุมต่าง (เฟสรวมมองไม่เห็นอยู่แล้ว) → −67.5 − 22.5 = −90° · และขนาด: 1.85²/4 = 85.4% · 0.77²/4 = 14.6% ✔
อย่าคิดว่า “หมุนเท่าไร ผลต้องเป็นเท่านั้น” ค่ะ — H เอาสองวงมาบวก/ลบกัน มุมของผลลัพธ์จึงเป็นมุมของเวกเตอร์ลัพธ์ ไม่ใช่มุมที่เราหมุน · ลองวาด 1 กับ 1∠45° แล้วบวก/ลบดูนะคะ ได้ +22.5° กับ −67.5° → ต่างกัน 90°

ผัง B — payload (85.4% / 14.6% ที่ −90°) ถูกแบ่งครึ่งอยู่ในสองฝั่งของ bob

1.4 gate แรกของกล่อง ค คือ CNOT ที่ alice คุม ep — มันสลับของระหว่างวงคู่ไหนบ้าง
ถูกต้องค่ะ — control = alice → ทำเฉพาะวงคี่ · target = ep (0x2) → คู่ที่ต่างกัน 2 · ได้คู่ 1↔3 และ 5↔7 · จากผัง B ของที่วง 1 (7.3% ∠−90) ย้ายไปวง 3 และของที่วง 7 ย้ายไปวง 5 — เฟสติดไปด้วย
แยก control กับ target ให้ขาดค่ะ: ใครคุม → กรองว่าทำวงไหน (alice = 1 → วงคี่) · ใครโดน → บอกว่าคู่ห่างกันเท่าไร (ep = 0x2 → ห่าง 2) → คู่ที่เป็นไปได้จึงมีแค่ 1↔3 กับ 5↔7
1.5 (circle rotation) ต่อด้วย H บน alice (ตัวสุดท้ายก่อน READ) · ของ 7.3% ∠−90 ที่ค้างอยู่ที่วง 3 ถูกแบ่งไปเป็นวง 2 กับ 3 อย่างละ 3.65% — แต่เฟสของสองวงนี้ต่างกัน 180° (วง 2 = −90° · วง 3 = +90°) เพราะอะไร
ใช่ค่ะ — นี่คือเครื่องมือข้อ 4 ในกล่องบนสุด: H จับคู่ (2, 3) แล้วให้ วง 2 = (a₂+a₃)/√2 · วง 3 = (a₂−a₃)/√2 · ตอนนั้น a₂ = 0 เหลือแต่ a₃ ∠−90 → วง 2 ได้ +a₃ (คง −90°) · วง 3 ได้ −a₃ (−90 + 180 = +90°) · เครื่องหมายลบของ H = การหมุนครึ่งรอบ จำประโยคนี้ไว้ค่ะ
ไม่ต้องหาที่มาไกลค่ะ เครื่องหมายลบมาจากตัว H เอง — H ให้ผล บวกที่วงบิต 0 และผล ลบที่วงบิต 1 · แล้ว “ลบ” ในภาษา circle notation แปลว่าอะไร? (= หมุนเข็มไปครึ่งรอบ)

ผัง C — ครบ 8 วง · สังเกตว่าทุกคู่ (0,1) (2,3) (4,5) (6,7) มีขนาดเท่ากันเสมอ นี่คือเหตุผลที่ Alice อ่านได้ 4 แบบด้วยโอกาสเท่าๆ กัน (25% ต่อแบบ)

ข้อใหญ่ที่ 2 · จุดพลิก + วงจรที่ถูกดัดแปลง

Alice อ่านค่าแล้ว Bob แก้ — ผังขยับยังไง

ข้อนี้เริ่มจากผัง C ข้างบน แล้วสมมติผลการอ่านของ Alice ให้ · ส่วนวงจรรูปที่ 2 ข้างล่างนี้ เหมือนรูปที่ 1 ทุกอย่าง ยกเว้นกล่อง ง — เทียบลูกศรทีละเส้นก่อนนะคะ

รูปที่ 2 — ต้นทางของลูกศรประสีฟ้าทั้งสองเส้นถูกสลับกัน
2.1 ใช้วงจรที่ถูก (รูปที่ 1) · สมมติ Alice อ่านได้ alice = 1 และ ep = 1 — จากผัง C เหลือวงไหน ค่าเท่าไร (อย่าลืมปรับให้รวมกันเป็น 100%)
ถูกต้องค่ะ — วงที่รอดคือวงที่ alice = 1 และ ep = 1 → เลขวงต้องติดทั้ง 0x1 และ 0x2 → วง 3 (bob = 0) กับ วง 7 (bob = 1) · ค่าเดิม 3.65% กับ 21.4% รวมกันได้ 25% → หารด้วย 25% ได้ 14.6% กับ 85.4% · เฟสไม่เปลี่ยนตอน READ วง 3 จึงยังค้างที่ +90°
READ ไม่ได้หมุนหรือย้ายอะไรเลยค่ะ มันแค่ลบวงที่ไม่ตรงกับผลที่อ่านได้ทิ้ง แล้วขยายวงที่เหลือให้รวมเป็น 100% · alice = 1 → ต้องติดบิต 0x1 · ep = 1 → ต้องติดบิต 0x2 → เหลือวงไหนบ้าง?

ผัง D — qubit ของ Bob ตอนนี้ “เกือบใช่” payload แล้ว แต่ขนาดสลับฝั่ง (bob = 1 หนัก 85.4%) และเฟสผิดทิศ (+90° แทน −90°)

2.2 (circle rotation) Bob ได้บิต (1, 1) จึงทำ ⊕ ตามด้วย φ(180°) ตามรูปที่ 1 — หลังทำครบสองตัว ผังกลายเป็นอะไร (ไล่จากผัง D)
เยี่ยมค่ะ ไล่ครบสองจังหวะ — ⊕ บน bob (0x4) สลับคู่ 3↔7 → วง 3 = 85.4% ∠0 · วง 7 = 14.6% ∠+90 · จากนั้น φ(180°) บน bob หมุนเฉพาะวง 4–7 → วง 7 ไปที่ 90 + 180 = 270° = −90° · ได้ 85.4% ที่ 0° กับ 14.6% ที่ −90° = payload ของ Alice เป๊ะ 🎯 นี่คือ teleportation ที่สำเร็จ ในภาษา circle notation
ทำทีละตัวค่ะ · ⊕ บน bob = สลับของระหว่างคู่ที่ต่างกันแค่บิต 0x4 → คู่ 3↔7 (ขนาดสลับกัน เฟสติดไปด้วย) · แล้ว φ(180°) บน bob = หมุนเฉพาะวง 4–7 ไปครึ่งรอบ → +90 บวกอีก 180 ได้เท่าไร?
2.3 คราวนี้ใช้ วงจรรูปที่ 2 (ลูกศรสลับ) · สมมติ Alice อ่านได้ alice = 1 แต่ ep = 0 → เหลือวง 1 = 85.4% ∠0 และวง 5 = 14.6% ∠+90 · Bob จะได้อะไร
ถูกต้องค่ะ — ในรูปที่ 2 ตัวคุม ⊕ คือบิต alice = 1 → Bob พลิก (สลับ 1↔5) ทั้งที่ไม่ควรพลิก · ส่วนตัวคุม φ คือบิต ep = 0 → ไม่หมุน ทั้งที่ควรหมุน · ผลคือ 85.4% เด้งไปฝั่ง bob = 1 และ +90° ยังค้าง — ผิดทั้งขนาดและเฟส · (พอเอาไปเข้ากล่อง verify จะอ่านได้ 0 แค่ราวครึ่งหนึ่งของรอบ แทนที่จะเป็น 100%)
เช็กทีละลูกศรค่ะ: ⊕ ถูกคุมด้วยบิตของ alice (= 1) → ทำ · φ ถูกคุมด้วยบิตของ ep (= 0) → ไม่ทำ · แต่รอบนี้ของจริงต้องการตรงกันข้าม (ไม่พลิก แต่ต้องหมุน) → พลาดทั้งสองอย่าง
2.4 ถ้ารันวงจรรูปที่ 2 หลายๆ รอบ Bob ได้ payload ถูกกี่ % ของรอบทั้งหมด
ใช่ค่ะ — ผัง C บอกเราแล้วว่าผลของ Alice ออกมา 4 แบบเท่าๆ กัน แบบละ 25% · ถ้าสองบิตเท่ากัน สลับสายก็ไม่มีผล → ถูก · ถ้าต่างกัน (01, 10) → พังแบบข้อ 2.3 · 2 ใน 4 = 50%
คิดเป็นเคสค่ะ: บิต 2 ตัวมี 4 แบบ โอกาสเท่ากันหมด (ดูผัง C) · แบบไหนบ้างที่ “สลับสายแล้วผลเหมือนเดิม”? — คือแบบที่ค่าสองบิตเท่ากันอยู่แล้ว
ข้อใหญ่ที่ 3 · วงจรเปลือย

ไม่มีกรอบกล่อง + มุมเปลี่ยนเป็น 60°

รอบนี้ถอดกรอบกล่องออกทั้งหมด เหลือแต่ gate ล้วนๆ เปลี่ยนมุม prep payload เป็น 60° และปล่อยมุมของกล่องสุดท้ายไว้เป็น ? ให้พี่เติมเองค่ะ

รูปที่ 3 — วงจรเดียวกันแบบไม่มีป้ายกล่อง · ป้ายมุมอยู่แถวบนตรงคอลัมน์ของ gate นั้น
3.1 ถ้าจะวาดกรอบ “send” กลับเข้าไป มันต้องครอบ gate ชุดไหน
ถูกต้องค่ะ — “send” = ผูก + ยุบ: CNOT (alice คุม ep) → H บน alice → READ ทั้งคู่ · จำง่ายๆ ว่า กล่อง send จบที่ detector เสมอ เพราะผลผลิตของมันคือบิตคลาสสิก 2 ตัว · (นี่คือ gate ชุดเดียวกับข้อ 1.4–1.5 นั่นเอง)
ใช้ “ผลลัพธ์ของกล่อง” เป็นตัวนำค่ะ — send ต้องคายของออกมาเป็น บิตคลาสสิก 2 ตัว จึงต้องจบที่ detector · ชุด H–φ–H บน alice คือ prep payload ส่วนชุดที่มีลูกศรประคือ receive
3.2 payload ที่ปั้นด้วย H → φ(60°) → H มีโอกาสอ่านได้ 0 กี่ % และเฟสของวงคี่เป็นเท่าไร (ใช้วิธีเวกเตอร์แบบข้อ 1.3)
ครบทั้งสองส่วนเลยค่ะ — ขนาด: P(อ่านได้ 0) = cos²(φ/2) → cos²(30°) = 75% (เช็คกับของเดิม: cos²(22.5°) = 85.4% ✔) · เฟส: (1 + 1∠60°) ชี้ที่ +30° · (1 − 1∠60°) ชี้ที่ −60° → ต่างกัน −90° · ที่น่าจำคือมันเป็น −90° เสมอไม่ว่าใช้มุมอะไร (ลอง 45° ก็ได้ −90° เท่ากัน) → กล่อง H–φ–H เปลี่ยนได้แค่ “ขนาด” ส่วนเฟสล็อกที่ −90° ตลอด
แยกสองส่วนค่ะ · ขนาด ใช้ cos²(φ/2) = cos²(30°) = 0.75 → ตัดข้อ 50% ทิ้งได้ทันที · เฟส ลองวาด 1 กับ 1∠60° แล้วบวก/ลบ: ผลบวกชี้ +30° ผลลบชี้ −60° ต่างกันเท่าไร? (ไม่ได้โตตามมุมที่ใส่นะคะ)
3.3 มุม ? ในคอลัมน์เกือบสุดท้าย (บนสาย bob) ต้องเป็นเท่าไร
ใช่ค่ะ — verify = prep กลับด้าน · prep ใช้ φ(+60°) → verify ใช้ φ(−60°) (H ย้อนกลับตัวเองอยู่แล้วจึงไม่ต้องเปลี่ยน) · ถ้าใส่ผิด ผลอ่านจะไม่ใช่ 0 ทุกครั้ง ทั้งที่ส่วนอื่นของวงจรถูกหมด — เป็นกับดักที่หาสาเหตุยากมาก
กล่องสุดท้ายมีไว้ “แกะสิ่งที่กล่อง prep ทำ” ค่ะ · ถ้า prep หมุนทวนเข็ม 60° แล้วจะแกะคืน ต้องหมุนไปทางไหน เท่าไร?
3.4 (circle rotation) ถ้าลบ H สองตัวที่ขนาบ φ(60°) ออก เหลือ φ(60°) โดดๆ กระทำกับ alice ที่ยังเป็น |0⟩ — payload จะเป็นอะไร
นี่คือแก่นของทั้งบทเลยค่ะ 🎯 — φ เล็งวงคี่ แต่ตอนนั้น วงคี่ว่างสนิท · หมุนของว่างก็ยังว่างอยู่ดี → ไม่มีอะไรเกิดขึ้น · H ตัวหน้าจึงจำเป็น (เทของใส่วงคี่ก่อน เฟสถึงจะมีอะไรให้หมุน) และ H ตัวหลังคือตัว แปลงเฟสกลับมาเป็นขนาดวงที่วัดเห็นได้ — เหมือนที่พี่เจอมาแล้วในข้อ 1.2 และ 1.3
ย้อนไปดูผังก่อนถึง φ ค่ะ: alice = |0⟩ แปลว่าวงคี่มีขนาดเท่าไร? แล้วการหมุนเข็มของวงที่ว่างเปล่า จะเปลี่ยนอะไรได้บ้าง?
3.5 (circle rotation · ปิดท้าย) ถ้ามีคนแก้ φ(180°) ในช่วง receive ให้เป็น φ(90°) · ในรอบที่ Bob ต้องแก้เฟส (เช่นเคสผัง D ที่วง 7 ค้างอยู่ที่ +90°) จะเกิดอะไรขึ้น
