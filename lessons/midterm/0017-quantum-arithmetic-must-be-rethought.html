เลขคณิตควอนตัมต้องคิดใหม่ทั้งหมด

บท 0016 ปิดท้ายด้วยแผนที่ QPU primitives 4 ขั้น · Lec 05 ทั้งคาบคือ ขั้นที่ ② — “ทำ digital logic ทั้งก้อน บน superposition” · แต่ก่อนจะสร้างวงจรบวกเลขได้ ต้องเข้าใจก่อนว่า ทำไมยกวงจรบวกเลขของคอมพิวเตอร์ปกติมาใช้ตรงๆ ไม่ได้ — บทนี้ตอบคำถามนั้นค่ะ

บทนี้จับ 3 อย่าง
① Toffoli ตัวเดียวทำงานกับทุกกิ่งของ superposition พร้อมกัน — นี่คือของที่ logic เดิมทำไม่ได้
② กติกา 2 ข้อที่ทุก operation บน QPU ห้ามละเมิด (คัดลอกไม่ได้ · ต้องย้อนกลับได้)
③ ต่อจากนี้เราจะเลิกคิดทีละ qubit แล้วคิดเป็น quantum integer แทน

ส่วนที่ 1 — gate ตัวเดียว ทำสองงานพร้อมกัน

ทำไมไม่ยกวงจรเดิมมาใช้เลย?

คอมพิวเตอร์ปกติมีวงจรบวกเลขที่ถูก optimize มาหลายสิบปีแล้ว คำถามที่ตรงไปตรงมาที่สุดคือ — ทำไมไม่แค่เปลี่ยน bit เป็น qubit แล้วยกวงจรเดิมมาแปะบน QPU ซะเลย?

ปัญหาอยู่ที่ สมมติฐานเบื้องหลังการออกแบบ ค่ะ · วงจรเดิมถูกออกแบบมาให้ทำงานกับ อินพุตชุดเดียวต่อครั้ง · แต่บน QPU register ที่เราจะป้อนเข้าไปมักอยู่ใน superposition และเราต้องการให้เลขคณิตนั้นส่งผลต่อ ทุกค่าใน superposition พร้อมกัน นี่แหละคือที่มาของ quantum advantage ทั้งหมดในบทต่อๆ ไป

ประโยคทองของทั้งคาบ: ความได้เปรียบของ QPU ไม่ได้มาจาก “คำนวณเร็วขึ้น” แต่มาจากการที่ operation หนึ่งครั้งทำงานกับทุกค่าใน superposition พร้อมกัน → เลขคณิตของเราต้องถูกสร้างขึ้นมาใหม่ให้รองรับข้อนี้

ตัวอย่างที่เล็กที่สุด: if (a and b) then invert c

เอา single-qubit register 3 ตัว ชื่อ a (0x1), b (0x2), c (0x4) · logic ที่อยากได้คือ “ถ้า a และ b เป็น ∣1⟩ ทั้งคู่ ให้พลิกค่า c” — อันนี้ทำได้ด้วย Toffoli ตัวเดียว (CCNOT: ● สองจุดบน a,b + ⊕ บน c)

มอง Toffoli ด้วย circle notation: มันคือการ สลับค่าในวง ∣3⟩ กับวง ∣7⟩ ไม่ว่าในสองวงนั้นจะมีอะไรอยู่ก็ตาม · (∣3⟩ = a=1,b=1,c=0 · ∣7⟩ = a=1,b=1,c=1 — คือคู่ที่ต่างกันแค่ค่าของ c ตอนที่ a และ b เป็น 1 ทั้งคู่พอดี)

กรณีที่ 1 — b = 0 : gate ไม่มีผลอะไรเลย

สถานะคือ ∣1⟩ เต็มวงเดียว (a=1, b=0, c=0) · วงที่ไฮไลต์ส้มคือคู่ ∣3⟩↔∣7⟩ ที่ Toffoli สลับ — แต่ ทั้งคู่ว่างเปล่า สลับแล้วจึงไม่เกิดอะไรขึ้น · c ไม่ถูกพลิก ตรงตามที่ logic สั่งเป๊ะ

กรณีที่ 2 — b อยู่ใน superposition : gate ทำสองงานพร้อมกัน

คราวนี้ใส่ HAD บนสาย b ก่อน → b กลายเป็น (∣0⟩+∣1⟩)/√2 · แล้ว c ควรจะเป็นอะไร? คำตอบที่ถูกต้องคือ ทั้งถูกพลิกและไม่ถูกพลิก พร้อมกันใน superposition

ก่อน Toffoli สถานะคือ (∣1⟩ + ∣3⟩)/√2 · Toffoli ย้าย amplitude จาก ∣3⟩ ไป ∣7⟩ → เหลือ ∣1⟩ + ∣7⟩√2

กิ่ง ∣1⟩ (b=0)
c ยัง = 0 — gate ไม่ทำงานบนกิ่งนี้
กิ่ง ∣7⟩ (b=1)
c ถูกพลิกเป็น 1 — gate ทำงานบนกิ่งนี้

gate เดียว ทำสองงานตรงข้ามกันในเวลาเดียวกัน — Toffoli มีในคอมพิวเตอร์แบบเดิมด้วย แต่เวอร์ชันเดิมทำแบบนี้ไม่ได้เด็ดขาด เพราะมันรับได้ทีละอินพุต · นี่คือความหมายของคำว่า “operation ที่ทำงานบน superposition ได้จริง”

ลองไล่เอง: ถ้าเปลี่ยนเป็นเขียน a=1, b=0, c=1 แล้วใส่ HAD ที่ b แล้วค่อย Toffoli — สถานะสุดท้ายคืออะไร? (ใบ้: ∣index⟩ = a·1 + b·2 + c·4)
ถูกต้องค่ะ! ก่อน HAD = ∣5⟩ (1+0+4) · HAD ที่ b แตกเป็น (∣5⟩+∣7⟩)/√2 · แล้ว Toffoli สลับ ∣3⟩↔∣7⟩ → ของใน ∣7⟩ ย้ายไป ∣3⟩ เหลือ (∣3⟩+∣5⟩)/√2 · สังเกตว่าคราวนี้ Toffoli ย้อนงานเดิม เพราะ c เริ่มที่ 1 อยู่แล้ว
ยังไม่ใช่ค่ะ · ลำดับคือ ① c=1 → ∣5⟩ ② HAD ที่ b → (∣5⟩+∣7⟩)/√2 ③ Toffoli สลับคู่ ∣3⟩↔∣7⟩ เสมอ — ของใน ∣7⟩ จึงถูกย้ายไป ∣3⟩ · คำตอบคือ (∣3⟩+∣5⟩)/√2

ส่วนที่ 2 — กติกา 2 ข้อ และระดับที่เราจะเขียนโปรแกรมจริง

นอกจากข้อ “ต้องทำงานบน superposition ได้” ข้างบนแล้ว ยังมีกติกาอีก 2 ข้อ ที่ operation ทุกตัวบน QPU ห้ามละเมิด · ทั้งคาบนี้เวลาเจอวงจรแปลกๆ ที่ดูอ้อมโลก เหตุผลจะย้อนกลับมาที่สองข้อนี้เสมอ

กติกาข้อ 1 — ย้ายได้ แต่คัดลอกไม่ได้

qubit คัดลอกไม่ได้ · นี่เป็นความต่างมหาศาลจาก CPU แบบเดิม เพราะการคัดลอก/ย้ายบิต เป็น operation ที่ CPU ทำบ่อยที่สุดในชีวิต

ย้ายได้ ✓
ใช้ exchange instruction (สลับกับอีก qubit) — ค่าเดิมที่ต้นทางหายไป เพราะมันแค่ย้ายที่
คัดลอกไม่ได้ ✗
ไม่มี QPU ตัวไหนมีคำสั่ง COPY → operator = ที่ใช้กันเป็นปกติในโค้ดทั่วไป ใช้กับ qubit ไม่ได้

กติกาข้อ 2 — ทุกอย่างที่ไม่ใช่ READ ต้องย้อนกลับได้

กฎของกลศาสตร์ควอนตัมบังคับว่า operation พื้นฐานของ QPU ทุกตัวที่ไม่ใช่ READ ต้อง reversible (ย้อนกลับได้) — คือดูจากเอาต์พุตแล้วต้องบอกได้เสมอว่าอินพุตคืออะไร · READ เป็น operation เดียวที่ irreversible

AND gate แบบเดิม2 อินพุต → 1 เอาต์พุต · เห็นผลลัพธ์ 0 ก็เดาไม่ออกว่าอินพุตคือ 00, 01 หรือ 10 → ข้อมูลหายไป
✗ → ✓
Toffoli3 เข้า → 3 ออก · a กับ b ยังอยู่ครบ ส่วน c ถูก XOR ทับ · รัน Toffoli ซ้ำอีกครั้งได้สถานะเดิมกลับมาเป๊ะ
กับดัก: เห็นว่า READ ย้อนกลับไม่ได้ อาจเกิดไอเดียว่า “งั้นก็โรย READ เยอะๆ สิ จะได้ทำ operation ที่ย้อนกลับไม่ได้ตามใจ” — ระวังค่ะ! ทำแบบนั้นการคำนวณจะกลาย เป็นแบบคลาสสิกไปเรื่อยๆ จน quantum advantage หายหมด

สูตรสำเร็จที่สไลด์ให้ไว้: วิธีที่ง่ายที่สุดในการเอาวงจรแบบเดิมมาลง QPU คือ แทนที่มันด้วย วงจรที่สมมูลกันแต่ใช้เฉพาะ operation ที่ย้อนกลับได้ เช่น Toffoli แล้วค่อยยกไปวางบน quantum register — ซึ่งเกือบจะทำได้ตรงๆ เลย ท่านี้คือแก่นของทั้งบท 0018–0022

ทำไม AND gate แบบเดิมถึงยกมาใช้บน QPU ตรงๆ ไม่ได้?
ใช่ค่ะ — 2 อินพุตยุบเหลือ 1 เอาต์พุต แปลว่าข้อมูลหายไป ระหว่างทาง = irreversible → ผิดกติกาข้อ 2 · ทางแก้คือใช้ Toffoli ที่เก็บ a, b ไว้ครบ แล้ว XOR ผลลงสายที่สาม (เดี๋ยวเจอเต็มๆ ในบทท้ายคาบ)
ยังไม่ใช่ค่ะ · ประเด็นไม่ใช่เรื่องความเร็วหรือจำนวน qubit แต่เป็นเรื่องข้อมูลหาย — เห็นเอาต์พุต 0 แล้วบอกไม่ได้ว่าอินพุตเป็น 00, 01 หรือ 10 → ย้อนกลับไม่ได้ = ผิดกติกาข้อ 2

เลิกคิดทีละ qubit — คิดเป็น quantum integer

เวลาเขียนโปรแกรมทั่วไป เราแทบไม่เคยหยิบ logic gate มาต่อเองทีละตัว เราไว้ใจให้ compiler กับ CPU จัดการให้ · quantum computation ก็ไม่ต่างกัน — ถ้าจะเขียนซอฟต์แวร์ QPU จริงจัง เราต้องทำงานกับ qubyte และ quantum integer เป็นหลัก มากกว่าจะจิ้มทีละ qubit

โลกดิจิทัลลอจิกทั้งหมดสร้างขึ้นได้จาก NAND gate ตัวเดียว
↔
โลกควอนตัมquantum integer operation ที่เราต้องใช้ สร้างขึ้นได้จาก elementary QPU operation
🔴 สไลด์ p10 พิมพ์ผิด — สไลด์เขียนว่า NAND คือ NOT(b AND b) ซึ่งตกตัว a ไป (แบบนั้นจะกลายเป็น NOT ของตัวเดียว) · ของจริงคือ a NAND b = NOT(a AND b) · ตอนสอบถ้าอ้างตามสไลด์ก็ตอบตามสไลด์ แต่รู้ของจริงไว้ด้วยนะคะ (จุดสไลด์ผิดจุดที่ 9 ของคอร์ส)

ตั้งแต่บทหน้าไป ไดอะแกรมทั้งหมดจะใช้ integer ขนาด 4 qubit ที่เรียกว่า quantum nibble หรือ qunibble (ล้อคำว่า nibble = 4 bit ในยุคไมโครคอมพิวเตอร์ยุคแรก) · เลือก 4 เพราะวาดง่าย แต่ทุกตัวอย่างขยายไปใช้กับ register ที่ใหญ่กว่าได้หมด — ขนาด integer ที่รองรับได้ขึ้นอยู่กับจำนวน qubit ที่ QPU หรือ simulator มี

อยากย้ายค่าจาก qubit p ไป qubit q — ทำยังไงถึงถูกกติกา?
ถูกค่ะ! QPU ย้ายได้ด้วย exchange แต่คัดลอกไม่ได้ · ตัวเลือก CNOT เป็นกับดักคลาสสิก — ถ้า p อยู่ใน superposition มันไม่ได้ก๊อป p ลง q แต่ทำให้สองสาย entangled กัน (นี่คือกลไกเดียวกับ scratch qubit ที่จะเจอในบท 0021) · ส่วน READ ก็ทำลาย superposition ทิ้งไปแล้ว
ยังไม่ใช่ค่ะ · CNOT ดูเหมือนคัดลอกเฉพาะตอน p เป็น ∣0⟩/∣1⟩ ชัดๆ เท่านั้น — ถ้า p อยู่ใน superposition มันจะทำให้ entangled ไม่ใช่ copy · ส่วน READ ทำลาย superposition · คำตอบคือ exchange (SWAP)
ทดสอบความจำก่อนปิดหน้า — ตอบในใจก่อนกดดูเฉลย (8 ข้อ)
  1. ทำไมยกวงจรบวกเลขแบบเดิมมาใช้ตรงๆ ไม่ได้? — มันถูกออกแบบให้รับอินพุตชุดเดียว แต่บน QPU อินพุตอยู่ใน superposition และเราต้องการให้ผลเกิดกับทุกค่าพร้อมกัน
  2. Toffoli ทำอะไรใน circle notation? — สลับค่าในวง ∣3⟩ กับ ∣7⟩ เสมอ ไม่ว่าในวงจะมีอะไร
  3. ทำไม b=0 แล้ว Toffoli ไม่มีผล? — สองวงที่ถูกสลับ (∣3⟩, ∣7⟩) ว่างทั้งคู่
  4. b เป็น superposition แล้วผลคืออะไร? — (∣1⟩+∣7⟩)/√2 คือ c ทั้งถูกพลิกและไม่ถูกพลิกพร้อมกัน — gate เดียวทำสองงาน
  5. กติกาข้อ 1 คือ? — qubit คัดลอกไม่ได้ · ย้ายได้ด้วย exchange instruction · operator = ใช้กับ qubit ไม่ได้
  6. กติกาข้อ 2 คือ? — ทุก operation ที่ไม่ใช่ READ ต้องย้อนกลับได้ · READ เป็นตัวเดียวที่ irreversible
  7. วิธีย้ายวงจรคลาสสิกลง QPU? — แทนที่ด้วยวงจรสมมูลที่ใช้เฉพาะ operation แบบย้อนกลับได้ (เช่น Toffoli) แล้วค่อยยกไปวางบน quantum register
  8. qunibble คือ? — quantum integer ขนาด 4 qubit ที่จะใช้วาดตัวอย่างทั้งคาบ · ขยายไป register ใหญ่กว่าได้ทั้งหมด
สรุปบทนี้ใน 3 บรรทัด
① เลขคณิตควอนตัมไม่ใช่การยกวงจรเดิมมาใช้ — มันถูกสร้างใหม่ให้ทำงานกับ ทุกกิ่งของ superposition พร้อมกัน
② กติกาที่ห้ามละเมิด: คัดลอกไม่ได้ · ทุกอย่างที่ไม่ใช่ READ ต้องย้อนกลับได้
③ ต่อจากนี้คิดเป็น quantum integer (qunibble 4 qubit) ไม่ใช่ทีละ qubit — บทหน้าเริ่มด้วยเลขคณิตตัวแรกจริงๆ: increment / decrement
