Lesson 0009 · Lec 03 ต่อ · gate ตัวแรกที่ “ข้าม qubit” ได้

CNOT กับ entanglement: จาก “if” ธรรมดาๆ ไปสู่สิ่งที่ฟิสิกส์คลาสสิกอธิบายไม่ได้

บท 0008 จบด้วยข้อจำกัดว่า gate เดี่ยวสร้าง entanglement (การพัวพัน) ไม่ได้ ค่ะ บทนี้เราจะได้เครื่องมือที่ทำได้ — CNOT — ครึ่งแรกดูว่ามันคืออะไร ทำงานยังไงในภาษา operator pairs แล้วเอามาสร้าง Bell pair ครึ่งหลังคือคำถามที่ค้างมาตั้งแต่บทที่แล้ว: entanglement มันแปลกยังไง ทำไมนักฟิสิกส์ถึงต้องมี Bell's theorem มายืนยัน

จับหลัก 5 อย่างพอ
  1. CNOT = “if control เป็น 1 ค่อย NOT ตัว target” — สัญลักษณ์ ● (control) เชื่อมเส้นตั้งไป ⊕ (target)
  2. ในภาษา operator pairs: CNOT = NOT แบบเลือกคู่ — สลับเฉพาะคู่ที่บิต control เป็น 1
  3. CNOT เป็น inverse ของตัวเอง (ทำสองครั้ง = ไม่ได้ทำ)
  4. ถ้า control อยู่ใน superposition → ได้ Bell pair = entanglement จริงครั้งแรก
  5. Bell's theorem: ความสัมพันธ์นี้อธิบายด้วย local hidden variables ไม่ได้ — แต่ก็ส่งข้อมูลเร็วกว่าแสงไม่ได้

CNOT — “if” ตัวแรกของ QPU และ Bell pair

1. ปัญหาที่ค้างไว้: gate เดี่ยวไปไม่ถึง

ทุก gate ที่เราเรียนมาจนถึงบท 0008 (NOT, HAD, PHASE, RNOT …) เป็น single-qubit gate ทั้งหมด — ยิงใส่เส้นเดียว จับ operator pairs ของเส้นนั้น แล้วทำเหมือนกันทุกคู่ ไม่ว่าอีก qubit จะเป็นอะไรก็ตาม มันจึงไม่มีทางสร้างความสัมพันธ์ระหว่าง qubit ได้เลย

สไลด์ 40 นิยามของใหม่ว่า multi-qubit operation คือ operation ที่ “ต้องใช้ qubit มากกว่าหนึ่งตัว ถึงจะทำงานได้” และตัวแรกที่เราจะเจอคือ CNOT

2. CNOT คืออะไร — คิดเป็น “if” ก่อน

นิยามจากสไลด์ 40

“Apply the NOT operation to a target qubit, but only if a condition qubit has the value 1.” — แปลไทย: NOT ตัว target ก็ต่อเมื่อ qubit ควบคุม (control) มีค่าเป็น 1

ถ้าคิดแบบโปรแกรมเมอร์ก็คือ if (control == 1) target = NOT target; เท่านั้นเอง — ตรงนี้ ยังไม่มีอะไรควอนตัมเลย CPU ธรรมดาก็ทำ conditional logic ได้ (สไลด์ 44 ย้ำเองเลยค่ะ) ความมหัศจรรย์จะโผล่ตอนหัวข้อ 5

สัญลักษณ์วงจร (ข้อสอบชอบออก!)

CNOT
● = control · ⊕ = target
NOT (เทียบให้ดู)
ไม่มี ● ไม่มีเส้นตั้ง
จุดที่วาดผิดกันบ่อย

จุดทึบ ● อยู่ฝั่ง control · ⊕ อยู่ฝั่ง target เสมอ — สลับกันแล้วความหมายเปลี่ยนคนละเรื่อง และ ต้องมีเส้นตั้งเชื่อม สองเส้นเข้าด้วยกัน ถ้าไม่มีเส้นตั้ง = มันคือ gate เดี่ยวสองตัวที่บังเอิญอยู่คอลัมน์เดียวกัน ไม่ใช่ CNOT ค่ะ

3. CNOT ในภาษา operator pairs — “NOT ที่เลือกคู่มากขึ้น”

บท 0008 เราสรุปว่า NOT = สลับทุกคู่ ของ operator pairs ของเส้นนั้น CNOT ก็ใช้กติกาเดียวกันเป๊ะ แค่เพิ่มเงื่อนไข: สลับเฉพาะคู่ที่บิตของ control เป็น 1 (สไลด์ 41–42)

สไลด์ 42 ใช้ register 3 qubit วาดเทียบให้ดู โดย target = 0x1 และ control = 0x2:

คู่ของ 0x1 (target)บิต 0x2 ของคู่นั้นNOT เดี่ยวCNOT (control 0x2)
|0⟩ ↔ |1⟩  (000, 001)0สลับไม่ทำอะไร
|2⟩ ↔ |3⟩  (010, 011)1สลับสลับ
|4⟩ ↔ |5⟩  (100, 101)0สลับไม่ทำอะไร
|6⟩ ↔ |7⟩  (110, 111)1สลับสลับ
NOT เดี่ยวสลับ 4 คู่ · CNOT สลับแค่ 2 คู่ — คือค่าที่มี 1 อยู่ในบิตที่สอง (2, 3, 6, 7) ตรงตามสไลด์ 42
สูตรจำสั้นๆ

gate เดี่ยวกระทบ ครึ่งหนึ่ง ของสถานะ (บท 0008) → CNOT กระทบแค่ 1 ใน 4 เพราะโดนตัดด้วยเงื่อนไข control อีกชั้น (สูตรทั่วไป: control k ตัว → กระทบ 1/2k+1 ซึ่งจะได้ใช้อีกในบท 0010)

เช็คความเข้าใจ ① — register 3 qubit (วง |0⟩…|7⟩) ยิง CNOT โดยให้ control = 0x4 และ target = 0x1 จะสลับวงคู่ไหนบ้าง? (ลองหาเองก่อนนะคะ)
เป๊ะค่ะ! วิธีคิด: คู่ มาจาก target (0x1) → (0,1)(2,3)(4,5)(6,7) · เงื่อนไข มาจาก control (0x4) → เอาเฉพาะคู่ที่บิต 0x4 เป็น 1 คือค่า 4–7 → เหลือ (4,5) กับ (6,7)
ยังไม่ใช่ค่ะ — แยกสองขั้นให้ชัด: ใครกำหนดคู่ = target (0x1 → คู่ที่ต่างกัน 1 คือ (0,1)(2,3)(4,5)(6,7)) · ใครกำหนดว่าคู่ไหนได้สลับ = control (0x4 → ต้องเป็นค่า 4,5,6,7) ตัดกันแล้วได้ (4,5) และ (6,7)

4. CNOT ย้อนกลับตัวเองได้

สไลด์ 43: เหมือน NOT เลยค่ะ — CNOT เป็น inverse ของตัวเอง ทำสองครั้งติดกันจะกลับไปสถานะเดิม เหตุผลง่ายมากในภาษา operator pairs: “สลับคู่เดิมสองครั้ง” = ไม่ได้สลับ ส่วนคู่ที่ไม่โดนก็ไม่โดนทั้งสองรอบ

5. คำถามสำคัญ: ถ้า control อยู่ใน superposition ล่ะ?

นี่คือจุดที่บทนี้เปลี่ยนจาก “if ธรรมดา” เป็นฟิสิกส์ค่ะ (สไลด์ 44–50) วงจรที่ใช้สั้นมาก แค่ HAD หนึ่งตัว + CNOT หนึ่งตัว บน register 2 qubit ที่ตั้งต้นเป็น |0⟩:

สไลด์ 45 · qubit ชื่อ a (เส้นบน = น้ำหนักน้อยสุด) และ b — a เป็น control · b เป็น target ปิดท้ายด้วย detector (READ) ทั้งสองเส้น

เดินทีละสเต็ป

0) ตั้งต้น |0⟩ (ทั้งคู่เป็นศูนย์) → วง |0⟩ เต็ม 100% วงอื่นว่าง (สไลด์ 45)
1) HAD ใส่ a — a คือ qubit น้ำหนักน้อยสุด → superposition ของ 0 กับ 1 → วง |0⟩ กับ |1⟩ อย่างละ 50% (สไลด์ 46–47)
2) CNOT (control a, target b) — คู่ของ target b คือ (0,2) และ (1,3) เงื่อนไข a=1 → เอาเฉพาะคู่ (1,3) → สลับวง |1⟩ กับ |3⟩ (สไลด์ 49)
3) ผลลัพธ์: |0⟩ 50% และ |3⟩ 50% — วง |1⟩ กับ |2⟩ ว่างเปล่า (สไลด์ 48)
|0⟩ 50%
|1⟩ 0
|2⟩ 0
|3⟩ 50%
สถานะนี้มีชื่อว่า Bell pair (คู่เบลล์) — เขียนเป็น |00⟩ + |11⟩√2

สไลด์ 48 อธิบายด้วย “เหตุผลแบบ if” ว่า: ถ้า a เป็น 0 → ไม่ทำอะไรกับ b → ทั้ง register เป็น 00 = |0⟩ แต่ถ้า a เป็น 1 → b โดน NOT → ทั้ง register เป็น 11 = |3⟩ และในเมื่อ a อยู่ใน superposition ทั้งสองกรณีก็เกิดขึ้นพร้อมกัน

นี่คือ entanglement ตัวเป็นๆ

อ่านสอง qubit นี้เมื่อไหร่ ผลจะ สุ่ม แต่ ตรงกันเสมอ — ได้ 00 หรือ 11 อย่างละ 50% ไม่มีทางได้ 01 หรือ 10 เลย (สไลด์ 50) ลองนึกถึงเหตุผลของ GHZ ในบท 0008 ดูค่ะ — เขียนแยกเป็น “qubit เดี่ยวสองตัวโยนเหรียญเอง” ไม่ได้ เพราะถ้าอิสระจริงต้องมีโอกาสได้ 01 บ้าง

เช็คความเข้าใจ ② — คราวนี้เปลี่ยนโจทย์: register 2 qubit ตั้งต้นที่ |2⟩ (คือ b=1, a=0) แล้วทำ HAD ใส่ a ตามด้วย CNOT (control a, target b) ผลลัพธ์คือสถานะไหน? (คำนวณเองก่อนนะคะ)
ถูกต้องค่ะ! ไล่ดู: |2⟩ → HAD ใส่ a ได้ |2⟩ + |3⟩ (10 กับ 11) → CNOT คู่ (1,3) โดนสลับ ส่วน (0,2) ไม่โดน → วง |3⟩ ย้ายไป |1⟩ เหลือ |1⟩ + |2⟩ = (|01⟩+|10⟩)/√2 นี่คือ Bell state อีกตัวที่ผลอ่านตรงข้ามกันเสมอ — entangled เหมือนกัน แค่สหสัมพันธ์กลับด้าน
ยังไม่ใช่ค่ะ — เดินทีละสเต็ป: |2⟩ = 10 → HAD ใส่ a แตกเป็น |2⟩ (10) กับ |3⟩ (11) → CNOT (control a, target b) สลับคู่ (1,3) เท่านั้น → |3⟩ กลายเป็น |1⟩ ส่วน |2⟩ ไม่โดนแตะ → ได้ |1⟩ + |2⟩ (ผลอ่านตรงข้ามกันเสมอ) ข้อคิด: CNOT ไม่ได้แปลว่า “ตรงกันเสมอ” — ขึ้นกับสถานะตั้งต้นค่ะ
ครึ่งหลัง

entanglement มันแปลกยังไง — และ Bell's theorem

6. “ก็แค่บิตสองตัวที่ตรงกัน จะแปลกตรงไหน?”

สไลด์ 53 ตั้งคำถามนี้เองเลยค่ะ — บิตธรรมดาสองตัวที่สุ่มแล้วตรงกันเสมอ ไม่เห็นน่าตกใจตรงไหน เพราะโลกคลาสสิกมีคำอธิบายที่ “ธรรมดามาก” อยู่ สองแบบ (สไลด์ 54):

① common cause (สาเหตุร่วมในอดีต) มีอะไรบางอย่างในอดีตบังคับให้ค่าทั้งสองเท่ากันไว้แล้ว เช่นก๊อปปี้กันมาตั้งแต่แรก → ถ้าเป็นแบบนี้ ความสุ่มที่เห็นเป็นแค่ภาพลวง (ค่าถูกกำหนดไว้แล้ว เราแค่ยังไม่รู้)
② communication (สื่อสารกันตอนอ่าน) ค่าสุ่มจริงๆ ณ วินาทีที่อ่าน แต่ทั้งสองตัวคุยกันทันเพื่อให้ตรงกัน

สไลด์ 55 ย้ำประโยคสำคัญ: “สองแบบนี้คือคำอธิบายเดียวที่เป็นไปได้” สำหรับบิตคลาสสิก — ซึ่งแปลว่า ถ้าใครพิสูจน์ได้ว่า Bell pair ไม่ใช่ทั้งสองแบบ ก็แปลว่ามันไม่ใช่ของคลาสสิกอีกต่อไป

7. Bell's theorem — วิธีตัดสิน

John Bell เสนอการทดลองที่ตัดสินเรื่องนี้ได้เด็ดขาด (สไลด์ 56–57) วิธีคิดคือ:

  1. สมมติว่าโลกเป็นคลาสสิกจริง — มี local hidden variables (ตัวแปรซ่อนเร้นเฉพาะที่) คือ “ค่าถูกกำหนดล่วงหน้าไว้แล้ว เราแค่มองไม่เห็น” และ ไม่มีอะไรเดินทางเร็วกว่าแสง
  2. Bell พิสูจน์ว่าถ้าเป็นแบบนั้น ตัวเลขสหสัมพันธ์ที่วัดได้ต้องอยู่ในกรอบหนึ่ง เสมอ — กรอบนี้เรียกว่า Bell inequalities (อสมการเบลล์)
  3. ทดลองจริงกับอนุภาคพัวพัน → ผลออกมาเกินกรอบ คือ ละเมิด Bell inequalities ซ้ำแล้วซ้ำเล่า (สไลด์ 58)
สรุปที่ต้องตอบได้

ไม่มีทฤษฎีคลาสสิกแบบ local hidden variable ใดๆ เลียนแบบผลของควอนตัมได้ — entanglement จึงเป็น ทรัพยากรทางฟิสิกส์ที่มีอยู่จริง (real physical resource) ไม่ใช่แค่ปัญหาปรัชญาหรือความรู้ที่เรายังขาด (สไลด์ 59)

กับดักยอดฮิต

“ละเมิด Bell inequality” ไม่ได้แปลว่าส่งข้อมูลเร็วกว่าแสงได้นะคะ สไลด์ 58 เขียนชัดว่า “It does not enable faster-than-light communication” — มันแค่ ตัดคำอธิบายแบบคลาสสิกทิ้ง เท่านั้น เหตุผลว่าทำไมส่งข้อมูลไม่ได้ อยู่ในหัวข้อ 8 ค่ะ

เช็คความเข้าใจ ③ — ผลการทดลองที่ “ละเมิด Bell inequalities” สรุปอะไรได้?
ใช่เลยค่ะ — Bell's theorem ตัดตัวเลือกทิ้ง ไม่ได้บอกว่ามีสัญญาณวิ่ง: คำอธิบาย ① (สาเหตุร่วม/ค่าถูกกำหนดไว้แล้ว) ถูกตัดโดยการละเมิดอสมการ ส่วน ② (สื่อสารกัน) ถูกตัดด้วยข้อจำกัดความเร็วแสง → เหลือข้อสรุปเดียว: ธรรมชาติเป็นควอนตัมโดยเนื้อแท้ (สไลด์ 59)
ยังไม่ใช่ค่ะ — ตัวเลือกที่พี่เลือกเป็นคำอธิบายที่ ถูกตัดทิ้งไปแล้ว พอดี ข้อสรุปจริงคือ “ไม่มีทฤษฎี local hidden variable ใดอธิบายได้” และสไลด์ 58 ย้ำว่า ส่งข้อมูลเร็วกว่าแสงไม่ได้ ด้วย

8. เอาไปใช้จริง: Bell pair = ความสุ่มที่แชร์กันได้

สไลด์ 60 พลิกจากฟิสิกส์มาเป็นวิศวกรรม: ถ้าเราแยก qubit สองตัวของ Bell pair ไปคนละที่ (entanglement ไม่สนระยะทาง) แล้วต่างคนต่างอ่าน — ทั้งคู่จะได้ เลขสุ่มตัวเดียวกัน โดยไม่ต้องส่งอะไรหากันเลย

qubit เดี่ยว + HADอ่านแล้วได้เลขสุ่ม 1 บิต
(QRNG จากบท 0006)

Bell pairอ่านแล้วได้เลขสุ่ม 1 บิต

ความสุ่มที่ตรงกันโดยไม่ต้องส่งข้อความ = shared randomness ซึ่งสไลด์ 60 บอกว่าเป็น “fundamental building block ของความปลอดภัยบนอินเทอร์เน็ตยุคใหม่” (คิดถึงกุญแจลับที่สองฝ่ายมีตรงกัน โดยไม่เคยส่งกุญแจผ่านสายเลย)

แล้วทำไมส่งข้อมูลเร็วกว่าแสงไม่ได้?

เพราะ ไม่มีใครเลือกได้ว่าผลจะออกอะไร ค่ะ ฝั่งที่อ่านก่อนได้เลขสุ่ม จะบังคับให้เป็น 0 หรือ 1 ตามใจไม่ได้ → เลยส่งข้อความไม่ได้ ได้แค่ความสุ่มที่ตรงกัน และอีกฝั่งก็ไม่มีทางรู้ว่าเราอ่านไปแล้วหรือยัง จนกว่าจะเทียบกันผ่านช่องทางปกติ (ช้ากว่าแสงเสมอ) — ประเด็นนี้จะได้ลงมือทำเองใน capstone บท 0012

  • b.cnot(a) อ่านว่า “b โดน CNOT โดยมี a เป็น control” — ตัวที่เขียนนำหน้าจุดคือ target ส่วนตัวในวงเล็บคือ control (คนสับสนตรงนี้บ่อยมากค่ะ)
  • รันซ้ำหลายรอบ: ค่าที่ออกสุ่มทุกครั้ง แต่ a_result กับ b_result จะเท่ากันเสมอ — นั่นแหละหลักฐาน entanglement
เช็คความเข้าใจ ④ — ถ้าลบบรรทัด a.had(); ทิ้งไป (เหลือแค่ CNOT) ผลการรันจะเป็นยังไง?
ถูกต้องค่ะ! ประเด็นคือ CNOT เพียงลำพังไม่ได้สร้าง entanglement — มันเป็นแค่ if ธรรมดา ต้องมี superposition ที่ control ก่อน (HAD) มันถึงจะ “ทำทั้งสองกรณีพร้อมกัน” แล้วเกิดการพัวพัน นี่คือใจความของสไลด์ 44
ยังไม่ใช่ค่ะ — ถ้าไม่มี HAD สถานะยังเป็น |0⟩ นิ่งๆ → control = 0 → CNOT ไม่ทำอะไร → อ่านได้ 0 กับ 0 ทุกรอบ ไม่มีความสุ่ม ข้อสรุป: CNOT ลำพังไม่สร้าง entanglement — ต้องคู่กับ superposition ที่ control
เช็คความเข้าใจ ⑤ — แอนกับบ๊อบถือ qubit คนละตัวของ Bell pair แอนอ่านได้ 1 ข้อไหนบรรยายสถานการณ์ได้ถูกต้อง?
เป๊ะค่ะ! สองส่วนต้องถูกทั้งคู่: (ก) ผลตรงกันเสมอ (สไลด์ 50) และ (ข) เลือกผลไม่ได้ → ส่งข้อมูลไม่ได้ (สไลด์ 58) สิ่งที่ได้จริงคือ shared randomness เท่านั้น
ยังไม่ใช่ค่ะ — จำเป็นคู่: ผลตรงกันเสมอ (ไม่ใช่ 50/50 อีกแล้วหลังแอนอ่าน) แต่ แอนบังคับผลตัวเองไม่ได้ จึงส่งข้อความไม่ได้ และ Bell's theorem ก็ไม่ได้บอกว่ามี “สัญญาณวิ่ง” — มันบอกว่าคำอธิบายแบบคลาสสิกใช้ไม่ได้ต่างหาก
🧠 ทบทวนจากความจำก่อนเปิดดู (ปิดหน้าจอ พูดออกมาดังๆ / วาดลงกระดาษ)
  1. วาดสัญลักษณ์ CNOT บน register 2 เส้น โดยให้เส้นบนเป็น target — วาดถูกไหม?
  2. register 3 qubit · CNOT control 0x1 target 0x4 → สลับวงคู่ไหนบ้าง (บอกครบ)
  3. ทำไม CNOT ถึงกระทบแค่ 1 ใน 4 ของวงทั้งหมด ในขณะที่ NOT กระทบครึ่งหนึ่ง
  4. คำอธิบายแบบคลาสสิกสองแบบสำหรับ “บิตสุ่มที่ตรงกัน” คืออะไร และ Bell ตัดทิ้งได้ยังไง
  5. Bell pair ให้อะไรกับเราได้จริง และให้ไม่ได้อะไร

เฉลยย่อ: 1) ⊕ บนเส้นบน · ● บนเส้นล่าง · มีเส้นตั้งเชื่อม   2) คู่จาก target 0x4 = (0,4)(1,5)(2,6)(3,7) แล้วกรองด้วย control 0x1=1 → (1,5) และ (3,7)   3) เพราะ target ตัดครึ่งหนึ่ง (จับคู่) แล้ว control ตัดอีกครึ่ง   4) common cause / communication — Bell inequality ถูกละเมิดตัดแบบแรก, ความเร็วแสงตัดแบบหลัง   5) ให้ shared randomness · ให้การส่งข้อมูลเร็วกว่าแสงไม่ได้

10. สรุปก่อนไปบทหน้า

  • CNOT = NOT ตัว target เมื่อ control เป็น 1 · สัญลักษณ์ ●—⊕ เชื่อมด้วยเส้นตั้ง
  • ในภาษา operator pairs: คู่มาจาก target · เงื่อนไขมาจาก control → กระทบ 1 ใน 4
  • CNOT เป็น inverse ของตัวเอง
