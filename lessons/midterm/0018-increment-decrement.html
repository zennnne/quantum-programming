Quantum Programming · Lec 05 · บทที่ 0018

increment / decrement — เลขคณิตตัวแรกบน QPU

บท 0017 วางกติกาไว้แล้ว ว่า operation บน QPU คัดลอกไม่ได้ และ ต้องย้อนกลับได้ · บทนี้เราจะสร้าง วงจรบวก 1 / ลบ 1 ขึ้นมาจริงๆ ภายใต้กติกานั้น — และมันคือ วงจรแม่ของทั้งคาบค่ะ วงจรบวกเลขสองตัว · negate · conditional execution ในบทถัดๆ ไป ล้วนเป็นวงจรตัวนี้ที่ถูกดัดแปลง

บทนี้จับ 3 อย่าง
① อ่านวงจร +1 / −1 บน qunibble (4 qubit) ให้ออก — และเห็นว่า decrement คือ increment กลับด้านเป๊ะ
② หลักเบื้องหลังมันคือ การทดเลข (carry) ที่เราเรียนมาตั้งแต่ประถม เขียนใหม่ด้วย multi-condition CNOT
③ ตรวจวงจรนี้ด้วยเกณฑ์ “ควอนตัมจริง” 2 ข้อ แล้วต่อยอดเป็น add(12) ที่มี overflow wrap

ส่วนที่ 1 — วงจร +1 / −1 กับหลักการทดเลข

ปูพื้นก่อน: บวก 1 ในเลขฐานสอง เกิดอะไรขึ้นบ้าง

เราใช้ qunibble (quantum integer 4 qubit) ตามที่ปูไว้ในบทที่แล้ว · สายทั้งสี่มีชื่อตาม ค่าประจำหลัก แบบเลขฐานสิบหก: 0x1 (บิตต่ำสุด), 0x2, 0x4, 0x8 (บิตสูงสุด) รวมแล้วนับได้ 0–15

refresher: การทดเลขฐานสอง — ลองบวก 1 ทีละกรณีแล้วสังเกตว่า “บิตไหนพลิก”
0100 + 1 = 0101 → พลิกแค่บิต 0x1
0101 + 1 = 0110 → บิต 0x1 เป็น 1 อยู่ จึงทดขึ้นไปพลิกบิต 0x2 ด้วย
0111 + 1 = 1000 → บิตล่าง 3 ตัวเป็น 1 หมด จึงทดขึ้นไปถึงบิต 0x8
กฎที่ได้: บิตหนึ่งจะพลิก ก็ต่อเมื่อบิตที่ต่ำกว่ามันทั้งหมดเป็น 1

อ่านกฎนั้นอีกรอบช้าๆ ค่ะ — “ถ้าบิตล่างเป็น 1 ครบทุกตัว ค่อยพลิกบิตนี้” — นี่คือ คำนิยามของ multi-condition CNOT เป๊ะๆ เลย · บิตล่างคือ control (●) และบิตที่จะพลิกคือ target (⊕)

บิตที่จะพลิกเงื่อนไข (ทดเลข)gate ที่ใช้
0x80x1, 0x2, 0x4 เป็น 1 ทั้งหมดNOT ที่มี 3 control
0x40x1, 0x2 เป็น 1 ทั้งคู่CCNOT (Toffoli)
0x20x1 เป็น 1CNOT
0x1ไม่มีเงื่อนไข — พลิกเสมอNOT เดี่ยว

เอาสี่แถวนี้มาเรียงเป็นวงจร ก็ได้ increment ครบแล้วค่ะ

ทำไมต้องเรียง “control เยอะ → control น้อย”

จุดนี้เป็นหัวใจที่หลุดง่ายที่สุดของบทค่ะ · เงื่อนไขการทดทุกข้อพูดถึง ค่าของบิตล่าง “ก่อน” บวก · ถ้าเราพลิกบิต 0x1 ไปก่อน (เอา X:0 ขึ้นหน้า) gate ที่เหลือจะไปอ่านค่าที่เปลี่ยนไปแล้ว → ทดผิดทั้งแถบ

การเรียงจาก control มากที่สุดลงมา ทำให้ทุก gate ได้อ่านบิตล่างในสภาพเดิมเสมอ gate ที่พลิกบิตล่าง จะถูกทำเป็นตัวสุดท้ายเสมอ

โจทย์ a = ∣3⟩ = 0011₂ (0x1=1, 0x2=1, 0x4=0, 0x8=0) — เดินทีละ gate
① NOT 3 control ที่ 0x8 : ต้องการ 0x1,0x2,0x4 = 1 ครบ · แต่ 0x4 = 0 → ไม่ทำงาน · ค่ายังเป็น 0011
② CCNOT ที่ 0x4 : ต้องการ 0x1,0x2 = 1 ทั้งคู่ · เป็นจริง → พลิก 0x4 → 0111
③ CNOT ที่ 0x2 : ต้องการ 0x1 = 1 · เป็นจริง → พลิก 0x2 → 0101
④ NOT ที่ 0x1 : พลิกเสมอ → 0100 = ∣4⟩ ✓ (3 + 1 = 4)
ประโยคทองของสไลด์ (หน้า 21): วงจร increment เริ่มด้วย three-condition CNOT ที่สั่งว่า “ถ้าบิตล่างของ integer เป็น 1 ทุกตัว ค่อยพลิกบิตบนสุด” — นี่คือ carry operation ของเลขคณิตแบบเดิมตรงๆ · ทำซ้ำไล่ลงมาทีละบิต ก็ได้ add-and-carry เต็มรูปแบบ โดยใช้ multi-condition CNOT อย่างเดียวทั้งวงจร

decrement = increment ที่กลับลำดับ

ไม่ต้องออกแบบวงจรลบใหม่เลยค่ะ · แค่เอา gate ชุดเดิมมาเรียงย้อนหลัง ก็ได้ −1 ทันที — ซึ่งเป็นผลพลอยได้ตรงๆ จากกติกาข้อ 2 (ทุก op ต้อง reversible) ที่เรียนไปบทที่แล้ว · ข้างล่างคือวงจรเต็มตามสไลด์ ทั้ง prepare · increment · decrement

สังเกตกล่อง prepare ไว้ก่อนนะคะ — เขียนค่า 1 ลง register แล้วใส่ HAD กับ PHASE(45°) ที่สาย 0x4 · เดี๋ยวส่วนที่ 2 จะอธิบายว่ามันเตรียม superposition อะไรไว้ให้เรา

// QCEngine — สไลด์หน้า 13–14
var num_qubits = 4;  qc.reset(num_qubits);
var a = qint.new(num_qubits, 'a');

a.write(1);              // prepare
a.hadamard(0x4);
a.phase(45, 0x4);

a.add(1);                // increment
a.subtract(1);           // decrement

ในโค้ดจริงเราไม่ได้ไล่วาง gate เองค่ะ — เรียก a.add(1) / a.subtract(1) ระดับ integer แล้ว QCEngine กางเป็นวงจรข้างบนให้ (นี่คือประเด็น “เขียนโปรแกรมระดับ quantum integer” จากบท 0017 ที่เห็นผลจริงครั้งแรก)

ลองคิดดู: ทำไมวงจร increment ต้องเรียงจาก gate ที่มี control เยอะที่สุดก่อน แล้วจบด้วย NOT เดี่ยวที่บิตต่ำสุด?
ถูกต้องค่ะ! ทุกเงื่อนไขการทดพูดถึงค่าก่อนบวก ของบิตล่าง · ถ้าเอา X:0 ขึ้นก่อน gate ที่เหลือจะอ่านค่าที่เปลี่ยนไปแล้ว → ผลผิดทันที · ลองไล่ ∣3⟩ ด้วยลำดับกลับดูก็ได้ค่ะ จะได้ ∣0⟩ แทนที่จะเป็น ∣4⟩
ยังไม่ใช่ค่ะ — gate ทุกตัวในวงจรนี้ “ทำพร้อมกันไม่ได้” ก็จริง แต่เหตุผลไม่ใช่เรื่องเวลาหรือน้ำหนักหลัก · มันคือเรื่องลำดับการอ่านค่า: เงื่อนไขทดทุกข้ออ้างถึงบิตล่างก่อนบวก จึงต้องพลิกบิตล่างเป็นอย่างสุดท้าย

ส่วนที่ 2 — วงจรนี้ “ควอนตัมจริง” ไหม? แล้วต่อยอดเป็น add(12)

ตอนนี้เรามีวงจรบวกเลขแล้ว · แต่วงจรที่บวกเลขได้ ยังไม่ได้แปลว่ามันควอนตัม — วงจรบวกในซีพียูก็บวกได้เหมือนกัน · สไลด์หน้า 15 ตั้งเกณฑ์ไว้ 2 ข้อ ให้ตรวจ

① Reversibility
ต้องย้อนกลับได้ · ตรวจแล้ว ✓ — decrement คือ increment ที่เรียง operation ย่อยกลับด้าน · ต่างจาก logic แบบเดิมที่ input/output แยกขาตายตัว จับมารันย้อนทางแล้วพัง (สไลด์หน้า 16)
② Superposition operation
ต้องทำงานกับ input ที่เป็น superposition ได้ ไม่ใช่แค่ค่าเดียว · ข้อนี้ต้องพิสูจน์ด้วยการดู circle notation ก่อน/หลัง (สไลด์หน้า 17–20)

กล่อง prepare เตรียมอะไรไว้ให้เรา

ย้อนไปดูกล่อง prepare: write(1) → hadamard(0x4) → phase(45, 0x4)

  • เขียน 1 → register อยู่ที่ ∣1⟩ (0001₂)
  • HAD ที่บิต 0x4 → บิตนั้นแตกเป็น 0 กับ 1 พร้อมกัน → ได้ ∣1⟩ กับ ∣1+4⟩ = ∣5⟩ อย่างละครึ่ง
  • PHASE(45°) ที่บิต 0x4 → หมุนเข็มเฉพาะวงที่บิต 0x4 เป็น 1 = ∣5⟩ เท่านั้น (มุมบวก = ทวนเข็ม)
∣ψ⟩ = ( ∣1⟩ + ei·45°∣5⟩ ) / √2

16 วง (4 qubit = 2⁴ = 16 ค่า) · มีแค่ ∣1⟩ กับ ∣5⟩ ที่มีพื้นที่ อย่างละ 50% · เข็มของ ∣1⟩ ชี้ขึ้นตรง (0°) ส่วน ∣5⟩ เอียงไป 45° ทวนเข็ม

รัน increment แล้วเกิดอะไรขึ้น

∣ψ⟩ = ( ∣2⟩ + ei·45°∣6⟩ ) / √2

อ่านภาพนี้ให้ครบสองชั้นนะคะ:

  1. ทุกวงเลื่อนไปทีละ 1 ตำแหน่ง พร้อมกัน — 1→2 และ 5→6 · gate ชุดเดียวทำงานกับ ทุกกิ่งของ superposition พร้อมกัน ไม่ต้องรันสองรอบ ⇒ ผ่านเกณฑ์ข้อ ②
  2. เฟสติดไปกับค่าด้วย — ∣5⟩ ที่มีเข็ม 45° กลายเป็น ∣6⟩ ที่ยังมีเข็ม 45° · increment ไม่ไปยุ่งกับ magnitude หรือ phase ของใครเลย มันย้ายป้ายชื่ออย่างเดียว
จำภาพนี้ไว้: operation เลขคณิตบน QPU = การสับเปลี่ยนตำแหน่งของวง โดยพกทั้งขนาดและเข็มติดตัวไปด้วย · ที่มันย้อนกลับได้ก็เพราะเป็นการสับเปลี่ยน (permutation) ไม่ใช่การทับค่า — ตรงกับกติกาข้อ 2 ของบท 0017 พอดี
ลองคิดดู: ถ้ารัน a.subtract(1) กับสถานะ ( ∣1⟩ + ei·45°∣5⟩ )/√2 แทนที่จะเป็น add — จะได้อะไร?
ถูกต้องค่ะ! decrement เลื่อนทุกวงถอยหลัง 1 ตำแหน่ง พร้อมพกเฟสไปด้วยเหมือนเดิม → 1→0 และ 5→4 · เข็มของ ∣4⟩ ยังเป็น 45° เท่าเดิม เพราะวงจรนี้ไม่แตะเฟสของใคร
ยังไม่ใช่ค่ะ — ข้อ 2 คือผลของ add (เลื่อนไปข้างหน้า) ส่วนข้อ 3 ผิดตรงที่ไปเปลี่ยนเฟสเป็น 90° · จำหลักไว้: วงจรตระกูลนี้ ย้ายตำแหน่งวงอย่างเดียว ไม่แตะเข็ม

ต่อยอด: บวกด้วยเลขอื่นที่ไม่ใช่ 1

ถ้าไม่ได้อยากบวก 1 ล่ะ? เรียก a.add(12) ได้เลย — แต่จุดที่น่าสนใจคือ วงจรที่ได้ออกมาหน้าตาคนละเรื่องเลย เหลือแค่ 2 gate เท่านั้น

เหตุผลอยู่ที่เลขฐานสองของ 12 ค่ะ: 12 = 1100₂ — มีแต่บิต 0x8 กับ 0x4 ที่เป็น 1 · บิต 0x1 กับ 0x2 ไม่โดนอะไรเลย วงจรเลยไม่ต้องมี gate ไปแตะสองสายล่างสุด

โจทย์ ไล่ทั้งสองกิ่งพร้อมกัน — เริ่มจาก a = ∣1⟩ = 0001 และ a = ∣5⟩ = 0101
① X:0x4 (พลิกบิต 0x4 เสมอ) · 0001 → 0101 · 0101 → 0001
② CNOT: 0x4 → 0x8 · กิ่งแรก 0x4 = 1 → พลิก 0x8 → 1101 = ∣13⟩ · กิ่งสอง 0x4 = 0 → ไม่พลิก → 0001 = ∣1⟩
ตรวจ 1 + 12 = 13 ✓ · 5 + 12 = 17 → ล้นช่วง 4 บิต วนกลับเป็น 17 − 16 = 1 ✓
∣ψ⟩ = ( ei·45°∣1⟩ + ∣13⟩ ) / √2

ดูเข็มให้ดีนะคะ — ∣1⟩ ในภาพนี้มีเข็ม 45° ทั้งที่ตอนแรก ∣1⟩ เข็มตั้งตรง · เพราะวงที่มาลงตำแหน่ง 1 ตอนนี้คือวงที่เคยเป็น ∣5⟩ (ซึ่งพกเข็ม 45° มาด้วย) · ส่วน ∣13⟩ ที่เข็มตั้งตรงคือวงที่เคยเป็น ∣1⟩ เฟสเดินตามค่าไปทุกที่

ข้อจำกัดที่สไลด์เน้น (หน้า 23): โปรแกรมนี้บวก ค่าดิจิทัลคงที่ เข้ากับ quantum register — ตัวเลขที่จะบวกถูก “ฝัง” อยู่ในตัววงจรเอง · อยากบวกเลขอื่นเมื่อไหร่ ต้องเปลี่ยนชุด gate ใหม่ทั้งชุด · แล้วถ้าอยากบวกค่าควอนตัมสองตัวเข้าด้วยกันล่ะ? ค่าที่จะบวกก็อยู่ใน superposition เหมือนกัน → เปลี่ยน gate ตามไม่ทันแน่ๆ นั่นคือโจทย์ของบท 0019
ลองคิดดู: ถ้ารัน a.add(12) กับ a = ∣5⟩ (ค่าเดียว ไม่ใช่ superposition) ผลลัพธ์คือ?
ถูกต้องค่ะ! qunibble มี 4 qubit = เก็บได้แค่ 0–15 · 5 + 12 = 17 จึงวนกลับเป็น 17 mod 16 = 1 — พฤติกรรมเดียวกับ integer overflow ของภาษาโปรแกรมทั่วไปเลยค่ะ ไม่ใช่เรื่องควอนตัมพิเศษอะไร
ยังไม่ใช่ค่ะ — register ขยายตัวเองไม่ได้ (มี 4 สายก็คือ 4 สาย) และวงจรก็บวก 12 เต็มๆ ไม่ได้บวกแค่ 4 · สิ่งที่เกิดคือ overflow wrap: 17 mod 16 = 1 → ได้ ∣1⟩
ทดสอบความจำก่อนปิดบท — ตอบในใจก่อนกดดูเฉลย (8 ข้อ)
  1. qunibble คือ? — quantum integer ขนาด 4 qubit · สายชื่อ 0x1, 0x2, 0x4, 0x8 ตามค่าประจำหลัก · เก็บค่าได้ 0–15
  2. กฎการทดเลขฐานสอง? — บิตหนึ่งจะพลิกเมื่อบวก 1 ก็ต่อเมื่อ บิตที่ต่ำกว่ามันทั้งหมดเป็น 1
  3. วงจร increment เรียงยังไง? — NOT 3 control (→0x8) · CCNOT (→0x4) · CNOT (→0x2) · NOT เดี่ยว (→0x1) · จาก control เยอะสุดไปน้อยสุด
  4. ทำไมเรียงแบบนั้น? — เงื่อนไขทดอ้างถึงค่าบิตล่างก่อนบวก จึงต้องพลิกบิตล่างเป็นอันสุดท้าย
  5. decrement มาจากไหน? — increment ที่เอา gate มาเรียงย้อนลำดับ ทั้งกล่อง
  6. เกณฑ์ “ควอนตัมจริง” 2 ข้อ? — ① Reversibility ② Superposition operation
  7. increment ทำอะไรกับ circle notation? — เลื่อนทุกวงไป 1 ตำแหน่งพร้อมกัน โดยพก magnitude และ phase ติดไปด้วย (∣1⟩+ei45°∣5⟩ → ∣2⟩+ei45°∣6⟩)
  8. ทำไม add(12) มีแค่ 2 gate? — 12 = 1100₂ แตะแค่บิต 0x4 กับ 0x8 · วงจรขึ้นกับตัวเลขที่บวก · และผลลัพธ์ wrap เมื่อล้น (5+12 → ∣1⟩)
สรุปบทนี้ใน 3 บรรทัด
① วงจร +1 = การทดเลข ที่เขียนใหม่ด้วย multi-condition CNOT เรียงจาก control เยอะไปน้อย · −1 = วงจรเดิมกลับลำดับ
② มันควอนตัมจริงทั้ง 2 ข้อ — ย้อนกลับได้ และเลื่อนทุกวงใน superposition พร้อมกัน โดยพกเฟสไปด้วย
③ add(12) โชว์ว่าวงจรขึ้นกับตัวเลขคงที่ที่จะบวก + มี overflow wrap — ข้อจำกัดนี้เองที่ผลักเราไปสู่ a += b ในบทหน้า
