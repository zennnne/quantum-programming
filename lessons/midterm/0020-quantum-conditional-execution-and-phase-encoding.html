Quantum Programming · Lec 05 · บทที่ 0020

เงื่อนไขแบบควอนตัม และการเก็บคำตอบไว้ในเฟส

สามบทที่ผ่านมาเราสร้าง “เครื่องคิดเลข” ของ QPU จนครบ — +1 / −1, a += b, เลขติดลบ บทนี้คือจุดที่สไลด์ตั้งชื่อหัวข้อว่า “Getting Really Quantum” ค่ะ — เราจะเอาเลขคณิตพวกนั้นมารันแบบ มีเงื่อนไข ทั้งที่ตัวเงื่อนไขเองยังอยู่ใน superposition (คือทั้งทำและไม่ทำพร้อมกัน) แล้วปิดท้ายด้วยกลเม็ดที่สำคัญที่สุดของทั้งคาบ: ย้ายคำตอบจาก “ขนาดวง” ไปเก็บไว้ใน “ทิศเข็ม”

บทนี้จับ 3 อย่าง
① quantum-conditional execution — CPU ต้องอ่านค่าก่อนตัดสินใจ แต่ QPU ไม่ต้อง เลยทำได้ทั้งสองทางพร้อมกัน
② ทริกยืมบิตเครื่องหมาย — QPU เช็คได้แค่ “บิตนี้เป็น 1 ไหม” เราจึงเลื่อนค่าให้เงื่อนไขที่อยากได้กลายเป็นบิตเดียว
③ phase-encoded result — วงจรโครงเดิมเป๊ะ เปลี่ยนแค่ไส้กลาง → คำตอบไปอยู่ในเฟส โดยขนาดวงไม่ขยับเลย

ส่วนที่ 1 — เงื่อนไขที่ตัวมันเองอยู่ใน superposition

“if” บน CPU กับ “if” บน QPU ไม่เหมือนกันตรงไหน

บนคอมพิวเตอร์ทั่วไป เวลาเขียน if (x) { … } สิ่งที่ CPU ทำจริงๆ คือ อ่านค่า x ออกมาดูก่อน แล้วค่อยตัดสินใจว่าจะรันบล็อกนั้นหรือไม่ — ตัดสินใจครั้งเดียว ได้คำตอบเดียว

CPU — ต้องอ่านก่อน
ค่าเงื่อนไขเป็น 0 หรือ 1 อย่างใดอย่างหนึ่ง · CPU อ่านมันขึ้นมา แล้วเลือกเส้นทางเดียว → logic ก้อนนั้นรัน หรือ ไม่รัน
QPU — ไม่ต้องอ่าน
ค่าเงื่อนไขเป็นทั้งเซ็ตและไม่เซ็ตพร้อมกันได้ · เราไม่ READ มัน แค่เอาไปเป็น control → logic ก้อนนั้นทั้งรันและไม่รันพร้อมกันในสถานะเดียว
“บน QPU ค่าหนึ่งเป็นทั้งเซ็ตและไม่เซ็ตพร้อมกันใน superposition ได้ ดังนั้น operation ที่ขึ้นกับค่านั้นจะทั้งรันและไม่รันพร้อมกันใน superposition” — และเราเอาแนวคิดนี้ไปใช้กับ logic ก้อนใหญ่ๆ ได้ ไม่ใช่แค่ gate เดียว (slide 33)

พูดให้ตรงขึ้นอีกนิด: มันไม่ใช่เวทมนตร์ใหม่ — เราเห็นมาตั้งแต่ บท 0009 แล้วว่า CNOT ที่ control อยู่ใน superposition จะพลิกและไม่พลิก target พร้อมกัน · ของใหม่ในบทนี้คือ “สเกล” — เราจะเอา วงจรเลขคณิตทั้งก้อน (increment chain ของบท 0018) ไปแขวนไว้ใต้ control ตัวเดียว

โจทย์ของสไลด์: “เพิ่มค่า b ทีละ 1 เฉพาะเมื่อ a อยู่ในช่วงที่กำหนด”

สไลด์ตั้งโจทย์ไว้แบบนี้ — register a 3 qubit อยู่ใน superposition ของ 1 กับ 5 · register b 3 qubit อยู่ใน superposition ของ 1 กับ 3 (โดยกิ่ง b = 3 พกเฟส 45° ติดมาด้วย) · เราอยากได้ b += 1 เฉพาะกิ่งที่ a น้อยกว่า 3

ผลลัพธ์ที่ต้องการคือ b จบลงในสถานะที่ทั้ง “ถูกบวก” และ “ไม่ถูกบวก” พร้อมกัน เพราะกิ่ง a = 1 เข้าเงื่อนไข ส่วนกิ่ง a = 5 ไม่เข้า

ปัญหา: QPU ไม่มีคำสั่ง “ถ้า a < 3”

gate ที่เรามีทั้งหมดควบคุมด้วยสิ่งเดียวเท่านั้น — จุด ● บนสายเส้นหนึ่ง ซึ่งแปลว่า “ทำ ถ้าqubit เส้นนี้เป็น 1” · มันเช็คบิตเดียว ไม่ใช่ช่วงของตัวเลข แล้วเราจะเช็ค “a < 3” ยังไง?

ทริกยืมบิตเครื่องหมาย — ถ้าเช็คช่วงไม่ได้ ก็เลื่อนค่าให้เงื่อนไขกลายเป็นบิตเดียว ทำ a -= 3 ก่อน · ค่าที่เดิมน้อยกว่า 3 จะกลายเป็นค่าติดลบ ซึ่งใน two's complement แปลว่า บิตเครื่องหมาย (0x4) ติด 1 พอดี → เอาบิตนั้นไปเป็น ● ได้ทันที

นี่คือเหตุผลที่บท 0019 ต้องปู two's complement ไว้ก่อนค่ะ — บิตเครื่องหมายที่ “มาฟรี” จากการเข้ารหัสแบบนั้น กลายเป็นตัวเช็คเงื่อนไขให้เราใช้ฟรีๆ

แล้วพอใช้เสร็จ ต้อง a += 3 คืน เพื่อคืนสภาพ a ให้เหมือนเดิม (ศัพท์ที่บท 0021 จะเรียกว่า uncompute) — ไม่งั้น a จะเละไปตลอด ทั้งที่เราแค่ยืมมันมาดูแป๊บเดียว

โค้ด โปรแกรม QCEngine ทั้งหมดมีแค่ 3 บรรทัด (slide 34–35):
a.subtract(3);
// if high bit of a is set then b += 1
b.add(1, a.bits(0x4));
a.add(3);

วงจรเต็ม

ดูเหมือนวงจรใหญ่ แต่จริงๆ มีของใหม่แค่กล่องเดียวค่ะ — อีก 4 กล่องเราอ่านเป็นมาหมดแล้ว:

กล่องคืออะไรเคยเจอที่ไหน
a = (1, 5)WRITE 1 ที่ a·0x1 แล้ว H ที่ a·0x4บท 0005 (HAD สร้าง superposition)
b = (1, 3)WRITE 1 ที่ b·0x1 แล้ว H + PHASE 45° ที่ b·0x2บท 0006 (PHASE ใส่เฟสให้กิ่งเดียว)
a -= 3decrement chain 2 ชุด (−2 แล้ว −1)บท 0018 เป๊ะๆ
if (a<0) then b++increment chain ของ b ที่ทุก gate พ่วง ● จาก a·0x4🆕 ของใหม่บทนี้
a += 3กล่อง a -= 3 เรียงย้อนลำดับบท 0018 (ย้อนลำดับ = ย้อน operation)

ไส้ในของกล่องใหม่: increment ธรรมดา + ● หนึ่งจุด

เทียบกันตรงๆ เลยนะคะ — บนคือ b++ ธรรมดาจากบท 0018 ล่างคือตัวเดียวกันหลังพ่วง control:

สูตรทั่วไปที่ต้องจำให้ขึ้นใจ: จะทำ logic ก้อนไหนแบบมีเงื่อนไข ก็แค่ เอา ● ของ qubit เงื่อนไขไปแปะเพิ่มในทุก gate ของก้อนนั้น — จำนวน gate เท่าเดิม แค่ control เยอะขึ้นตัวละ 1 จุด (เป็นวิธีคิดเดียวกับ a += b ในบท 0019 ที่พ่วง ● จากบิตของ b เข้าไปในทุก gate)

เงื่อนไขจริงคือ a ค่าไหนบ้าง?

สไลด์เขียนเงื่อนไขว่า “a < 3” แต่ถ้าไล่ตามวงจรจริง มันคือ “บิต 0x4 ของ (a − 3) เป็น 1” ซึ่งไม่เหมือนกันเป๊ะ เพราะ register 3 บิตวนกลับ (mod 8) ค่ะ ลองไล่เอง:

① บิต 0x4 ติด แปลว่า a − 3 ต้องอยู่ใน {4, 5, 6, 7}
② ย้ายข้าง (mod 8): a ∈ {7, 0, 1, 2}
③ แปลเป็นภาษาคน: a < 3 หรือ a > 6 — ตรงกับที่สไลด์ p36 เขียนว่า “only circles in columns 0, 1, 2, and 7 are affected”
⚠️ สไลด์ p35 เขียนผิด — ประโยค “subtracting 3 from a will cause its lowest-weight qubit to be set” ขัดกับโค้ดในหน้าเดียวกันที่ใช้ a.bits(0x4) ซึ่งเป็น qubit น้ำหนักสูงสุด (บิตเครื่องหมาย) · คำว่า “top bit” ในสไลด์ก็กำกวม เพราะในรูป สายบนสุดคือ 0x1 (บิตต่ำสุด) · ตอนสอบตอบตามสไลด์ แต่ของจริงคือ highest-weight qubit (0x4) นะคะ

ดูผลด้วย circle notation

เพราะมี 6 qubit (a 3 + b 3) จึงมี 2⁶ = 64 สถานะ · สไลด์เลยจัดเป็นตาราง: แกนนอน = ค่าของ a (0–7) · แกนตั้ง = ค่าของ b (0–7) · เลข ket = b×8 + a

แสดงเฉพาะแถว b = 0–4 (แถว b = 5, 6, 7 ว่างเปล่าทั้งก่อนและหลัง)

ก่อน conditional add — วงเต็ม 4 วงที่ (a,b) = (1,1), (5,1), (1,3), (5,3) · สองวงแถว b = 3 พกเฟส 45°

หลัง conditional add — วงที่ขยับ (ไฮไลต์ส้ม) คือคอลัมน์ a = 1 ที่เลื่อนลง 1 แถว ส่วนคอลัมน์ a = 5 อยู่นิ่งสนิท

สามอย่างที่ต้องอ่านให้ออกจากภาพคู่นี้:

① ทำและไม่ทำพร้อมกัน
คอลัมน์ a = 1 ขยับลง คอลัมน์ a = 5 อยู่นิ่ง — ในสถานะเดียวกัน นี่คือหน้าตาจริงของคำว่า conditional execution แบบควอนตัมค่ะ
② ขนาดวงไม่เปลี่ยน
4 วง ¼ เท่ากันทั้งก่อนและหลัง — increment แค่ย้ายที่ของ amplitude ไม่ได้สร้างหรือทำลาย (เพราะมันคือ permutation ที่ reversible)
③ เฟสติดไปด้วย
เฟส 45° ของกิ่ง b = 3 ถูกพาไปที่ b = 4 ครบถ้วน — เหมือนที่บท 0018 พิสูจน์ว่า increment เป็น “superposition operation” ของจริง
ทำไมต้อง a += 3 ปิดท้าย ทั้งที่คำตอบอยู่ใน b ไปแล้ว?
ถูกต้องค่ะ — a -= 3 เป็นแค่การยืม เพื่อดันบิตเครื่องหมายให้ติด · ถ้าไม่คืน a ก็จะถือค่าผิดไปตลอดทั้งโปรแกรม · รูปแบบ “ทำ → ใช้ → ย้อน” นี้จะกลายเป็นสูตรหลักในบท 0021 (uncompute)
ยังไม่ใช่ค่ะ — คำตอบอยู่ใน b เรียบร้อยแล้วจริง แต่ a เละอยู่ เพราะโดนลบ 3 ไป · a += 3 คือการคืนสภาพ a ไม่ได้ไปยุ่งกับ b เลย
ไล่เองนะคะ — ระหว่าง a = 0 กับ a = 3 ค่าไหนทำให้ b ถูก +1? (คิด a − 3 ใน two's complement 3 บิต แล้วดูบิต 0x4)
เป๊ะค่ะ — 0 − 3 = −3 = 101₂ บิต 0x4 ติด → เข้าเงื่อนไข · ส่วน 3 − 3 = 0 = 000₂ บิต 0x4 ไม่ติด → ไม่เข้า · สังเกตว่า “a < 3” ไม่รวม a = 3 พอดี
ลองใหม่นะคะ — เงื่อนไขไม่ได้ดูว่า “a น้อยกว่า 3 ไหม” ตรงๆ แต่ดูว่า ผลลัพธ์ของ a − 3 มีบิต 0x4 ติดไหม · 3 − 3 = 0 = 000₂ ไม่มีบิตไหนติดเลยค่ะ

ส่วนที่ 2 — ย้ายคำตอบไปเก็บไว้ในเฟส

ส่วนที่ 1 คำตอบถูกเก็บไว้ใน magnitude — วงย้ายแถว = ค่าของ b เปลี่ยน ส่วนที่ 2 เราจะใช้วงจรโครงเดียวกันเป๊ะ (ลบ 3 → เงื่อนไข → บวก 3 คืน) แต่เปลี่ยนไส้กลาง จาก “increment b” เป็น “พลิกเฟส” แทน

“Encoding calculation results in a register's relative phases is a crucial skill for programming a QPU” (slide 37) — นี่ไม่ใช่ลูกเล่นเสริมนะคะ มันคือฐานของ oracle ที่อัลกอริทึมจริงทุกตัว (Grover, Shor) ยืนอยู่บน · และเป็นสิ่งที่บิตธรรมดาทำไม่ได้เลย เพราะบิตไม่มี “เฟส” ให้เขียนลงไป

โจทย์ใหม่: พลิกเฟส 180° ถ้า (a < 3 และ b == 1)

คราวนี้ a 3 qubit กระจายเท่ากันใน {0,1,2,3} และ b 2 qubit อยู่ใน {1, 3}

// Flip the phase if a is less than 3
// and b is equal to 1
a.subtract(3);
b.not(~1);
qc.phase(180, a.bits(0x4), b.bits());
b.not(~1);
a.add(3);

กลเม็ดใหม่ 1: b.not(~1) — แปลง “เท่ากับ 1” ให้เป็น “1 ทุกบิต”

ปัญหาเดิมกลับมาอีกรอบค่ะ: ● เช็คได้แค่ “บิตนี้เป็น 1 ไหม” แต่เราอยากเช็ค “b เท่ากับ 1” ซึ่งแปลว่า b·0x1 = 1 และ b·0x2 = 0 — เจ้าเลข 0 ตัวนี้แหละที่ ● เช็คให้ไม่ได้

ต้องการb·0x1 = 1 และ b·0x2 = 0
→ ● ตัวเดียวเช็คไม่ได้ เพราะมันดูแค่เลข 1
→
วิธีแก้พลิก b·0x2 ด้วย X ก่อน
→ เงื่อนไขกลายเป็น “1 ทั้งสองบิต” = ● ล้วนๆ ใช้ได้เลย

b.not(~1) อ่านว่า “พลิกทุกบิตของ b ยกเว้น บิต 0x1” — ในที่นี้ b มี 2 บิต จึงพลิกแค่ b·0x2 ตัวเดียว · แล้วต้องพลิกกลับหลังใช้เสร็จ (uncompute อีกชั้นหนึ่ง ซ้อนอยู่ข้างในชั้นของ a ∓ 3)

กลเม็ดใหม่ 2: qc.phase(180, …) = CZ สามขา

สัญลักษณ์นี้เคยเจอตอน บท 0010 แล้วค่ะ — จุดทึบ ● ต่อด้วยเส้นตั้ง ไม่มี ⊕ เลย · มันสมมาตร ไม่มีใครเป็น control ใครเป็น target ความหมายคือ “ถ้าทุกสายที่มีจุดเป็น 1 พร้อมกัน → คูณเฟส 180° (คือคูณ −1)” · บทนี้มี 3 จุด บน a·0x4, b·0x1, b·0x2

วงจรเต็ม

เทียบกับวงจรส่วนที่ 1 ทีละกล่อง — กล่องหัวและกล่องท้ายเหมือนกันเป๊ะทุกตัว ต่างกันแค่กล่องกลาง:

ส่วนที่ 1 (magnitude)ส่วนที่ 2 (phase)
กล่องกลางincrement chain 3 gate ที่พ่วง ●X → CZ 3 ขา → X รวม 3 คอลัมน์
ผลต่อ magnitudeวงย้ายแถว (ค่า b เปลี่ยน)ไม่ขยับเลยแม้แต่วงเดียว
ผลต่อเฟสเฟสเดิมถูกพาติดไปด้วยวงที่เข้าเงื่อนไขกลับหัว 180°
READ แล้วเห็นไหมเห็น — ความน่าจะเป็นเปลี่ยนไม่เห็นเลย — ความน่าจะเป็นเท่าเดิม

ดูผลด้วย circle notation

คราวนี้ 5 qubit = 32 สถานะ · ตาราง 8 คอลัมน์ (a = 0–7) × 4 แถว (b = 0–3) · ket = b×8 + a · เริ่มต้นมี 8 วงที่มี amplitude เท่ากันหมด (แต่ละวง 1⁄8 ของความน่าจะเป็น) เข็มชี้ขึ้นตรงทุกวง

ก่อน conditional phase — 8 วง เข็มชี้ขึ้นตรงหมด

หลัง conditional phase — ขนาดวงทั้ง 8 เท่าเดิมเป๊ะ เปลี่ยนแค่เข็มของ |8⟩, |9⟩, |10⟩ ที่กลับหัวลง 180°

ไล่เช็คทีละวงว่าทำไมได้ 3 วงพอดี:

|8⟩,|9⟩,|10⟩ a = 0,1,2 (< 3 ✓) และ b = 1 (✓) → พลิก 180°
|11⟩ b = 1 ✓ แต่ a = 3 ไม่น้อยกว่า 3 → ไม่พลิก
|24⟩–|27⟩ a เข้าเงื่อนไขบ้าง แต่ b = 3 ไม่เท่ากับ 1 → ไม่พลิกสักวง
“When this operation is complete, the magnitudes of the register are unchanged. The probabilities of READing each value remain just as they were, unable to show that this operation was ever performed” (slide 38) — เราคำนวณเสร็จแล้ว แต่ผลการวัดไม่รู้เรื่องเลย ผลลัพธ์ถูก “ทำเครื่องหมาย” ไว้ในเฟสเท่านั้น
อย่าเพิ่งเข้าใจผิดนะคะ — “เก็บคำตอบไว้ในเฟส” ไม่ได้แปลว่าอ่านคำตอบได้เลย ตรงกันข้าม ณ จุดนี้เรา READ แล้วไม่เห็นอะไรต่างจากเดิมเลยสักนิด · มันมีประโยชน์เพราะขั้นต่อไปมี gate ที่แปลงความต่างของเฟสให้กลายเป็นความต่างของ magnitude ได้ (= amplitude amplification ของ Lec 06) · ตอนนี้ให้จำแค่ว่า เฟสคือที่พักคำตอบชั่วคราวที่ปลอดภัย เพราะมันไม่ไปรบกวนความน่าจะเป็น
รันวงจรส่วนที่ 2 จนจบแล้ว READ ทั้ง register ทันที จะเกิดอะไรขึ้น?
ใช่เลยค่ะ — นี่คือประเด็นทั้งหมดของหน้า 38 · เฟสมองไม่เห็นจากการ READ ตรงๆ ต้องมีขั้นตอนแปลงเฟส → magnitude ก่อน (Lec 06) ถึงจะเก็บเกี่ยวคำตอบได้
ยังไม่ใช่ค่ะ — การหมุนเฟสไม่แตะขนาดวงเลยแม้แต่นิดเดียว ความน่าจะเป็นจึงเท่าเดิมทั้ง 8 สถานะ · จะเห็นผลก็ต่อเมื่อมี gate มาแทรกสอด เฟสเหล่านั้นให้กลายเป็นขนาดก่อน
ถ้าตัด b.not(~1) ทั้งสองตัวออกจากวงจร (เหลือแค่ CZ 3 ขา) เงื่อนไขที่ได้จะกลายเป็นอะไร?
ถูกต้องค่ะ — ● บน b·0x1 และ b·0x2 พร้อมกันแปลว่า 11₂ = 3 · เราอยากได้ b == 1 = 01₂ จึงต้องพลิก b·0x2 ก่อน ให้เลข 0 ที่เราต้องการกลายเป็นเลข 1 ที่ ● อ่านได้
ลองอีกทีนะคะ — X สองตัวนั้นไม่ได้ติดกัน มี CZ คั่นอยู่ตรงกลาง จึงไม่หักล้างกัน · ถ้าเอาออก ● สองจุดบน b จะหมายถึง “b·0x1 = 1 และ b·0x2 = 1” ตรงๆ
ทดสอบความจำก่อนปิดหน้า — ตอบในใจให้ครบก่อนกดดูนะคะ
  1. “if” บน CPU ต้องทำอะไรก่อนตัดสินใจ ที่ QPU ไม่ต้องทำ?
  2. จะทำ logic ก้อนหนึ่งแบบมีเงื่อนไขบน QPU ต้องแก้วงจรยังไง?
  3. ทำไมต้อง a -= 3 ก่อน แทนที่จะเช็ค “a < 3” ตรงๆ?
  4. บิตไหนของ a ที่ถูกใช้เป็น control และมันมีความหมายว่าอะไร?
  5. เงื่อนไขจริงของวงจรส่วนที่ 1 ครอบคลุม a ค่าไหนบ้าง (ตอบเป็นเซต)?
  6. b.not(~1) ทำอะไร และทำไปทำไม?
  7. สัญลักษณ์ “● 3 จุดต่อด้วยเส้นตั้ง ไม่มี ⊕” คือ gate อะไร?
  8. หลัง phase encoding แล้ว READ จะเห็นความต่างไหม เพราะอะไร?

เฉลยย่อ: ① อ่านค่าเงื่อนไขออกมาดู ② เอา ● ของ qubit เงื่อนไขไปแปะเพิ่มในทุก gate ③ เพราะ ● เช็คได้แค่ “บิตนี้เป็น 1 ไหม” ไม่ใช่ช่วงตัวเลข การลบทำให้เงื่อนไขยุบเหลือบิตเดียว ④ บิต 0x4 = บิตเครื่องหมายของ two's complement (ติด = ค่าติดลบ) ⑤ {7, 0, 1, 2} คือ a < 3 หรือ a > 6 ⑥ พลิกทุกบิตของ b ยกเว้น 0x1 — เพื่อแปลงเงื่อนไข “b == 1” ให้กลายเป็น “ทุกบิตเป็น 1” ที่ ● อ่านได้ ⑦ CZ หลายขา / conditional phase 180° (สมมาตร ไม่มี control–target) ⑧ ไม่เห็น เพราะ magnitude เท่าเดิมทุกวง

สรุปบทนี้
① QPU ทำ conditional execution ได้โดยไม่ต้องอ่านเงื่อนไข → logic ทั้งรันและไม่รันพร้อมกัน
② วิธีทำ = แปะ ● ของ qubit เงื่อนไขเข้าไปในทุก gate ของ logic ก้อนนั้น
③ ● เช็คได้แค่ “บิตนี้เป็น 1 ไหม” → ใช้เลขคณิตเลื่อนค่า (a −= 3 · b.not(~1)) ให้เงื่อนไขที่ต้องการยุบเหลือ “บิตติด 1” แล้วย้อนคืนเสมอ
④ เปลี่ยนไส้กลางเป็น CZ → คำตอบไปอยู่ในเฟส โดย magnitude ไม่ขยับ = ฐานของ oracle

บทหน้า (0021) จะเจอโจทย์ที่ทริกของบทนี้เอาไม่อยู่ — abs(a) ซึ่งย้อนกลับไม่ได้โดยธรรมชาติ ทางออกคือ scratch qubit (คิวบิตทด) และ สูตร compute → use → uncompute ที่บทนี้เห็นเงาๆ ไปแล้วสองชั้นค่ะ
