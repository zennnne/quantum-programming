Quantum Programming · Lec 04 · บทที่ 0014

★ อ่านวงจร teleportation ให้ขาด

บท 0013 เล่าเรื่องราวของ teleportation ครบแล้ว — Alice วัด 2 บิต ส่งไปให้ Bob แก้ · บทนี้คือบทอ่านแผนที่ เราจะเรียน “ภาษา” สองภาษา ที่บท 0015 จะใช้พร้อมกันตลอด: ภาษาแรกคือตัววงจร (gate อะไร เรียงยังไง แบ่งเป็นกล่องอะไรบ้าง) ภาษาที่สองคือผัง circle notation 8 วง ที่ใช้ดูสถานะของ 3 qubit ค่ะ

ทำไมบทนี้สำคัญเป็นพิเศษ

หน้า 15 ของสไลด์คือหน้าที่สำคัญที่สุดของ Lec 04 — และมีสัญลักษณ์ที่พี่ Zen ยังไม่เคยเจอมาก่อน 3 ตัว โผล่มาพร้อมกันหมดในหน้าเดียว โดยเฉพาะ ลูกศรประสีฟ้า = การควบคุม gate ด้วยบิตคลาสสิก ซึ่งเป็นหัวใจของ teleportation (และเป็นเรื่องออกสอบ เพราะอาจารย์ออกสอบ “หน้าตาวงจร”)

บทนี้จับ 3 อย่าง เท่านั้น: ① สัญลักษณ์ใหม่ 3 ตัว ② วงจรเต็ม 5 กล่องว่ากล่องไหนทำอะไร ③ ผัง 8 วงอ่านยังไง (บิตไหนคุมแถว บิตไหนคุมคอลัมน์)

ลูกศรประสีฟ้าชี้ลง (ตัวใหม่ของบทนี้) = การควบคุมแบบคลาสสิก — ต้นทางถูก READ ไปแล้ว เหลือเป็นบิตธรรมดา 0/1 หนึ่งตัว แล้วเอาบิตนั้นมาตัดสินว่า “จะทำ gate ปลายทางไหม” · เขียนเป็นโค้ดคือ if (bit) { bob.not(); } ตรงๆ เลย · ไม่สร้าง entanglement และวิ่งเร็วกว่าแสงไม่ได้ เพราะบิตนั้นต้องเดินทางผ่านสายธรรมดา

⚠️ สไลด์ปน 2 เวอร์ชัน (จุดที่ 7 ของคอร์ส) — ต้องรู้ก่อนเจอบท 0016

วงจรหน้า 15 นี้ prep payload = H → φ(45°) → H แต่โค้ด OpenQASM ที่หน้า 6 เขียน x; h; t; (= X → H → φ45) และวงจรบน IBM หน้า 16 เขียน H → T → H · ไม่ใช่ชุดเดียวกัน — สไลด์หยิบมาจากคนละที่ · บทเรียนของเรา (0014–0015) เดินตามเวอร์ชันวงจรหน้า 15 เพราะเป็นตัวที่ให้ payload = 85.4% / 14.6% ตรงกับ walkthrough ทุกหน้า ส่วนเวอร์ชัน IBM ค่อยไปว่ากันในบท 0016 ค่ะ

ข้อ 1. สมมติมีคนลบลูกศรประสีฟ้าทั้งสองเส้นออกจากวงจร แล้วให้ Bob ทำ ⊕ และ φ(180°) ทุกครั้งไม่สนบิตที่ได้รับ — ผลจะเป็นยังไง
ถูกต้องค่ะ — ลูกศรประคือ “ทำก็ต่อเมื่อบิตเป็น 1” ถ้าทำทุกรอบ ก็จะถูกเฉพาะรอบที่บิตทั้งสองเป็น 1 อยู่แล้ว (คือ 1 ใน 4 ของรอบทั้งหมด) · นี่คือสิ่งที่เกิดขึ้นจริงบน IBM QX ในบท 0016 เพราะเครื่องนั้นเขียน if ไม่ได้ → ต้องมาคัดรอบที่ใช้ได้ทีหลัง เรียกว่า post-selection
ยังไม่ใช่ค่ะ — ลองคิดแบบนี้: gate ที่ถูกลูกศรคุมจะทำงาน “เมื่อบิต = 1” เท่านั้น · ถ้าทำทุกรอบโดยไม่ดูบิต แล้วรอบไหนล่ะที่ผลออกมาเหมือนเดิมพอดี?
ข้อ 2. ถ้าตัดกล่อง entangle ทิ้ง (ไม่สร้าง Bell pair เลย แต่กล่องอื่นเหมือนเดิมทุกอย่าง) จะเกิดอะไรขึ้น
ใช่เลยค่ะ — Alice ยังได้บิตสุ่ม 2 บิตอยู่ดี (READ ให้ค่าเสมอ) แต่บิตพวกนั้นจะไม่เกี่ยวอะไรกับ qubit ของ Bob เลย · entanglement คือ “สายที่ต่อไว้ก่อน” ทำให้ 2 บิตนั้นกลายเป็นคำสั่งที่มีความหมายกับ Bob · เชื่อมกับบท 0013: ส่วนที่ขาดของข้อมูลถูกจ่ายไปแล้วตอนแชร์ entanglement
ลองแยกสองคำถามค่ะ: (1) Alice ยัง READ ได้ค่าออกมาไหม — ได้เสมอ เพราะ READ ให้ 0/1 เสมอ · (2) แล้วค่านั้นเกี่ยวอะไรกับ qubit ของ Bob ไหม ถ้าไม่มีสายเชื่อมไว้ก่อน?
ส่วนที่ 2

ผัง circle notation 8 วง + สารบัญ Step 1–5

วงจรบอกว่า “ทำอะไรบ้าง” แต่ไม่ได้บอกว่า “ข้างในเป็นยังไง” · ตัวที่บอกคือ circle notation ที่พี่ Zen ใช้มาตั้งแต่บท 0008 — แต่ครั้งนี้เป็น 3 qubit จึงมี 2³ = 8 วง ค่ะ

2.1 น้ำหนักบิต: ใครเป็นบิตไหน

สามสายในวงจร ประกอบกันเป็นเลขฐานสอง 3 บิตหนึ่งตัว โดยตกลงกันไว้ว่า

alice = 1 (บิตต่ำสุด)  ·  ep = 2  ·  bob = 4

เพราะฉะนั้น “วง |5⟩” หมายถึงสถานะที่ 5 = 4 + 1 = bob = 1, ep = 0, alice = 1 (เขียนเป็นบิตเรียง bob · ep · alice ได้ 101)

ผังมาตรฐานของบทนี้ (สไลด์หน้า 20–22) — ตัวเลขใต้วงคือบิตเรียง bob · ep · alice · ภาพนี้คือสถานะเริ่มต้น: ทุก qubit เป็น |0⟩ → วง |0⟩ เต็มวงเข็มชี้ขึ้น (phase 0) อีก 7 วงว่าง
ทิศทางในผังควบคุมโดยอ่านยังไง
แถว (บน / ล่าง)bob (น้ำหนัก 4) แถวบน = bob 0 (|0⟩–|3⟩) · แถวล่าง = bob 1 (|4⟩–|7⟩)
ครึ่งซ้าย / ครึ่งขวาep (น้ำหนัก 2) 2 คอลัมน์ซ้าย = ep 0 · 2 คอลัมน์ขวา = ep 1
คอลัมน์คู่ / คี่alice (น้ำหนัก 1) สลับทีละคอลัมน์: alice = 0, 1, 0, 1
ทำไมต้องจัด 2 แถว × 4 คอลัมน์ (ไม่เรียงยาว 8 วงรวด)

เพราะจัดแบบนี้แล้ว “qubit ตัวหนึ่ง = ทิศทางหนึ่งในผัง” พอดี → เวลามี gate ทำงานกับ qubit ตัวไหน เราจะเห็นเป็นการจับคู่วงตามทิศนั้นทันที เช่น gate บน bob = จับคู่บน–ล่าง · gate บน alice = จับคู่ซ้าย–ขวาติดกัน · บท 0015 จะใช้ประโยชน์จากข้อนี้ทุกขั้นตอนเลยค่ะ

ข้อ 3. ระหว่างเดินโปรแกรม มีอยู่จังหวะหนึ่งที่เหลือแค่ 4 วงที่มีค่า คือ |0⟩ |3⟩ |5⟩ |6⟩ · ลองถอดเป็นบิต (bob·ep·alice) ทั้งสี่วงดู แล้วเลือกข้อที่บรรยาย “กติกาที่วงพวกนี้มีร่วมกัน” ได้ถูกต้อง
เยี่ยมค่ะ! 000 · 011 · 101 · 110 — ทุกตัวมีจำนวนเลข 1 เป็นคู่ พูดอีกแบบคือ alice XOR ep XOR bob = 0 · นี่คือสถานะหลัง Step 3.1 พอดี (พัวพันกันครบทั้งสามตัว) ที่บท 0015 จะเจอ — จำหน้าตานี้ไว้ก่อนได้เลย
ลองเขียนออกมาเรียงกันดูค่ะ: |0⟩=000 · |3⟩=011 · |5⟩=101 · |6⟩=110 แล้วนับ “จำนวนเลข 1” ในแต่ละแถว — ได้ 0, 2, 2, 2 · อะไรที่เหมือนกันทุกแถว?

2.2 สารบัญ Step 1–5 — แผนที่ของบท 0015

สไลด์หน้า 23–26 ค่อยๆ แปะป้าย step ลงบนวงจรเดิม แล้วหน้าถัดจากนั้นอีกครึ่งบท ก็คือการเลื่อนเส้นประสีแดงไปทีละ step แล้วดูว่าผัง 8 วงเปลี่ยนยังไง นี่คือสารบัญที่ต้องจำเป็นโครงค่ะ

1 Create an Entangled Pair — กล่อง entangle · ep.had(); bob.cnot(ep);
2 Prepare the Payload — กล่อง prep payload · ปั้น payload 85.4% / 14.6% ที่ phase −90°
3.1 Link the Payload to the Entangled Pair — ตัว CNOT ในกล่อง send (● ที่ alice → ⊕ ที่ ep)
3.2 Put the Payload into a Superposition — ตัว H ในกล่อง send (บนสาย alice)
3.3 READ Both of Alice's Qubits — detector สองตัวท้ายกล่อง send → ได้ bit_p, bit_n
4 Receive and Transform — กล่อง receive · Bob แก้ตามลูกศรประสองเส้น
5 Verify the Result — กล่อง verify · ต้องอ่านได้ 0 ถ้าสำเร็จ

สังเกตว่า Step 3 ถูกแตกเป็น 3.1 / 3.2 / 3.3 — เพราะกล่อง send กล่องเดียว มีสามจังหวะที่ความหมายต่างกันมาก (ผูก → กระจาย → วัด) และเป็นช่วงที่ยากที่สุดของทั้งโปรแกรมค่ะ

ทดสอบความจำก่อนปิดบท (ลองตอบในใจก่อนกดดู)
  1. ลูกศรประสีฟ้าต่างจากเส้นตั้งทึบยังไง? → ประ = ควบคุมด้วยบิตคลาสสิก (ต้นทางถูก READ แล้ว ไม่สร้าง entanglement, ช้ากว่าแสงไม่ได้) · ทึบ = ควบคุมแบบควอนตัม ทำงานทุกกิ่ง superposition และสร้าง entanglement ได้
  2. ในวงจร ลูกศรจาก ep ไปคุม gate อะไร? จาก alice ล่ะ? → ep คุม ⊕ (NOT) · alice คุม φ (PHASE 180°)
  3. ทำไมสาย alice กับ ep ถึงวาดเป็นเส้นจางในครึ่งหลังของวงจร? → เพราะถูก READ ไปแล้ว = qubit ถูกทำลาย เหลือแค่บิตคลาสสิก (หน้าตาของ no-cloning)
  4. 5 กล่องชื่ออะไร เรียงยังไง? → entangle · prep payload · send · receive · verify
  5. |6⟩ คือ alice/ep/bob เท่าไหร่? → 6 = 4+2 → bob 1, ep 1, alice 0 (แถวล่าง คอลัมน์ที่ 3)
  6. กล่อง verify ทำอะไร? → prep payload แบบย้อนกลับ (φ เป็น −45°) แล้ววัด → ถ้า teleport สำเร็จต้องได้ 0 เสมอ
สรุปบทนี้ · บทหน้า

ตอนนี้พี่ Zen อ่านแผนที่ได้ทั้งสองภาษาแล้ว — วงจร 5 กล่อง (พร้อมสัญลักษณ์ write ▷, ลูกศรประคลาสสิก, กล่องมีชื่อ) และ ผัง 8 วง (alice=1 · ep=2 · bob=4) · บท 0015 คือบทที่หนักที่สุดของ Lec 04: เราจะเอาเส้นประสีแดงไปวางทีละจุดบนวงจร แล้วดูผัง 8 วงเปลี่ยนไปทีละ step ตั้งแต่ Step 1 จนถึง Step 5 — ถ้าบทนี้แน่น บทหน้าจะเป็นแค่ “การเดินตามแผนที่” ค่ะ
