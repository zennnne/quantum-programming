เก็บ matrix: quantum simulation

ข้อมูลที่เราเก็บใน register ซับซ้อนขึ้นมาเรื่อยๆ: ตัวเลข (บท 0034) → vector (บท 0035) → และบทนี้คือ matrix (เมทริกซ์) · คำตอบของบทนี้อาจดูแปลกในตอนแรก: เราจะไม่เก็บ matrix ไว้เป็นตัวเลข แต่จะทำให้มันกลายเป็น QPU operation ที่เอาไปกระทำกับ vector ได้ · เครื่องมือที่ใช้ทำแบบนี้มีชื่อว่า quantum simulation (การจำลองเชิงควอนตัม)

ทำไมต้องเรียนบทนี้: จับหลัก 4 อย่าง ① จะบอกว่า QPU operation "แทน" matrix ได้ ต้องมี eigen decomposition เดียวกัน และต้องสร้างจาก gate พื้นฐานได้อย่าง efficient ② quantum simulation ใช้ได้กับ Hermitian matrix เท่านั้น (matrix อื่นแปลงด้วย block matrix ได้) ③ หัวใจคือ U = exp(−iHt) ซึ่งทำได้ 3 ขั้น: แตก H → จำลองทีละชิ้น → ประกอบกลับ (Lie product formula, Figure 9-9) ④ ต้นทุนอยู่ใน Table 9-2 · บทนี้ใช้คณิตมากที่สุดเท่าที่เรียนมา หนูจึงแทรกกล่องทบทวนคณิตไว้ตรงที่ต้องใช้ทุกจุด และมีสัญลักษณ์วงจรใหม่ 1 แบบ (Figure 9-9) ซึ่งเพิ่มลงชีตแล้ว

ส่วนที่ 1 · "แทน matrix ได้ถูก" แปลว่าอะไร (p40–48)

1.1 วิธีที่ตรงที่สุด: เก็บทีละแถว แต่ใช้งานไม่ได้

สมมติมี matrix ขนาด m × n (m แถว n หลัก) · วิธีที่คิดได้ทันทีคือใช้ m register แล้ว amplitude-encode แต่ละแถวเหมือนเป็น vector หนึ่งตัว (register ละ log₂ n qubit แบบบท 0035) (p40) · วิธีนี้ใส่ตัวเลขเข้า QPU ได้จริง แต่สไลด์ชี้ว่ายังไม่ได้แทนข้อมูลในฐานะ matrix เพราะไม่ชัดเลยว่าจะทำของพื้นฐานอย่าง transpose (สลับแถวกับหลัก) หรือคูณ matrix กับ vector ที่อยู่ใน register อื่นได้ยังไง

ลองถามกลับว่าปกติเราใช้ matrix ทำอะไร คำตอบเกือบทุกครั้งคือเอาไปคูณกับ vector และ vector ของเราก็อยู่ใน register อยู่แล้ว (amplitude encoding) · สไลด์เลยตั้งเป็นข้อกำหนดว่า: ให้เข้ารหัส matrix เป็น QPU operation ที่กระทำกับ register ของ vector ได้ (p41)

เก็บ matrix เป็นตัวเลขเหมือนจดสูตรอาหารลงกระดาษ · ข้อมูลครบทุกอย่าง แต่กระดาษทำอาหารเองไม่ได้
→
เก็บ matrix เป็น operationเหมือนมีพ่อครัวที่จำสูตรได้ · ยื่นวัตถุดิบ (vector) ให้ ก็ได้อาหาร (M·v) ออกมาทันที
ทบทวนคณิต · คูณ matrix กับ vector แถวที่ i ของผลลัพธ์ = เอาแถวที่ i ของ matrix ไปคูณกับ vector ทีละตัวแล้วบวกกัน · ตัวอย่างที่ใช้ทั้งบท: M = [[2, 1], [1, 2]]
M · [1, 0] = [2·1 + 1·0, 1·1 + 2·0] = [2, 1] · คือ matrix เป็น "เครื่องแปลง vector" ตัวหนึ่ง

1.2 เกณฑ์แบบตรงๆ: input เดียวกัน ต้องได้ output เดียวกัน

QPU operation U จะ "แทน" matrix M ได้ ก็ต่อเมื่อ ทุก vector v ให้ผลตรงกัน (p42):

M · v  ↔  U|v⟩   (ผลของ U ต้องเป็น amplitude encoding ของ M·v)

นิยามนี้ถูก แต่ใช้จริงลำบาก เพราะ vector มีได้ไม่จำกัด เราไล่เช็คทีละตัวไม่ได้ · สไลด์เลยหาเกณฑ์ที่ง่ายกว่า โดยใช้ของที่เรารู้จักแล้วจาก Lec 08

1.3 เกณฑ์ที่ง่ายกว่า: eigen decomposition เดียวกัน

ทบทวนบท 0031: QPU operation ถูกระบุได้ครบด้วยเซตของ eigenstate กับ eigenphase ของมัน (เหมือนลายนิ้วมือ) · matrix ก็มีของแบบเดียวกัน เรียกว่า eigenvector (เวกเตอร์เฉพาะ) กับ eigenvalue (ค่าเฉพาะ) (p42–43)

ทบทวนคณิต · eigenvector คืออะไร eigenvector คือ vector ที่พอเข้า matrix แล้วทิศไม่เปลี่ยน แค่ถูกยืด/หดด้วยตัวคูณ λ (eigenvalue): M · v = λ v
ใช้ M = [[2, 1], [1, 2]]: M · [1, 1] = [3, 3] = 3 · [1, 1] → eigenvalue 3 · M · [1, −1] = [1, −1] = 1 · [1, −1] → eigenvalue 1
แต่ M · [1, 0] = [2, 1] → ทิศเปลี่ยน → ไม่ใช่ eigenvector

เทียบกับ QPU operation: eigenstate คือ state ที่ U ทำแล้วไม่เปลี่ยน แค่ได้ global phase: U|ψ⟩ = eiθ|ψ⟩ · จะเห็นว่าเป็นแนวคิดเดียวกัน ต่างกันแค่ว่า matrixยืดได้ แต่ QPU operation หมุน phase ได้อย่างเดียว · ดังนั้น "eigen decomposition เดียวกัน" แปลว่า (p43):

ฝั่ง matrix Mฝั่ง QPU operation U
eigenvector [1, 1] กับ [1, −1]eigenstate = amplitude encoding ของ eigenvector → [1,1]/√2 = |+⟩ · [1,−1]/√2 = |−⟩
eigenvalue 3 กับ 1eigenphase "สัมพันธ์กับ" (related to) eigenvalue · สไลด์ไม่ได้บอกว่าเท่ากัน

หมายเหตุ: ÷√2 คือการ normalize จาก Caveat 2 ของบท 0035 · ส่วน "สัมพันธ์กันยังไง" เดี๋ยวจะเห็นในส่วนที่ 2 (คือ θ = −λt)

ลองใช้เกณฑ์เอง: matrix M = [[2, 1], [1, 2]] มี eigenvector [1, 1] กับ [1, −1] · ถ้า QPU operation U แทน M ได้ถูกต้อง ข้อไหนต้องเป็นจริง?
ถูกค่ะ · [1, 1] เป็น eigenvector ของ M → amplitude encoding ของมันคือ |+⟩ ต้องเป็น eigenstate ของ U = ได้ตัวเดิมคืนมา เปลี่ยนแค่ global phase · ส่วน "ยาวขึ้น 3 เท่า" QPU ทำไม่ได้ เพราะ state ต้องมีความน่าจะเป็นรวม 100% เสมอ
ลองเริ่มจาก eigenvector ของ M ก่อนนะคะ · [1, 1] พอ normalize แล้วเป็น state อะไร · แล้ว eigenstate คือ state ที่ U ทำแล้วได้อะไรคืนมา? (ระวังด้วยว่า QPU "ยืด" state ไม่ได้)

1.4 "เกือบพอ": ต้องสร้างได้จริง และต้องเร็ว

ถ้าเจอ U ที่ eigen decomposition ตรงกับ M แล้ว จบหรือยัง? สไลด์ตอบว่า "เกือบ" (Almost) (p44) · เพราะสิ่งที่เราอยากได้ไม่ใช่แค่คำอธิบายทางคณิตของ U · เราต้องได้ prescription (วิธีทำ) ที่บอกว่าจะต่อ U ขึ้นมาจริงด้วย gate เดี่ยว/หลาย qubit พื้นฐานยังไง และวิธีนั้นต้อง efficient (มีประสิทธิภาพ) คือไม่ใช้ gate เยอะจนโปรแกรมทั้งตัวช้าจนไม่มีประโยชน์ (p45)

นิยามจากสไลด์ (p45) "A good matrix representation is a procedure for associating a matrix with a QPU operation that can be efficiently implemented through basic single- and multi-qubit operations."
การแทน matrix ที่ดี = วิธีจับคู่ matrix กับ QPU operation ที่สร้างจาก gate พื้นฐานได้อย่างมีประสิทธิภาพ · สรุปเป็นเช็กลิสต์ 3 ข้อ: ① eigen decomposition เดียวกัน ② มีวิธีสร้างจาก gate พื้นฐาน ③ วิธีนั้น efficient · สำหรับ matrix บางประเภท quantum simulation ให้ได้ครบทั้ง 3 ข้อ

1.5 quantum simulation ใช้ได้กับ Hermitian matrix เท่านั้น

quantum simulation เป็นคำเรียกรวม (catch-all term) ของกลุ่มวิธีที่หา QPU operation ซึ่ง implement ได้ efficient มาแทน Hermitian matrix (เมทริกซ์เฮอร์มิเชียน) (p46) · แต่ละวิธีใช้ทรัพยากรต่างกัน และอาจมีเงื่อนไขเพิ่มต่างกัน แต่อย่างน้อยที่สุด ทุกวิธีต้องการให้ matrix เป็น Hermitian

นิยามจากสไลด์ (p46) Hermitian matrix คือ matrix ที่ H = H† · โดย † (adjoint) หาได้จากการ transpose (สลับแถวกับหลัก) แล้ว complex conjugate (สังยุคเชิงซ้อน) ทุกตัว
ทบทวนคณิต · หา H† ทีละขั้น complex conjugate = กลับเครื่องหมายส่วนจินตภาพ: (1 + i)* = 1 − i · ส่วนจำนวนจริงไม่เปลี่ยน: 3* = 3
ตัวอย่าง A = [[2, 1−i], [1+i, 3]] → transpose = [[2, 1+i], [1−i, 3]] → conjugate = [[2, 1−i], [1+i, 3]] = A เดิม → Hermitian ✓
ข้อสังเกตที่ช่วยเช็คเร็ว (หนูเติมเอง ไม่อยู่ในสไลด์): ① ตัวบนเส้นทแยงต้องเป็นจำนวนจริง ② ตัวที่อยู่ตรงข้ามกันข้ามเส้นทแยงต้องเป็นคู่ conjugate กัน ③ matrix จำนวนจริงที่สมมาตร เช่น M = [[2,1],[1,2]] เป็น Hermitian เสมอ
ลองเช็คเอง: matrix ไหนเป็น Hermitian? (ลองหา transpose + conjugate ในกระดาษก่อนกด)
ถูกค่ะ · transpose ได้ [[0, −i], [i, 0]] → conjugate ได้ [[0, i], [−i, 0]] = ตัวเดิม ✓ · (นี่คือ matrix ของ gate Y ที่เราเคยเจอนั่นเอง) · ข้อ 1 ตัวตรงข้าม 2 กับ 3 ไม่เท่ากัน · ข้อ 3 มี i บนเส้นทแยง · ข้อ 4 conjugate ของ i คือ −i ไม่ใช่ i
ใช้ข้อสังเกตในกล่องคณิตนะคะ · บนเส้นทแยงเป็นจำนวนจริงไหม · ตัวที่อยู่ตรงข้ามกันข้ามเส้นทแยงเป็นคู่ conjugate กันไหม (i คู่กับ −i)

1.6 ถ้า matrix ไม่ใช่ Hermitian: ห่อด้วย block matrix

บังคับให้เป็น Hermitian จะทำให้ใช้งานได้แคบไปไหม? สไลด์ตอบว่าไม่ (p47) · ถ้ามี matrix X ที่ไม่ใช่ Hermitian ให้สร้าง matrix ใหญ่ขึ้นแบบนี้:

H = [ 0    X ]
      [ X†   0 ]

ทำไมได้ Hermitian: ลองหา H† โดยสลับ block ข้ามเส้นทแยงแล้วใส่ † ทุกชิ้น · ได้ [[0, (X†)†], [X†, 0]] = [[0, X], [X†, 0]] = H เดิม ✓ · สไลด์บอกว่าต้นทุนในการสร้าง matrix ใหญ่ขึ้นเป็นค่าคงที่ที่จ่ายครั้งเดียว (constant one-off) จึงมักไม่สำคัญ (p47–48)

ตัวอย่าง X = [[1, 2], [3, 4]] (ไม่ใช่ Hermitian เพราะ 2 ≠ 3) · X เป็นจำนวนจริง → X† = transpose = [[1, 3], [2, 4]]
ผล H = [[0, 0, 1, 2], [0, 0, 3, 4], [1, 3, 0, 0], [2, 4, 0, 0]] · ขนาด 4 × 4 · ตรวจด้วย numpy แล้วว่า H = H† ✓
⚠️ สไลด์เขียนขนาดผิด (p47–48) สไลด์บอกว่า X ขนาด m × n จะได้ H ขนาด 2m × 2n และ block ศูนย์ขนาด m × n · ข้อความนี้ถูกเฉพาะตอน m = n · ของจริง: X† มีขนาด n × m → ศูนย์บนซ้ายต้องเป็น m × m และล่างขวาเป็น n × n → H มีขนาด (m+n) × (m+n) (Hermitian ต้องเป็น matrix จัตุรัสอยู่แล้ว) · เช่น X ขนาด 2 × 3 จะได้ H ขนาด 5 × 5 ไม่ใช่ 4 × 6 · ข้อความเดียวกันนี้อยู่ในหนังสือ O'Reilly ด้วย · ตอบตามสไลด์ตอนสอบ แต่รู้ของจริงไว้นะคะ
X เป็น matrix ขนาด 3 × 3 ที่ไม่ใช่ Hermitian · ห่อเป็น H = [[0, X], [X†, 0]] แล้วได้ H ขนาดเท่าไร?
ถูกค่ะ · m = n = 3 → สูตรสไลด์ 2m × 2n = 6 × 6 และสูตรจริง (m+n) × (m+n) = 6 × 6 ตรงกันพอดี · ถ้าโจทย์ให้ m ≠ n ค่อยต้องระวังว่าสไลด์กับของจริงจะได้ไม่เท่ากัน
H มี block 2 × 2 และแต่ละ block มีขนาดเท่า X (3 × 3) · ลองนับจำนวนแถวกับหลักรวมดูนะคะ

ส่วนที่ 2 · quantum simulation ทำงานยังไง และแพงแค่ไหน (p49–61)

2.1 QPU ทำได้แค่ unitary → ใช้ U = exp(−iHt)

ถ้าเขียนแบบเต็มทางคณิต state ของ register คือ vector ของจำนวนเชิงซ้อน และ QPU operation ก็คือ matrix ตัวหนึ่ง (p49) · ไอเดียแรกคือ "หา QPU operation ที่ matrix ของมันเท่ากับข้อมูลของเรา" แต่ทำไม่ได้ เพราะ QPU operation ที่สร้างได้จริงมีแค่ matrix กลุ่มเดียว คือ unitary matrix (เมทริกซ์ยูนิแทรี)

ทำไมต้องเป็น unitary (หนูเติม intuition เอง): unitary คือ operation ที่รักษาความน่าจะเป็นรวมไว้ที่ 100% เสมอ · ทุก gate ที่เราใช้มา (H, X, PHASE, CNOT) เป็นแบบนี้หมด · แต่ M = [[2,1],[1,2]] ยืด [1,1] ไปเป็น [3,3] ซึ่งยาวขึ้น 3 เท่า ถ้า QPU ทำแบบนี้ได้ ความน่าจะเป็นรวมจะเกิน 100% ซึ่งเป็นไปไม่ได้ (ตรงกับ Caveat 2 ในบท 0035)

ทางออกของสไลด์: ถ้า H เป็น Hermitian แล้ว (p49–50)

U = exp(−iHt)    เป็น unitary เสมอ

นี่คือเหตุผลที่ quantum simulation ใช้ได้แค่กับ Hermitian matrix · หน้าที่ของ quantum simulation จึงสรุปได้ว่า หาวงจรที่ทำ exp(−iHt) ได้อย่าง efficient (p50)

ทบทวนคณิต · ทำไม exp(−iHt) "เปลี่ยนการยืดเป็นการหมุน" eiφ คือจุดบนวงกลมรัศมี 1 ที่ทำมุม φ · ขนาดเป็น 1 เสมอ (เหมือนเข็มใน circle notation ที่หมุนได้แต่ยาวเท่าเดิม)
eigenvector v ของ H ที่ eigenvalue λ จะได้ U·v = e−iλt v · Hermitian มี eigenvalue เป็นจำนวนจริงเสมอ → e−iλt มีขนาด 1 → "การยืด λ เท่า" กลายเป็น "การหมุน phase ไป −λt" แทน · นี่คือความหมายของคำว่า eigenphase "สัมพันธ์กับ" eigenvalue ในข้อ 1.3: θ = −λt (เป็นความรู้เสริม สไลด์บอกแค่ "related to")

ลองดูตัวอย่างจริง: M = [[2,1],[1,2]] กับ t = π/6 (คำนวณด้วย numpy) · |+⟩ มี λ = 3 → หมุน −3 · 30° = −90° · |−⟩ มี λ = 1 → หมุน −30° · ทั้งสองแบบเป็น global phase เพราะทุกวงหมุนเท่ากัน:

2.2 t คืออะไร และทำไมถึงชื่อ "simulation"

  • t คือเวลาที่ใช้ทำ operation exp(−iHt) · ในวิชานี้ถือว่าการเลือก t เป็นรายละเอียดของ hardware ข้ามไปได้ (p50)
  • ชื่อนี้มาจากงานเดิมของมัน: แต่ก่อนใช้จำลองวัตถุควอนตัม เช่น โมเลกุลและวัสดุ · ในฟิสิกส์ Hermitian matrix ที่อธิบายระบบเรียกว่า Hamiltonian (แฮมิลโทเนียน) (นี่คือที่มาของตัวอักษร H) และ exp(−iHt) บอกว่าระบบเปลี่ยนไปตามเวลายังไง · บทนี้เอาเครื่องมือเดียวกันมาใช้กับข้อมูลแทน

2.3 H แบบไหน "ง่าย"

สไลด์ยกตัวอย่าง H ที่หาวงจรมาทำ exp(−iHt) ได้ง่าย 2 แบบ (p51): ① มีค่าเฉพาะบนเส้นทแยง (diagonal) ② กระทำกับ qubit จำนวนน้อยมาก

ทำไม diagonal ถึงง่าย (หนูเติมตัวอย่างเอง): exp ของ matrix ทแยงคือเอา exp ไปใส่ทีละช่องบนเส้นทแยง · เช่น H = diag(0, π/2), t = 1 → exp(−iHt) = diag(1, e−iπ/2) = diag(1, −i) ซึ่งก็คือ PHASE(−90°) ที่เรารู้จักแล้ว (ตรวจด้วย numpy ✓)

ปัญหาคือ Hermitian matrix ของข้อมูลจริงมักไม่ใช่ทั้งสองแบบ · quantum simulation จึงต้องแตก matrix ที่ยาก ให้เป็นหลาย matrix ที่ง่าย (p51)

2.5 ขั้น 3: Lie product formula และ Figure 9-9

สมมติว่าแตก H = H₁ + … + Hₙ ได้แล้ว · Lie product formula (สูตรผลคูณของลี) บอกว่าประมาณ U = exp(−iHt) ได้แบบนี้ (p54–55): ทำ U₁ = exp(−iH₁δt), …, Uₙ = exp(−iHₙδt) ต่อกันตามลำดับ โดยแต่ละตัวทำแค่ช่วงเวลาสั้นๆ δt แล้ววนทั้งชุดซ้ำ m รอบ

exp(−iHt) ≈ (U₁ U₂ … Uₙ)m    โดย δt = t/m

⚠️ สไลด์เขียนแค่ U₁ = exp(−iH₁δt), …, Uₙ = exp(−iHₙδt) แล้วเล่าเป็นคำพูด · บรรทัดสูตรรวมข้างบนกับ δt = t/m หนูเขียนสรุปเองจากสูตร Lie product ที่ใช้กันทั่วไป

ทำไมต้องหั่นเป็นชิ้นเล็กแล้ววนหลายรอบ (หนูเติม intuition เอง): ถ้า H₁ กับ H₂ ทำสลับลำดับกันแล้วได้ผลเหมือนกัน ทำแต่ละตัวครั้งเดียวยาวๆ ก็จะได้คำตอบตรงเป๊ะ (m = 1) · แต่ส่วนใหญ่ลำดับมีผล ทำ H₁ จนเสร็จแล้วค่อยทำ H₂ จึงได้คำตอบเพี้ยน · ทางแก้คือทำสลับกันทีละนิด

2.6 ขั้น 1: แตก H ด้วย graph coloring

⚠️ หัวสไลด์ p56–58 พิมพ์ผิด หัวสไลด์เขียนว่า "Destructing H" แต่เนื้อหาคือขั้น Deconstruct (การแตก H) · ถ้าข้อสอบใช้คำว่า Destructing ให้เข้าใจว่าเป็นเรื่องเดียวกัน

วิธีในกลุ่ม product formula แต่ละวิธีแตก H ต่างกัน ใช้คณิตหนัก และตั้งเงื่อนไขกับ H ต่างกัน (p56) · สไลด์ยกตัวอย่างวิธีหนึ่ง:

  1. ถ้า H เป็น sparse (เบาบาง) คือส่วนใหญ่เป็นศูนย์ และเข้าถึงตัวที่ไม่เป็นศูนย์ได้อย่าง efficient
  2. มอง H เป็น adjacency matrix (เมทริกซ์ประชิด) ของ graph (กราฟ): ช่อง (j, k) ไม่เป็นศูนย์ = มี edge เชื่อม vertex j กับ k
  3. แก้ coloring problem (ปัญหาระบายสีกราฟ) บนกราฟนั้น → แต่ละสีจะรวมเป็นชิ้น Hᵢ ที่ simulate ง่าย
