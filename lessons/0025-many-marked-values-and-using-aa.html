Quantum Programming · Lec 06 · บทที่ 0025

mark หลายค่า — คลื่นถี่ขึ้น และ AA เอาไปใช้ทำอะไร

บทที่แล้ว (0024) เรา mark ค่าเดียว แล้วเห็นว่าความน่าจะเป็น แกว่งเป็นคลื่น ยอดแรกอยู่ที่รอบ ⌊π√(2ⁿ)/4⌋ · แต่โจทย์จริงมักมีคำตอบถูกหลายตัว — บทนี้ลองเปลี่ยนตัวแปรเดียวคือ m = จำนวนค่าที่ถูก mark แล้วดูว่าคลื่นเปลี่ยนยังไง จนไปถึงคำถามว่า “แล้ว AA เอาไปทำอะไรได้จริง”

ทำไมต้องเรียนบทนี้ — จับหลัก 4 อย่าง: ① m มากขึ้น → คลื่นถี่ขึ้น (ขึ้นกับจำนวน ไม่ใช่ค่าไหน) ② m = N/4 ได้ 100% ในรอบเดียว · m = N/2 พังสนิท (50% ตลอด) ③ สูตร NAA = ⌊(π/4)√(2ⁿ/m)⌋ — ต้องรู้ m ก่อน ④ ไม่รู้ m? → AA + QFT = Quantum Sum Estimation · และ AA เร่งอัลกอริทึมคลาสสิกแบบ quadratic

ส่วนที่ 1 · mark 1, 2, 3, 4 ค่า → คลื่นถี่ขึ้นเรื่อยๆ

โค้ด: flip ทีละค่าใน n2f แล้ว mirror ครั้งเดียว

แก้จากโค้ดบท 0024 นิดเดียว — ใส่ลิสต์ n2f (numbers to flip) แล้วในแต่ละรอบ AA ให้ flip ทุกค่าในลิสต์ (ท่าเดิม not(~n) → cphase(180) → not(~n)) ก่อนเรียก Grover() ครั้งเดียว

var n2f = [4, 7];                  // ค่าที่จะ flip
var number_of_iterations = 50;
qc.reset(4);
var reg = qint.new(4, 'reg');
reg.write(0);
reg.hadamard();

for (var i = 0; i < number_of_iterations; ++i) {
    for (var j = 0; j < n2f.length; ++j) {   // flip: ทีละค่า
        var marked_term = n2f[j];
        reg.not(~marked_term);
        reg.cphase(180);
        reg.not(~marked_term);
    }
    reg.Grover();                              // mirror: ครั้งเดียวต่อรอบ

    var prob = 0;                              // รวมโอกาสของทุกค่าที่ mark
    for (var j = 0; j < n2f.length; ++j)
        prob += reg.peekProbability(n2f[j]);
    qc.print('iters: ' + i + ' prob: ' + prob);
}

“สำเร็จ” ในบทนี้ = READ ได้ค่าใดค่าหนึ่งในกลุ่มที่ mark → เลยต้องบวกความน่าจะเป็นของทุกตัว

ฝึกนับ: ถ้า n2f = [4, 7] AA 1 รอบ จะมีเกต CZ 4 ขา (cphase(180) ทั้งรีจิสเตอร์) กี่ตัว?
ใบ้: อย่าลืมว่าข้างใน mirror ก็มี CZ อยู่ (บท 0023)
ถูกค่ะ — flip 2 ค่า = CZ 2 ตัว + mirror มี CZ อีก 1 ตัว = 3 · ส่วน flip ยาวขึ้นตาม m แต่ mirror เท่าเดิมเสมอ
ยังไม่ใช่ค่ะ — flip แต่ละค่ามี CZ ของตัวเอง (2 ค่า = 2 ตัว) และ mirror = H→X→CZ→X→H มีอีก 1 → รวม 3

ผลหลัง AA 1 รอบ: m ต่างกัน วงโตต่างกัน

สังเกต: ค่าที่ mark ค่าไหนก็ได้ (4, 7, 8…) ผลรวมเท่าเดิม — สิ่งที่ทำให้ตัวเลขเปลี่ยนคือจำนวน m เท่านั้น

⚠️ ทิศเข็มในสไลด์ p21–p23 ต่างจากรูปนี้ — สไลด์วาด marked ชี้ทางหนึ่ง ค่าอื่นชี้อีกทาง และสลับทิศไปมาระหว่างรูป ส่วนรูปข้างบนคาโฮะคำนวณตรงจาก “หลัง AA 1 รอบ” (convention เดียวกับบท 0024) ซึ่งเฟสเท่ากันหมด · ไม่ต้องตกใจ — เพราะ ที่วัดได้มีแค่ relative phase และสิ่งที่รูปอยากสื่อคือขนาดวง ซึ่งตรงกัน · อีกจุด: รูปชื่อ “Two values flipped” แต่วาดสถานะหลังขยายแล้ว ไม่ใช่หลัง flip เฉยๆ (หลัง flip เฉยๆ วงยังเท่ากันหมด)

m = 4 จาก 16: รอบแรก 100% แล้ววนทุก 3 รอบ

กรณีพิเศษ — mark |4⟩ |7⟩ |8⟩ |14⟩ (1 ใน 4 ของรีจิสเตอร์) แล้วดู 4 รอบแรก (สไลด์ Figure 6-14):

  • รอบ 1: ค่าอื่นหายเกลี้ยง (วงว่าง) → READ ได้ค่าที่ mark แน่นอน
  • รอบ 2: วงเท่ากันหมด แต่เฟสแยกสองกลุ่ม → กลับไป 25% (= 4/16 เท่าสุ่ม)
  • รอบ 3: เท่ากันหมดและเฟสตรงกันหมด = หน้าตาเหมือนสถานะเริ่มต้นเป๊ะ (หลัง HAD) → รอบถัดไปจึงซ้ำรอบ 1 → คาบ = 3
⚠️ แกน x ของกราฟในสไลด์ (p21–p29) เริ่มที่ 0 — แต่ “0” คือหลังทำ AA ไปแล้ว 1 รอบ เพราะกราฟพล็อตตาม i ในโค้ด ซึ่งพิมพ์หลัง Grover() · ดูได้จากจุด x=0 ของกรณี m = 4 ที่เป็น 100% (ถ้าเป็น 0 รอบจริงต้อง 25%) · กราฟข้างบนคาโฮะนับแบบ “รอบที่ 1, 2, …” · ตอนสอบถ้าโจทย์ชี้กราฟ ให้อ่านตามแกนสไลด์ แต่รู้ว่าคลาดกัน 1

ส่วนที่ 2 · ดันจนสุด: m = N/2 พัง → สูตรที่มี m → เอาไปใช้

m = 7: ยังขยายได้ แต่คุ้มไหม?

mark 7 จาก 16 คลื่นถี่มาก (คาบ ≈ 2.2 รอบ) รอบแรกได้ 68.4% · สไลด์ชี้ว่า ต่อให้ READ ได้ค่าที่ “ถูก” ก็ไม่ค่อยมีประโยชน์ — เกือบครึ่งรีจิสเตอร์เป็นคำตอบถูกอยู่แล้ว สุ่มเดาเอาก็ได้ 43.75%

ทายก่อนอ่านต่อ: mark 8 จาก 16 (ครึ่งหนึ่งพอดี) ทำ AA ไป 10 รอบ โอกาส READ ได้ค่าที่ mark เป็นเท่าไร?
ถูกค่ะ — m = N/2 แล้ว AA ไม่ทำอะไรเลย ได้ 50% ตลอดกาล เท่ากับสุ่ม · ไปดูเหตุผลข้างล่าง
ยังไม่ใช่ค่ะ — คำตอบคือ 50% ทุกรอบ (Figure 6-19 จุดทุกจุดนอนราบที่ 50%) · ทำไมถึงเป็นแบบนั้น อ่านต่อข้างล่างนะคะ

ทำไม m = 8 พังสนิท: relative phase

  1. จำจากบท 0003: สิ่งที่วัดผลได้คือเฟสสัมพัทธ์ (relative phase) ระหว่างวง ไม่ใช่เฟสของแต่ละวงเอง
  2. พลิกเฟส 8 ค่า → ได้ “ครึ่งหนึ่ง 0° / ครึ่งหนึ่ง 180°” · แต่พลิกอีก 8 ค่าที่เหลือก็ได้หน้าตาแบบเดียวกันทุกอย่าง (ต่างกันแค่เฟสรวมทั้งก้อน) → ในทางกายภาพ “mark กลุ่มนี้” กับ “mark อีกกลุ่ม” แยกกันไม่ออก
  3. เมื่อ QPU แยกไม่ออกว่ากลุ่มไหนคือคำตอบ mirror ก็ไม่มีทางดันกลุ่มไหนให้โต → magnitude เท่ากันตลอด → 50%

ในรูป: รอบ 1 วงเท่ากันแต่เฟสแยกครึ่ง · รอบ 2 flip ทำให้เฟสกลับมาตรงกันหมด = สถานะเริ่มต้น → วนแค่ 2 สภาพนี้ไปเรื่อยๆ (คาโฮะคำนวณยืนยันแล้ว แถว 2nd ของสไลด์ p28 ที่ “ชี้ลงหมด” ถูกต้อง)

สมมาตร: m > N/2 ไม่ต้องคิดแยก — mark 12 จาก 16 ให้ผลเหมือน mark 4 จาก 16 ทุกอย่าง แค่สลับว่าอะไรคือ “สำเร็จ” กับ “ล้มเหลว” (m = 12: รอบ 1, 2, 3 = 0%, 75%, 75% = 100 − ของ m = 4)

สูตรจำนวนรอบเมื่อมี m ค่าที่ mark

จากการทดลองข้างบน สไลด์สรุปว่า ความถี่ของการแกว่งขึ้นกับจำนวนค่าที่ flip เท่านั้น ไม่ขึ้นกับว่า flip ค่าไหน → ขยายสูตรบท 0024 ให้มี m:

NAA = ⌊ (π/4) · √(2ⁿ / m) ⌋
  • n = จำนวน qubit · 2ⁿ = N ขนาดรีจิสเตอร์ · m = จำนวนค่าที่ mark · ⌊ ⌋ = ปัดลง
  • m = 1 → กลับเป็นสูตรเดิม ⌊π√(2ⁿ)/4⌋ พอดี
  • ตรงกับตาราง: n = 4 → m = 1 ได้ 3 · m = 2 ได้ ⌊2.22⌋ = 2 · m = 3 ได้ ⌊1.81⌋ = 1 · m = 4 ได้ ⌊1.57⌋ = 1
ลองคำนวณ: รีจิสเตอร์ 6 qubit มีคำตอบถูก 4 ค่า ควรทำ AA กี่รอบ?
ใบ้: π/4 ≈ 0.785
ถูกค่ะ — 2⁶/4 = 16 → √16 = 4 → 0.785 × 4 = 3.14 → ปัดลง = 3 (ได้ ≈ 96%)
ยังไม่ใช่ค่ะ — 2⁶ = 64 · 64/4 = 16 · √16 = 4 · (π/4)×4 = π ≈ 3.14 → ปัดลงได้ 3 · (6 = ลืมหาร m · 4 = ลืมคูณ π/4)
ไก่กับไข่ — สูตรนี้ใช้ได้ต่อเมื่อรู้ m · แต่ถ้าไม่รู้ว่ามีคำตอบถูกกี่ตัว จะรู้ได้ยังไงว่าต้องวนกี่รอบ? ทำเกินก็ร่วง ทำขาดก็ต่ำ · สไลด์บอกว่า “จะกลับมาตอบด้วย primitive ตัวอื่น” → ดูข้างล่าง

เอา AA ไปใช้ ① Quantum Sum Estimation (การประมาณผลรวมเชิงควอนตัม)

เชื่อมจุดที่เพิ่งเห็น: ความถี่ของคลื่นบอก m — เหมือนดูความถี่ชิงช้าแล้วรู้ความยาวเชือก

AAทำให้ความน่าจะเป็น “แกว่ง” ด้วยความถี่ที่ขึ้นกับ m
+
QFT — Quantum Fourier Transformprimitive ตัวถัดไป (Lec 07) READ “ความถี่” ของสิ่งที่แกว่งในรีจิสเตอร์ออกมาได้

รวมกัน = วงจรที่ READ ออกมาได้ไม่ใช่แค่ “คำตอบหนึ่งตัว” แต่เป็นตัวเลขที่บอกว่ามีคำตอบกี่ตัว → นี่คือ Quantum Sum Estimation (รายละเอียดเต็มเรียนภายหลัง) · และรู้ m แล้วก็เอาไปแทนสูตร NAA ได้ = แก้ปัญหาไก่กับไข่

เอา AA ไปใช้ ② เร่งอัลกอริทึมคลาสสิกแบบ quadratic (กำลังสอง)

AA ใช้เป็น subroutine ได้กับโจทย์ที่ต้องเรียกตัวตรวจคำตอบซ้ำๆ เช่น boolean satisfiability (หาค่า true/false ที่ทำให้นิพจน์ตรรกะเป็นจริง) และการหา global / local minima (ค่าต่ำสุดรวม / ค่าต่ำสุดเฉพาะที่)

ส่วนของ AAบทบาทในงานจริงเปลี่ยนตามโจทย์?
flipencode ตัวตรวจคำตอบ (เทียบเท่า subroutine คลาสสิกที่เช็กว่าคำตอบใช้ได้ไหม)✅ เปลี่ยน
mirrorแปลงเฟส → magnitude❌ เหมือนเดิมทุกงาน

“quadratic” มาจาก √ ในสูตร: คลาสสิกต้องไล่ตรวจราว N ครั้ง · AA ใช้ราว (π/4)√N รอบ · N = 1,000,000 → ≈ 785 รอบ

ค้นคำตอบถูก 1 ตัวใน N = 10,000 ตัว — AA ต้องวนประมาณกี่รอบ?
ถูกค่ะ — √10,000 = 100 → × π/4 ≈ 78.5 → 78 รอบ · เทียบคลาสสิกที่อาจต้องตรวจเป็นหมื่นครั้ง
ยังไม่ใช่ค่ะ — (π/4)·√10,000 = 0.785 × 100 ≈ 78 · (100 = ลืม π/4 · 7854 = ลืมถอดรูท · 5000 = ค่าเฉลี่ยของคลาสสิก)

  5. m = 8 จาก 16 ได้เท่าไร เพราะอะไร?

  6. m = 12 จาก 16 คิดยังไง?

  9. AA + QFT อ่านอะไรออกมาได้ ชื่อเทคนิคว่าอะไร?

  10. ใช้ AA เร่งอัลกอริทึมคลาสสิก ส่วนไหนเปลี่ยนตามโจทย์ ได้ speedup แบบไหน?
    flip = ตัวตรวจคำตอบ (mirror คงที่) · quadratic

สรุปบทนี้

  • multi-flip: flip ทุกค่าใน n2f → Grover() 1 ครั้ง ต่อรอบ · ความน่าจะเป็น = ผลรวมของทุกค่าที่ mark
  • m มากขึ้น → คลื่นถี่ขึ้น (คาบ 6.2 → 4.3 → 3.5 → 3) · ขึ้นกับจำนวน ไม่ใช่ค่าไหน
  • m = N/4 → 100% รอบแรก วนทุก 3 รอบ · m = N/2 → 50% ตลอด (relative phase) · m > N/2 = สมมาตร
  • NAA = ⌊(π/4)√(2ⁿ/m)⌋ ต้องรู้ m → ไม่รู้ใช้ AA + QFT = Quantum Sum Estimation
  • AA = subroutine เร่ง quadratic · flip = ตัวตรวจคำตอบ (เปลี่ยน) · mirror = คงที่
  • ⚠️ สไลด์: แกน x = 0 คือหลัง 1 รอบ · ทิศเข็มรูป p21–23 สลับไปมา (ดูขนาดวงเป็นหลัก)
