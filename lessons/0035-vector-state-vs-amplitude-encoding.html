เก็บ vector: state encoding vs amplitude encoding

บทที่แล้วเราโหลดตัวเลขทีละตัวเข้า register (fixed point, RAM, QRAM) · บทนี้ขยับขึ้นอีกขั้นเป็น vector (เวกเตอร์) ซึ่งก็คือรายการตัวเลขหลายตัวเรียงกัน และเป็นข้อมูลที่เจอบ่อยมากใน quantum machine learning (p22) · มีวิธีเก็บอยู่ 2 แบบ: แบบตรงไปตรงมาที่เปลือง qubit กับแบบควอนตัมที่ประหยัดมาก แต่มีเงื่อนไขซ่อนอยู่ 2 ข้อ

ทำไมต้องเรียนบทนี้: จับหลัก 3 อย่าง ① state encoding = 1 component ใช้ 1 register (เปลือง qubit แต่ไม่ต้องมี QRAM) ② amplitude encoding = ทุก component อยู่ใน amplitude ของ register เดียว ใช้แค่ ⌈log₂ n⌉ qubit ③ ราคาที่ต้องจ่ายมี 2 ข้อ: output อ่านทีละค่าไม่ได้ และ vector ต้อง normalize (พื้นที่วง = amplitude² ไม่ใช่ amplitude) · บทนี้ไม่มีสัญลักษณ์วงจรใหม่ แต่ที่น่าจะออกสอบคือการนับ qubit และการอ่านค่าจาก circle notation

1.2 วิธีแรก: state encoding (การเข้ารหัสแบบสถานะ)

วิธีที่ตรงไปตรงมาที่สุด: ให้แต่ละ component มี register ของตัวเอง แล้วเขียนค่าลงไปเป็นเลขฐานสองแบบที่เราทำมาตลอด (p22) · ค่าแต่ละตัวอยู่ในช่วง 0–3 → ใช้ register ละ 2 qubit · มี 4 component → 4 register × 2 qubit = 8 qubit (Figure 9-6, p23)

Figure 9-6 · แต่ละ register อยู่ใน basis state ตัวเดียว (วงเต็มวงเดียว) ไม่มี superposition เลย

state encodingเหมือนจดคะแนนนักเรียน 4 คนลงกระดาษ 4 แผ่น แผ่นละคะแนน · อ่านง่าย แต่เปลืองกระดาษ

1.3 วิธีที่สอง: amplitude encoding (การเข้ารหัสลงแอมพลิจูด)

ลองนึกย้อนไปว่า register ขนาด n qubit มีวงอยู่ 2ⁿ วง และทุกวงมี amplitude ของตัวเอง (บท 0003) · state encoding ใช้แค่วงเดียวต่อ register แล้วทิ้งวงที่เหลือว่างไว้ · ไอเดียของ amplitude encoding คือใช้ทุกวงให้คุ้ม: เอา component ตัวที่ i ไปเป็น amplitude ของวง |i⟩ ใน register เดียว (p25)

Figure 9-7 · register 2 qubit เดียว · วง |3⟩ ใหญ่สุดเพราะ component ตัวที่ 3 มีค่ามากสุด · (ขนาดวงที่วาดตรงนี้ normalize แล้ว ซึ่งจะอธิบายในส่วนที่ 2)

ประโยคทอง: state encoding เก็บค่าไว้ในว่าวงไหนเต็ม · amplitude encoding เก็บค่าไว้ในว่าแต่ละวงใหญ่แค่ไหน · vector ที่มี n component ใช้แค่ ⌈log₂ n⌉ qubit (เพราะต้องมีวงอย่างน้อย n วง)
ทบทวนคณิต: ⌈log₂ n⌉ แปลว่า "ต้องยก 2 กำลังเท่าไรถึงจะได้อย่างน้อย n" แล้วปัดขึ้น · n = 4 → 2² = 4 → 2 qubit · n = 8 → 2³ = 8 → 3 qubit · n = 5 → 2² = 4 ไม่พอ ต้องใช้ 2³ = 8 → 3 qubit (วงที่เกินมาปล่อย amplitude เป็น 0) · ข้อสังเกต: n = 1,000,000 → แค่ 20 qubit (2²⁰ ≈ 1.05 ล้าน) · state encoding จะต้องใช้ล้าน register!
สไลด์เขียนไม่ชัด (p25): สไลด์เขียน ceil(log(n)) โดยไม่บอกฐาน · ที่ถูกคือ log ฐาน 2 · และสไลด์ใช้ตัว n ซ้ำกันทั้ง "n qubit มี 2ⁿ amplitude" กับ "vector n component" ซึ่งเป็นคนละ n · ตอนสอบเขียน ⌈log₂ n⌉ โดย n = จำนวน component

ลองแยกคิดทีละฝั่งนะคะ · amplitude encoding: ต้องมีวงอย่างน้อย 8 วง → กี่ qubit? · state encoding: ค่า 7 ต้องใช้กี่บิต แล้วมีกี่ component?

1.5 ในโค้ด: amplitude_encode() (Example 9-3, p28)

QCEngine มีฟังก์ชันสำเร็จรูป รับ array ของ vector กับ register ที่ใหญ่พอ แล้วเตรียม register ให้อยู่ใน amplitude encoding ของ vector นั้น:

// We have ensured that our input vector has a length
// that is a power of two
var vector = [-1.0, 1.0, 1.0, 5.0, 5.0, 6.0, 6.0, 6.0];
// Create register of right size to amplitude-encode vector
var num_qubits = Math.log2(vector.length);   // 8 component → 3 qubit
qc.reset(num_qubits);
var amp_enc_reg = qint.new(num_qubits, 'amp_enc_reg');
// Generate amplitude encoding in amp_enc_reg
amplitude_encode(vector, amp_enc_reg);
  • คอมเมนต์บรรทัดแรกบอกว่า vector ยาวเป็นกำลังของ 2 → Math.log2 ได้จำนวนเต็มพอดี (ถ้าไม่ใช่ก็ต้องปัดขึ้นและเติม 0 เอง)
  • component แรกเป็น −1.0 → amplitude ติดลบ = phase 180° (เข็มชี้ลง) · นี่คือสิ่งที่ state encoding ทำไม่ได้: เครื่องหมายไปอยู่ใน phase ได้ตรงๆ

สไลด์ไม่ได้แสดงผลลัพธ์ · คาโฮะคำนวณเองว่าหลัง normalize (หารด้วย √161 ≈ 12.69 ซึ่งจะอธิบายในส่วนที่ 2) จะได้ register หน้าตาประมาณนี้:

ตัวเลขใต้วง = amplitude · วง |0⟩ (ส้ม) เล็กเท่า |1⟩ |2⟩ แต่เข็มชี้ลง เพราะ amplitude ติดลบ

typo ในสไลด์ (p28–29): 'amp_enc_reg’ ปิดด้วย smart quote (’) ซึ่ง JavaScript จะ error · โค้ดข้างบนแก้เป็น ' แล้ว

1.6 เดี๋ยวนะ QCEngine ไม่มี QRAM แล้วทำได้ยังไง? (p29)

vector ถูกส่งเข้าไปเป็น JavaScript array ที่อยู่ใน RAM ธรรมดา แต่การโหลดข้อมูลเป็น superposition ควรต้องใช้ QRAM (บท 0034) · คำตอบของสไลด์คือ: สร้างวงจร amplitude encoding โดยไม่มี QRAM ก็ทำได้ แต่ทำแบบ efficient ไม่ได้ · amplitude_encode() ใน QCEngine จึงเป็นการจำลองที่ช้าแต่ใช้งานได้ ของสิ่งที่จะทำได้เร็วถ้ามี QRAM จริง

ข้อไหนอธิบาย amplitude_encode() ใน QCEngine ได้ตรงกับสไลด์ที่สุด?
ถูกค่ะ · ไม่มี QRAM ก็สร้างได้ แต่ต้นทุนสูง · QCEngine จึงเป็น "การจำลองที่ช้า" ของ QRAM ไม่ใช่ QRAM จริง
ยังไม่ใช่ค่ะ · สไลด์ p29 บอกว่าทำได้โดยไม่มี QRAM แต่มีจุดอ่อนอยู่ข้อนึง ลองนึกว่าข้อไหนพูดถึงจุดอ่อนนั้น

2.1 Caveat 1: output ที่เป็นควอนตัมอ่านไม่ได้ (p31–33)

ย้อนไปพื้นฐานจาก Lec 02: READ แล้วได้ผลลัพธ์เดียวแบบสุ่ม และ superposition ยุบ · ถ้า vector ถูกกระจายไว้ใน amplitude ของ superposition เราจะอ่านค่าแต่ละ component กลับออกมาไม่ได้ (สไลด์ใช้คำว่า un-READable)

ตอนเป็น input · ไม่ค่อยมีปัญหา
เราโหลดมาจาก memory เอง → รู้ทุก component อยู่แล้ว ไม่จำเป็นต้องอ่านกลับ
ตอนเป็น output · มีปัญหา
app ที่รับ input เป็น amplitude-encoded vector มักให้ output เป็น amplitude-encoded vector ด้วย → คำตอบติดอยู่ใน amplitude ที่อ่านออกมาตรงๆ ไม่ได้
amplitude-encoded outputข้อมูลล้านตัวอยู่ใน register 20 qubit แต่ READ ได้ทีละ "เลขวง" เดียวแบบสุ่ม แล้วของทั้งหมดหายไป

ห้องสมุดที่ยืมได้เล่มเดียวหนังสือล้านเล่มอยู่ในห้องเดียว แต่ได้ยืมแค่ 1 เล่มแบบจับฉลาก แล้วห้องสมุดก็ปิดถาวร

แต่ไม่ใช่ว่าไร้ประโยชน์: แม้จะรู้ค่าทีละ component ไม่ได้ แต่ยังรู้ global properties (คุณสมบัติภาพรวม) ของ vector ได้ (สไลด์บอกว่าจะเห็นในบทหลังๆ) · ซึ่งก็คือแนวคิดเดียวกับที่เราใช้มาตลอดใน QFT และ phase estimation: ไม่ได้อ่านทุก amplitude แต่จัดการให้คำตอบที่ต้องการไปรวมอยู่ในวงที่ READ ได้ · สไลด์สรุปว่า "no free lunch" คือไม่มีของฟรี ต้องใช้ความระมัดระวังและความเจ้าปัญญา (p32)

นิสัยที่สไลด์อยากให้มี (p33): เห็น quantum machine learning app ไหนอ้างว่าเร็วกว่าแบบดั้งเดิมมหาศาล · ให้ถามทันทีว่า "output ของมันเป็น quantum output หรือเปล่า?" ถ้าใช่ ต้องถามต่อว่าจะดึงคำตอบที่ใช้ได้จริงออกมายังไง เพราะการอ่านอาจกินความเร็วที่ได้มาจนหมด
มีคนอ้างว่าวงจรของเขา "คูณ matrix กับ vector ขนาดล้านตัวได้ในเวลาแค่ไม่กี่ขั้น" และ output อยู่ใน amplitude ของ register 20 qubit · ตาม Caveat 1 ข้อไหนเป็นคำถามที่ควรถามกลับมากที่สุด?
ถูกค่ะ · 20 qubit เก็บได้จริง (2²⁰ ≈ ล้าน) แต่ READ ได้แค่ผลเดียวแล้วยุบ · ถ้าต้องการ component ทุกตัว ความเร็วที่อ้างก็ไม่มีความหมาย · ต้องรู้ว่าดึงคำตอบออกมายังไง (เช่นถามแค่ global property)
ข้อนั้นก็เป็นคำถามที่ถามได้ค่ะ แต่ไม่ใช่ประเด็นของ Caveat 1 · Caveat 1 พูดถึงปลายทางของวงจร: ตอนจบคำตอบอยู่ใน amplitude แล้วเราทำอะไรกับมันได้บ้าง?

2.2 Caveat 2: vector ต้อง normalize (p34–36)

คำถามจากสไลด์ (p34): amplitude ของ register 2 qubit เป็น [0, 1, 2, 3] หรือ [6, 1, 1, 4] ได้จริงไหม? → ไม่ได้ · เพราะมีกฎที่เราเผลอลืมไปตอนใช้ circle notation ที่เน้นภาพ:

|a₀|² + |a₁|² + … + |aₙ₋₁|² = 1

ทำไม? เพราะ |amplitude|² ของแต่ละวง = ความน่าจะเป็นที่ READ แล้วได้ค่านั้น และ READ แล้วต้องได้สักค่าแน่นอน → ความน่าจะเป็นรวมต้องเป็น 100% · กฎนี้เรียกว่า normalization (การทำให้เป็นหน่วย) (p35) · [0, 1, 2, 3] ได้ 0² + 1² + 2² + 3² = 14 ≠ 1 → กฎฟิสิกส์ไม่ยอมให้มี register แบบนี้

วิธีแก้ (p36): หารทุก component ด้วยความยาวของ vector ซึ่งก็คือ √(ผลรวมกำลังสอง):

① ผลรวมกำลังสอง: 0² + 1² + 2² + 3² = 0 + 1 + 4 + 9 = 14
② ตัวหาร = √14 ≈ 3.74 (เรียกว่า normalization factor)
③ [0, 1, 2, 3] ÷ 3.74 = [0.00, 0.27, 0.53, 0.80]
④ เช็ค: 0² + 0.27² + 0.53² + 0.80² ≈ 0 + 0.07 + 0.28 + 0.64 ≈ 1 ✓
สไลด์ใช้คำผิด (p36): สไลด์เขียนว่า "หารด้วย summed squares" แต่ summed squares ของ [0,1,2,3] คือ 14 ไม่ใช่ 3.74 · ตัวเลข 3.74 ในสไลด์คือ √14 ซึ่งถูกต้อง · ตัวเลขถูก แต่ถ้อยคำผิด → ตอนสอบให้หารด้วย √(ผลรวมกำลังสอง) เสมอ

normalize แล้วข้อมูลเสียไหม? (p36) ส่วนใหญ่ไม่เสีย: ในเชิงเรขาคณิตมันแค่ย่อความยาวของลูกศร แต่ทิศทางเหมือนเดิม · สัดส่วนระหว่าง component ยังอยู่ครบ (0.80 ยังเป็น 3 เท่าของ 0.27) · ถ้า app ต้องการความยาวเดิมด้วย ก็เก็บ normalization factor (3.74) ไว้ใน register อื่นได้เสมอ · ส่วนจะ "ดีพอ" ไหมขึ้นกับว่า app ต้องการอะไร

2.4 ทำไมชื่อ amplitude encoding ไม่ใช่ magnitude encoding (p39)

ตัวอย่างที่ผ่านมามีแต่จำนวนจริง · แต่ amplitude ของแต่ละวงมีทั้ง magnitude (ขนาด) และ relative phase (เฟสสัมพัทธ์) → amplitude เป็นจำนวนเชิงซ้อนได้ · แปลว่า amplitude encoding เก็บ vector เชิงซ้อน (ที่ normalize แล้ว) ได้ด้วย · ชื่อจึงเป็น amplitude encoding (ใช้ทั้งขนาดและ phase) ไม่ใช่ magnitude encoding (ใช้แค่ขนาด) · สไลด์บอกว่าจะไม่ทำตัวอย่างแบบเชิงซ้อนให้ดู · ตัวอย่างข้างล่างคาโฮะทำเพิ่มเอง:

0.6² + 0.8² = 0.36 + 0.64 = 1 ✓ · component ที่สองเป็นจำนวนจินตภาพ → เข็มหมุนไป 90° · state encoding เก็บแบบนี้ไม่ได้เลย

ปิดท้ายสไลด์ (p38) ปูทางต่อ: หลาย app (โดยเฉพาะ quantum machine learning) ต้องจัดการ matrix (array 2 มิติ) ไม่ใช่แค่ vector → คำถามของบทหน้าคือจะ encode matrix ยังไง

ทดสอบความจำก่อนปิดบท (พยายามตอบเองก่อนเปิด)
  1. state encoding กับ amplitude encoding เก็บค่าไว้ที่ไหนของ register? → ว่าวงไหนเต็ม (register ละ component) / ขนาดของทุกวง (register เดียว)
  2. vector 16 component ใช้ amplitude encoding กี่ qubit? → ⌈log₂ 16⌉ = 4
  3. ข้อดีเดียวของ state encoding คืออะไร? → ไม่ต้องใช้ QRAM
  4. QCEngine ทำ amplitude_encode() ได้ทั้งที่ไม่มี QRAM เพราะอะไร? → ทำได้โดยไม่มี QRAM แต่ไม่ efficient (เป็นการจำลองที่ช้า)
  5. Caveat 1 คืออะไร และตอนไหนไม่เป็นปัญหา? → quantum output อ่านทีละ component ไม่ได้ · ตอนเป็น input ไม่เป็นปัญหาเพราะรู้ค่าอยู่แล้ว
  6. normalize [0, 1, 2, 3] ต้องหารด้วยอะไร? → √14 ≈ 3.74 (สไลด์เขียน "summed squares" ซึ่งผิด)
  7. วงระบายครึ่งวง amplitude เท่าไร? → √0.5 ≈ 0.71
  8. ทำไมชื่อ amplitude ไม่ใช่ magnitude encoding? → เก็บ phase ได้ด้วย → เก็บ vector เชิงซ้อนได้
