QFT — อ่าน “ความถี่” ที่ซ่อนอยู่ในเฟส

คาบที่แล้ว amplitude amplification (AA) ช่วยเราได้ตอนที่มีค่าเดียวเฟสแปลกแยกจากเพื่อน (0023–0026) · แต่ถ้าคำตอบไม่ได้อยู่ที่ค่าใดค่าหนึ่ง แต่ซ่อนอยู่ใน“รูปแบบ” (pattern) ที่เข็มเฟสหมุนไปทั้ง register ล่ะ? บทนี้รู้จัก primitive ตัวที่สอง: QFT

ทำไมต้องเรียนบทนี้ — จับหลัก 4 อย่าง: ① ถ้าเข็มเฟสหมุนเป็นจังหวะแต่ magnitude เท่ากันหมด → READ เฉยๆ ได้ค่าสุ่ม และ AA ก็ช่วยไม่ได้ ② ใส่ QFT ก่อน READ → ได้ค่าเดียวแน่นอน = จำนวนรอบที่เข็มหมุนครบตลอด register (ความถี่) ③ หน้าตาวงจร QFT 4 สาย: H + CPHASE มุมลบ (−90/−45/−22.5) เป็นขั้นบันได + SWAP ท้าย (เรื่องสอบ) ④ QFT เขียนผลลงregister เดิม (in-place) เพราะตัวมัน reversible → เลยเรียกว่า “transform”

ส่วนที่ 1 · เกมทายสถานะ ที่ READ ธรรมดาแพ้

นิยามจากสไลด์ (p2) — QFT (Quantum Fourier Transform, การแปลงฟูเรียร์เชิงควอนตัม) คือ primitive ที่ให้เราเข้าถึงรูปแบบและข้อมูลที่ซ่อนอยู่ใน relative phase และ magnitude ของ register · AA ก็จัดการเฟสเหมือนกัน แต่ QFT ใช้วิธีของตัวเองที่ต่างออกไป · และ QFT ยังช่วยเตรียม superposition ซับซ้อนได้ง่ายด้วย (เก็บไว้บท 0029)

โจทย์: register 4 qubit เป็นสถานะ A, B หรือ C สักอัน — อันไหน?

ทุกวงขนาดเท่ากันหมด (1/16 = 6.25%) ต่างกันแค่ทิศของเข็ม (0° = ชี้ขึ้น · บวก = ทวนเข็มนาฬิกา)

สถานะ A — เข็มสลับ 0° / 180° ทีละวง

สถานะ B — เข็มเพิ่มทีละ 90°

สถานะ C — เข็มเพิ่มทีละ 45°

Figure 7-1 (สไลด์ p3–4) · ⚠️ A/B/C ชุดนี้คนละชุดกับ A/B/C ของคาบ AA (สไลด์เตือนเอง)

ตาเราเห็นชัดว่าสามแถวต่างกัน · แต่ถ้า READ register ตรงๆ 1 ครั้ง จะแยกได้ไหมว่าเป็นสถานะไหน?
ถูกค่ะ — READ เห็นแค่ magnitude ซึ่งเท่ากันหมด 6.25% ทุกวงทั้งสามสถานะ → ได้เลข 0–15 สุ่มเท่าๆ กัน · และ AA ก็ช่วยไม่ได้ เพราะไม่มีวงไหนเฟสโดดเด่นต่างจากเพื่อน — ทุกวงต่างจากวงข้างๆ เท่ากันหมด (p4)
ยังไม่ใช่ค่ะ — READ มองไม่เห็นเฟส เห็นแค่ magnitude ที่เท่ากันหมด → สุ่ม 0–15 เท่าๆ กันทุกสถานะ · ส่วน AA ต้องมีค่าที่เฟสแปลกแยก (oddball) แต่ที่นี่ไม่มีวงไหนแปลกกว่าเพื่อนเลย (p4)

ใส่ QFT ก่อน READ → เหลือวงเดียว เต็ม 100%

C หลัง QFT

Figure 7-2 (สไลด์ p5) · B ซ่อนไว้ก่อน ให้ทายในข้อถัดไป

สังเกตความเชื่อมโยง (p6): ไล่จาก |0⟩ ไป |15⟩ ใน A เข็มวนกลับมาที่ 0° ทั้งหมด 8 ครั้ง → READ ได้ 8 · ใน C เข็มหมุนครบ 2 รอบ → READ ได้ 2

ทายก่อนดูสไลด์ — สถานะ B (เพิ่มทีละ 90°) หลัง QFT แล้ว READ จะได้เลขอะไรแน่นอน?
ถูกค่ะ! B หมุน 0→90→180→270 แล้ววนกลับ ทุก 4 วง → ครบ 16 ÷ 4 = 4 รอบ → READ ได้ |4⟩ (Figure 7-2 แถวกลาง) · สิ่งที่ QFT เผยออกมาคือ signal frequency (ความถี่สัญญาณ) ที่ซ่อนอยู่ในเฟส
ลองนับใหม่ค่ะ — ไม่ได้ถามมุม แต่ถามว่าเข็มหมุนครบกี่รอบตลอด 16 วง · B กลับมา 0° ทุก 4 วง (ที่ |0⟩ |4⟩ |8⟩ |12⟩) → ครบ 4 รอบ → READ ได้ 4

ความถี่ ≠ คาบ — จุดที่สับสนง่ายที่สุด

ในบทนี้ “คาบ” = กี่วงถึงจะวนกลับ · “ความถี่” = วนกลับกี่ครั้งตลอด register · สองตัวคูณกันได้ขนาด register เสมอ

สถานะมุมเพิ่มทีละคาบ (วงต่อรอบ)ความถี่ (รอบต่อ register)QFT แล้ว READ ได้
A180°288
B90°444
C45°822
คาบ × ความถี่ = 16 (= 2จำนวน qubit)  ·  มุมที่เพิ่มต่อวง = ความถี่ × 360° ÷ 16
กับดัก — A มีคาบ 2 แต่ QFT ให้ 8 · อย่าตอบคาบ · QFT ตอบความถี่เสมอ (B บังเอิญคาบ = ความถี่ = 4 เพราะ 4 × 4 = 16 · อย่าใช้ B จำกฎ)

โค้ดที่สร้าง A/B/C (Example 7-1, สไลด์ p7)

var num_qubits = 4;
qc.reset(num_qubits);
var signal = qint.new(num_qubits, 'signal')
var which_signal = 'A';
// prepare the signal
signal.write(0);
signal.hadamard();              // 16 วงเท่ากัน เข็มชี้ขึ้นหมด
if (which_signal == 'A') {
    signal.phase(180, 1);
} else if (which_signal == 'B') {
    signal.phase(90, 1);
    signal.phase(180, 2);
} else if (which_signal == 'C') {
    signal.phase(45, 1);
    signal.phase(90, 2);
    signal.phase(180, 4);
}
signal.QFT()
refresher: phase(θ, mask) (บท 0008) — ใส่เฟส θ ให้ทุกวงที่บิตตาม mask เป็น 1 (ตัวเลขตัวหลังคือ bitmask) · หลายคำสั่งซ้อนกัน → มุมบวกกัน · ตัวอย่าง C วง |5⟩ = 0101 → บิต 0x1 กับ 0x4 เป็น 1 → 45° + 180° = 225° ตรงกับรูป · เคล็ด: มุมบนบิต 0x1, 0x2, 0x4 เท่าตัวไปเรื่อยๆ (45, 90, 180) → วง |k⟩ ได้ 45° × k พอดี
อยากได้สัญญาณความถี่ 1 (เข็มหมุนครบ 1 รอบพอดีตลอด 16 วง) ต้องใส่ phase ชุดไหนหลัง hadamard()?
ถูกค่ะ — มุมต่อวง = 1 × 360° ÷ 16 = 22.5° · ใส่ให้บิต 0x1 แล้วเท่าตัวขึ้นไป → |k⟩ ได้ 22.5° × k · |15⟩ = 337.5° แล้ววนกลับ 360° พอดี = 1 รอบ → QFT แล้ว READ ได้ 1 (หนูจำลองวงจรเช็คแล้ว ได้ |1⟩ 100%)
ยังไม่ใช่ค่ะ — มุมต่อวง = ความถี่ × 360° ÷ 16 = 22.5° · วง |k⟩ ต้องได้ 22.5° × k · ให้บิตน้อยสุด (mask 1) ได้ 22.5° แล้วเท่าตัวขึ้นไป: 45 บน mask 2 · 90 บน mask 4 · 180 บน mask 8 · (ชุดที่ใส่ 360° = ไม่ได้ใส่อะไรเลย เพราะ 360° ≡ 0°)

เรียก QFT ใน QCEngine ได้ 2 แบบ (p7): qc.QFT() — ระดับ global รับชุด qubit เป็น argument · qint.QFT() — method ของ qint ทำกับทุก qubit ใน qint นั้น (อย่าง signal.QFT() ข้างบน)

บทนี้ยังไม่ต้องเข้าใจว่าทำไมแต่ละ gate ถึงทำงาน (นั่นคือบท 0030) · แต่ต้องจำหน้าตาให้ได้เพราะออกสอบ · อ่านกล่อง QFT จากซ้ายไปขวาจะเห็นเป็นขั้นบันได:

① H บนสาย 0x8 (สายบนสุดของบิตสูง) → CPHASE จาก 0x8 ไปหา 0x4, 0x2, 0x1 มุม −90°, −45°, −22.5°
② H บน 0x4 → CPHASE ไปหา 0x2, 0x1 มุม −90°, −45°
③ H บน 0x2 → CPHASE ไปหา 0x1 มุม −90°
④ H บน 0x1 (ไม่มีใครเหลือให้คุยด้วย)
⑤ SWAP กลับหัว: 0x1↔0x8 และ 0x2↔0x4
→ ทุกขั้น: มุมเริ่มที่ −90° แล้วหารครึ่งทุกครั้งที่ไกลออกไปอีก 1 สาย · มุมติดลบทั้งหมด
สัญลักษณ์ SWAP 2 แบบในคอลัมน์เดียวกัน (จุดสอบ!) — ท้ายวงจร 0x1↔0x8 วาดเป็น ×—× ตามปกติ · แต่ 0x2↔0x4 วาดเป็นเส้นสายไขว้กันเฉยๆ ไม่มี × · ความหมายเหมือนกันทุกอย่าง คือสลับค่า 2 สาย (น่าจะวาดแบบนี้เพราะเส้นตั้งของ ×—× พาดผ่าน 0x2 กับ 0x4 อยู่แล้ว ถ้าใส่ × ซ้อนจะอ่านไม่ออก)
ถ้าลืม SWAP ท้ายวงจร สถานะ C (ความถี่ 2 = 0010) จะ READ ได้อะไร?
ถูกค่ะ — ก่อน SWAP ผลอยู่ในลำดับบิตกลับหัว: 0010 อ่านกลับเป็น 0100 = 4 · SWAP 0x1↔0x8 กับ 0x2↔0x4 คือการกลับลำดับบิตให้ถูก (หนูจำลองวงจรเช็คแล้ว) · เหตุผลที่ผลออกมากลับหัวจะเห็นในบท 0030
ยังไม่ใช่ค่ะ — SWAP คู่ 0x1↔0x8 กับ 0x2↔0x4 = กลับลำดับบิตทั้ง 4 ตัว · ไม่มี SWAP ผลจะค้างในรูปกลับหัว: 0010 → 0100 = 4 · (ยังได้ค่าเดียวแน่นอน ไม่ได้สุ่ม แค่ค่าผิด)

ทำไมเรียกว่า “transform” — QFT ทำงาน in-place (p16)

นึกถึงวงจรเลขคณิตใน Lec 05 (บท 0019–0021): เรามักต้องมี register แยกไว้รับผล เพราะ QPU ต้อง reversible (ย้อนกลับได้) — ทำ a += b ได้ แต่ทำ “a = b” ทับของเดิมทิ้งไม่ได้ · QFT ไม่ต้องทำแบบนั้น เพราะตัววงจร reversible อยู่แล้วโดยธรรมชาติ (มีแต่ H, CPHASE, SWAP ซึ่งย้อนกลับได้ทุกตัว) → ผลลัพธ์ลงregister เดิมได้เลย = ทำงาน in-place → เลยได้ชื่อว่า transform

ทำไม QFT ถึงเขียนผลทับลง register เดียวกับ input ได้ โดยไม่ต้องมี output register แยก?
ถูกค่ะ — ทุก gate ในวงจรย้อนกลับได้ (reversible) ข้อมูลไม่หาย → จึงแปลง register “ในที่” ได้ · แถมแปลว่ามี inverse ด้วย (invQFT ใช้ทำของเจ๋งๆ ในบท 0029)
ยังไม่ใช่ค่ะ — QFT ไม่ได้ READ อะไรเลย (READ จะทำลายเฟส) และ input/output ใช้ 4 qubit เท่ากัน · เหตุผลจริงคือวงจร QFT reversible ในตัว ข้อมูลไม่หาย จึงเขียนทับที่เดิมได้ (p16)
ทดสอบความจำ (ปิดหน้าจอก่อนแล้วตอบ)
  1. ทำไมสถานะ A/B/C ถึงแยกด้วย READ ไม่ได้ และทำไม AA ช่วยไม่ได้?
    magnitude เท่ากันหมด → READ สุ่ม · ไม่มีเฟสไหนโดดเด่น (oddball) ให้ AA ขยาย
  2. QFT แล้ว READ ได้เลขอะไร?
    ความถี่ = จำนวนรอบที่เข็มเฟสหมุนครบตลอด register (ไม่ใช่คาบ)
  3. register 4 qubit เข็มเพิ่มทีละ 180° → คาบ? ความถี่? READ หลัง QFT?
    คาบ 2 · ความถี่ 8 · READ ได้ 8
  4. เขียน phase ชุดที่ให้สถานะ C
    hadamard() แล้ว phase(45,1) · phase(90,2) · phase(180,4)
  5. วาดวงจร QFT 4 สายจากความจำ
    H(0x8) → CP −90/−45/−22.5 · H(0x4) → CP −90/−45 · H(0x2) → CP −90 · H(0x1) · SWAP 0x1↔0x8 + 0x2↔0x4 (สายไขว้)
  6. ทำไม QFT ถึงเรียกว่า transform?
    reversible ในตัว → เขียนผลลง register เดิม (in-place)

สรุปบทนี้

  • เฟสที่หมุนเป็นจังหวะตลอด register = สัญญาณ · READ ตรงๆ ได้ค่าสุ่ม · AA ช่วยไม่ได้เพราะไม่มี oddball
  • QFT แปลงสัญญาณนั้นเป็นค่าเดียวที่ READ ได้แน่นอน = ความถี่ (A → 8 · B → 4 · C → 2)
  • คาบ × ความถี่ = 2n · มุมต่อวง = ความถี่ × 360° ÷ 2n · QFT ตอบความถี่ ไม่ใช่คาบ
  • วงจร QFT = ขั้นบันได H + CPHASE มุมลบหารครึ่ง เริ่มจากบิตสูง + SWAP กลับลำดับบิตท้ายวงจร (มีแบบ × และแบบสายไขว้)
  • QFT in-place เพราะ reversible → เรียกว่า transform · ใช้ได้ทั้ง qc.QFT() และ qint.QFT()
  • AA ดึงข้อมูล “ค่าเฉพาะ” · QFT ดึงข้อมูล “รูปแบบ”
