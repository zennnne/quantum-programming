DFT ญาติฝั่งคลาสสิก — ทำไมสัญญาณจริงได้ peak คู่

บท 0027 เราใส่ QFT แล้วได้ peak เดียวสวยๆ ทุกครั้ง · แต่สไลด์เตือนว่านั่น “เลือกตัวอย่างมาแล้ว” · บทนี้ไปดู DFT ฝั่งคลาสสิกซึ่งทำคณิตเดียวกันเป๊ะ แล้วจะเจอของแปลก: sine wave ความถี่ 8 กลับได้ peak สองอัน ที่ 8 และ 248 · ไขปริศนานี้ได้ ก็จะรู้ว่าต้องอ่านผล QFT ยังไงไม่ให้หลงค่ะ

ทำไมต้องเรียนบทนี้ — จับหลัก 4 อย่าง: ① QFT = DFT บน quantum register · FFT = วิธีคำนวณ DFT แบบเร็ว = คู่แข่งตัวจริงของ QFT ② DFT พาสัญญาณไป frequency space: magnitude = ความถี่นั้นแรงแค่ไหน · phase = เหลื่อม (offset) กันแค่ไหน ③ สัญญาณจริง ได้ peak คู่ที่ f กับ N − f · สัญญาณเชิงซ้อน ได้ peak เดียว ④ ใน QFT: เข้ารหัสในเฟส = เชิงซ้อน → peak เดียว · เข้ารหัสใน magnitude = จริง → peak คู่ (เรื่องสอบ)

ตัวย่อคืออะไร (p9–12)ทำงานกับ
DFT (Discrete Fourier Transform, การแปลงฟูเรียร์แบบไม่ต่อเนื่อง) การแปลงแบบคลาสสิก ดึงข้อมูลความถี่ออกจากสัญญาณ ลิสต์ตัวเลขธรรมดา (sample)
FFT (Fast Fourier Transform) อัลกอริทึมตัวหนึ่งที่คำนวณ DFT · ผลเหมือน DFT เป๊ะแต่เร็วกว่ามาก · เร็วที่สุดที่รู้จัก ลิสต์ตัวเลขธรรมดา → ตัวที่ QFT ต้องเอาชนะ
QFT การแปลงแบบเดียวกับ DFT สัญญาณที่เก็บอยู่ใน quantum register

ข้อจำกัดร่วมของ FFT กับ QFT: ความยาวสัญญาณต้องเป็นกำลังของ 2 (16, 256, …) — ฝั่ง QPU ก็ตรงตัวอยู่แล้ว เพราะ register n qubit มี 2ⁿ ค่า

บท 0029 จะเทียบ “ความเร็ว” ของ QFT กับอีกตัวหนึ่ง — ตามสไลด์ เราควรเทียบกับตัวไหน?
ถูกค่ะ DFT เป็นแค่ “นิยามว่าต้องได้ผลอะไร” ส่วน FFT คือวิธีคำนวณที่เร็วที่สุดที่ใช้จริง — จะชนะต้องชนะตัวนี้
ยังไม่ใช่ค่ะ DFT คือ “ผลลัพธ์ที่ต้องการ” ยังไม่ใช่วิธีคำนวณ · ตัวที่คำนวณได้เร็วที่สุดและใช้จริงคือ FFT (p12)

DFT กินอะไร: sample ที่เป็นจำนวนเชิงซ้อน

DFT ทำงานกับ sample แบบไม่ต่อเนื่อง (จุดที่เก็บค่ามาเป็นระยะ เช่นเสียงดนตรีหรือรูปภาพดิจิทัล) · ปกติเรามองสัญญาณเป็นจำนวนจริง แต่ DFT รับจำนวนเชิงซ้อนได้ด้วย — ซึ่งสำคัญมากกับเรา เพราะ state ของ register ก็คือลิสต์ของจำนวนเชิงซ้อน (p22)

refresher: จำนวนเชิงซ้อน = วงกลม 1 วง (p22) — ทุกครั้งที่เจอคำว่า complex number ให้นึกถึงวงใน circle notation: ขนาดวง = magnitude · ทิศเข็ม = phase · ถ้าวางเข็มบนระนาบ ระยะที่เข็มยื่นไปทางแนวนอน = ส่วนจริง แนวตั้ง = ส่วนจินตภาพ · จำนวนจริงล้วนคือเข็มที่ชี้ได้แค่ 2 ทาง (บวก / ลบ) — ส่วนจินตภาพ = 0

ตัวอย่างในสไลด์ (p23–25): sine wave ความถี่เดียว (ถ้าเป็นเสียงคือ pure tone, เสียงบริสุทธิ์) เก็บมา 256 sample · แต่ละ sample เก็บเป็น complex float 16 byte (ส่วนจริง 8 + ส่วนจินตภาพ 8) → buffer 256 × 16 = 4,096 byte · ถึงส่วนจินตภาพจะเป็น 0 หมด ก็ต้องเผื่อที่ไว้ เพราะ output ของ DFT เป็นจำนวนเชิงซ้อน 256 ค่า

ถ้าเก็บ sample 2,048 จุด แบบเดียวกับสไลด์ ต้องใช้ buffer กี่ byte?
ถูกค่ะ 2,048 × 16 = 32,768 · อย่าลืมว่า 16 byte มาจากส่วนจริง 8 + ส่วนจินตภาพ 8
ลองใหม่ค่ะ — 1 sample = 16 byte (จริง 8 + จินตภาพ 8) · ถ้าได้ 16,384 แปลว่าลืมเผื่อส่วนจินตภาพ

DFT คายอะไรออกมา: frequency space

output ช่องที่ j ของ DFT (j = 0 … 255) คือความถี่ j = “สั่นครบ j รอบตลอดช่วงที่เก็บ” · ในแต่ละช่อง (p25):

magnitude ของช่อง j
ความถี่ j มีอยู่ในสัญญาณมากแค่ไหน (ความสูงของ peak)
phase ของช่อง j
คลื่นความถี่ j เหลื่อม (offset) ไปแค่ไหน

เราเรียกโลกฝั่งขวานี้ว่า frequency space (ปริภูมิความถี่) (p27) · ลองดูของจริง: sine ที่สั่น 8 รอบใน 1 วินาที

⚠️ รูปในสไลด์ p24/p26/p27 นับได้แค่ 6 รอบ — หนูเปิดรูปจริง (p24) นับยอดคลื่นได้ 6 ยอดจริงๆ แต่ข้อความบอก “สั่นครบ 8 รอบ = 8 Hz” และ peak ติดป้าย 8 / 248 · รูปด้านบนหนูวาดให้ครบ 8 รอบตามข้อความ · ตอบตามตัวเลขในสไลด์ตอนสอบ (8 Hz, peak 8 กับ 248) แค่รู้ไว้ว่ารูปวาดไม่ตรงเฉยๆ

peak มีความกว้าง (p27): สไลด์ชี้ว่ารอบฐาน peak มีค่าเล็กๆ ไม่เป็นศูนย์ เพราะ output มีจำนวน bit จำกัด peak จึงแหลมเป็นเส้นเดียวไม่ได้เสมอไป — QFT ก็เป็นแบบนี้ได้ (ค่าเล็กๆ รั่วไปช่องข้างๆ) · รูปบนแหลมเป๊ะเพราะ 8 รอบลงช่องพอดี ลองดูกรณี 8.4 รอบซึ่งไม่ลงช่องพอดี:

ส่วนที่ 2 · peak สะท้อน: สัญญาณจริง vs สัญญาณเชิงซ้อน

248 มาจากไหน?

peak ที่ 248 เรียกว่า mirror-image peak (peak สะท้อน) (p28) · เกิดกับ DFT ของสัญญาณจริงทุกตัว (ทุก sample เป็นจำนวนจริง ซึ่งสัญญาณในชีวิตจริงเกือบทั้งหมดเป็นแบบนี้): peak ที่ f จะมีคู่ที่ N − f เสมอ (256 − 8 = 248) · ครึ่งหลังของผลลัพธ์จึงเป็นแค่ภาพสะท้อนของครึ่งแรก ใช้ได้จริงแค่ 256 / 2 = 128 ช่องแรก

sine จริง 256 sample สั่น 20 รอบ → DFT ได้ peak ที่ตำแหน่งไหนบ้าง?
ถูกค่ะ N − f = 256 − 20 = 236 · ช่องมีแค่ 0–255 ดังนั้น “256” ไม่มีอยู่จริง
ยังไม่ใช่ค่ะ คู่สะท้อนคือ N − f = 256 − 20 · (108 = 128 − 20 คือสะท้อนรอบผิดจุด)

ทำไมถึงเป็นคู่? — ล้อหมุนสองล้อ

สไลด์บอกแค่ “มันเป็นแบบนั้น” หนูขอเติม “ทำไม” ให้ค่ะ

สัญญาณเชิงซ้อน = เข็มที่หมุนวน เข็มยาวคงที่ หมุนทวนเข็มนาฬิกา f รอบ · มีทิศการหมุนชัดเจน → DFT บอกได้เลยว่า “f รอบ ทวนเข็ม” = peak เดียวที่ f
≠
สัญญาณจริง = เงาบนผนัง เห็นแค่ส่วนจริง (แนวนอน) แกว่งไปกลับ · ดูจากเงาไม่รู้ว่าเข็มหมุนทวนหรือตามเข็ม · จริงๆ แล้วมันคือสองเข็มหมุนสวนกันครึ่งๆ
คณิตเบื้องหลัง (ดูผ่านๆ ได้) — เข็มทวนเข็ม + เข็มตามเข็มที่ยาวเท่ากัน: ส่วนแนวตั้งหักล้างกันหมด เหลือแต่แนวนอนแกว่งไปมา = cos θ = ½(ทวนเข็ม θ) + ½(ตามเข็ม θ) · DFT จึงเจอ สองความถี่: +f กับ −f · แล้ว −f ไปโผล่ช่อง N − f เพราะถอยหลัง f ช่อง = เดินหน้า N − f ช่อง (เหมือนนาฬิกา: ถอย 1 ชั่วโมง = เดิน 11 ชั่วโมง)

ยืนยันด้วยตา: สัญญาณเชิงซ้อน (เส้นทึบ = ส่วนจริง · เส้นประ = ส่วนจินตภาพ) ไม่มีภาพสะท้อน (p29) ทั้ง 256 ช่องมีความหมายหมด

กลับมาที่ QFT: เข้ารหัสไว้ตรงไหน?

ในบท 0027 สัญญาณอยู่ใน relative phase (magnitude เท่ากันหมด เข็มหมุนวน) = สัญญาณเชิงซ้อน → ไม่มีความซ้ำซ้อนแบบสมมาตร → QFT ได้ peak เดียว (p29) · และนี่คือคำตอบของคำถามท้ายบท 0027: ถ้าเข็มหมุนตามเข็มนาฬิกา ความถี่ f จะอ่านได้ 2ⁿ − f

เข้ารหัสในเฟส — เข็มหมุนทวนเข็ม 1 รอบ (ทีละ 22.5°) → หลัง QFT ได้ |1⟩ แน่นอน

เข้ารหัสในเฟส — หมุนตามเข็ม 1 รอบ (ทีละ −22.5°) → หลัง QFT ได้ |15⟩ แน่นอน

แต่ถ้าเข้ารหัสสัญญาณไว้ใน magnitude แทน (p30, Figure 7-12) — ขนาดวงแกว่งตาม cos 1 รอบ และเข็มชี้ได้แค่ขึ้น (+) หรือลง (−):

Figure 7-12 — สัญญาณใน magnitude (ขนาดวงเทียบกับวง |0⟩ · |4⟩ และ |12⟩ ว่าง)

Figure 7-13 — หลัง QFT: |1⟩ กับ |15⟩ อย่างละครึ่ง เข็มชี้ขึ้นทั้งคู่ = peak สะท้อนแบบ DFT เป๊ะ (p31)

⚠️ กับดัก (p30): “เข็มพลิกไปมาแล้ว = เชิงซ้อน” ผิด! — เฟส 180° คือเครื่องหมายลบเท่านั้น ถ้าเข็มมีแค่ 0° กับ 180° ทุกค่าเป็นจำนวนจริง (บวกหรือลบ) → นับเป็นสัญญาณจริง → ได้ peak คู่
บทสรุปที่ต้องจำ (p31) — ก่อนตีความผล QFT ต้องถามก่อนว่า input เข้ารหัสไว้ในเฟสหรือ magnitude: เข็มหมุนวน (เชิงซ้อน) → peak เดียว · ขนาดวงแกว่ง / เข็มมีแค่ขึ้นลง (จริง) → peak คู่ f กับ 2ⁿ − f

แถม (หนูจำลองเช็คเอง ไม่ได้อยู่ในสไลด์): ถ้าเปลี่ยน cos เป็น sin ใน Figure 7-12 จะได้ |1⟩ กับ |15⟩ ขนาดเท่าเดิม แต่เข็มชี้ −90° กับ +90° แทน 0° — นี่แหละ “phase บอก offset” จากส่วนที่ 1 (sin คือ cos ที่เหลื่อมไปหนึ่งในสี่รอบ)

register 4 qubit เข้ารหัส cos ที่สั่น 3 รอบไว้ใน magnitude แล้ว QFT → READ จะได้อะไร?
ถูกค่ะ เข้ารหัสใน magnitude = สัญญาณจริง → peak คู่ 3 กับ 16 − 3 = 13 ขนาดเท่ากัน
ยังไม่ใช่ค่ะ magnitude = สัญญาณจริง → peak คู่ · และคู่สะท้อนคือ 2ⁿ − f โดย 2ⁿ = 16 (ไม่ใช่ 32)
register 4 qubit magnitude เท่ากันหมด เข็มหมุนตามเข็มนาฬิกาทีละ 90° (|1⟩ = −90°, |2⟩ = −180°, …) → QFT แล้ว READ ได้?
ถูกค่ะ 90° × 16 วง = 4 รอบ ตามเข็ม → เชิงซ้อน peak เดียวที่ 16 − 4 = 12
ลองนับใหม่ค่ะ: 16 วง × 90° = 4 รอบ · เข็มหมุนวน = เชิงซ้อน → peak เดียว · หมุนตามเข็ม → อยู่ที่ 2ⁿ − f
ทดสอบความจำ — ปิดจอแล้วตอบก่อนเปิดดู
  1. QFT, DFT, FFT ต่างกันยังไง? ตัวไหนคือคู่แข่งของ QFT?
    DFT = การแปลงคลาสสิก · FFT = อัลกอริทึมเร็วของ DFT (คู่แข่ง) · QFT = DFT บน quantum register
  2. output ของ DFT แต่ละช่องบอกอะไร 2 อย่าง?
    magnitude = ความถี่นั้นแรงแค่ไหน · phase = offset
  3. sine จริง 256 sample สั่น 8 รอบ → peak ที่ไหน? ใช้ได้กี่ช่อง?
    8 กับ 248 · ใช้ได้ครึ่งแรก 128 ช่อง
  4. ทำไมสัญญาณจริงถึงได้ peak คู่?
    จริง = สองเข็มหมุนสวนกัน (+f และ −f) · −f โผล่ที่ N − f
  5. QFT: เข้ารหัสในเฟส vs magnitude ได้ผลต่างกันยังไง?
    เฟส (เชิงซ้อน) → peak เดียว · magnitude (จริง) → peak คู่ f กับ 2ⁿ − f
  6. เข็มมีแค่ 0° กับ 180° นับเป็นสัญญาณแบบไหน?
    จริง — 180° คือเครื่องหมายลบ

สรุปบทนี้

  • QFT ทำการแปลงเดียวกับ DFT แต่ทำบน quantum register · FFT คือวิธีคำนวณ DFT ที่เร็วที่สุด = ตัวที่ QFT ต้องชนะ · ยาวต้องเป็นกำลัง 2
  • DFT รับ sample เชิงซ้อน (วงกลม 1 วง) · 256 sample × 16 byte = 4,096 byte · output เชิงซ้อน 256 ค่า
  • frequency space: ช่อง j = ความถี่ j · magnitude = ความแรง · phase = offset · peak มีความกว้างได้ (QFT ก็เช่นกัน)
  • สัญญาณจริง → peak คู่ f กับ N − f ใช้ได้แค่ครึ่งแรก · สัญญาณเชิงซ้อน → peak เดียว
  • QFT: เข้ารหัสในเฟส → peak เดียว (หมุนตามเข็มได้ 2ⁿ − f) · ใน magnitude → peak คู่ (Figure 7-13: |1⟩ & |15⟩)
