Quantum Programming · Lec 11 · บทที่ 0041 (บทแรกของ Lec 11)

QSS: ไม่ได้เร็วขึ้น แต่ noise คนละแบบ + ผ้าใบเปล่า

Lec 11 ไม่มี primitive ใหม่เลยสักตัว · ทั้งคาบคือการเอาของเก่า 3 อย่าง (quantum arithmetic · amplitude amplification · QFT) มาประกอบเป็นงานจริงด้าน computer graphics ชื่อ Quantum Supersampling (QSS) · บทนี้ตั้งโจทย์ก่อนว่า supersampling คืออะไรและ QSS ให้อะไร แล้วเริ่มก้าวแรกของคำตอบ คือเอาภาพเข้าไปอยู่ใน QPU ด้วยการวาดลง phase

ทำไมต้องเรียนบทนี้: จับหลัก 4 อย่าง ① supersampling = สุ่มหลายจุดต่อ pixel แล้วเก็บแค่ค่าเฉลี่ย ② QSS ไม่ได้เร็วขึ้น สิ่งที่ได้คือ ลักษณะของ noise ที่ต่างไป ③ phase encoding: pixel ขาว/ดำ = phase 0° / 180° · HAD ทุก qubit ของ qx, qy = ผ้าใบเปล่า ④ PHASE(180) ตัวเดียวระบายได้ 128 pixel แต่ READ ออกมาดูไม่ได้ (ปมที่บท 0044 จะมาแก้)

ส่วนที่ 1 · โจทย์: supersampling คืออะไร และ QSS ให้อะไร (p1–9)

1.1 QIP: เอา QPU มาช่วยงานภาพ

Quantum Image Processing (QIP) (การประมวลผลภาพเชิงควอนตัม) คือการใช้ QPU เพิ่มความสามารถด้าน image processing · สไลด์บอกตรงๆ ว่าสาขานี้ยังอยู่ในช่วงเริ่มต้นมาก (p2) รูปประกอบหน้า p2 เป็นแค่ภาพแนวคิด (ภาพ → แปลงเป็น quantum state → QPU ประมวลผล → แปลงกลับเป็นภาพ) ไม่ใช่เนื้อหาหลัก · คาบนี้เลือกดู QIP ตัวอย่างเดียวคือ QSS (p3)

1.2 ปัญหาตั้งต้น: 1 pixel ต้องแทนของหลายอย่าง

เริ่มจากวิธีสร้างภาพแบบ ray tracing (การตามรอยรังสี) · สำหรับ pixel แต่ละช่องของภาพ โปรแกรมจะยิง "ray" (เส้นตรงทางคณิตศาสตร์) จากกล้อง ผ่าน pixel นั้น ไปยัง scene · ray ไปชนวัตถุอะไร สีของวัตถุนั้นก็กลายเป็นสีของ pixel (แบบง่ายสุด ไม่คิดเงาสะท้อนหรือความโปร่งใส) (p6–7)

ยิง ray เดียวต่อ pixel ก็ได้ภาพที่ "ถูก" แต่มีปัญหา 2 ข้อ (p8)

  • ของที่อยู่ไกล (เช่นต้นไม้ใน Figure 11-2) ขอบและรายละเอียดเล็กๆ หายไป
  • พอกล้องหรือวัตถุขยับ จะเกิด noise pattern กวนตา บนของที่ลายถี่ๆ อย่างใบไม้หรือรั้วไม้ระแนง

ทำไมถึงเป็นแบบนั้น ลองดู pixel ช่องเดียวที่ขยายออกมาเป็น 4×4 ช่องย่อย ช่องย่อยพวกนี้เรียกว่า subpixel (จุดย่อยใน pixel) · สมมติขอบของวัตถุสีดำพาดผ่าน pixel นี้พอดี

ภาพนี้คาโฮะวาดเองเพื่ออธิบาย · ในสไลด์ใช้ Figure 11-2 (pixel 1 ช่องขยายเป็น subpixel แล้วมี ray พุ่งไปชนต้นไม้)

ray เดียวจะตกที่ช่องขาวหรือช่องดำช่องใดช่องหนึ่ง pixel นั้นเลยออกมาขาวล้วนหรือดำล้วน ทั้งที่ของจริงควรเป็นเทา 62.5% · ขยับกล้องนิดเดียว ray ไปตกอีกช่อง สีก็กระโดด นั่นคือที่มาของ noise pattern

วิธีแก้ = supersampling (p9): ยิงหลาย ray ต่อ pixel (ปกติหลักร้อยถึงหลักพัน) โดยเปลี่ยนทิศทีละนิด แล้วเก็บเฉพาะสีเฉลี่ย ที่เหลือทิ้งหมด · เรียกอีกชื่อว่า Monte Carlo sampling (การสุ่มตัวอย่างแบบมอนติคาร์โล) · ยิ่ง sample มาก noise ในภาพสุดท้ายยิ่งลด
ชิมแกงทั้งหม้อตักหลายช้อนจากหลายจุดในหม้อ แล้วสรุปเป็นคำเดียวว่า "เค็มประมาณนี้" ไม่มีใครจดรสของแต่ละช้อนไว้

supersamplingสุ่มหลายจุดใน 1 pixel แล้วสรุปเป็นสีเดียว ผลของแต่ละ ray ถูกคำนวณแต่ไม่ถูกเก็บ

นิยามในสไลด์ (p3) พูดเรื่องเดียวกันจากอีกมุม: supersampling = เทคนิคที่ภาพซึ่งคอมพิวเตอร์สร้างไว้ที่ ความละเอียดสูง ถูกลดลงเป็นความละเอียดต่ำกว่า ด้วยการเลือก sample pixel · ภาพความละเอียดสูงก็คือชั้น subpixel ส่วนภาพความละเอียดต่ำคือภาพสุดท้ายที่เราเห็น

① pixel หนึ่งถูกยิง 8 ray · ชนของสีขาว 6 ray ชนของสีดำ 2 ray · supersampling เก็บอะไรไว้เป็นค่าของ pixel นี้
ถูกค่ะ 6/8 = 75% · คำนวณ 8 ครั้งแต่เก็บเลขเดียว จำประโยคนี้ไว้ เพราะมันคือเหตุผลที่คนคิดจะเอา QPU มาทำ
supersampling เก็บเฉพาะค่าเฉลี่ย (6 จาก 8 = ขาว 75%) ผลรายตัวของ ray ถูกทิ้งหมด (p9)

1.3 ทำไมงานนี้ถึงน่าจะเหมาะกับ QPU

สไลด์ p9 สังเกตว่า supersampling เป็นงานที่ คำนวณขนานกันเยอะมาก (ผลของ ray จำนวนมาก) แต่สุดท้ายต้องการแค่ผลรวม ไม่ต้องการผลแต่ละตัว · ฟังคุ้นไหมคะ นี่คือรูปร่างเดียวกับงานที่ QPU ถนัดมาตลอดทั้งเทอม: คำนวณทุกค่าพร้อมกันใน superposition แล้วดึงคำตอบสรุปออกมาแค่ค่าเดียว (เหมือน QFT ดึงความถี่ ออกมาจากทั้ง register)

ข้อจำกัด: ray-tracing engine เต็มรูปแบบบน QPU ต้องใช้ qubit มากกว่าที่มีในปัจจุบันมาก · คาบนี้เลยไม่ทำ ray tracing แต่ให้ QPU วาดภาพความละเอียดสูงด้วยวิธีที่ง่ายกว่า เพื่อศึกษาเฉพาะขั้นสุดท้าย คือขั้นลดความละเอียด (p9)

1.4 ผลลัพธ์ล่วงหน้า: QSS ไม่ได้เร็วขึ้น

QSS ถูกคิดขึ้นเพื่อเร่งความเร็ว supersampling และตามเกณฑ์นั้นมันล้มเหลว (p4) · แต่พอวิเคราะห์ตัวเลขกลับเจอของน่าสนใจ: error เฉลี่ยต่อ pixel พอๆ กับวิธีเดิม แต่ character of noise (ลักษณะของ noise) ต่างกันมาก

ทำไม noise แบบ QSS ถึงดีกว่า (p5): สมมติได้ภาพมา 1 ภาพ มีเวลา 15 นาทีลบ noise ด้วยมือ · ภาพจาก QSS ทำได้ค่อนข้างง่าย (จิ้มแก้ทีละจุด มีไม่กี่จุด) · ภาพแบบเดิมแทบเป็นไปไม่ได้ เพราะต้องแก้ทุก pixel

QSS ประกอบจาก primitive 3 ตัวที่เรียนมาแล้วทั้งหมด (p5): quantum arithmetic (Lec 05) · amplitude amplification (Lec 06) · QFT (Lec 07)

จุดที่สไลด์เขียนไม่ตรง (ตอบตามสไลด์ตอนสอบ แต่รู้ของจริงไว้): p4 ข้อความบอกว่า error "about the same" แต่ตัวเลขในรูปคือ 2% กับ 1% (สไลด์ถือว่าระดับเดียวกัน จุดที่เน้นคือลักษณะ noise) · p5 อ้าง amplitude amplification ว่ามาจาก "Chapter 6" ปนกับ "lecture 5 / lecture 7" ในประโยคเดียวกัน (เลขบทของหนังสือหลุดมา ในวิชานี้ AA = Lec 06) · เลขรูปกระโดดจาก Figure 11-2 ไป 11-4 ไม่มี 11-3
② ข้อไหนสรุปผลของ QSS เทียบกับ Monte Carlo ได้ตรงกับสไลด์ที่สุด
ใช่ค่ะ ข้อได้เปรียบของ QSS อยู่ที่ noise ไปกระจุกอยู่ไม่กี่ pixel ส่วน pixel ที่ถูกเป๊ะมีมากขึ้น (34% → 41%) ไม่ใช่เรื่องความเร็ว
QSS ล้มเหลวเรื่อง speedup (p4) · สิ่งที่ได้แทนคือลักษณะ noise ที่ต่างไป: บาง pixel เพี้ยนหนัก ที่เหลือเป๊ะ

ส่วนที่ 2 · ก้าวแรก: เอาภาพเข้า QPU ด้วยการวาดลง phase (p10–14)

2.1 phase encoding: ให้ phase เป็นสีของ pixel

จะ supersample ด้วย QPU ได้ ต้องมีวิธีแทนภาพใน register ก่อน · มีหลายวิธี (สไลด์สรุปวิธีอื่นไว้ท้ายคาบ) วิธีที่คาบนี้ใช้คือ phase encoding (การเข้ารหัสด้วย phase): ค่าของ pixel ถูกแทนด้วย phase ของ superposition (p10)

phase 0° ขีดชี้ขึ้น · สไลด์ระบายวงเป็นสีชมพู · หมายถึง pixel ที่ไม่ถูกระบาย
phase 180° ขีดชี้ลง · สไลด์ระบายวงเป็นสีเขียว · หมายถึง pixel ที่ถูกระบาย (ถูก flip)

ทำไมต้องเป็น phase · สไลด์ให้เหตุผลข้อเดียว: เพราะมันทำให้ข้อมูลภาพเข้ากันได้กับ amplitude amplification · ย้อนไป บท 0023: ขั้น flip ของ AA คือการกลับ phase ของค่าที่เราสนใจเป็น 180° ดังนั้น "pixel ที่ถูกระบาย" กับ "ค่าที่ถูก flip" คือของสิ่งเดียวกัน โปรแกรมวาดรูปของเราจะเสียบเข้าไปเป็น flip ของ AA ได้ตรงๆ (ใช้จริงในบท 0044)

2.2 quantum pixel shader กับผ้าใบเปล่า

pixel shader คือโปรแกรม (ปกติรันบน GPU) ที่รับตำแหน่ง x, y แล้วให้สีออกมา · ในคาบนี้สีมีแค่ดำหรือขาว · เราจะสร้าง quantum pixel shader โดยเริ่มจาก register 4 qubit สองตัว (p11)

  • qx = ตำแหน่งแนวนอน 0–15 · qy = ตำแหน่งแนวตั้ง 0–15
  • HAD ทุก qubit → superposition ของทุกค่า (x, y) = 16 × 16 = 256 ตำแหน่งพร้อมกัน

state นี้คือ blank canvas (ผ้าใบเปล่า): มีครบทุก pixel ขนาดเท่ากันหมด phase 0° หมด ยังไม่มีใครถูกระบาย

Figure 11-4 (ซีกวงจร) · A blank quantum canvas · HAD ของ qx กับ qy อยู่คนละคอลัมน์

วิธีอ่านผ้าใบ: เลื่อนขวา = qx เพิ่ม · เลื่อนลง = qy เพิ่ม (qy = 0 อยู่บนสุด) · สไลด์พิมพ์เลขใต้วงเป็น qx + 16·qy เช่นวงที่ qx = 10, qy = 3 คือ |58⟩ เพราะ qy อยู่ 4 บิตบนของ register รวม 8 qubit

2.3 วาดครั้งแรก: ระบายครึ่งขวา

โจทย์: "if qx ≥ 8 then invert phase" · ดูเหมือนต้องเปรียบเทียบตัวเลข แต่จริงๆ ใช้ qubit ตัวเดียวพอ

ทวน binary: qx มี 4 บิต น้ำหนัก 8, 4, 2, 1 · เลข 0–7 เขียนได้เป็น 0000 ถึง 0111 (บิต 0x8 เป็น 0 ทุกตัว) · เลข 8–15 เขียนได้เป็น 1000 ถึง 1111 (บิต 0x8 เป็น 1 ทุกตัว) → qx ≥ 8 ก็คือ "บิต 0x8 ของ qx เป็น 1"

และ PHASE(180) บน qubit ตัวหนึ่ง กลับ phase ของทุกค่าที่ qubit นั้นเป็น 1 (เรื่องเดิมจาก บท 0008) → PHASE(180) ที่ qubit 0x8 ของ qx ตัวเดียวจบ (p12)

Figure 11-5 (ซีกวงจร) · Phase-flipping half of the image · กล่องขวาไม่มีชื่อ มีแต่ป้าย 180° · φ อยู่บนสาย qx 0x8 สายเดียว
// Set up and clear the canvas
qc.reset(8);
var qx = qint.new(4, 'qx');
var qy = qint.new(4, 'qy');
qc.write(0);
qx.hadamard();
qy.hadamard();

// Invert if qx >= 8
qc.phase(180, qx.bits(0x8));

คราวนี้ลองทายก่อน แล้วค่อยไปกดดูของจริงในผ้าใบข้างล่าง

③ อยากระบายครึ่งล่างของผ้าใบแทน ต้องเปลี่ยนบรรทัดสุดท้ายเป็นอะไร
ถูกค่ะ ครึ่งล่าง = qy ≥ 8 = บิต 0x8 ของ qy เป็น 1 (qy = 0 อยู่บนสุด ค่ามากอยู่ล่าง)
ครึ่งล่างคือแถว qy = 8–15 ซึ่งเป็นกลุ่มที่บิต 0x8 ของ qy เป็น 1 → qy.bits(0x8)
④ ถ้าใช้ qc.phase(180, qx.bits(0x1)) ผ้าใบจะออกมาเป็นลายอะไร (คิดก่อนว่า qx ค่าไหนบ้างที่บิต 0x1 เป็น 1)
ใช่ค่ะ บิต 0x1 เป็น 1 เมื่อ qx เป็นเลขคี่ (1, 3, 5, …, 15) → 8 คอลัมน์ × 16 แถว = 128 pixel เหมือนเดิม แค่เรียงเป็นลายทาง
บิต 0x1 คือบิตหลักหน่วย เป็น 1 เมื่อ qx เป็นเลขคี่ → เขียวที่คอลัมน์ 1, 3, 5, …, 15 เป็นลายทางตั้ง
⑤ (เสริม · สไลด์ช่วงนี้ไม่ได้ถาม) ถ้าสั่ง PHASE(180) สองตัว ที่ qx 0x8 และ qy 0x8 ผ้าใบจะเป็นยังไง
เก่งมากค่ะ มุมขวาล่างโดนกลับ 2 รอบ (180° + 180° = 360° = 0°) เลยกลับมาเป็นชมพู · ผลรวมคือ XOR ไม่ใช่ OR หรือ AND
มุมขวาล่าง (qx ≥ 8 และ qy ≥ 8) โดน PHASE(180) สองรอบ = หมุน 360° กลับมาที่เดิม → เหลือเขียวแค่มุมขวาบนกับซ้ายล่าง (เป็น XOR)

ลองเองเลยค่ะ: กดปุ่มเพื่อใส่ / ถอด PHASE(180) บน qubit แต่ละตัว ตรวจคำตอบข้อ ③ ④ ⑤ แล้วลองหาลายหมากรุกดู

ข้อสังเกตจากการเล่น: PHASE(180) บน qubit เดี่ยวๆ กี่ตัวก็ตาม ระบายได้ครั้งละครึ่งผ้าใบพอดี (128 pixel) หรือไม่ก็ไม่ระบายเลย · จะระบายเฉพาะมุมเดียว (เงื่อนไขแบบ AND) ต้องใช้ gate ที่มี control อย่าง CZ ซึ่งคือเรื่องของบทถัดไป

2.4 ข่าวดีและข้อแม้: วาดได้ แต่อ่านไม่ได้

ข่าวดี ใช้ QPU instruction ตัวเดียวระบายได้ 128 pixel · บน GPU ต้องรัน pixel shader 128 ครั้ง (p14)
ข้อแม้ (the catch) ถ้า READ ผลลัพธ์ จะได้แค่ค่าสุ่มของ qx และ qy ภาพที่วาดไว้อ่านออกมาไม่ได้ (p14)
ทวน: ทำไม READ ไม่เห็น phase (บท 0003) · โอกาสที่ READ ได้ค่าไหน = ขนาดของวงของค่านั้น (magnitude ยกกำลังสอง) phase ไม่อยู่ในสูตรเลย · ผ้าใบเรามี 256 วงขนาดเท่ากัน amplitude = +1/16 (ชมพู) หรือ −1/16 (เขียว) · ยกกำลังสองแล้วได้ 1/256 เท่ากันทุกวง ไม่ว่าจะระบายไว้ลายไหน
⑥ หลังระบายครึ่งขวาแล้ว READ ทันที โอกาสที่จะได้ qx ≥ 8 (ตกในครึ่งที่ระบาย) เป็นเท่าไร
ถูกค่ะ 128 วง × 1/256 = 50% เท่ากับก่อนระบายเป๊ะ · READ ตรงๆ จึงแยกผ้าใบที่ระบายแล้วกับผ้าใบเปล่าไม่ออกเลย
ทุกวงยังมีโอกาส 1/256 เท่าเดิม (phase ไม่เปลี่ยนขนาด) → ครึ่งขวา 128 วง = 128/256 = 50% เท่ากับตอนผ้าใบเปล่า
ปมที่ค้างไว้: ภาพอยู่ใน phase ครบทุก pixel แต่เรามองไม่เห็น · โชคดีที่ supersampling ไม่ได้ต้องการภาพทุก pixel อยู่แล้ว ต้องการแค่ผลรวม (ระบายไปกี่ subpixel) · และเรามีเครื่องมือเปลี่ยน "ความต่างของ phase" ให้เป็น "ความต่างของขนาด" อยู่แล้ว คือ mirror ของ AA · บท 0044 จะเอา AA + QFT มานับจำนวนที่ถูก flip โดยไม่ต้องอ่านทีละ pixel

ทดสอบความจำ (ปิดหน้าจอส่วนบนก่อนตอบ)

supersampling แก้ปัญหาอะไร และเก็บอะไรไว้ แก้ปัญหายิง 1 ray ต่อ pixel แล้วขอบ/รายละเอียดเล็กหาย + เกิด noise pattern ตอนขยับ · ยิงหลาย ray ต่อ pixel แล้วเก็บแค่ค่าเฉลี่ย (= Monte Carlo sampling)
QSS ชนะ Monte Carlo ตรงไหน และไม่ชนะตรงไหน ไม่ชนะเรื่องความเร็ว · ชนะที่ลักษณะ noise: บาง pixel เพี้ยนหนักเป็นจุดดำ/ขาว ที่เหลือเป๊ะ (Figure 11-1: 2% / 34% เทียบ 1% / 41%) → ลบด้วยมือง่ายกว่า
วาดวงจรผ้าใบเปล่า และวงจรระบายครึ่งขวา 8 สาย (qx 0x1–0x8 อยู่บน · qy 0x1–0x8 อยู่ล่าง) write 0 ทุกสาย → H ของ qx 4 ตัว → H ของ qy 4 ตัว (คอลัมน์ถัดไป) · ระบายครึ่งขวา = เพิ่มกล่องป้าย 180° ที่มี φ บนสาย qx 0x8 สายเดียว
ทำไม PHASE(180) ตัวเดียวถึงระบายได้ 128 pixel แต่ READ แล้วไม่เห็นภาพ PHASE(180) กลับ phase ของทุกค่าที่ qubit นั้นเป็น 1 ซึ่งมีครึ่งหนึ่งของ 256 ค่า · READ ขึ้นกับขนาดวงอย่างเดียว ทุกวงยังเป็น 1/256 จึงได้แค่ qx, qy สุ่ม

สรุป

  • QIP = ใช้ QPU กับงานภาพ ยังอยู่ช่วงเริ่มต้น · คาบนี้ดูตัวอย่างเดียวคือ QSS (p2–3)
  • supersampling / Monte Carlo sampling = หลาย sample ต่อ pixel เก็บแค่ค่าเฉลี่ย · งานขนานที่ต้องการแค่ผลรวม จึงน่าจะเหมาะกับ QPU (p6–9)
  • QSS ไม่ได้เร็วขึ้น แต่เปลี่ยนลักษณะ noise เป็นจุดเพี้ยนหนักไม่กี่จุด · ใช้ arithmetic + AA + QFT (p4–5)
  • phase encoding: ค่า pixel อยู่ใน phase (0° / 180°) เพื่อให้เข้ากับ AA · HAD ทั้ง qx, qy = blank canvas 16×16 (p10–11)
  • qc.phase(180, qx.bits(0x8)) = ระบายครึ่งขวา 128 pixel ในคำสั่งเดียว แต่ READ ได้แค่ค่าสุ่ม (p12–14)
