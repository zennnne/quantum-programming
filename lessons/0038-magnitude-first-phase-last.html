ต่อ logic ยาวๆ: magnitude ก่อน phase ทีหลัง

บท 0037 เราได้ phase logic มา 6 ตัว (NOT, OR, NOR, AND, NAND, XOR) · แต่โจทย์จริงที่จะเอาไปค้นหาไม่ได้มีแค่ gate ตัวเดียว มักเป็นประโยคยาวๆ เช่น (a OR NOT b) AND c · บทนี้ตอบคำถามว่า "จะต่อ phase logic หลายตัวเข้าด้วยกันยังไง" ซึ่งคำตอบคือ ต่อตรงๆ ไม่ได้ แต่มีทริกที่ใช้แก้ได้ และทริกนี้จะถูกใช้ซ้ำไปจนจบคาบ

ทำไมต้องเรียนบทนี้: จับหลัก 4 อย่าง ① phase logic ต่อกันตรงๆ ไม่ได้ เพราะ output อยู่ใน phase แต่ input ต้องเป็นค่าในรีจิสเตอร์ ② ทริก: ทำทุกขั้นด้วย magnitude logic ยกเว้นขั้นสุดท้าย ซึ่งใช้ phase logic ③ วงจรรูปแบบ compute → pAND → uncompute (Figure 10-4) ④ ฟังก์ชัน bit_or / inv_bit_or / phase_and · ข้อ ③ กับ ④ ถูกใช้ซ้ำทุกวงจรที่เหลือของ Lec 10 (ปริศนาลูกแมว/เสือ และ 3-SAT) ถ้าเข้าใจบทนี้ วงจร 7 สายท้ายคาบจะเป็นแค่บล็อกเดิมที่เรียงต่อกัน

ทางแก้ของหนังสือคือ (p15):

1.3 ตัวอย่างประจำคาบ: (a OR NOT b) AND c (Figure 10-3)

Figure 10-3 เป็นแผนภาพ logic gate แบบคลาสสิก (ยังไม่ใช่วงจรควอนตัม): สาย b ผ่าน NOT → เข้า OR คู่กับ a → ผลของ OR เข้า AND คู่กับ c (p16)

b → NOT → OR(a, ·) → AND(·, c) → (a OR NOT b) AND c

เป้าหมายแบบ phase logic: รีจิสเตอร์ a, b, c อยู่ใน uniform superposition ทั้ง 8 ค่า แล้วพลิก phase ของทุกค่าที่ทำให้ประโยคเป็นจริง (p16)

ลองใช้ทริกเอง: ในประโยค (a OR NOT b) AND c ขั้นไหนต้องทำด้วย phase logic?
ถูกค่ะ AND เป็น operation นอกสุด (ทำเป็นลำดับสุดท้าย) จึงเป็นตัวเดียวที่ใช้ phase logic · NOT กับ OR ทำด้วย magnitude logic แล้วเก็บผลไว้ใน scratch
ยังไม่ใช่ค่ะ ดูว่า gate ไหนอยู่ท้ายสุดของแผนภาพ ตัวนั้นเท่านั้นที่ใช้ phase logic ได้ ตัวที่อยู่ก่อนหน้าต้องส่งผลต่อเป็นค่า 0/1
ก่อนดูวงจร ลองคิดเอง: จาก 8 ค่าของ (a, b, c) มีกี่ค่าที่ทำให้ (a OR NOT b) AND c เป็นจริง? (ใบ้: c ต้องเป็น 1 ก่อนเลย)
ถูกค่ะ c = 1 เหลือ 4 แถว แล้วตัดแถวที่ a = 0, b = 1 ออก (เพราะ a OR NOT b = 0) จึงเหลือ (a,b,c) = (0,0,1), (1,0,1), (1,1,1) · เดี๋ยวส่วนที่ 2 จะแปลงเป็นเลข |n⟩
ลองใหม่ค่ะ ล็อก c = 1 ไว้ก่อน (เหลือ 4 แถว) แล้วดูว่าแถวไหนทำให้ a OR NOT b = 0 · มีแค่แถวเดียวคือ a = 0, b = 1

2.2 ข้างในกล่อง (a OR NOT b): OR สร้างจาก Toffoli ด้วย De Morgan

ควอนตัมไม่มี gate OR สำเร็จรูป แต่มี Toffoli ซึ่งก็คือ AND ที่เขียนผลลง target (บท 0022) · เราจึงสร้าง OR จาก AND ด้วยกฎของ De Morgan:

q1 OR q2 = NOT( NOT q1 AND NOT q2 )

แปลงเป็นวงจรได้ทีละขั้น (นี่คือฟังก์ชัน bit_or(q1, q2, out) ที่ p20):

① X ที่ q1, q2 → ตอนนี้สายเก็บ NOT q1 และ NOT q2
② Toffoli → out = NOT q1 AND NOT q2
③ X ที่ out → out = NOT(NOT q1 AND NOT q2) = q1 OR q2 ✓ · และ X ที่ q1, q2 คืนค่า input เดิม

ข้อสังเกต: ขั้น ③ มี X 3 ตัวในคอลัมน์เดียว แต่ทำ 2 หน้าที่: X ที่ out ทำ NOT ตัวนอกของ De Morgan ส่วน X ที่ q1, q2 แค่คืนค่าให้ input

ไล่ bit_or ด้วยมือ: ถ้า q1 = 0, q2 = 0, out = 0 จบวงจรแล้ว out เป็นเท่าไหร่ และทำไม?
ถูกค่ะ หลัง X ขั้น ① สาย q1, q2 เป็น 1 ทั้งคู่ Toffoli จึงทำงาน เขียน out = 1 แล้ว X ขั้น ③ พลิก out กลับเป็น 0 · ตรงกับ 0 OR 0 = 0 ✓ · กรณีอื่นอีก 3 แบบ Toffoli ไม่ทำงาน out จึงค้างที่ 0 แล้ว X พลิกเป็น 1
อย่าลืม X ขั้น ① ค่ะ มันพลิก 0,0 เป็น 1,1 ก่อนถึง Toffoli · Toffoli จึงทำงาน แล้ว X ที่ out ตอนท้ายค่อยพลิกกลับ

2.3 ⊕ สองตัวติดกันบนสาย 0x2 คืออะไร

ใน Figure 10-4 สาย b (0x2) มี ⊕ สองตัวติดกันตอนต้นกล่อง: ตัวแรกคือ qc.not(2) (ทำ NOT b) และตัวที่สองคือ X ตัวแรกข้างใน bit_or · เราจึงเรียก bit_or กับ (a, NOT b) แทน (a, b) ได้ผลเป็น a OR NOT b ตามที่ต้องการ

X สองตัวติดกันหักล้างกันเอง (X·X = ไม่ทำอะไร) แล้วทำไมสไลด์ยังวาดทั้งสองตัว?
ถูกค่ะ วงจรวาดตามโค้ดตรงๆ: qc.not(2) แล้วตามด้วย bit_or(...) ซึ่งเป็นฟังก์ชันสำเร็จรูป · ถ้าตัดทิ้งทั้งคู่ผลก็ยังเหมือนเดิม (ตอนสอบวาดตามสไลด์นะคะ) · การเขียนแบบนี้ทำให้ bit_or ใช้ซ้ำได้ทุกที่ ซึ่งบท 3-SAT ก็ใช้แบบนี้
ยังไม่ใช่ค่ะ ถ้าลบ X สองตัวนี้ออก ผลก็ยังเหมือนเดิม (มันหักล้างกันอยู่แล้ว) · เหตุผลจริงคือวงจรวาดตามโค้ด ซึ่งเรียก qc.not(2) แยกไว้ก่อนเรียกฟังก์ชัน bit_or

2.4 uncompute: ทำไมต้องล้าง scratch

หลังช่วงแรก scratch เก็บค่า a OR NOT b ไว้เป็น 0/1 · แปลว่าค่าของ scratch ผูกกับ a, b (entangle) · ถ้าทิ้งไว้แบบนี้ รีจิสเตอร์ abc จะไม่ใช่ 8 วงที่มีแต่ phase ต่างกันอีกต่อไป ค่าที่ scratch ต่างกันจะแยกกันอยู่คนละโลกและ interfere กันไม่ได้ · พอเอาไปเข้า mirror ของ AA ก็จะไม่ได้ผลอย่างที่ต้องการ (p18 · ทวนเรื่องนี้ที่บท 0021b)

วิธีล้างคือทำทุก gate ของช่วงแรกย้อนหลัง · ทุก gate ในช่วงนั้น (X, Toffoli) เป็น inverse ของตัวเอง จึงแค่กลับลำดับ · ส่วน pAND ไม่ได้เปลี่ยนค่าในรีจิสเตอร์ (แค่แปะ −1) จึงไม่ไปรบกวนการล้าง และเครื่องหมาย −1 จะติดอยู่ที่ค่า abc ต่อไป

compute (ซ้าย → ขวา)
X(b) → X(a,b) → Toffoli → X(a,b,out)
uncompute (กลับลำดับ)
X(a,b,out) → Toffoli → X(a,b) → X(b)

2.5 โค้ด QCEngine (p19–20)

// Encoding example in phase logic     ← สไลด์เขียน # ซึ่ง JS ไม่รู้จัก
qc.reset(4);
var reg = qint.new(4, 'reg');           ← สไลด์พิมพ์ 'reg’ (quote ไม่ตรงกัน)
qc.write(0);
reg.hadamard();                         ← ⚠️ ดูกล่องเตือนด้านล่าง

// (a OR NOT b)
qc.not(2);                              // NOT b  (0x2)
bit_or(1,2,8);                          // 0x8 = 0x1 OR 0x2

// pAND
phase_and(4|8);                         // CZ ระหว่าง c (0x4) กับ scratch (0x8)

// uncompute
inv_bit_or(1,2,8);
qc.not(2);

// binary logic OR using ancilla as output
function bit_or(q1, q2, out) {
    qc.not(q1|q2);
    qc.cnot(out, q1|q2);                // Toffoli: target = out, control = q1, q2
    qc.not(q1|q2|out);
}
// reversed binary logic OR (to uncompute)
function inv_bit_or(q1, q2, out) {
    qc.not(q1|q2|out);
    qc.cnot(out, q1|q2);
    qc.not(q1|q2);
}
// Phase-logic AND (pAND)
function phase_and(qubits) {
    qc.cz(qubits);
}

จุดที่ต้องอ่านให้ออก: qc.cnot(out, q1|q2) ใส่ target ก่อน control และเมื่อ control มี 2 qubit ก็คือ Toffoli · inv_bit_or เป็น bit_or ที่กลับลำดับบรรทัดเท่านั้น · phase_and(4|8) = CZ บนทุก qubit ใน mask → พลิกเมื่อทุกตัวเป็น 1 (p20)

⚠️ สไลด์ p19 เขียน reg.hadamard(); แบบไม่มี mask · ตามโค้ด reg มี 4 qubit จึงหมายถึง H ทั้ง 4 สายรวม scratch 0x8 แต่ Figure 10-4 วาด H แค่ 3 สาย · หนูลอง simulate ด้วย numpy แล้ว: ถ้าทำตามรูป (H 3 สาย) จะได้ Figure 10-5 พอดี · แต่ถ้า H ลง scratch ด้วยตามโค้ดตรงตัว จะได้ 16 ค่าปนกัน: scratch ค้างเป็น 0 ครึ่งหนึ่ง และ 1 อีกครึ่งหนึ่ง · ครึ่งที่ scratch = 0 พลิก |4⟩ |5⟩ |7⟩ ถูกต้อง แต่ครึ่งที่ scratch = 1 กลับพลิกแค่ |6⟩ · → ของที่ถูกน่าจะเป็น reg.hadamard(0x1|0x2|0x4) หรือให้ reg มีแค่ 3 qubit · ตอนสอบ: วาดวงจรตาม Figure 10-4 (H 3 สาย) และรู้ไว้ว่าบรรทัดนี้ในสไลด์ไม่ตรงกับรูป · (typo เล็กน้อยอื่นๆ: # ใช้เป็น comment และ 'reg’ ใช้ quote คนละแบบ · p18 พิมพ์ "a ORNOT b" ติดกัน)

  5. scratch ของบทนี้ต่างจาก scratch ของ phase XOR ยังไง? → บทนี้เริ่ม |0⟩ เก็บผลจริง entangle → ต้อง uncompute · XOR ใช้ |−⟩ + kickback → ไม่ต้อง
  6. ผล Figure 10-5 พลิกวงไหน? → |4⟩ |5⟩ |7⟩ (ค่า = a + 2b + 4c)
  7. สไลด์ p19 ผิดตรงไหน? → reg.hadamard() ไม่มี mask ทั้งที่รูปมี H 3 สาย (+ # กับ quote)

สรุป

  • phase logic ต่อกันตรงๆ ไม่ได้: output อยู่ใน phase แต่ input ต้องเป็นค่าในรีจิสเตอร์ (p14)
  • ทริก: ทุก operation ยกเว้นตัวสุดท้ายใช้ magnitude logic · ตัวสุดท้ายใช้ phase logic (p15)
  • ตัวอย่าง (a OR NOT b) AND c (Figure 10-3) → AND คือตัวสุดท้าย จึงเป็น pAND (p16)
  • Figure 10-4: X(b) + bit_or ลง scratch 0x8 → pAND = CZ(0x4, 0x8) → inv_bit_or + X(b) (p17–19)
  • bit_or = OR แบบ De Morgan ด้วย Toffoli · inv_bit_or = กลับลำดับ · phase_and = CZ (p20)
  • scratch แบบนี้ entangle → ต้อง uncompute (ต่างจาก scratch |−⟩ ของ XOR)
  • Figure 10-5: พลิก |4⟩ |5⟩ |7⟩ (p21) · ⚠️ reg.hadamard() ในสไลด์ไม่มี mask
