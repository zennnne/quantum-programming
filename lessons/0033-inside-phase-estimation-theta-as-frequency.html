Quantum Programming · Lec 08 · บทที่ 0033 (บทปิดคาบ)

ข้างใน phase estimation: เปลี่ยน θ เป็นความถี่

สองบทที่แล้วเราใช้ phase_est() เป็นกล่องดำ: ใส่ eigenstate กับ cont_u แล้วอ่านได้ 8 = 180° · บทนี้เราจะเปิดกล่องดูว่าข้างในทำยังไง · ข่าวดีคือไม่มีของใหม่เลย ทุกชิ้นเป็นของที่พี่เรียนมาแล้ว: phase kickback (บท 0010), controlled operation (บท 0012) และ invQFT (บท 0030) · แค่เอามาต่อกันให้ถูกที่ค่ะ

ทำไมต้องเรียนบทนี้: จับหลัก 3 อย่าง ① ใส่ U ตรงๆ กับ eigenstate ได้แค่ global phase → อ่านไม่ได้ · ต้องทำให้ θ กลายเป็นความถี่ของ register ให้ invQFT อ่าน ② สูตรคือ “หมุน |k⟩ ด้วย kθ” · ทำได้ด้วย H ทุกสาย → controlled-U^(2ʲ) → phase kickback ③ วงจรเต็ม (Figure 8-12) = H → cU, cU², cU⁴, … → invQFT → READ · รูปนี้น่าจะออกสอบที่สุดของคาบ

ส่วนที่ 1 · เป้าหมาย: ทำให้ θ กลายเป็น “ความถี่” (p33–38)

1.1 ไอเดียง่ายๆ ที่ใช้ไม่ได้ (p33–34 · Figure 8-7)

เรามีทั้ง U และ eigenstate ของมันอยู่ในมือ · ไอเดียแรกที่ใครๆ ก็คิดคือ “ก็เอา U ไปทำกับ eigenstate ตรงๆ เลยสิ”

ผลคือทุกวงหมุนไปเท่ากันหมด (ในสไลด์หมุนตามเข็มราว 30° ทุกวง) · ตามนิยามจากบท 0031: U|ψ⟩ = eiθ|ψ⟩ → θ ถูกเก็บไว้จริง แต่อยู่ในรูป global phase ซึ่ง READ ไม่ได้ (p34)

ปมของทั้งคาบ: ข้อมูลที่เราอยากได้ “ติดอยู่ในเฟส” อีกแล้ว · และเป็นเฟสแบบที่แย่ที่สุดด้วย คือ global phase ที่ไม่มีวงไหนต่างจากวงอื่น ให้จับได้เลย

1.2 เครื่องมือที่อ่านเฟสได้: invQFT (p35)

ย้อนไปบท 0029–0030: invQFT อ่าน “ความต่างเฟสที่ซ้ำเป็นคาบ” (periodic phase differences) ออกมาเป็นตัวเลขที่ READ ได้ · เช่น register 3 qubit ที่เฟสหมุนครบ 2 รอบตลอด 8 วง → invQFT อ่านได้ 2

ดังนั้นโจทย์ใหม่ของเราคือ: ทำยังไงให้ θ ไปเป็น “ความถี่” ของ relative phase ใน register แล้วปล่อยให้ invQFT ทำที่เหลือ

1.3 หน้าตาของเป้าหมาย (p36–37 · Figure 8-8)

ถ้า θ = 90° = ¼ รอบ → อยากได้ register ที่เฟสเดินทีละ 90° · ถ้า θ = 180° → เดินทีละ 180°

Readout / 8 = θ / 360° → 2/8 = 90/360 · 4/8 = 180/360

นี่คือ Equation 8-1 (R = θ/360° × 2ᵐ) จากบท 0032 และกฎ n/2ᴺ × 360° ของบท 0030 ตัวเดียวกันเป๊ะ · ตอนนี้เราเห็นแล้วว่ามันมาจากไหน: ตัวเลขที่อ่านได้ = จำนวนรอบที่เฟสหมุนตลอด register

สไลด์พิมพ์ผิด (p37): เขียนว่า “frequency of 2/8 = 4/1” · ที่ถูกคือ 2/8 = 1/4 (ตรงกับประโยคก่อนหน้า 90/360 = 1/4) · ถ้าเจอข้อสอบลอกประโยคนี้มา ตอบตามสไลด์ได้ แต่รู้ไว้ว่าความหมายจริงคือ ¼ ค่ะ

1.4 สูตรสร้างเป้าหมาย: หมุน |k⟩ ด้วย kθ (p37–38 · Figure 8-9)

เริ่มจาก equal superposition (ทุกวงเท่ากัน เฟส 0°) แล้วหมุนวงที่ k ด้วย k × θ · ลองกับ θ = 90°:

บันไดวนทุกขั้นหมุนไปจากขั้นก่อนเท่ากัน · ขั้นที่ k หมุนรวม k เท่าของมุมต่อขั้น · นับว่าเดินจากล่างถึงบนแล้ววนกี่รอบ ก็รู้มุมต่อขั้น
≈
register หลังหมุน |k⟩ ด้วย kθวงที่ k มีเฟส kθ · invQFT “นับจำนวนรอบ” ตลอด 2ᵐ วง · ได้จำนวนรอบ → ย้อนกลับเป็น θ
ประโยคสรุปของส่วนที่ 1 (p38): ถ้าเราหมุน state ที่ k ของ register ด้วย k × eigenphase ได้ · invQFT ก็อ่าน eigenphase ออกมาได้
ป้ายในสไลด์ไม่สม่ำเสมอ (p38): 4 × 90° เขียน 360° (ไม่ลด) แต่ 5 × 90° เขียน 90° (ลด mod 360 แล้ว) · ไม่ผิด แค่เขียนคนละแบบ · 360° = 0° = เข็มชี้ขึ้นเหมือนกัน
ลองเองก่อน: θ = 135° กับ register 3 qubit · หมุน |k⟩ ด้วย kθ แล้ว invQFT · อ่านได้เท่าไร? (คำใบ้: คิดก่อนว่า |8⟩ ถ้ามีจะหมุนรวมกี่รอบ)
ถูกค่ะ · 8 วง × 135° = 1080° = 3 รอบ → อ่านได้ 3 · เช็คด้วยสูตร 135/360 × 8 = 3 ✓ (เฟสจริงของแต่ละวง: 0, 135, 270, 45, 180, 315, 90, 225 — กระโดดไปมาแต่ระยะห่างเท่ากันทุกขั้น)
ยังไม่ใช่ค่ะ · ลองนับรอบ: 8 ขั้น × 135° = 1080° = กี่รอบของ 360°? หรือใช้ R = θ/360° × 2ᵐ

ส่วนที่ 2 · วงจรที่ทำตามเป้า: cont_u + phase kickback (p39–48)

2.1 ทบทวน phase kickback ก่อน (บท 0010)

qubit ควบคุมอยู่ใน |+⟩ · qubit เป้าหมายเป็น eigenstate ของ U (ที่นี่ใช้ |1⟩ ซึ่งเป็น eigenstate ของ PHASE(90°)) · แล้วทำ controlled-U:

มีแค่วง |3⟩ (ctrl = 1) ที่ได้เฟส 90° · ภาพนี้เล่าได้ 2 แบบ และถูกทั้งคู่:

มุมมอง A: เฟสอยู่ที่ eigenstate
“ถ้า ctrl = 1 eigenstate ได้ global phase θ” → ฟังดูไร้ประโยชน์
มุมมอง B: เฟส “เด้งกลับ” ไปที่ ctrl
“|1⟩ ของ ctrl ได้ relative phase θ เทียบกับ |0⟩” → อ่านได้ถ้ามี invQFT

circle notation มีภาพเดียว · “เฟสอยู่ที่ไหน” เป็นแค่การตีความ · phase estimation เลือกมุมมอง B ค่ะ

2.2 หมุน k เท่า: ให้บิตที่ j คุม U^(2ʲ) (p39–40 · Figure 8-10)

ทีนี้ขยายเป็น register k หลายบิต · บิตที่มีน้ำหนัก 2ʲ คุมกล่อง U^(2ʲ) (= ทำ U ซ้ำ 2ʲ ครั้ง) · ลองกับ k = 1001₂ = 9:

① บิตที่เป็น 1: 0x1 กับ 0x8 → กล่องที่ทำงานจริงคือ U¹ และ U⁸ · U² กับ U⁴ ไม่ทำงาน
② รวม = U¹ · U⁸ = U⁹ = ทำ U ทั้งหมด 9 ครั้ง
③ ทุกครั้งที่ทำ U กับ eigenstate ได้ θ เพิ่ม → รวม 9θ · ทั่วไป: ทำ U ทั้งหมด k ครั้ง → หมุน kθ

นี่คือทริคเลขฐานสองเดิมจากบท 0008 · k ใดๆ เขียนเป็นผลรวมของ 2ʲ ได้เสมอ → ใช้กล่องแค่ m กล่องก็ทำ U ได้ทุกจำนวนครั้งตั้งแต่ 0 ถึง 2ᵐ − 1

ถ้า k = 6 (register 4 บิตเดิม) · กล่องไหนบ้างที่ทำงาน และหมุนรวมเท่าไร?
ถูกค่ะ · 6 = 0110₂ = 2 + 4 → บิต 0x2 คุม U² และบิต 0x4 คุม U⁴ → U⁶ → 6θ
ยังไม่ใช่ค่ะ · แตก 6 เป็นเลขฐานสองก่อน (6 = 4 + 2) แล้วดูว่าบิตไหนเป็น 1

2.3 ทุก k พร้อมกัน: H ทุกสาย (p41 · Figure 8-11)

วงจรเมื่อกี้ทำได้ทีละ k · แต่เป้าหมายของเราคือทุก |k⟩ ได้ kθ พร้อมกัน · ทางแก้คือท่าเดิมที่ใช้มาทั้งเทอม: HAD ทุกสายของ register บน → ได้ uniform superposition ของทั้ง 2ᵐ ค่า

สไลด์ p41 ยังเล่าด้วยมุมมอง A: “ถ้าบนเป็น |0⟩ eigenstate หมุน 0 · ถ้าบนเป็น |1⟩ หมุน θ · …” → ดูเหมือนยังได้แค่ global phase ที่ไร้ประโยชน์ใน register ล่าง

2.4 มองแบบ kickback → ได้เป้าหมายพอดี → invQFT (p42–44 · Figure 8-12)

สลับไปมุมมอง B (p42): เฟส kθ “เด้งกลับ” มาเป็น relative phase ของ |k⟩ ใน register บน · θ = 90° กับ 3 qubit → |0⟩ ได้ 0°, |1⟩ ได้ 90°, |2⟩ ได้ 180°, … = Figure 8-9 ในส่วนที่ 1 เป๊ะ · เหลือแค่ invQFT แล้ว READ

3 ข้อที่สไลด์ย้ำใต้รูป (p44) ① ต้องมี cont_u แบบ conditional เพราะทุก U^(2ʲ) ถูกคุมด้วย qubit ของ register บน ② register ล่างยังเป็น eigenstate เดิมตอนจบ (เฟสเด้งขึ้นไปข้างบนหมดแล้ว) — ตรงกับ Figure 8-4 ที่ qin ไม่เปลี่ยน ③ ขนาด register บนจำกัดความแม่น เพราะ invQFT แยกได้แค่ 2ᵐ ความถี่ → ความละเอียด 360°/2ᵐ (บท 0032)
ป้ายกล่องสุดท้าย U^(2ⁿ) น่าจะผิด (p32, p39–44 · โผล่ 6 หน้า = จุดสอบ) · n ในรูปคือจำนวน qubit ของ eigenstate (register ล่าง) · แต่เลขชี้กำลังต้องผูกกับ register บน: บิตแรกคุม U = U^(2⁰) ดังนั้นถ้าบนมี m qubit กล่องสุดท้าย = U^(2^(m−1)) (วงจร 4 สายบนนี้ = U⁸) · ตอบตามสไลด์ (U^(2ⁿ)) ตอนสอบ แต่รู้ของจริงไว้ค่ะ · อ่านเพิ่ม: บนจอสไลด์ใช้ n กับ register บนด้วย (p41 “2ⁿ ค่า”) — ตัวอักษรชนกัน ในบทเรียนนี้หนูใช้ m กับ register บนตลอด
หลังรันวงจรเต็มจบ · θ ถูกเก็บอยู่ในรูปไหน ก่อนที่ invQFT จะทำงาน?
ถูกค่ะ · kickback ย้ายเฟสมาเป็น relative phase kθ ของ |k⟩ ข้างบน (magnitude ยังเท่ากันทุกวง) · invQFT แปลงความถี่นั้นเป็นตัวเลขที่ READ ได้
ยังไม่ใช่ค่ะ · global phase อ่านไม่ได้ (ส่วนที่ 1.1) และ register ล่างยังเป็น eigenstate เดิม · ลองนึกถึงมุมมอง B ในข้อ 2.1

2.5 กลับไปอ่านโค้ด: 3 บรรทัด = 3 ขั้น (p31–32)

ตอนนี้โค้ดที่สไลด์บอกว่า “Pretty concise!” อ่านออกทุกบรรทัดแล้ว:

function phase_est(q_in, q_out, cont_u) {
    // ① HAD the output register
    q_out.had();
    // ② Apply conditional powers of u
    for (var j = 0; j < q_out.numBits; j++)
        cont_u(q_out, q_in, 1 << j);   // บิต j คุม U^(2ʲ)
    // ③ Inverse QFT on output register
    q_out.invQFT();
}
บรรทัดในวงจรทำไปเพื่อ
q_out.had()คอลัมน์ Hทุก k พร้อมกัน (2.3)
cont_u(…, 1 << j)กล่อง U, U², U⁴, …|k⟩ ได้เฟส kθ ผ่าน kickback (2.2, 2.4)
q_out.invQFT()กล่อง invQFTอ่านความถี่ → R = θ/360° × 2ᵐ (1.3)
โค้ดในสไลด์จัดบรรทัดเพี้ยน 2 จุด (p31–32) (ก) q_out.had(); ไปต่อท้ายบรรทัด // HAD the output register → ถ้ารันตาม JS จริงจะถูก comment ทิ้ง · (ข) q_out.invQFT(); ย่อหน้าเท่ากับตัวใน loop แต่ for ไม่มีปีกกา → จริงๆ ทำครั้งเดียวหลัง loop · โค้ดข้างบนหนูจัดบรรทัดให้ถูกแล้ว · ถ้าข้อสอบถาม “ขั้นตอน” ตอบ 3 ขั้นตามนี้ได้เลยค่ะ

2.6 ยกกำลัง cont_u ต้องเร็ว (p45)

กล่อง U^(2ʲ) ถ้าทำแบบซื่อๆ (naive) = เรียก cont_u ซ้ำ 2ʲ ครั้ง · กล่องท้ายๆ จะโตเร็วมาก

register บน m = 4 · ทำทุกกล่องแบบซื่อๆ · ต้องเรียก U รวมกี่ครั้ง?
ถูกค่ะ · 1 + 2 + 4 + 8 = 15 = 2⁴ − 1 · ถ้า m = 20 จะเป็นล้านครั้ง → exponential ในขณะที่ตัว phase estimation เองแค่ O(m²)
ยังไม่ใช่ค่ะ · กล่อง U, U², U⁴, U⁸ เรียก U กี่ครั้งต่อกล่อง? บวกกันดูค่ะ

ทางแก้ของสไลด์: ส่ง subroutine ที่ทำ “กำลัง n” ของ U ได้เร็วในตัว (cont_u(n)) ไม่ใช่วนเรียกซ้ำ · นี่คือเหตุผลเดียวกับ “O(m²) จะหายถ้า cont_u แพง” ในบท 0032

เกร็ด (ไม่ออกสอบคาบนี้): Shor's algorithm (Ch 12) ใช้ phase estimation กับ U = “คูณ mod N” ซึ่งยกกำลัง 2ʲ ได้เร็วด้วยการยกกำลังสองซ้ำ (modular exponentiation) — เลยไม่ติดปัญหานี้

2.7 สรุปคาบ Lec 08 (p46–47)

phase estimation = 3 วัตถุดิบที่เรียนมาแล้ว (p46): ① phase kickback ② controlled unitary (cont_u) ③ invQFT · เส้นทางของ θ: global phase (อ่านไม่ได้) → kickback → relative phase ใน register บน → invQFT → ตัวเลขที่ READ ได้

บทถัดไปของหนังสือ (p47) เปลี่ยนจาก “QPU ทำงานยังไง” เป็น “เอา QPU ไปทำอะไร”: Ch 9 data structure · Ch 10 quantum search · Ch 11 computer graphics · Ch 12 Shor's factoring · Ch 13 machine learning · (p48 = Q&A)

ทดสอบความจำก่อนปิดบท (พยายามตอบเองก่อนเปิด)
  1. ทำไมแค่ทำ U กับ eigenstate ถึงไม่พอ? → ได้แค่ global phase · READ ไม่ได้
  2. register แบบไหนที่ invQFT อ่าน θ ได้? → |k⟩ มีเฟส kθ (θ เป็นความถี่)
  3. บิตที่มีน้ำหนัก 2ʲ คุมกล่องอะไร? → U^(2ʲ) · รวมแล้วเป็น U^k
  4. วาดวงจรเต็มจากความจำ (ลำดับคอลัมน์)? → write 0 → H ทุกสาย → cU, cU², cU⁴, … → invQFT → READ บน
  5. ป้ายกล่องสุดท้ายในสไลด์ vs ของจริง? → สไลด์ U^(2ⁿ) · จริง U^(2^(m−1))
  6. register ล่างตอนจบเป็นอะไร? → eigenstate เดิม
  7. 3 วัตถุดิบของ phase estimation? → kickback · controlled-U · invQFT

สรุป

  • U บน eigenstate = global phase อ่านไม่ได้ → ต้องย้าย θ ไปเป็นความถี่ของ register บน
  • เป้าหมาย: |k⟩ ได้เฟส kθ → invQFT อ่านได้ R = θ/360° × 2ᵐ (Figure 8-8, 8-9)
  • บิต 2ʲ คุม U^(2ʲ) → รวม U^k · H ทุกสาย → ทุก k พร้อมกัน · kickback → เฟสไปอยู่ที่ |k⟩ ข้างบน
  • วงจรเต็ม: H → controlled-U^(2ʲ) → invQFT → READ · register ล่างยังเป็น eigenstate เดิม · สไลด์ป้าย U^(2ⁿ)
  • ยกกำลังแบบซื่อๆ = 2ᵐ − 1 ครั้ง → ต้องมี cont_u ที่ทำกำลังได้เร็ว
