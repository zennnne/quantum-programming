Quantum Programming · Lec 11 · บทที่ 0042

วาดรูปลงใน phase: ลายจุด ลายทาง เส้นโค้ง

บทที่แล้วเราระบายได้แค่ "ครึ่งผ้าใบ" ด้วย PHASE(180) ตัวเดียว · บทนี้จะวาดรูปที่ซับซ้อนขึ้น 3 รูป คือลายหมากรุกที่มุม ลายทางเฉียง และเสี้ยววงกลม · ข่าวดีคือทั้ง 3 รูปใช้สูตรเดียวกัน และเป็นสูตรที่พี่ Zen เรียนมาแล้วใน Lec 10

ทำไมต้องเรียนบทนี้: จับหลัก 4 อย่าง ① ทุกรูปวาดด้วยสูตร คำนวณ → flip phase → uncompute ต่างกันแค่ขั้น "คำนวณ" ② dither: คำนวณด้วย CNOT (เช็คว่าบิตไม่เท่ากัน) แล้ว flip ด้วย CZ 3 จุด ③ ลายทางเฉียง: คำนวณด้วยการลบ qx − 2·qy แล้ว flip ที่บิตบนสุด ④ เสี้ยววงกลม: คำนวณ x² + y² − r² ลง register แยกชื่อ qacc แล้ว flip ที่บิตเครื่องหมาย · register เล็กไปจะ overflow เป็นแถบโค้ง
สูตรประจำบท (มาจาก บท 0038 · magnitude ก่อน phase ทีหลัง):
คำนวณเงื่อนไขให้ไปโผล่ที่ qubit ตัวหนึ่ง → PHASE(180) / CZ ที่ qubit นั้น → ทำขั้นคำนวณย้อนกลับ
ขั้นแรกเป็น magnitude logic (ย้ายค่าไปมา) · ขั้นกลางเป็น phase logic (ฝังคำตอบลง phase) · ขั้นท้ายคือ uncompute เพื่อคืน register ให้เหมือนเดิม เหลือไว้แต่ phase

ส่วนที่ 1 · วาดด้วยเงื่อนไขซ้อน: dither กับลายทางเฉียง (p15–17)

1.1 ก้าวแรก: เงื่อนไขแบบ AND ต้องใช้ CZ

ทวนจากบทที่แล้ว: PHASE(180) บน qubit เดี่ยวๆ ระบายได้ทีละครึ่งผ้าใบเสมอ · ถ้าอยากระบายเฉพาะ "qx ≥ 8 และ qy ≥ 8" (มุมขวาล่างมุมเดียว) ต้องใช้ gate ที่ flip เฉพาะตอนทุก qubit ที่เลือกเป็น 1 พร้อมกัน ซึ่งก็คือ CZ (= CPHASE 180°) จาก บท 0010 · ใน บท 0037 เราเรียกมันว่า phase-logic AND

① ถ้าเริ่มจากผ้าใบที่ระบายครึ่งขวาไว้แล้ว (PHASE(180) ที่ qx 0x8) แล้วสั่ง CZ(qx 0x8, qy 0x8) ต่ออีกตัว ผ้าใบจะเป็นยังไง
ถูกค่ะ มุมขวาล่างเขียวอยู่แล้ว โดน flip อีกรอบ (180° + 180° = 360°) เลยกลับเป็นชมพู · การ flip ซ้ำ = "ลบสีออก" จำไว้ เพราะ dither ใช้ทริกนี้ตรงๆ
มุมขวาล่างเขียวอยู่ก่อนแล้วจาก PHASE ตัวแรก · CZ มา flip มุมนั้นซ้ำอีกรอบ = หมุนครบ 360° กลับเป็นชมพู → เหลือเขียวแค่มุมขวาบน 64 วง

1.2 dither pattern: ระบายแค่ครึ่งเดียวของมุม

dither pattern (ลายจุดสลับ) คือการเรียงจุดดำกับจุดขาวสลับกันถี่ๆ ให้มองไกลๆ แล้วเห็นเป็นสีเทา · ถ้าสลับกันแบบครึ่งต่อครึ่งเหมือนตารางหมากรุก จะได้ 50% gray (เทา 50%) · ตรงกับเรื่อง supersampling พอดี: ถ้ามุมนี้ถูกเฉลี่ยรวมเป็น pixel เดียว ค่าที่ได้คือ "ถูกระบายครึ่งหนึ่ง"

เงื่อนไขในสไลด์ (p15) มี 3 ข้อที่ต้องจริงพร้อมกัน

  • qx ≥ 8 → บิต 0x8 ของ qx เป็น 1
  • qy ≥ 8 → บิต 0x8 ของ qy เป็น 1
  • บิตต่ำสุด (0x1) ของ qx ไม่เท่ากับของ qy → ข้อนี้เองที่ทำให้เกิดลายสลับ

สองข้อแรกเสียบ CZ ได้เลย เพราะเป็น "บิตนี้เป็น 1" · แต่ข้อสามเป็น "สองบิตไม่เท่ากัน" ไม่มี qubit ตัวไหนเก็บคำตอบนี้ไว้ → ต้องคำนวณให้มันไปโผล่ที่ qubit สักตัวก่อน

ทวน: "ไม่เท่ากัน" = XOR · a XOR b ได้ 1 ก็ต่อเมื่อ a ≠ b · และ CNOT ทำ XOR ให้ฟรี: CNOT (control = b, target = a) เปลี่ยน a ให้เป็น a XOR b (บท 0009)
① คำนวณ: qx.cnot(qy, 0x1) → บิต 0x1 ของ qx กลายเป็น (qx₀ XOR qy₀) ชั่วคราว = "1 เมื่อสองบิตไม่เท่ากัน"
② flip phase: CZ 3 จุดที่ qx 0x1 · qx 0x8 · qy 0x8 → flip เมื่อเงื่อนไขครบทั้ง 3 ข้อ
③ uncompute: qx.cnot(qy, 0x1) ซ้ำอีกรอบ → บิต 0x1 ของ qx กลับเป็นค่าเดิม (XOR สองรอบหักล้างกัน)
Figure 11-6 (ซีกวงจร) · Adding a dither pattern · กล่องกลาง = "invert color if qx>=8" · กล่องขวา = "50% gray in corner"

วิธีจำกล่องขวา: ⊕ – จุดดำ 3 จุด – ⊕ · ⊕ ทั้งสองตัวอยู่บนสาย qx 0x1 โดยมี ● อยู่ที่ qy 0x1 · จุดดำ 3 จุดตรงกลางอยู่ที่ qx 0x1, qx 0x8, qy 0x8 (สไลด์วาดเป็นจุดดำล้วน ไม่มี φ ไม่มีป้ายองศา)

// Invert if qx >= 8
qc.phase(180, qx.bits(0x8));

// 50% gray in the corner
qx.cnot(qy, 0x1);
qc.cphase(180, qy.bits(0x8), qx.bits(0x8|0x1));
qx.cnot(qy, 0x1);

ทำไมออกมาเป็นหมากรุก: มุมขวาล่างเขียวอยู่ก่อนแล้วจาก PHASE ตัวแรก (กล่อง 180°) · กล่องขวามา flip ซ้ำเฉพาะวงที่บิต 0x1 ไม่เท่ากัน วงพวกนั้นเลยกลับเป็นชมพู (ทริกเดียวกับข้อ ①) · บิต 0x1 ไม่เท่ากันคือ qx กับ qy เป็นคู่-คี่คนละแบบ → ชมพูกับเขียวสลับกันทั้งแนวนอนและแนวตั้ง

② ในรูป Figure 11-6 วง qx = 11, qy = 14 เป็นสีอะไร เพราะอะไร (เขียนเลขฐานสองของ 11 กับ 14 ดูบิตท้ายก่อน)
ถูกค่ะ 11 = 1011 (บิตท้าย 1) · 14 = 1110 (บิตท้าย 0) → ไม่เท่ากัน · รอบแรกจาก PHASE ที่ qx 0x8 รอบสองจาก CZ 3 จุด → กลับเป็นชมพู
11 = 1011, 14 = 1110 → qx ≥ 8 โดน flip รอบแรก · qy ≥ 8 และบิตท้ายไม่เท่ากัน (1 กับ 0) โดน CZ 3 จุด flip รอบสอง → 360° = ชมพู
③ นับดู: ผ้าใบ Figure 11-6 มีวงเขียวทั้งหมดกี่วง (มุมขวาบนกี่วง + มุมขวาล่างกี่วง)
ใช่ค่ะ มุมขวาบน 64 + ครึ่งหนึ่งของมุมขวาล่าง 32 = 96 · ตัวเลข "ถูกระบายไปกี่วง" แบบนี้แหละคือสิ่งที่ QSS จะมานับในบท 0044

ทำไมต้องมี CNOT ตัวหลัง: ถ้าไม่ uncompute บิต 0x1 ของ qx จะค้างเป็น (qx₀ XOR qy₀) แปลว่าตำแหน่ง x ของ pixel ถูกเปลี่ยน (ในแถว qy เลขคี่ คอลัมน์ติดกันจะสลับที่กัน) · เราอยากเปลี่ยนแค่ "สี" ไม่อยากย้าย pixel จึงต้องคืนค่า qx ให้เหมือนเดิมทุกครั้ง เหลือไว้แต่ phase

1.3 ลายทางเฉียง: เปลี่ยนขั้น "คำนวณ" เป็นการลบเลข

สไลด์ p17: "With a little arithmetic from lecture 5, we can create more interesting patterns" · โค้ดมีแค่ 3 บรรทัด หน้าตาเป็นสูตรประจำบทเป๊ะ

// fun stripes
qx.subtractShifted(qy, 1);      // คำนวณ:   qx ← qx − 2·qy
qc.phase(180, qx.bits(0x8));    // flip:     ถ้าบิตบนสุดของ qx เป็น 1
qx.addShifted(qy, 1);           // uncompute: qx ← qx + 2·qy (คืนค่าเดิม)

คอมเมนต์หลัง // ทางขวาเป็นของคาโฮะ · ในสไลด์มีแต่ // fun stripes บรรทัดเดียว

ทวน 2 เรื่องจาก Lec 05: ① shifted = เลื่อนบิตไปทางซ้ายก่อนบวก/ลบ · เลื่อน 1 ตำแหน่ง = คูณ 2 → subtractShifted(qy, 1) คือลบด้วย 2·qy ② register 4 บิตเก็บได้แค่ 0–15 · ลบแล้วติดลบจะวนกลับ (mod 16) เช่น 1 − 2 = −1 → เก็บเป็น 15 (บท 0019)

กลางสูตรคือบรรทัดเดิมจากบทที่แล้ว (PHASE ที่ qx 0x8 = "flip ถ้า qx ≥ 8") แต่ตอนที่มันทำงาน qx ถูกเปลี่ยนเป็น qx − 2·qy ไปแล้ว · ผลรวมจึงเป็น "flip ถ้า (qx − 2·qy) mod 16 ≥ 8" · ลองไล่ทีละแถว

qy = 0 ลบ 0 → เงื่อนไขคือ qx ≥ 8 เหมือนบทที่แล้ว → เขียวที่ qx = 8–15
qy = 1 ลบ 2 → qx = 10–15 ได้ 8–13 (เขียว) · qx = 0, 1 ได้ −2, −1 วนเป็น 14, 15 (เขียว) → แถบเขียวเลื่อนขวา 2 ช่อง แล้วส่วนที่ล้นวนมาโผล่ทางซ้าย
qy = 4 ลบ 8 → เขียวสลับฝั่งมาอยู่ที่ qx = 0–7
qy = 8 ลบ 16 = ลบ 0 (mod 16) → กลับมาเหมือนแถว qy = 0 · ลายจึงวนซ้ำทุก 8 แถว
④ แถว qy = 3 วงเขียวอยู่ที่ qx ค่าไหนบ้าง (คำนวณ (qx − 6) mod 16 แล้วดูว่า ≥ 8 ไหม อย่าเพิ่งเลื่อนขึ้นไปดูรูป)
ถูกค่ะ qx = 14, 15 ได้ 8, 9 · qx = 0–5 ได้ −6 ถึง −1 วนเป็น 10–15 · รวม 8 วงเหมือนทุกแถว แค่เลื่อนไป 6 ช่อง
ลบ 6: qx = 14, 15 → 8, 9 (≥ 8) · qx = 0–5 → −6…−1 วนเป็น 10…15 (≥ 8) · qx = 6–13 → 0–7 (ไม่ถึง) → เขียวที่ 0–5 กับ 14–15

คราวนี้ดูวงจรจริง · ยาว 16 คอลัมน์ แต่อ่านเป็น 3 ก้อนตามสูตร: ลบ (6 คอลัมน์) → φ (1 คอลัมน์) → บวกคืน (6 คอลัมน์ เป็นภาพสะท้อนกระจกของก้อนแรก)

ส่วนที่ 2 · วาดเส้นโค้งด้วยการยกกำลังสอง (p18–21)

2.1 เสี้ยววงกลม = เงื่อนไข x² + y² < r²

สไลด์ p18: จะวาดรูปทรงซับซ้อนขึ้น ต้องใช้คณิตศาสตร์ซับซ้อนขึ้น · Example 11-2 วาดเสี้ยววงกลม (quarter-circle) รัศมี 13 pixel โดยมีจุดศูนย์กลางอยู่ที่มุมซ้ายบน (qx = 0, qy = 0)

ทวน: จุดอยู่ในวงกลมเมื่อไร · ระยะจากจุดศูนย์กลางถึงจุด (x, y) คือ √(x² + y²) (พีทาโกรัส) · จุดอยู่ข้างในวงกลมรัศมี r เมื่อระยะนั้นน้อยกว่า r → ยกกำลังสองสองข้างได้ x² + y² < r² (ไม่ต้องถอดราก) · ในที่นี้ r = 13 → r² = 169

ต้องใช้ของ 2 อย่างที่ตัวอย่างก่อนหน้าไม่มี

  • ยกกำลังสอง → ใช้ addSquared() จาก Lec 05 (อภิธานศัพท์: a.addSquared(b) = a += b·b)
  • ที่ทดเลข → ลายทางเฉียงคำนวณทับลงใน qx ได้เลย แต่ x² + y² ใหญ่เกินกว่าจะใส่ใน 4 บิต จึงต้องมี register ใหม่ชื่อ qacc (accumulator = ตัวสะสมผลบวก) ขนาด 10 qubit · ทำหน้าที่เดียวกับ scratch ใน บท 0021

รวมทั้งโปรแกรมใช้ 18 qubit = qx 4 + qy 4 + qacc 10 · HAD ทำเฉพาะ qx กับ qy ส่วน qacc เริ่มที่ 0
ทำไมต้อง 10 · สไลด์ให้เหตุผลว่ากัน overflow ตอนยกกำลังสองแล้วบวกกัน: ค่ามากสุดคือ 15² + 15² = 450

2.2 ทริกเปรียบเทียบ: ลบแล้วดูบิตเครื่องหมาย

QPU ไม่มีคำสั่ง "ถ้าน้อยกว่า" ตรงๆ · ทริกคือเปลี่ยน A < B ให้เป็น A − B ติดลบ แล้วอาศัยว่าเลขติดลบแบบ two's complement มีบิตบนสุดเป็น 1 เสมอ (บท 0019) · พอคำตอบไปอยู่ที่ qubit ตัวเดียวแล้ว ก็ PHASE(180) ที่ตัวนั้นได้เลย เหมือนสูตรเดิมทุกอย่าง

var radius = 13;
var acc_bits = 10;
// (ตั้งค่า qx, qy, qacc และ hadamard qx, qy แล้ว)

// fill if x^2 + y^2 < r^2
qacc.addSquared(qx);                      // ┐
qacc.addSquared(qy);                      // ├ คำนวณ: qacc = x² + y² − 169
qacc.subtract(radius * radius);           // ┘
qacc.phase(180, 1 << (acc_bits - 1));     // flip: ถ้าบิตบนสุดเป็น 1 (ติดลบ)
qacc.add(radius * radius);                // ┐
qacc.subtractSquared(qy);                 // ├ uncompute: ย้อนลำดับ 3 บรรทัดบน
qacc.subtractSquared(qx);                 // ┘

คอมเมนต์ทางขวาเป็นของคาโฮะ · 1 << (acc_bits - 1) = 1 เลื่อนซ้าย 9 ตำแหน่ง = 0x200 = บิตบนสุดของ register 10 บิต · Figure 11-8 ในสไลด์ไม่มีรูปวงจร มีแต่โค้ดกับ circle notation
