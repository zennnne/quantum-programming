ปริศนาลูกแมว/เสือ: รันครั้งเดียวต้องถูก

บท 0038 เราได้ทริก "magnitude ก่อน phase ทีหลัง" มาแล้ว แต่ยังหยุดอยู่แค่การ mark คำตอบไว้ใน phase ซึ่งยังอ่านออกมาไม่ได้ · บทนี้จะเอาทริกนั้นไปแก้ปริศนาจริง แล้วต่อด้วย mirror ของ AA จนอ่านคำตอบออกมาได้ 100% · นี่เป็นครั้งแรกที่เราได้เห็น Quantum Search ทำงานครบตั้งแต่ต้นจนจบ

ทำไมต้องเรียนบทนี้: จับหลัก 4 อย่าง ① SAT คือคำถามว่า "มี input ไหนทำให้ประโยค logic เป็นจริงบ้าง" ซึ่ง phase logic ตอบได้ตรงตัว ② แปลงปริศนาเป็นวงจร: ป้าย 2 แผ่นกับกติกาของพระราชา = OR · NOT · XNOR ③ ถ้าใช้คอมพิวเตอร์ธรรมดาแล้วรันได้ครั้งเดียว โอกาสถูกมีแค่ 25% ④ QPU: OR, NOT ใช้ magnitude logic → XNOR ใช้ phase logic ผ่าน kickback → uncompute → mirror → 100%

ส่วนที่ 1 · ปริศนา และเหตุผลที่คอมพิวเตอร์ธรรมดาแก้ไม่ได้ (p22–30)

1.1 SAT: โจทย์ที่ phase logic เกิดมาเพื่อตอบ

ทวนบท 0037: phase logic พลิก phase ของทุกค่าที่ satisfy (ทำให้ประโยคเป็นจริง) · ทีนี้ถ้าเราตั้งคำถามกลับด้านว่า "มีค่าไหนบ้างไหมที่ทำให้ประโยคนี้เป็นจริง" คำถามนี้มีชื่อเรียกว่า boolean satisfiability (ปัญหาความสอดคล้องบูลีน) หรือเรียกย่อว่า SAT (p22)

phase logicใส่ทุก input เข้าไปพร้อมกัน แล้วแอบทำเครื่องหมาย (ด้วยหมึกล่องหน) ไว้ที่ input ที่ทำให้ประโยคเป็นจริง
+
AA (ไฟ UV)ขยายตัวที่มีเครื่องหมายให้ magnitude ใหญ่ขึ้น จนตอน READ มีโอกาสสูงที่จะได้ตัวนั้น = ตอบ SAT

SAT ไม่ได้มีไว้แก้ปริศนาเล่นๆ อย่างเดียว ในวิทยาการคอมพิวเตอร์ใช้กันจริงใน model checking (การตรวจโมเดลของระบบ) · planning ใน AI (การวางแผน) · software verification (การพิสูจน์ว่าโปรแกรมทำงานถูก) (p22) · แต่สไลด์เลือกเริ่มจากปริศนาก่อนเพราะเห็นภาพง่ายกว่า

2.3 หัวใจของบท: XNOR ด้วย phase kickback

ทวนจากบท 0037: phase XOR ใช้ scratch ที่เป็น |−⟩ แล้วยิง CNOT จาก input 2 ตัวเข้าไป · CNOT ที่ target เป็น |−⟩ จะไม่เปลี่ยน scratch แต่ดีด −1 กลับไปที่ state ที่ control = 1 (phase kickback) · พอยิง 2 ครั้งจาก p กับ q จะได้ phase = (−1)p ⊕ q

ในวงจรนี้ p = noteA (= A OR B) และ q = สาย A (ซึ่งตอนนี้เก็บ NOT A อยู่) · ลองคำนวณเอง:

หลัง CNOT 2 ตัว (ยังไม่ทำ X บน scratch) ค่าไหนของ boxes ที่มี phase ต่างจากอีก 3 ค่า? (ค่า = A + 2B · ใบ้: ใช้คอลัมน์ป้าย A กับป้าย B จากตาราง 1.3)
ถูกค่ะ |2⟩ มีป้าย A = 1 และป้าย B = 1 → 1 ⊕ 1 = 0 → phase ไม่ถูกพลิก · อีก 3 ค่าป้ายไม่ตรงกัน (⊕ = 1) → ถูกพลิกเป็น 180° · คำตอบที่ถูกคือตัวเดียวที่ไม่ถูกพลิก
ลองใหม่ค่ะ คำนวณ (ป้าย A) ⊕ (ป้าย B) ทีละแถว · ⊕ = 1 แปลว่าถูกพลิก · หาแถวที่ ⊕ = 0 ซึ่งมีแถวเดียว

แถวบน = phase XOR (พลิกตัวที่ป้ายไม่ตรงกัน) · แถวล่าง = phase XNOR (พลิกตัวที่ satisfy)

X ตัวที่ 3 บน scratch ทำอะไร? X บน |−⟩ ได้ −|−⟩ (X สลับ |0⟩ กับ |1⟩ ใน (|0⟩ − |1⟩)/√2 ได้ (|1⟩ − |0⟩)/√2) · คือคูณ −1 ให้ทั้งรีจิสเตอร์ ทุกวงหมุน 180° พร้อมกัน → จาก "XOR" กลายเป็น "XNOR" · แต่เดี๋ยวก่อน การคูณ −1 ทั้งรีจิสเตอร์คือ global phase ซึ่งวัดไม่ได้ · สองรูปข้างบนจึงเป็นสถานะเดียวกันทางฟิสิกส์ (คาโฮะเช็คกับ numpy แล้ว: วงจรเต็มได้ |2⟩ = −0.5 และตัวอื่น = +0.5 ตรงกับรูปขวา)

ข้อสังเกตของสไลด์ p36: mirror ขยายค่าที่ phase ต่างจากตัวอื่น ไม่จำเป็นต้องเป็นค่าที่ phase ลบ · สไลด์บอกว่า "ในกรณีนี้คำตอบที่ถูกมี phase บวก ส่วนตัวที่ผิดมี phase ลบ" ซึ่งก็คือรูปซ้าย · ไม่ว่าจะเป็นรูปซ้ายหรือรูปขวา mirror ก็ได้ผลเหมือนกัน เพราะ flip ที่มีผลคือ flip สัมพัทธ์ (relative) ไม่ใช่ global
โค้ด p33 เตรียม scratch ด้วย anc.not(); anc.hadamard(); · scratch จะอยู่ในสถานะอะไร?
ถูกค่ะ X|0⟩ = |1⟩ แล้ว H|1⟩ = (|0⟩ − |1⟩)/√2 = |−⟩ · และต้องเป็น |−⟩ ด้วย ถึงจะเกิด kickback · ถ้าเป็น |+⟩ CNOT จะไม่ทำอะไรกับ phase เลย

2.4 โค้ด QCEngine (p32–34)

qc.reset(4);
var boxes = qint.new(2, 'boxes');
var noteA = qint.new(1, 'noteA');
var anc   = qint.new(1, 'anc');
qc.write(0);
boxes.hadamard();              // ทั้ง 4 แบบพร้อมกัน
// noteA = A OR B   (magnitude)
qc.not(0x1|0x2);
qc.cnot(0x4, 0x1|0x2)          // Toffoli: target 0x4, control A,B
qc.not(0x1|0x2|0x4);
// NOT A            (magnitude, เขียนทับสาย A)
qc.not(0x1);
anc.not(); anc.hadamard();     // scratch → |−⟩  (คอมเมนต์ในสไลด์เขียน |+>)
// (A OR B) XNOR (NOT A)   (phase)
qc.cnot(0x8, 0x4);             // kickback จาก noteA
qc.cnot(0x8, 0x1);             // kickback จากสาย A (= NOT A)
qc.not(0x8);                   // XOR → XNOR (−1 ทั้งรีจิสเตอร์)
anc.hadamard(); anc.not();     // คืน scratch เป็น |0⟩
// uncompute (ย้อนลำดับ)
qc.not(0x1);
qc.nop();                      // = คอลัมน์ว่างในรูป
qc.not(0x1|0x2|0x4);
qc.cnot(0x4, 0x1|0x2)
qc.not(0x1|0x2);
boxes.Grover();                // mirror
var result = boxes.read();
var catA = result & 1 ? 'kitten' : 'tiger';
var catB = result & 2 ? 'kitten' : 'tiger';

จำรูปแบบ qc.cnot(target, control) ของ QCEngine: target มาก่อน · ส่วน result & 1 ดูบิตของกล่อง A และ result & 2 ดูบิตของกล่อง B (1 = kitten)

2.5 ทำไมต้อง uncompute ก่อนเข้า mirror

ระหว่างที่คำนวณ noteA ผูกกับ boxes (entangle) และสาย A ก็ถูกเปลี่ยนเป็น NOT A อยู่ · mirror ทำงานบน boxes 2 สายเท่านั้น ถ้า noteA ยังเก็บค่าที่ต่างกันในแต่ละแถว วงทั้ง 4 ของ boxes จะไม่ interfere กันครบ (บท 0021b) · uncompute จึงคืน noteA เป็น 0 และสาย A เป็นค่าเดิม เหลือไว้แค่ −1 ที่ติดอยู่กับ |2⟩ ซึ่งเป็นสิ่งเดียวที่เราต้องการ

2.6 mirror 1 รอบ → 100%

ก่อน mirror: 4 วงขนาดเท่ากัน (amplitude 0.5) และ |2⟩ ถูกพลิก · mirror = สะท้อนรอบค่าเฉลี่ย (บท 0026):

|0⟩ |1⟩ |3⟩ 2 × 0.25 − 0.5 = 0
|2⟩ 2 × 0.25 − (−0.5) = 1 → ความน่าจะเป็น 1² = 100%

จำนวนรอบเช็คได้ด้วยสูตรจากบท 0024: NAA = ⌊(π/4)·√(2ⁿ/m)⌋ = ⌊(π/4)·√(4/1)⌋ = ⌊1.57⌋ = 1 รอบ (p36) · และ 4 ค่ากับคำตอบ 1 ตัว เป็นกรณีพิเศษที่ 1 รอบได้ 100% พอดี

สรุปผล (p35): รันโปรแกรม QPU ครั้งเดียว อ่านได้ A = 0 (เสือ) · B = 1 (ลูกแมว) ด้วยความน่าจะเป็น 100% → เปิดกล่อง B 🐱 · phase logic ทำหน้าที่เป็น flip ใน AA iteration จึงต้องตามด้วย mirror เดิม · ทั้งหมดนี้คือ Quantum Search ที่ครบวงจร: H → compute → phase logic → uncompute → mirror → READ
