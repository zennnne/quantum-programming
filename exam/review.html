Qubit เดี่ยว & Bloch sphere

1. bit vs qubit · bra-ket

บิตคลาสสิกเป็นได้แค่ 0 หรือ 1 · qubit เก็บ ส่วนผสม ของทั้งสองไว้ เขียนด้วย bra-ket ว่า ∣0⟩ กับ ∣1⟩ (ket = เวกเตอร์สถานะ)

∣ψ⟩ = a∣0⟩ + b∣1⟩  ·  ∣a∣² + ∣b∣² = 1

misconception อันดับ 1

“superposition (การซ้อนทับ) = เป็น 0 และ 1 พร้อมกัน อ่านได้ทั้งคู่” → ผิด
มันคือ “ส่วนผสมที่ยังไม่มีคำตอบ” เหมือนเหรียญที่กำลังหมุนอยู่ ไม่ใช่เหรียญที่มีสองหน้าให้หยิบ — และเมื่ออ่าน (READ) qubit 1 ตัว ได้ออกมาแค่ 1 บิตธรรมดา เท่านั้น qubit จึงไม่ใช่ “ที่เก็บข้อมูล 2 เท่าฟรี”

2. amplitude = magnitude + relative phase

ค่า a, b เรียกว่า amplitude เป็นจำนวนเชิงซ้อน จึงมี 2 ลูกบิด ต่อหนึ่งวง

ลูกบิดความหมายเชิงภาพอ่าน (READ) แล้วเห็นไหม
magnitude (ขนาด ∣a∣) ความยาวเข็ม / ขนาดวงในของ circle notation เห็น — โอกาสวัดได้ = ∣a∣²
relative phase (เฟสสัมพัทธ์ θ) ทิศของเข็ม (หมุน) — ไม่เปลี่ยนความยาว ไม่เห็นตอนวัดครั้งเดียว แต่เผยตัวตอน interference (การแทรกสอด)
refresher จำนวนเชิงซ้อน

เขียนได้ 2 แบบ: a + bi (พิกัดฉาก) หรือ r·e^(iθ) (พิกัดเชิงขั้ว) — แบบหลังคือแบบที่ตรงกับเข็มนาฬิกา: r = ความยาวเข็ม (magnitude) · θ = ทิศเข็ม (phase)
ที่ต้องใช้จริงมีแค่: ∣r·e^(iθ)∣² = r² → phase ไม่กระทบโอกาสวัด

global vs relative

หมุนทุกวงด้วยมุมเท่ากัน = global phase → วัดผลอย่างไรก็เหมือนเดิม ไม่มีความหมาย
หมุนบางวงเทียบกับวงอื่น = relative phase → มีความหมาย นี่คือเหตุผลที่ PHASE หมุนแค่วง ∣1⟩ ก็พอ

3. circle notation

1 วง = 1 สถานะฐาน · ในวงมีวงในสีทึบกับเข็มหนึ่งอัน — กติกาที่ออกสอบมี 3 ข้อ

  1. รัศมีวงใน = magnitude · พื้นที่วงใน = ความน่าจะเป็น (∣a∣²) — จำเป็น “พื้นที่” ไม่ใช่ “รัศมี”
  2. ทิศเข็ม = phase · มุมบวก = ทวนเข็มนาฬิกา (convention ของวิชานี้)
  3. normalization: พื้นที่ของทุกวงรวมกัน = 1 เสมอ

4. NOT (X) และ HAD (H)

NOT / X — สลับวง ∣0⟩ ↔ ∣1⟩ (สลับทั้งขนาดและเข็ม) · เป็น its own inverse (NOT·NOT = ไม่ทำอะไร)

HAD / H — สร้าง superposition 50/50 จาก ∣0⟩ หรือ ∣1⟩ และเป็น its own inverse เหมือนกัน

H∣0⟩ = (∣0⟩ + ∣1⟩)/√2  ·  H∣1⟩ = (∣0⟩ − ∣1⟩)/√2

ทำไม H∣1⟩ ต้องมีเครื่องหมายลบ — 3 เหตุผล

1. orthogonality (ความตั้งฉาก) — ∣0⟩ กับ ∣1⟩ ตั้งฉากกัน ผลลัพธ์ H∣0⟩ กับ H∣1⟩ ก็ต้องตั้งฉากกันด้วย ลอง inner product: (1·1 + 1·(−1))/2 = 0 ✓ ถ้าเป็นบวกทั้งคู่จะไม่ตั้งฉาก

2. reversibility (ย้อนกลับได้) — ถ้า H∣0⟩ กับ H∣1⟩ ให้ผลเหมือนกันเป๊ะ ก็ย้อนกลับไม่ได้ว่ามาจากอะไร เครื่องหมายลบคือสิ่งเดียวที่แยกสองเส้นทางนี้ออกจากกัน

3. interference — พอ H อีกที เทอมบวกกับเทอมลบหักล้างกัน (destructive) เหลือ ∣0⟩ ตัวเดียว → นี่คือเหตุผลที่ H·H = ไม่ทำอะไร

ทั้งสามเรื่องนี้คือ “เครื่องหมายลบ = เข็มชี้ลง = −1 ในเวกเตอร์ = relative phase 180°” สิ่งเดียวกัน เล่า 3 ภาษา

5. READ และ WRITE

คำสั่งทำอะไรย้อนกลับได้ไหม
READ วัด → สุ่มยุบเหลือ 0 หรือ 1 ตามความน่าจะเป็น · ลบ phase ทิ้งทั้งหมด ไม่ได้ — คำสั่งเดียวในวิชานี้ที่ irreversible (และเป็นตัวเดียวที่สุ่ม)
WRITE ตั้งค่า qubit ให้เป็น ∣0⟩ หรือ ∣1⟩ แบบแน่นอน — ตั้งเป็น superposition ไม่ได้ ไม่ได้ เพราะสร้างจาก READ
WRITE สร้างจาก READ + NOT

WRITE ไม่ใช่คำสั่งพื้นฐานจริงๆ — วิธีทำคือ READ ก่อน (บังคับให้เป็น 0 หรือ 1 แน่ๆ) แล้วถ้าได้ค่าไม่ตรงที่ต้องการ ค่อย NOT · ที่ WRITE ย้อนกลับไม่ได้ก็เพราะข้างในมี READ อยู่นี่เอง

6. QRNG — โปรแกรมควอนตัมตัวแรก → ดูโค้ด

วงจรสั้นที่สุดที่มีประโยชน์จริง: WRITE(0) → HAD → READ ได้บิตสุ่มแท้ 1 บิต (ทำ 8 สายขนานกันก็ได้ random byte)

7. PHASE(θ)

หมุนเข็มเฉพาะวง ∣1⟩ ไป θ องศา (ทวนเข็ม = บวก) · ไม่มีผลกับ ∣0⟩ เลย และไม่เปลี่ยนโอกาสวัด เพราะขนาดวงเท่าเดิม

counter-example ที่ต้องจำ

PHASE เป็น reversible แต่ไม่ใช่ its own inverse — PHASE(45°) สองที = PHASE(90°) ไม่ใช่กลับที่เดิม ต้องย้อนด้วย PHASE(−θ)
ข้อยกเว้น: PHASE(180°) = Z ตัวนี้ its own inverse (เพราะ 180+180 = 360 = ครบรอบ)

สถานะที่มีชื่อ 4 ตัว สร้างจาก HAD แล้วต่อ PHASE: ∣+⟩ (0°) · ∣−⟩ (180°) · ∣+Y⟩ (+90°, เข็มชี้ซ้าย) · ∣−Y⟩ (−90°, เข็มชี้ขวา)

8. no-cloning — คำสั่งที่หายไป

the missing operation

COPY ไม่มีในโลกควอนตัม — ก๊อป qubit ที่เราไม่รู้ค่าของมันไม่ได้เลย (จะรู้ค่าต้อง READ ซึ่งทำลาย state ไปแล้ว)

ผลที่ตามมาซึ่งจะเจอทั้งวิชา: ทำ backup state ไว้กันพลาดไม่ได้ · teleportation (Lec04) จึงเป็นการ “ย้าย” ไม่ใช่ “ก๊อป” ต้นทางต้องเสียไป · และข้อจำกัดนี้กลับกลายเป็นอาวุธของ QKD คือถ้ามีสปายมาดักอ่าน จะทิ้งร่องรอยไว้เสมอ

ทำ PHASE(90°) ต่อกัน 2 ครั้งบน ∣+⟩ แล้วอ่านผล จะได้อะไร
ถูกต้อง — PHASE บวกมุมสะสม และไม่แตะขนาดวงเลย โอกาสจึงไม่ขยับ
ยังไม่ใช่ — PHASE ไม่ใช่ its own inverse (มุมสะสมเป็น 180°) และ phase ไม่เคยเปลี่ยนโอกาสวัด
คำสั่งใดใน Lec02 ที่ ย้อนกลับไม่ได้ และลบ phase ทิ้ง
ถูกต้อง — READ เป็น op เดียวที่ irreversible และเป็นตัวเดียวที่สุ่มด้วย
ยังไม่ใช่ — HAD กับ PHASE ย้อนกลับได้ทั้งคู่ (H ด้วย H เอง, PHASE ด้วย PHASE(−θ))

9. เมทริกซ์ของ gate — X = HZH และ Z = HXH

gate 1 qubit ทุกตัวเขียนเป็นเมทริกซ์ 2×2 ได้ · การ “ต่อ gate” = การคูณเมทริกซ์ โดยตัวที่ทำก่อนอยู่ขวาสุด (อ่านวงจรซ้าย→ขวา แต่เขียนสูตรขวา→ซ้าย)

H = 1√2 111−1  ·  Z = 100−1  ·  X = 0110

X = H Z H — คูณคู่ในสุดก่อน
1) Z·H = 100−1 · 1√2 111−1 = 1√2 11−11 (แถวล่างโดน −1 คูณ → สลับเครื่องหมายทั้งแถว)
2) H·(ZH) = 12 111−1 · 11−11 = 12 1−11+11+11−1 = 12 0220
3) ดึง ½ เข้าไป = 0110 = X ✔
Z = H X H — สลับที่ H กับ Z ก็ได้อีกสมการ (สไลด์ p86–90)
1) X·H = 0110 · 1√2 111−1 = 1√2 1−111 (X = สลับสองแถว)
2) H·(XH) = 12 111−1 · 1−111 = 12 1+1−1+11−1−1−1 = 12 200−2
3) ดึง ½ เข้าไป = 100−1 = Z ✔
อ่านเป็นภาษาคน — ไม่ต้องท่องเมทริกซ์

H คือตัวสลับมุมมองระหว่างแกน X กับแกน Z (ดูข้อ 11) · เอา H ประกบหน้า-หลัง gate ตัวไหน gate นั้นจะเปลี่ยนไปทำงานบนอีกแกนหนึ่งทันที
ผลที่ใช้ได้จริง: QPU ที่ไม่มีปุ่ม NOT ก็ยังพลิกบิตได้ ด้วย had() → phase(180) → had()

10. RNOT (√NOT) — gate ที่โลกคลาสสิกไม่มีวันมี

“ครึ่งหนึ่งของการพลิกบิต” ไม่มีความหมายในโลกบิต แต่มีจริงในควอนตัม เพราะ qubit เดินผ่าน superposition ได้ · RNOT ทีเดียว = หยุดครึ่งทางระหว่าง ∣0⟩ กับ ∣1⟩ (50/50) · ทำสองที = NOT เต็มตัว

√NOT = 12 1+i1−i1−i1+i  ·  สัญลักษณ์วงจร = กล่อง √X

ตรวจว่า “ทำสองที = NOT” จริงไหม — กุญแจคือ i² = −1
1) ช่องบนซ้าย = ¼[(1+i)² + (1−i)²] · (1+i)² = 1+2i−1 = 2i · (1−i)² = 1−2i−1 = −2i → รวม = 0
2) ช่องบนขวา = ¼[(1+i)(1−i) + (1−i)(1+i)] = ¼[2 + 2] = 1
3) เมทริกซ์สมมาตร → ช่องล่างได้ 1 กับ 0 เหมือนกัน → 0110 = NOT ✔
RNOT = H · PHASE(90°) · H — หน้าตาเดียวกับ X = HZH เป๊ะ แค่เปลี่ยน 180° เป็น 90°
1) P(90)·H = 100i · 1√2 111−1 = 1√2 11i−i
2) H·(P(90)H) = 12 111−1 · 11i−i = 12 1+i1−i1−i1+i = √NOT ✔

11. Bloch sphere — qubit ทั้งตัวในลูกศรอันเดียว

หัวข้อนี้เขียนยาวกว่าข้ออื่นตั้งใจ เพราะเป็นจุดที่งงกันมากที่สุดของคาบนี้ — อ่านช้าๆ ทีละหัวข้อย่อยได้เลย

ทำไมต้องมีเครื่องมือนี้อีกอัน? circle notation เก่งตอนมีหลาย qubit (2ᴺ วง) แต่ตอนมี qubit เดียว มันเปลืองพื้นที่ไปหน่อย — เพราะ qubit เดียวมีลูกบิดจริงๆ แค่ 2 ตัว ของอย่างนี้วาดเป็นจุดบนทรงกลม ได้พอดี (ลูกโลกก็ใช้ 2 ตัวเลข: ละติจูด + ลองจิจูด)

ทำไม state อยู่บน “ผิว” ทรงกลม ไม่ใช่ข้างใน

เริ่มจาก ∣ψ⟩ = a∣0⟩ + b∣1⟩ → a, b เป็นจำนวนเชิงซ้อน = 4 ตัวเลขอิสระ แล้วโดนหักออก 2 ข้อ:

1. normalization ∣a∣² + ∣b∣² = 1 บังคับอยู่แล้ว → หายไป 1 ตัว
2. global phase ไม่มีความหมาย (ข้อ 2) → หมุนทั้งคู่พร้อมกันเท่าไรก็เป็น state เดิม → หายไปอีก 1 ตัว

เหลือ 2 ตัวเลข พอดี = θ (ความสูง) + φ (ลองจิจูด) ซึ่งก็คือผิวของทรงกลมเป๊ะๆ — ไม่มี “ระยะจากจุดศูนย์กลาง” ให้เล่นเลย เพราะ normalization ล็อกความยาวลูกศรไว้ที่ 1 ตลอด
(จุดข้างในทรงกลมมีความหมายจริง เรียก mixed state แต่ไม่อยู่ในขอบเขตวิชานี้)

∣ψ⟩ = cos(θ/2)∣0⟩ + eiφ sin(θ/2)∣1⟩

11.2 gate = การหมุน (นี่คือหัวใจ)

บนทรงกลม gate ทุกตัวของ 1 qubit คือ “หมุนลูกศรรอบแกนหนึ่ง เป็นมุมหนึ่ง” เท่านั้นเอง · ทิศบวก = ทวนเข็มนาฬิกาเมื่อมองจากปลายแกนบวกย้อนลงมา (กฎมือขวา)

gateหมุนรอบแกนโอกาสวัดเปลี่ยนไหมอุปมามือ (สไลด์ p72)
ROTX(θ) แกน X (นอน) เปลี่ยน — ลูกศรไต่ขึ้นลงระหว่างขั้ว เอียงมือ ไปหน้า / มาหลัง
ROTY(θ) แกน Y (นอน) เปลี่ยน เอียงมือ ซ้าย / ขวา
PHASE(θ) = ROTZ(θ) แกน Z (ตั้ง) ไม่เปลี่ยน — ลูกศรอยู่ละติจูดเดิมตลอด หมุนมือ รอบตัวเอง (มืออยู่ที่เดิม แค่หันคนละทาง)
X (NOT) แกน X · 180° เปลี่ยน — ∣0⟩ ↔ ∣1⟩ (พลิกขั้ว) ตีลังกาหน้า-หลังครึ่งรอบ
Z = PHASE(180°) แกน Z · 180° ไม่เปลี่ยน — ∣+⟩ ↔ ∣−⟩ หมุนรอบตัวเองครึ่งรอบ
HAD แกนเฉียง (X+Z)/√2 · 180° เปลี่ยน — ∣0⟩ ↔ ∣+⟩ , ∣1⟩ ↔ ∣−⟩ สลับแกน X ↔ Z เข้าหากัน
RNOT (√X) แกน X · 90° (ครึ่งทางของ NOT) เปลี่ยน — ∣0⟩ → เส้นศูนย์สูตร (50/50) ตีลังกาแค่ครึ่งของครึ่งรอบ

เห็นด้วยตาว่าทำไม PHASE ไม่เปลี่ยนโอกาสวัด

แกน Z คือแกนตั้ง หมุนรอบมันแล้วลูกศรอยู่ละติจูดเดิมเสมอ — สูงเท่าเดิม = θ เท่าเดิม = magnitude เท่าเดิม = โอกาสวัดเท่าเดิม เปลี่ยนแค่ “หันไปทางไหน” (φ)
ส่วน ROTX / ROTY หมุนรอบแกนนอน ลูกศรเลยไต่ขึ้นลงระหว่างสองขั้ว → θ เปลี่ยน → โอกาสเปลี่ยน
⇒ กลุ่มที่เปลี่ยนโอกาสวัดได้: HAD · NOT · ROTX · ROTY · กลุ่มที่ไม่เปลี่ยน: PHASE / ROTZ

ทำไม H ถึงสลับ X กับ Z ได้ (ย้อนไปข้อ 9)

HAD คือการหมุน 180° รอบแกนเฉียงที่อยู่กึ่งกลางระหว่างแกน X กับแกน Z พอดี ผลของมันคือสลับแกน X ↔ Z · เพราะงั้น “หมุนรอบ Z” (= Z gate) เมื่อเอา H ประกบหน้า-หลัง ก็กลายเป็น “หมุนรอบ X” (= X gate) เป๊ะ → X = HZH โดยไม่ต้องท่องเมทริกซ์เลย

เพื่อให้วงจรกับ circle notation ตรงกันโดยไม่ต้องแปลง — เห็น 0x2 บนวงจร ก็เปิดตารางไบนารีดูคอลัมน์ 0x2 ได้ทันทีว่ากระทบวงไหน ถ้าตั้งชื่อ Q1/Q2/Q3 ต้องมานั่งจำอีกชั้นว่า Q2 คือน้ำหนักเท่าไร (แล้วมักสลับ)

operator pairs — gate 1 qubit ทำงานใน register ยังไง

gate 1 qubit ที่ยิงใส่ register ไม่ได้แตะทีละวง แต่แตะทีละ คู่: จับวงที่ index ต่างกันเท่าน้ำหนักบิตของ qubit ที่ยิง มาเข้าคู่กัน — 8 วง → ได้ 4 คู่เสมอ

ยิงที่คู่ของวงในตารางไบนารี

ทริกไบนารี

อย่าไล่จับคู่ทีละวง ให้มองเป็นคอลัมน์: NOT = flip คอลัมน์นั้นทั้งคอลัมน์ (0↔1 ทุกแถว) แล้วดูว่าแต่ละแถวเลื่อนไปเป็นเลขอะไร · PHASE = เลือกเฉพาะแถวที่คอลัมน์นั้นเป็น 1 · READ = แบ่งตารางเป็นสองฝั่งตามคอลัมน์นั้น

worked example — state ตั้งต้นชุดเดียว ใช้ทั้ง 3 แบบ

สมมติ register 3 qubit อยู่ที่ |1⟩, |2⟩, |4⟩, |7⟩ อย่างละ 25% (วงเท่ากัน 4 วง เข็มชี้ขึ้นหมด):

(ก) NOT ที่ 0x1 — สลับของในแต่ละคู่

คู่ของ 0x1 = (0,1) (2,3) (4,5) (6,7) → ของในวง สลับที่กัน ทั้งขนาดและเข็ม ในตารางไบนารีคือ flip คอลัมน์ 0x1: 1→0, 2→3, 4→5, 7→6 → ดูโค้ด

จำคู่กันไว้

NOT ขยับของ (วงย้ายที่) แต่ PHASE ไม่ขยับของ (วงอยู่ที่เดิม หมุนแค่เข็ม) → ความน่าจะเป็นของทุกผลลัพธ์หลัง PHASE ยังเท่าเดิมเป๊ะ

(ข) PHASE(45°) ที่ 0x2 — หมุนเข็มของ "ฝั่งขวา" ของทุกคู่

คู่ของ 0x2 = (0,2) (1,3) (4,6) (5,7) — สมาชิกที่ index มากกว่าในแต่ละคู่คือตัวที่บิต 0x2 = 1 กลุ่มนั้นคือ |2⟩ |3⟩ |6⟩ |7⟩ ได้เข็มหมุน 45° ทวนเข็ม ที่เหลือไม่แตะ → ดูโค้ด

ทำไม PHASE แตะครึ่งหนึ่ง "เสมอ"

เพราะทุกวงถูกจับคู่หมด และในทุกคู่มีตัวที่บิตนั้นเป็น 1 อยู่ ตัวเดียว → กลุ่ม "บิตนั้น = 1" มี 2ᴺ⁄2 วง = ครึ่งพอดี ไม่ว่ายิงที่ qubit ไหนหรือ register ใหญ่แค่ไหน (ที่ 3 qubit ก็คือ 4 จาก 8 วง แม้บางวงจะว่างอยู่ก็ถือว่าถูกแตะ)

(ค) READ ที่ 0x4 — ตัดครึ่งที่ขัดกับผล แล้ว renormalize

READ ไม่ได้ทำทีละคู่แบบ NOT/PHASE แต่ใช้การแบ่งกลุ่มชุดเดียวกัน: ฝั่ง 0x4 = 0 คือ |0⟩–|3⟩ · ฝั่ง 0x4 = 1 คือ |4⟩–|7⟩ → ดูโค้ด

1 P(อ่านได้ 0) = ผลรวมพื้นที่ฝั่ง 0x4=0 = |1⟩ 25% + |2⟩ 25% = 50%
2 P(อ่านได้ 1) = |4⟩ 25% + |7⟩ 25% = 50%
3 สมมติอ่านได้ 1 → วงฝั่ง 0x4=0 (|0⟩–|3⟩) หายหมด
4 renormalize: ที่เหลือรวมได้ 50% ต้องดันกลับเป็น 100% → หารด้วย 0.5 ทุกวง → |4⟩ 50%, |7⟩ 50%

ส่วนที่ 6

CNOT — gate ตัวแรกที่ทำให้ qubit "รู้จักกัน"

gate ที่ผ่านมาทั้งหมดทำเหมือนกันทุกคู่ ในตารางไบนารี จึงสร้างความสัมพันธ์ระหว่าง qubit ไม่ได้เลย — multi-qubit operation คือคำตอบ และตัวแรกคือ CNOT = ถ้า control เป็น 1 ค่อย NOT ที่ target

ระวัง

● ไม่จำเป็นต้องอยู่เส้นบนเสมอ — สไลด์ Lec03 หน้า 41–42 วาง target ไว้เส้นบน (0x1) และ control ไว้เส้นล่าง (0x2) ให้ดูที่รูปสัญลักษณ์ (● หรือ ⊕) ไม่ใช่ตำแหน่งสูงต่ำ · และถ้าไม่มีเส้นตั้ง = ไม่ใช่ CNOT (เป็น NOT สองตัวแยกกัน)

CNOT ในภาษา operator pairs

ใช้ภาษาชุดเดิมจากส่วนที่ 4 ได้เลย — คู่มาจาก target · เงื่อนไขมาจาก control: CNOT ที่ target 0x1 / control 0x2 ก็ยังจับคู่แบบ NOT 0x1 คือ (0,1) (2,3) (4,5) (6,7) แต่สลับจริงเฉพาะคู่ที่บิต 0x2 = 1 เหลือแค่ (2,3) และ (6,7)

gateคู่ที่จับสลับจริงกี่คู่สัดส่วนที่โดน
NOT 0x1 (0,1) (2,3) (4,5) (6,7) 4 คู่ (ทุกคู่) ทั้งหมด
CNOT (target 0x1, control 0x2) (0,1) (2,3) (4,5) (6,7) 2 คู่ — (2,3) (6,7) ครึ่งหนึ่ง
CCNOT (target 0x1, control 0x2+0x4) (0,1) (2,3) (4,5) (6,7) 1 คู่ — (6,7) หนึ่งในสี่
เติม control 1 ตัว → คู่ที่โดนผลลดลงครึ่งหนึ่ง · control k ตัว = 1/2k+1 ของทั้งหมด

CNOT เป็น inverse ของตัวเอง — ยิงสองครั้งติดกันเท่ากับไม่ได้ทำอะไร (สลับแล้วสลับกลับ)

control อยู่ใน superposition → เกิด Bell pair → ดูโค้ด

ถ้า control เป็น 0 หรือ 1 ชัดเจน CNOT ก็แค่ทำ/ไม่ทำ NOT — ธรรมดามาก แต่ถ้า control อยู่ใน superposition (โดนย้อม HAD มาก่อน) CNOT จะทำ "ทำ" กับ "ไม่ทำ" พร้อมกัน ผลคือ Bell pair

แกนของมัน

เหลือแค่ |0⟩ (= 00) กับ |3⟩ (= 11) อย่างละ 50% → อ่านได้ 00 หรือ 11 เท่านั้น ไม่มีทางได้ 01 หรือ 10 แต่ละตัวยังสุ่ม 50/50 อยู่ · ความสัมพันธ์ต่างหากที่ถูกล็อกไว้ นี่คือ entanglement (ความพัวพัน)

อย่าจำผิด

CNOT ไม่ใช่ "ตัวสร้าง entanglement" โดยอัตโนมัติ — ถ้าลบ HAD ทิ้ง (control เป็น 0 ชัดเจน) ผลจะได้ 00 ทุกรอบ ไม่พัวพันเลย · ตัวที่ทำให้เกิด entanglement คือ HAD + CNOT ร่วมกัน

Bell's theorem — โครง 4 ขั้นที่ต้องเล่าได้

ผลการทดลอง: อ่าน qubit สองตัวที่พัวพันกัน ได้ผลตรงกันทุกรอบ ไม่ว่าจะแยกกันไกลแค่ไหน คำถามคือ "ทำไม" — และคำอธิบายแบบคลาสสิกมี 2 แบบเท่านั้น

ขั้น 1 · คำอธิบายแบบคลาสสิก 2 แบบ

คำอธิบายใจความอุปมา
สาเหตุร่วม (common cause) คำตอบถูกเขียนลงไปตั้งแต่ตอนสร้างคู่แล้ว เราแค่ยังไม่เปิดดู — คือมี local hidden variables (ตัวแปรซ่อนเฉพาะที่) ถุงมือคู่หนึ่ง แยกใส่กล่องส่งไปคนละทวีป เปิดเจอข้างซ้าย = อีกกล่องข้างขวาแน่
การสื่อสาร (communication) ตอนอ่านตัวแรก มันส่งสัญญาณไปบอกอีกตัวว่าให้ตอบอะไร โทรศัพท์ลับระหว่างสองกล่อง

ขั้น 2 · ทำไมทั้งคู่ไม่พอ

ทั้งสองคำอธิบายทำนายผลได้เหมือนกันหมดถ้าวัดแบบเดิมทุกรอบ — แต่พอเปลี่ยนมุมที่ใช้วัด สองภาพนี้ให้ทำนายที่ต่างกัน จึงเถียงกันด้วยการทดลองได้จริง ไม่ใช่แค่ปรัชญา

ขั้น 3 · Bell inequality

John Bell เขียนอสมการที่ทฤษฎีคลาสสิกแบบ local hidden variables ทุกแบบต้องเคารพ (เป็นเพดานของค่าความสัมพันธ์ที่เป็นไปได้) — แล้วชี้ว่าควอนตัมทำนายค่าที่เกินเพดานนั้น · ผลการทดลองจริง ละเมิดอสมการ ตามที่ควอนตัมทำนาย

ขั้น 4 · สรุป

  • ตัดคำอธิบายแบบ local hidden variables ทิ้ง → ธรรมชาติเป็นควอนตัมจริงๆ ไม่ใช่คลาสสิกที่เราแค่ไม่รู้ค่า
  • entanglement เป็นทรัพยากร — เป็นของที่หยิบไปใช้ทำงานได้ (Lec04 teleportation ใช้ตัวนี้เต็มๆ)
กับดักอันดับ 1 ของหัวข้อนี้

ละเมิด Bell inequality ≠ ส่งข้อมูลเร็วกว่าแสงได้ (สไลด์หน้า 58 เขียนไว้ชัด) เพราะเราเลือกผลของตัวเองไม่ได้ — ผลที่อ่านออกมาสุ่ม 50/50 เสมอ สิ่งที่แชร์กันจึงเป็นแค่ shared randomness (ความสุ่มชุดเดียวกัน) ไม่ใช่ช่องทางส่งข้อความ

CPHASE / CZ — เงื่อนไขบน PHASE

เอา PHASE (ส่วนที่ 4) มาผสมกับแนวคิด "เงื่อนไข" (ส่วนที่ 6) ตรงๆ ไม่มีของใหม่จากอากาศ: CPHASE(θ) = หมุนเข็มเฉพาะค่าที่ทั้งสอง qubit เป็น 1 พร้อมกัน

← เลื่อนดูได้

หัวใจของหัวข้อนี้

CPHASE / CZ สมมาตร — สลับว่าใครเป็น control ใครเป็น target แล้วผลเหมือนเดิมเป๊ะ เพราะเงื่อนไข "ทั้งคู่เป็น 1" ไม่แยกแยะว่าใครเป็นใคร นี่คือเหตุผลที่สัญลักษณ์เป็น φ—φ และ ●—● (สองข้างหน้าตาเหมือนกัน) ต่างจาก CNOT ที่ ●—⊕ คนละรูป

เงื่อนไข = ตัวกรอง

อย่ามอง control ว่า "สั่งให้ทำ" ให้มองว่ามันกรองวงออกไปครึ่งหนึ่ง: PHASE แตะครึ่งหนึ่ง (4 วงจาก 8) → CPHASE เติมเงื่อนไขอีกชั้น เหลือ 1/4 (2 วง) → control k ตัว เหลือ 1/2k+1 · ตัว gate ไม่เปลี่ยน เปลี่ยนแค่ว่า "แตะใครบ้าง"

ในภาษาเมทริกซ์ CZ = diag(1, 1, 1, −1) — แตะเฉพาะช่อง |11⟩ ช่องเดียว

ส่วนที่ 9 · จุดที่คนพลาดเยอะ

Phase kickback

เอา CPHASE ใส่เข้าไปโดยตั้งใจจะไปหมุนเฟสของ register 2 แต่ผลที่โผล่ออกมาคือ เฟสไปเกาะที่ register 1 แทน — เฟสมัน "เด้งกลับ" (kickback) → ดูโค้ด

← เลื่อนดูได้

ทำไมถึงเป็นอย่างนั้น

ผูกกับส่วนที่ 8 ตรงๆ: CPHASE สมมาตร จะบอกว่า reg1 คุม reg2 หรือ reg2 คุม reg1 ก็ถูกทั้งคู่ · และ reg2 ถูกเซ็ตเป็น |1⟩ ตลอดเวลา เงื่อนไขฝั่ง reg2 จึงจริงเสมอ เหลือเงื่อนไขขึ้นกับ reg1 ตัวเดียว → เฟสไปเกาะ reg1 · เฟสสะสม = 0° / 45° / 90° / 135° ตามค่าของ reg1

🔴 จุดที่ออกสอบแล้วคนพลาด

phase kickback ไม่เกิด entanglement — สถานะสุดท้ายยัง separable (แยกเขียนทีละ register ได้) อยู่: reg1 เป็นของ reg1 · reg2 = |1⟩ นิ่งๆ แยกกันได้สนิท

บทเรียนที่ต้องจำ: ใช้ gate 2 qubit ≠ เกิด entanglement เสมอไป (สไลด์หน้า 84 พูดชัดว่านี่คือ "algorithmic power without entanglement")

เงื่อนไข 2 ข้อที่ทำให้ kickback สะอาด: ① reg2 ต้องเป็น |1⟩ ② reg2 ต้องไม่อยู่ใน superposition — ถ้าผิดข้อใดข้อหนึ่ง ผลจะปนกันและอาจพัวพันจริง · kickback เป็นเครื่องมือหลักของ QFT / QPE / Grover / Simon

Teleportation

ย้าย state (สถานะ) ของ qubit หนึ่งไปโผล่ที่อีก qubit หนึ่ง โดยไม่ได้ส่งตัว qubit ไปไหนเลย — ใช้ คู่ entangled 1 คู่ + บิตคลาสสิก 2 บิต เท่านั้น

แกนของบทนี้ — อ่าน 4 บรรทัดนี้ให้เข้าใจก่อน แล้วค่อยเดิน step
  1. CNOT+HAD ฝั่ง Alice = Bell measurement ถามว่า "ความสัมพันธ์ payload–ep เป็นแบบไหนใน 4 แบบ" ไม่ได้ถามว่า payload คืออะไร → ข้อมูลจึงไม่ถูกทำลาย แต่ถูกผลักไปที่ Bob
  2. HAD จำเป็นเพราะ CNOT อย่างเดียวแยก 4 แบบไม่ออก — ความต่างบางคู่ซ่อนอยู่ในเฟส ซึ่ง READ มองไม่เห็น (โยงกลับ Lec02) · HAD = ตัวแปลง "ความต่างเชิงเฟส → ความต่างที่อ่านได้"
  3. READ 2 บิต = สุ่มหยิบ 1 ใน 4 แบบ → qubit ของ Bob = payload ต้นฉบับที่ถูกบิดแบบใดแบบหนึ่ง
  4. 2 บิตคลาสสิก = ใบสั่งว่าบิดแบบไหน → Bob บิดกลับ → เหตุผลที่ไม่เร็วกว่าแสง

ทุกอย่างที่เหลือในหน้านี้คือรายละเอียดของ 4 บรรทัดนี้ ถ้าตอบข้อสอบไม่ได้ ให้ย้อนกลับมาอ่านตรงนี้

อ่านวงจรเป็น 5 กล่อง
  1. entangle — HAD บน ep แล้ว CNOT(ep→bob) = สร้าง Bell pair
  2. prep payload 45° — H → φ(45°) → H บน alice เท่านั้น (ในข้อสอบ payload เป็นอะไรก็ได้ ตัวนี้แค่ตัวอย่าง)

READ = เลือกคอลัมน์มา 1 คอลัมน์ วงนอกคอลัมน์ magnitude เป็นศูนย์หมด แล้ว normalize ใหม่ → กลับมาเป็น 85.4/14.6 เท่าเดิม แค่ สลับหัวท้าย (โดน NOT) และเข็มกลับด้าน (โดน PHASE 180°)

4 เดิน 5 step

Step 1 — สร้าง Bell pair · ep.had(); bob.cnot(ep); → ดูโค้ด
HAD+CNOT คู่นี้คือสูตรสร้าง Bell pair เดียวกับ Lec03 → ep กับ bob สุ่ม 50/50 แต่ตรงกันเสมอ

Step 2 — เตรียม payload · alice.write(0); alice.had(); alice.phase(45); alice.had();
ในงานจริง payload มาจากไหนก็ได้ (คำนวณมา / entangle กับส่วนอื่น) — บทนี้เลือก H–φ45–H เพราะได้ pattern ที่อ่านง่ายในวง

Step 3.1 — เชื่อม payload เข้ากับคู่ entangled · ep.cnot(alice); (control = alice, target = ep)
ในภาษาวง = สลับวงในคู่ที่ alice = 1 (|1⟩↔|3⟩ และ |5⟩↔|7⟩) · หลังจากนี้เหลือเฉพาะวงที่ XOR ของทั้งสามบิต = 0 (000, 011, 101, 110) → จาก entangle 2 ตัว กลายเป็น ก้อน entangled 3 ตัว

⚠️ ตรงนี้คนงงกันเยอะ อ่านช้าๆ

ถึงตรงนี้ payload ยังไม่ได้ย้ายไปไหน — CNOT แค่ผูกมันเข้ากับอีกสองตัว ส่วนที่ทำให้ข้อมูล "ไหล" ไปหา Bob จริงๆ คือ HAD ใน Step 3.2 ต่างหาก ถ้าอ่าน Step 3.2 แล้วยังไม่เข้าใจ ให้ย้อนกลับไปอ่าน "แกน 4 บรรทัด" ข้อ 1–2 อีกรอบก่อน แล้วค่อยกลับมา

Step 3.2 — HAD บน payload · alice.had(); ← หัวใจของทั้งบท

ทำไมต้อง HAD ก่อน READ

หลัง CNOT อย่างเดียว สถานะที่ Bob "อาจจะได้" มีอยู่ 4 แบบ แต่บางคู่ในนั้นต่างกันแค่เฟส — และ READ อ่านเฟสไม่เห็นเลย (Lec02: READ เห็นแค่ขนาดวง ไม่เห็นทิศเข็ม) ถ้า Alice READ ตอนนี้ เธอจะแยกไม่ออกว่าเป็นแบบไหน แล้วข้อมูล magnitude+phase ของ payload ก็หายไปเฉยๆ

HAD คือเครื่องแปลง "ความต่างเชิงเฟส → ความต่างที่อ่านได้" (interference: วงที่เฟสตรงกันเสริมกัน วงที่เฟสตรงข้ามหักล้างกัน) พอผ่าน HAD แล้ว ทั้ง 4 แบบไปอยู่คนละคอลัมน์ที่ READ แยกออก → 2 บิตของ Alice จึงมีความหมายจริง

อีกมุมหนึ่ง: CNOT + HAD + READ 2 ตัว = Bell measurement คือการถามว่า "payload กับ ep สัมพันธ์กันแบบไหนใน 4 แบบ" ไม่ใช่ถามว่า "payload คืออะไร" → คำถามที่ไม่แตะเนื้อของ payload ข้อมูลจึงไม่ถูกทำลาย แต่ถูกผลักข้ามไปที่ bob

Step 3.3 — READ ทั้งสองตัวของ Alice · bit_p = alice.read(); bit_n = ep.read();
ทำลาย qubit ทั้งสองอย่างถาวร — และต้องทำลาย ไม่งั้นก็เท่ากับ copy สถานะ (ผิด no-cloning) · ผลลัพธ์ = สุ่มเลือก 1 ใน 4 คอลัมน์ ได้ 2 บิตคลาสสิก พอดี

Step 4 — Bob รับ 2 บิตแล้วบิดกลับ · if (bit_n) {bob.not();} if (bit_p) {bob.phase(180);} → ดูโค้ด
ผลลัพธ์: bob กลับมาเป็น payload เดิมเป๊ะ — 85.4% |0⟩ + 14.6% |1⟩ ที่ phase −90°

Step 5 — verify · bob.had(); bob.phase(-45); bob.had(); check = bob.read(); → ดูโค้ด
วิธีตรวจ = ให้ Bob รัน ขั้นตอนเตรียม payload แบบย้อนกลับ ถ้า teleport ถูกต้องจริง qubit ต้องกลับไปเป็น |0⟩ เป๊ะ → check ต้องได้ 0 เสมอ (ในวงเหลือวงเดียวเต็มวง เข็มชี้ขึ้น) · ถ้าอ่านได้ 1 เมื่อไร = teleport พลาด
⚠️ ข้อจำกัด: ถ้า Bob ได้ของที่ "เกือบถูก" การ verify ก็มักรายงานว่าสำเร็จ → ต้องรันหลายรอบถึงจะมั่นใจ

  • alice คือตัวที่ผ่าน HAD ก่อน READ — และ HAD คือเครื่องแปลงเฟสให้อ่านได้ (แกนข้อ 2) ดังนั้นบิตของ alice คือผลของการถามว่า "เฟสของสองสายเดิมตรงกันหรือกลับด้าน" → alice = ช่องรายงาน phase-flip = คุม Z
  • ดูที่ตารางก็เห็น: แถวที่ ep = 1 คือสองแถวที่วงสลับที่ (bit-flip) · แถวที่ alice = 1 คือสองแถวที่เข็มกลับด้าน (phase-flip) — ไม่ปนกันเลย

เกร็ดที่ช่วยไม่ให้เครียด: ลำดับที่ Bob ทำ X ก่อนหรือ Z ก่อน ไม่มีผล เพราะ XZ กับ ZX ต่างกันแค่ global phase (−1) ซึ่งวัดไม่ได้ · แต่ "บิตไหนคุม gate ไหน" สลับไม่ได้เด็ดขาด

แกนของคาบนี้: เอาเลขคณิตแบบดิจิทัลมาทำบน qubit register ที่อยู่ใน superposition (การซ้อนทับ) โดยไม่ละเมิดกฎ 2 ข้อของ QPU — แล้วปิดท้ายด้วยการแปลง logic gate ดิจิทัลทั้ง 6 ตัวให้เป็นวงจรควอนตัม

กติกา 2 ข้อ ที่ทุกอย่างในคาบนี้ต้องเคารพ

① ก๊อป qubit ไม่ได้ (no-cloning) → operator = ใช้ assign ค่าจาก qubit หนึ่งไปอีก qubit หนึ่งไม่ได้ · QPU ย้าย qubit ได้ด้วย exchange/SWAP แต่ไม่มี QPU ตัวไหน implement คำสั่ง COPY

② ทุก operation ที่ไม่ใช่ READ ต้อง reversible (ย้อนกลับได้) — READ เป็น operation เดียวที่ irreversible · ถ้าใช้ READ เยอะเพื่อเลี่ยงข้อนี้ การคำนวณจะกลายเป็นคลาสสิกและเสีย quantum advantage ไปหมด

Quantum-Conditional Execution

คลาสสิก: CPU ต้องอ่านค่าก่อน แล้วค่อยตัดสินใจว่าจะรัน logic หรือไม่ · QPU: ค่าหนึ่งเป็นทั้งเซ็ตและไม่เซ็ตพร้อมกันได้ → operation ที่ขึ้นกับค่านั้นจึงทั้งรันและไม่รันพร้อมกันใน superposition — ใช้ได้ถึงระดับรัน digital logic ก้อนใหญ่แบบมีเงื่อนไข

ทริกที่ต้องจำ — b.not(~1)

ปัญหา: control (●) อ่านได้แค่ "บิตนี้เป็น 1" · แต่เงื่อนไข b == 1 คือ 01₂ ซึ่งมีเลข 0 ปนอยู่

ทริก: พลิกบิตที่ควรเป็น 0 ให้เป็น 1 ก่อน (b.not(~1) = พลิกทุกบิตยกเว้น 0x1) → เงื่อนไขกลายเป็น "ทุกบิตของ b เป็น 1" ใช้ทุกบิตเป็น control ได้เลย → ใช้เสร็จแล้วพลิกกลับคืน → ดูโค้ด

Phase-Encoded Results

Scratch qubit & abs(a)

abs จับคู่หลายอินพุตไปเอาต์พุตเดียว (−3 และ 3 → 3) = ไม่ 1-ต่อ-1 = ไม่ reversible → ทำตรงๆ ไม่ได้ ต้องเพิ่ม scratch qubit (คิวบิตทด) เข้ามารับข้อมูลที่จะหาย (ในที่นี้คือ sign bit)

scratch ไม่ใช่การ copy

อ่านจาก circle notation: ถ้าไม่มี scratch ผังจะมีแค่แถวเดียว การย้ายวงของค่าลบไปทับช่องค่าบวกจะทำลาย magnitude/phase ที่อยู่ตรงนั้นอยู่แล้ว · scratch เพิ่มอีกแถวหนึ่ง ให้ย้ายลงไปได้โดยของเดิมไม่ถูกแตะ

ผลข้างเคียง: scratch จะ entangled (พัวพัน) กับ output register เสมอ — ไม่ใช่สำเนาแยกอิสระ · จึง READ ทิ้งไม่ได้ (จะทำลาย output ที่มันช่วยสร้าง) และมันแทบไม่เคยกลับไป |0⟩ เอง

Pitfalls

ลิสต์ลิงก์กลับไปจุดจริงในเนื้อหา — ไม่เขียนเนื้อซ้ำที่นี่

จุดที่คนมักพลาด

  • Lec01 · QPU คืออะไร — “QPU มาแทน CPU / เร็วกว่าทุกงาน” ผิด มันคือ co-processor ที่เก่งบางงาน
  • Lec01 · QPU คืออะไร — “ต้องเก่งฟิสิกส์ก่อนถึงเขียนโปรแกรมได้” ผิด (สไลด์เทียบกับ C++ กับทรานซิสเตอร์)
  • Lec02 · ข้อ 1 bit vs qubit — “superposition = เป็น 0 และ 1 พร้อมกัน อ่านได้ทั้งคู่” ผิด · qubit 1 ตัวอ่านได้ 1 บิตเท่านั้น
  • Lec02 · ข้อ 2 amplitude — “phase เปลี่ยน → โอกาสวัดเปลี่ยน” ผิด phase ไม่แตะ magnitude² · กับดักหลักของ Lec02
  • Lec02 · ข้อ 3 circle notation — จำผิดว่า “รัศมี = ความน่าจะเป็น” ของจริงคือ พื้นที่
  • Lec02 · ข้อ 5 READ/WRITE — “WRITE ตั้ง superposition ได้” ผิด ตั้งได้แค่ ∣0⟩ / ∣1⟩
  • Lec02 · ข้อ 6 QRNG — “รัน QRNG บน simulator = สุ่มแท้” ผิด simulator ยังใช้ PRNG
  • Lec02 · ข้อ 7 PHASE — “gate ควอนตัมทุกตัวเป็น its own inverse” ผิด PHASE(θ) ต้องย้อนด้วย PHASE(−θ)
  • Lec02 · ข้อ 8 no-cloning — “ก๊อป qubit เก็บไว้ก่อนแล้วค่อยวัด” ทำไม่ได้ ไม่มีคำสั่ง COPY
  • Lec02 · ข้อ 9 เมทริกซ์ — คูณผิดลำดับ · gate ที่ทำก่อนต้องอยู่ขวาสุด (วงจรอ่านซ้าย→ขวา แต่สูตรคูณขวา→ซ้าย)
  • Lec02 · ข้อ 10 RNOT — คิดว่า RNOT เป็น its own inverse เหมือน NOT · ทำสองทีได้ NOT ไม่ใช่กลับที่เดิม (ตัวย้อนคือ H·PHASE(−90°)·H)
  • Lec02 · ข้อ 10 RNOT — เดาว่า RNOT ทีเดียวแล้ว READ ได้ 1 ที่ 0% หรือ 100% · ของจริง 50% (หยุดครึ่งทางพอดี)
  • Lec02 · ข้อ 11 Bloch sphere — จำสลับว่า ROTX/ROTY แกนไหน · ROTY(90°)∣0⟩ = ∣+⟩ ส่วน ROTX(90°)∣0⟩ = ∣−Y⟩
  • Lec02 · ข้อ 11 Bloch sphere — คิดว่า PHASE เปลี่ยนโอกาสวัดได้ · หมุนรอบแกนตั้ง = ละติจูดเดิม = โอกาสเท่าเดิม
  • Lec02 · ข้อ 11 Bloch sphere — คิดว่า state อยู่ข้างในทรงกลมได้ · normalization ล็อกความยาวลูกศร = 1 → อยู่บนผิวเสมอ
  • Lec02 · ข้อ 11 Bloch sphere — เอาทรงกลมไปวาด 2 qubit · ใช้ได้กับ 1 qubit เท่านั้น หลายตัวต้อง circle notation (2ᴺ วง)
  • Lec02 · ข้อ 11 Bloch sphere — คิดว่า ∣+⟩ ∣−⟩ ∣+Y⟩ ∣−Y⟩ วัดแล้วต่างกัน · 50/50 เหมือนกันหมด ต่างแค่ phase
  • Lec02 · ข้อ 12 Spy Hunter — สรุปว่า “ค่าไม่ตรง = มีสปาย” · ต้อง HAD ตรงกันด้วย ถ้าฐานไม่ตรงให้ทิ้งทุกกรณี
  • Lec02 · ข้อ 12 Spy Hunter — คิดว่าสปายก๊อป qubit ผ่านไปเงียบๆ ได้ · no-cloning บังคับให้ต้อง READ = ทิ้งร่องรอย
  • Lec03 · 2ᴺ วง — เข้าใจผิดว่า 2 qubit วาด 2 วงต่อ qubit; ของจริง N qubit = 2ᴺ วง (เคส 2 qubit ที่ได้ 4 เท่ากันเป็นเรื่องบังเอิญ)
  • Lec03 · operator pairs — สลับกันระหว่าง "NOT ขยับของ" กับ "PHASE ไม่ขยับของ"; PHASE ไม่เปลี่ยนความน่าจะเป็นเลย
  • Lec03 · PHASE ครึ่งหนึ่ง — คิดว่า PHASE แตะทุกวง; แตะเฉพาะครึ่งที่บิตนั้น = 1 เสมอ ไม่ว่า register ใหญ่แค่ไหน
  • Lec03 · READ ใน register — คิดว่า READ qubit เดียวยุบทั้ง register; จริงๆ ตัดครึ่งที่ขัดกับผลแล้ว renormalize qubit ที่เหลือยังซ้อนทับอยู่
  • Lec03 · ชื่อสาย — เรียกสายว่า Q1/Q2/Q3; ต้องเรียกตามน้ำหนักบิต 0x1/0x2/0x4 และเส้นบนสุด = 0x1 (LSB)
  • Lec03 · phase kickback — คิดว่า “ใช้ gate 2 qubit แล้วต้อง entangle” · จริงๆ kickback ไม่เกิด entanglement สถานะยัง separable
  • Lec03 · CPHASE / CZ — นั่งหาว่าข้างไหน control ข้างไหน target · มัน สมมาตร สลับแล้วผลเหมือนเดิม สัญลักษณ์จึงเป็น φ—φ และ ●—●
  • Lec03 · swap test — อ่านได้ผลฝั่ง “เหมือน” แล้วสรุปว่าเหมือนแน่ · สรุปไม่ได้ ต้องรันซ้ำ — มีแต่ผลฝั่ง “ต่าง” ครั้งเดียวที่ฟันธงได้
  • Lec03 · CNOT + Bell pair — คิดว่า CNOT เดี่ยวๆ สร้าง entanglement · ต้องมี HAD ทำให้ control เป็น superposition ก่อน
  • Lec03 · Bell’s theorem — คิดว่าละเมิด Bell inequality = ส่งข้อมูลเร็วกว่าแสงได้ · เลือกผลไม่ได้ จึงเป็นแค่ shared randomness
  • Lec03 · CNOT บนวงจร — คิดว่า ● ต้องอยู่เส้นบนเสมอ · สไลด์ p41–42 วาง ● ไว้เส้นล่าง ให้ดูที่รูปสัญลักษณ์ ไม่ใช่ตำแหน่ง
  • Lec04 · ตาราง Bob 4 กรณี — จำสลับ X/Z · ท่องว่า “ep เป็นฝาแฝดของ bob → รายงานเรื่องบิต คุม NOT (X) · alice ผ่าน HAD → รายงานเรื่องเฟส คุม PHASE(180) = Z” (ลำดับ X/Z สลับได้ แต่บิตไหนคุม gate ไหนสลับไม่ได้)
  • Lec04 · teleportation คือ/ไม่ใช่อะไร — คิดว่า สื่อสารเร็วกว่าแสง · ก่อน Bob ได้ 2 บิตคลาสสิก เขาถือของที่ดูเหมือนสุ่มล้วน จึงเร็วเกินแสงไม่ได้
  • Lec04 · teleportation คือ/ไม่ใช่อะไร — คิดว่า ต้นฉบับยังอยู่ = ก๊อปสำเร็จ · Alice READ ทิ้งทั้ง payload และ ep เสมอ ถ้าไม่ทำลายก็ละเมิด no-cloning ทันที
  • Lec04 · teleportation คือ/ไม่ใช่อะไร — คิดว่าย้าย สสาร/ตัว qubit · ย้ายแค่ state (magnitude + relative phase) ตัว qubit ไม่ไปไหน

  • Lec04 · Step 3.1 — คิดว่า CNOT ของ Alice ย้าย payload ไปให้ Bob แล้ว · CNOT แค่ผูก 3 ตัวเข้าด้วยกัน ตัวที่ทำให้ข้อมูลไหลไปคือ HAD ใน Step 3.2
  • Lec04 · แกน 4 บรรทัด — คิดว่า Alice ต้องรู้ว่า payload คือสถานะอะไรก่อนส่ง · Bell measurement ถามแค่ “สัมพันธ์กันแบบไหนใน 4 แบบ” ไม่ได้ถามว่า payload คืออะไร
  • Lec04 · Step 5 verify — คิดว่า verify ได้ 0 ครั้งเดียว = teleport ถูกแน่นอน · ของที่ “เกือบถูก” ก็มักผ่าน ต้องรันหลายรอบ
  • Lec04 · post-selection — คิดว่า post-selection เป็นส่วนหนึ่งของโปรโตคอลจริง · เป็นแค่วิธีอ่านผลการทดลอง (ทิ้งรอบที่ Bob บังเอิญแก้ไม่ตรง) เพราะ QASM บน ibmqx4 ไม่มี if
  • Lec05 · abs(−4) — เห็น abs(−4) = −4 แล้วคิดว่าเป็นบั๊ก · เป็นคำตอบที่ถูก (+4 ล้นช่วง 3 บิต) · คำตอบผิดที่มักเลือกคือ 011 เพราะลืม +1 หลัง flip
  • Lec05 · scratch qubit — คิดว่า scratch คือการ copy ค่าไว้ · จริงๆ มัน entangled กับ output เสมอ จึง READ ทิ้งไม่ได้ และไม่กลับเป็น |0⟩ เอง
  • Lec05 · uncomputing — คิดว่า uncompute จะล้างคำตอบหายไปด้วย · ลำดับต้องเป็น compute → use → uncompute · ที่หายคือ scratch ไม่ใช่ผลที่ “ใช้” ไปแล้ว (uncompute ทันทีหลัง compute ต่างหากที่ล้างคำตอบทิ้ง)
  • Lec05 · c = a + b — เขียนบวกแบบภาษาคลาสสิก · ผิดทั้ง 2 กติกา (ทับค่าเดิมใน c = ไม่ reversible · ถ้าทำได้จะถอด b = c − a ได้ = ก๊อป qubit) ต้องใช้ +=
  • Lec05 · ลำดับ gate ของ increment — ไล่จากบิตต่ำขึ้นบิตสูง · ต้องไล่จาก gate ที่มี control เยอะสุดลงไปน้อยสุด ไม่งั้นเงื่อนไข carry อ่านค่าที่เปลี่ยนไปแล้ว · decrement = ชุดเดิมกลับหลัง ไม่ใช่วงจรใหม่ → ดูโค้ด
  • Lec05 · a.add(12) — สลับลำดับ X:2 กับ CNOT:2,3 · สลับแล้วได้ 1→5 ซึ่งผิด · และอย่าลืมว่า register 4 บิต wrap mod 16 (5 + 12 = 1)
