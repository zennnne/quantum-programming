Real Data — เอาข้อมูลจริงเข้า QPU

คาบนี้ตอบ 2 คำถาม: ① ข้อมูลที่ซับซ้อนกว่าจำนวนเต็ม (ทศนิยม · vector · matrix) แทนใน register ยังไง และ ② จะอ่านข้อมูลเข้า register ยังไง (ไม่ใช่ตั้งค่าทีละบิตด้วยมือ) — ไล่จากเล็กไปใหญ่: ตัวเลข 1 ตัว → memory (QRAM) → vector → matrix

1. Fixed point — แทนเลขทศนิยมด้วย qubit

แทนเลขไม่ใช่จำนวนเต็มใน binary มี 2 แบบ: fixed point (จุดทศนิยมตายตัว) กับ floating point (จุดทศนิยมลอยตัว) — floating ยืดหยุ่นกว่า แต่ qubit มีค่ามากและอยากให้ง่าย จึงเริ่มที่ fixed point: แบ่ง register เป็น 2 ส่วน

  • ส่วน integer — binary ปกติ น้ำหนักบิต 2⁰, 2¹, 2², … (ยิ่งสูงยิ่งใหญ่)
  • ส่วน fractional (เศษ) — น้ำหนักบิต ½¹, ½², ½³, … = ½, ¼, ⅛, … (ยิ่งลึกยิ่งเล็ก)

Qn.m = register n bit · m bit เป็นเศษ · (n − m) bit เป็นจำนวนเต็ม

(Q ใน Q notation ไม่ได้ย่อมาจาก quantum — มีไว้บอกว่าบิตเศษจบตรงไหน บิตจำนวนเต็มเริ่มตรงไหน)

ตัวอย่างบนสไลด์ (Figure 9-1): เก็บ 3.640625 ใน register 8 qubit แบบ Q8.6 (เศษ 6 bit + จำนวนเต็ม 2 bit) — ป้ายซ้ายแต่ละสาย = น้ำหนักของบิตนั้น · สายบนสุด = บิตน้ำหนักต่ำสุด (1/64) · ▷ เหลืองทึบ = write 1 · ▷ วงฟ้า = write 0

11.101001 → 2 + 1 + ½ + ⅛ + 1/64 = 2 + 1 + 0.5 + 0.125 + 0.015625 = 3.640625

ตัวนี้ลงตัวพอดีเป๊ะเพราะบังเอิญเป็นผลรวมของกำลังของ 2 — ปกติไม่โชคดีขนาดนั้น ต้องปัดเข้าค่าที่ใกล้สุด

เพิ่มบิตฝั่งไหนได้อะไรตัวเลข
ฝั่ง integer (n − m) เพิ่ม range (ช่วงค่าที่แทนได้) ค่าสูงสุดแบบไม่ติดลบ = 2n−m − ½m · เช่น Q8.6 → 4 − 1/64 = 3.984375 (คิดจากน้ำหนักบิต ไม่ได้เขียนบนสไลด์)
ฝั่ง fractional (m) เพิ่ม accuracy (ความแม่นยำของส่วนเศษ) ความละเอียด (ช่องห่างเล็กสุด) = ½m = ค่าบิตเศษตัวสุดท้าย · Q8.6 → 1/64 = 0.015625

ตัวอย่างปัดค่า (จากบทเรียน 0034): Q3.2 = จำนวนเต็ม 1 bit + เศษ 2 bit → ก้าวทีละ ¼ แทนได้ 0, 0.25, 0.5, …, 1.75 → อยากเก็บ 1.3 ได้ใกล้สุดคือ 1.25 (= 1 + ¼ · คลาด 0.05)

register ไม่รู้ตัวว่าตัวเองเป็น encoding อะไร

ต้องจำเองว่า register ไหนใช้ binary ธรรมดา / two's complement / fixed point ไม่งั้นตีความ state ผิด · และระวัง overflow (ล้น) — ผลใหญ่เกินที่ register แทนได้ → ได้ตัวเลขไร้ความหมาย · ทางแก้จริงทางเดียว = เพิ่ม qubit

อ่านตัวเต็ม → บท 0034 (fixed point · RAM · QRAM)

2. RAM vs QRAM

ทั้งคู่รับ register 2 ตัว: address (บอกตำแหน่ง) กับ output (รอรับค่า) แล้วตั้ง output = ค่าที่เก็บอยู่ ณ address นั้น — ต่างกันที่ QRAM ให้ทั้งสอง register เป็น qubit register จึงใส่ address เป็น superposition ได้

ประเด็นRAM ธรรมดาQRAM
ตั้งค่า register ด้วยค่าเดียว ได้ดี — write() / read() · CPU เป็นคนเลือก a[index] แล้วส่งค่าให้ QPU (QCEngine ก็ทำแบบนี้เบื้องหลัง) ได้
ตั้งเป็น superposition ของค่าที่เก็บไว้หลายค่า ไม่มีทาง — ข้อบกพร่องร้ายแรง ได้ — address เป็น superposition (เช่น H ที่บิต address) → output เป็น superposition ของค่า ณ address เหล่านั้น โดย amplitude ตามที่ใส่ใน address
ฮาร์ดแวร์ มีอยู่แล้ว หนังสือไม่บอกวิธีสร้าง (มีแค่ข้อเสนอเทคโนโลยี) · QPU ที่ทรงพลังอาจมาก่อน QRAM ที่ใช้ได้จริงนานมาก · โค้ดตัวอย่างรันบน simulator ที่เลียนพฤติกรรม QRAM — สำคัญที่แนวคิด fundamental resource (ทรัพยากรพื้นฐาน)

Figure 9-4 — address สายบน write 1 · สายล่าง write 0 แล้ว H → address = ∣1⟩ + ∣3⟩ → ตาราง: 01 → 110 (= 6), 11 → 111 (= 7) → output = ∣6⟩ + ∣7⟩ (50/50)

ข้อจำกัดของ QRAM ตามสไลด์

  • เขียน superposition กลับลง QRAM ไม่ใช่จุดประสงค์ — QRAM มีไว้อ่านค่าดิจิทัลที่เขียนแบบธรรมดา ในลักษณะ superposition · หน่วยความจำที่เก็บ superposition ไว้ได้ไม่จำกัดเวลา = persistent quantum memory เป็นฮาร์ดแวร์อีกชนิด และอาจสร้างยากกว่า QRAM
  • ยังไม่รู้ว่าฮาร์ดแวร์จริงจะหน้าตาแบบไหน — รายละเอียดการ implement อาจเปลี่ยนได้อีก
  • ไม่มี QRAM ก็สร้างวงจร amplitude encoding ได้ แต่ไม่ efficient (QCEngine จำลองแบบช้าแต่ใช้ได้)
ลำดับบิตบนสไลด์ RAM/QRAM ขัดกันเอง

ข้อความ p15 “เก็บ 3 (110) ที่ 0x01 และ 5 (111) ที่ 0x11” — ของจริง 110 = 6, 111 = 7 (อ่านซ้าย = MSB) ซึ่งตรงกับวง ∣6⟩ ∣7⟩ ใน Figure 9-4 · และ “0x01 / 0x11” จริงๆ คือ binary 01 / 11 · ถ้าถามตรงๆ ตอบตามสไลด์ แต่รู้ของจริงไว้

3. Vector: state encoding vs amplitude encoding

vector ยาว N เช่น v⃗ = [0, 1, 2, 3] (เจอบ่อยใน quantum machine learning) เก็บใน QPU ได้ 2 แบบ:

ประเด็นstate encodingamplitude encoding
เก็บยังไง component ละ 1 register เก็บค่าเป็นเลขฐานสองใน basis state เดียว (วงเต็มวงเดียว ไม่มี superposition) ทุก component อยู่ใน amplitude ของ superposition ใน register เดียว — component ที่ i = amplitude ของ ∣i⟩
ใช้กี่ qubit (vector ยาว N) N × (จำนวนบิตต่อ component) ⌈log₂ N⌉ — register k qubit มี 2k amplitude · N ไม่เป็นกำลังของ 2 ก็เติม 0 ให้ครบ
ต้องมี QRAM ไหม ไม่ต้อง — เก็บใน RAM ธรรมดาแล้วเตรียมทีละ register ต้องพึ่ง QRAM (ไม่มีก็ทำได้แต่ไม่ efficient)
อ่านค่าออกได้ไหม ได้ — แต่ละ register เป็น basis state ธรรมดา ไม่ได้ทีละ component (Caveat 1) — READ ได้ผลเดียวแบบสุ่มแล้ว state ยุบ · ได้แค่ global properties (คุณสมบัติภาพรวม)
เงื่อนไข เลือก binary encoding ให้เหมาะ (เช่น fixed point) ต้อง normalize: Σ∣aᵢ∣² = 1 (Caveat 2) · ใส่ค่าเชิงซ้อนได้ (ใช้ทั้ง magnitude + phase → จึงชื่อ amplitude ไม่ใช่ magnitude encoding)
ข้อเสียหลัก กิน qubit เยอะ (ทรัพยากรที่หายากสุด) และใช้พลัง QPU ไม่ได้ — จัดการ relative phase ยากเมื่อแต่ละ register เป็นแค่ binary ธรรมดา output ที่เป็น amplitude-encoded vector อ่านออกมาไม่ได้ (“no free lunch”)

4. Matrix encoding / quantum simulation

วิธีตรงๆ: matrix m × n → m register ยาว log₂(n) qubit แล้ว amplitude-encode ทีละ row — ใส่ข้อมูลเข้าได้ แต่ไม่ได้แทน “ในฐานะ matrix” (ไม่ชัดว่าจะ transpose หรือคูณกับ vector ยังไง) → เข้ารหัส matrix เป็น QPU operation ที่กระทำกับ register ที่เก็บ vector แทน

  • แทนได้ถูก = M·v ↔ U∣v⟩ ได้ผลตรงกันทุก v · เกณฑ์ที่ง่ายกว่า: eigen decomposition เดียวกัน — eigenstates ของ U = amplitude encoding ของ eigenvectors ของ M · eigenphases “สัมพันธ์กับ” eigenvalues (สไลด์ไม่ได้บอกว่าเท่ากัน)
  • แค่นั้น “เกือบพอ” — ต้องมี prescription (วิธีสร้างจาก gate พื้นฐาน) และต้อง efficient ด้วย = good matrix representation

Quantum simulation = คำเรียกรวมของวิธีหา QPU operation ที่ efficient เพื่อแทน Hermitian matrix (H = H† · † = transpose แล้ว complex conjugate) — ทุกเทคนิคอย่างน้อยต้องการ H ที่เป็น Hermitian เพราะ QPU operation ต้องเป็น unitary และ

U = exp(−iHt) เป็น unitary เสมอเมื่อ H เป็น Hermitian

t = เวลาที่ทำ operation (ถือเป็นรายละเอียด hardware) · ชื่อ “simulation” มาจากฟิสิกส์ — H ที่อธิบายระบบเรียกว่า Hamiltonian · matrix X ที่ไม่ Hermitian → ห่อเป็น block matrix ที่ใหญ่ขึ้น:

H = [ 0   X ; X†   0 ]

(บนซ้าย 0 · บนขวา X · ล่างซ้าย X† · ล่างขวา 0 → H† = H จึงเป็น Hermitian · overhead ทำครั้งเดียว มักไม่มีนัยสำคัญ)

3 ขั้น (เกือบทุกวิธี): ① Deconstruct — แตก H = H₁ + … + Hₙ ให้แต่ละชิ้น simulate ง่าย (เช่นมีแต่ diagonal หรือกระทำกับ qubit ไม่กี่ตัว) → ② Simulate components — หาวงจรของ Hᵢ แต่ละตัว → ③ Reconstruction — ประกอบกลับด้วย Lie product formula: ทำ U₁ = exp(−iH₁δt), …, Uₙ = exp(−iHₙδt) ต่อกันทีละช่วงสั้น δt แล้ววนทั้งชุดซ้ำ m รอบ

exp(−iHt) ≈ (U₁ U₂ … Uₙ)m

(สูตรบรรทัดนี้เป็นการสรุปเป็นสัญลักษณ์ — สไลด์พูดเป็นคำ ไม่ได้เขียนสูตรตรงๆ)

ขั้น ① ทำยังไง (ตัวอย่างของ product formula): ถ้า H เป็น sparse → มองเป็น adjacency matrix ของ graph แล้วแก้ coloring problem (vertex ที่มี edge ต่อกันห้ามสีเดียวกัน) — สีแต่ละสีจับกลุ่มสมาชิกเป็นชิ้น H₁ … Hₙ (สไลด์ไม่ได้อธิบายกลไกต่อ · หัวสไลด์เขียน “Destructing H” = Deconstructing)

ขนาด block matrix บนสไลด์

สไลด์: X ขนาด m × n → H ขนาด 2m × 2n และ block ศูนย์ขนาด m × n — ตอบตามสไลด์
ของจริง: X† เป็น n × m → block ศูนย์บนซ้าย m × m · ล่างขวา n × n · H = (m+n) × (m+n) (Hermitian ต้องจัตุรัส) — สองแบบตรงกันเฉพาะ m = n
