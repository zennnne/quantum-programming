Quantum Supersampling (QSS)

ภาพรวมทั้งคาบในบรรทัดเดียว

วาดภาพความละเอียดสูงลงใน phase → แบ่งเป็น tile → นับว่าแต่ละ tile โดน flip กี่ subpixel ด้วย AA + QFT (sum estimation) → แปลค่า READ ผ่าน lookup table → ได้ความสว่างของ pixel พร้อมบอกว่ามั่นใจแค่ไหน · QSS รวม primitive 3 ตัว: quantum arithmetic (Lec05) · amplitude amplification (Lec06) · QFT (Lec07)

1. QSS ไม่ได้เร็วกว่า แต่ noise คนละแบบ

supersampling (การสุ่มหลายจุดต่อ pixel) ของ ray tracing = ยิงหลาย ray ต่อ pixel (ปกติหลักร้อยถึงหลักพัน) แล้วเก็บแค่ค่าเฉลี่ย ที่เหลือทิ้งหมด เรียกอีกชื่อว่า Monte Carlo sampling · เป็นงานขนานที่สุดท้ายต้องการแค่ผลรวม ไม่ใช่ผลรายตัว → ฟังดูเหมาะกับ QPU

QSS ถูกสร้างมาเพื่อเร่งความเร็ว supersampling และล้มเหลวตามเกณฑ์นี้ · error เฉลี่ยต่อ pixel พอๆ กับวิธีเดิม แต่ลักษณะ (character) ของ noise ต่างกันมาก:

วิธีFigure 11-1Figure 11-12 (ภาพวงแหวน 64×64)หน้าตา noise
Conventional Monte Carlo error เฉลี่ย 2% · pixel ไม่ผิดเลย 34% error เฉลี่ย 9% · pixel ไม่ผิดเลย 23% ผิดนิดๆ ทุก pixel (เม็ดหยาบทั่วภาพ)
Quantum Supersampling error เฉลี่ย 1% · pixel ไม่ผิดเลย 41% error เฉลี่ย 6% · pixel ไม่ผิดเลย 46% ส่วนใหญ่เป๊ะ บาง pixel ผิดแรง (จุดดำ/ขาวเดี่ยวๆ)

4. 🔴 Sum estimation: นับว่า tile โดน flip กี่ subpixel ด้วย AA + QFT

เป้าหมายต่อ tile (p30): ประมาณจำนวน subpixel ที่ถูก flip (เรียก M จาก 16) · จำนวนนี้คือความสว่างของ pixel · วิธีเดิม (Monte Carlo) ต้องรันโปรแกรมวาดซ้ำหลายรอบ สุ่ม qx, qy ทุกรอบ ได้ดำหรือขาวทีละ sample แล้วเอามาบวกกัน · QSS ใช้ Quantum Sum Estimation: ให้โปรแกรมวาดรูปเป็น flip ของ AA แล้วต่อด้วย QFT

ทำไมต้องมีทั้ง AA และ QFT

AA (Lec06) — แปลง "จำนวน" เป็น "ความถี่" phase ที่วาดไว้ READ ตรงๆ ไม่ได้ (หัวข้อ 2) · แต่ AA ทำให้เกิดการแกว่งที่ขึ้นกับจำนวนค่าที่ถูก flip · ถ้าทำ AA หลายจำนวนรอบพร้อมกันใน superposition การแกว่งจะไปกางอยู่ตลอด register และ ความถี่ของมันขึ้นกับ M (p38)
QFT (Lec07) — อ่าน "ความถี่" ออกมาเป็นตัวเลข ความถี่ที่ซ่อนอยู่ใน register READ ตรงๆ ไม่ได้เหมือนกัน · ต้องใช้ QFT (ในโค้ดคือ invQFT) หาความถี่ → ได้จำนวนที่ถูก flip → ได้ความสว่าง (p38) · AA อย่างเดียวไม่มีตัวอ่าน · QFT อย่างเดียวไม่มีความถี่ให้อ่าน
จำนวนที่ถูก flip → ความถี่ของการแกว่ง → QFT อ่านความถี่ → READ → lookup table → ความสว่าง

ไล่ทีละขั้น (ตามโค้ด Example 11-4 · p33–34)

① เตรียม: write 0 แล้ว HAD qx, qy (ผ้าใบของ tile 16 subpixel) และ HAD register counter (ตัวนับ)
② counter = จำนวนรอบ AA: ค่าของ counter กำหนดว่าจะทำ AA กี่รอบ · HAD counter ไว้แล้ว = superposition ของจำนวนรอบ AA ทุกค่าพร้อมกัน (p37) · counter 4 qubit → 0 ถึง 15 รอบ
③ AA 1 รอบ (เรียกว่า G) = shader_quantum (flip = วาดรูป) + grover_iteration (mirror) · qubit ของ counter ที่มีน้ำหนัก 2ʲ คุม G ซ้ำ 2ʲ รอบ · เช่น counter = |6⟩ = 0x2 + 0x4 → G² · G⁴ = 6 รอบ
④ เกิดการแกว่ง: แต่ละแขนงของ counter ทำ AA ไม่เท่ากัน → amplitude แกว่งเป็นคาบตลอด counter register · ความถี่ขึ้นกับ M
⑤ invQFT บน counter → ความถี่กลายเป็นค่าที่มีโอกาส READ สูง
⑥ READ counter → แปลงผ่าน lookup table (qss_count_to_hits) เป็นจำนวน hits → ความสว่าง = hits ÷ จำนวน subpixel ใน tile

5. Lookup table + confidence: READ ได้ค่านี้ มั่นใจกี่ %

ค่าที่ READ จาก counter "เกี่ยวข้องกับ แต่ไม่เท่ากับ" จำนวน subpixel ขาว (p41) · QSS lookup table แปลง READ → จำนวน subpixel · ไม่ขึ้นกับภาพ (QSS นับแค่ว่าขาวกี่ตัว ไม่สนว่าตัวไหน) → สร้างครั้งเดียว reuse ได้กับทุกงานที่ tile กับ counter ขนาดเท่ากัน

① ตัวอย่างสไลด์ (p43): READ 10 → ไปแถว 10
② ช่องสว่างสุดที่คอลัมน์ 5 → น่าจะขาว 5 ตัว
③ แต่ 4 หรือ 6 ก็เป็นไปได้ (และน้อยลงไปคือ 3 หรือ 7) → error มาจากตรงนี้
