Quantum Fourier Transform (QFT)

ประโยคแกนของคาบนี้

AA ดึงข้อมูลของค่าเฉพาะที่ซ่อนในเฟส · QFT ดึง "รูปแบบ" (pattern) — คือความถี่ที่เฟสหมุนวนตลอด register — ออกมาเป็นจุดยอด (peak) ที่ READ เห็นได้ (สไลด์ p2, p69)

1. QFT ทำอะไร — ความถี่ในเฟส → จุดยอดที่ READ เห็น

2. DFT · จุดยอดคู่ (กระจก) · ความถี่ไม่ลงตัว

QFT = ทำ transform เดียวกับ DFT แต่ทำกับสัญญาณที่อยู่ใน quantum register · DFT = แบบคลาสสิก · FFT = อัลกอริทึมที่คำนวณ DFT ได้เร็วที่สุด = คู่แข่งตัวจริงของ QFT · ทั้ง FFT และ QFT ต้องใช้สัญญาณยาวเป็นกำลังของ 2 (p9–12)

DFT ของ sine wave จริง 8 Hz (256 sample, p23–28): output เป็นจำนวนเชิงซ้อน 256 ค่า — magnitude = ความถี่นั้นมีมากแค่ไหน, phase = offset · ได้ peak สองอัน ที่ 8 และ 256 − 8 = 248

สไลด์วาดไม่ตรงตัวเลข (p24/p26/p27)

รูปคลื่นในสไลด์นับได้แค่ 6 รอบ แต่ข้อความบอก "สั่นครบ 8 รอบ = 8 Hz" และ peak ติดป้าย 8 / 248 → ตอบตามตัวเลขในสไลด์: 8 Hz, peak 8 กับ 248

ทำไมมีกระจก? เกิดกับสัญญาณจริงเท่านั้น (p28–31) · สัญญาณที่เข้ารหัสในเฟสของ register เป็นจำนวนเชิงซ้อน → ไม่มีกระจก ได้ peak เดียว (ตัวอย่างข้อ 1) · แต่ถ้าเข้ารหัสใน magnitude (เฟสมีแค่ 0°/180° = บวก/ลบ ยังเป็นจำนวนจริง) → QFT ได้ peak คู่แบบ DFT เป๊ะ เช่น cos 1 รอบใน magnitude (Figure 7-12) → |1⟩ กับ |15⟩ เท่ากัน (Figure 7-13) ⇒ ต้องรู้ว่า input เข้ารหัสใน phase หรือ magnitude ถึงจะตีความถูก

ความถี่ไม่ลงตัว → peak แผ่ (p27): รอบฐาน peak มีค่าเล็กๆ ไม่เป็นศูนย์ (สไลด์ให้เหตุผลว่า output มีจำนวน bit จำกัด) และ QFT ก็เป็นแบบนี้ได้ — ค่ารั่วไปช่องข้างเคียง · เห็นชัดเมื่อจำนวนรอบไม่ลงช่องพอดี เช่น 8.4 รอบ:

3. Harmonics — square wave → หลายจุดยอด

พูดให้ตรงกว่า "บอกความถี่": DFT/QFT บอก ความถี่ + สัดส่วน + offset ของคลื่นไซน์ที่รวมกันได้เป็นสัญญาณ (p32) · ความสูงสัมพัทธ์ของ peak = ความถี่ไหนมีส่วนมากน้อย · ช่อง 0 = DC bias (เส้นฐานที่สัญญาณแกว่งรอบๆ) (p34)

square wave ไม่ใช่ไซน์เลย → ได้ peak ที่ฮาร์มอนิกคี่ ของความถี่หลัก (f, 3f, 5f, …) สูงลดลงราว 1, ⅓, ⅕ … (p35)

ใน QPU (p36–39): qc.had() แล้ว qc.phase(180, 16) บน qubyte = สลับ +/− ทีละ 16 ค่า = square wave 8 รอบ → QFT → peak ที่ 8 + 16k (8, 24, …, 248 รวม 16 ค่า) · โอกาส READ ได้ 8 หรือ 248 ≈ 0.405 ต่ออัน (รวม ≈ 81%) · ฮาร์มอนิกลำดับ k ลดลงราว 1/k² (เพราะความน่าจะเป็น = |amplitude|²)

เวอร์ชัน 4 qubit (Figure 7-6/7-7/7-8): phase(180, p) หลัง HAD ทุกสาย → peak อยู่ที่จำนวนคี่เท่าของ 8/p

4. QFT เร็ว แต่ใช้ยังไง → invQFT

อัลกอริทึมขนาด inputจำนวน operation
FFT (คลาสสิก)n บิตO(n·2ⁿ)
QFT (ควอนตัม)m qubitO(m²)

ในทางปฏิบัติ สัญญาณเล็กกว่า ~22 บิต (≈ 4 ล้าน sample) FFT บนโน้ตบุ๊กยังเร็วกว่า · เกินนั้น QFT ชนะและทิ้งห่างเร็วมาก (Figure 7-20, p41–42)

แต่ไม่ได้เอามาแทน FFT เพราะผล QFT ถูกล็อกอยู่ใน register → ติด 2 ปัญหา (p43–45):

  1. ใส่สัญญาณเข้ายังไง — ข้อมูลคลาสสิกทั่วไปอาจไม่มีวงจรง่ายๆ เตรียมให้ ต้นทุน initialize อาจกลืนความได้เปรียบของ QFT จนหมด หรือต้องเพิ่มฮาร์ดแวร์นอก QPU
  2. อ่านผลออกยังไง — ถ้า output เป็น superposition หลายความถี่ (เช่น square wave) READ ได้แค่ความถี่เดียวแบบสุ่ม

ยังใช้ได้ 2 กรณี (p46–47): (1) แอปยอมรับ "ความถี่หลักหรือจำนวนเท่าของมัน" แบบสุ่มได้ · (2) แอป verify คำตอบได้ → ผิดก็รันใหม่ (แบบนี้ใน Shor's algorithm, Lec12) ⇒ QFT มีค่าในฐานะ phase manipulation primitive

invQFT (p48–53): รับ register ที่แทน frequency space → คืนสัญญาณของความถี่นั้น · ใช้เตรียม superposition ที่แปรเป็นคาบได้ง่าย: เขียนเลขความถี่ลง register แล้วใส่ invQFT

  • ความถี่เดียว / ไม่สมมาตร → สัญญาณแปรเป็นคาบในเฟส · เฟสวงถัดไปเพิ่มทีละ n/2N × 360° ทวนเข็ม (p57) เช่น write(2) 4 qubit → ทีละ 45° · write(3) → ทีละ 67.5° (เฟสแกว่ง 3 รอบ)
  • คู่สมมาตร เช่น |1⟩ + |15⟩ → สัญญาณแปรเป็นคาบในmagnitude (สัญญาณจริง)
  • เปลี่ยนความถี่: QFT → บวก 1 → invQFT (สัญญาณเชิงซ้อนความถี่ 2 กลายเป็น 3)

ข้างในกล่อง (1 บรรทัดพอ): H + CPHASE มุมลดลงครึ่งหนึ่งทีละขั้น (90°, 45°, 22.5° …) + SWAP กลับลำดับบิต · QFT ใช้มุมลบ · invQFT ใช้มุมบวก

แยก QFT กับ invQFT ด้วยอะไร

ดูที่เครื่องหมายมุม CPHASE (QFT = −90°/−45°/… · invQFT = +90°/+45°/…) — ไม่ใช่ตำแหน่ง SWAP: สไลด์วาด invQFT แบบ SWAP ต้นวงจร (p49, p53) และแบบ SWAP ท้ายวงจร (p55, p63) ซึ่งให้ผลเท่ากัน
